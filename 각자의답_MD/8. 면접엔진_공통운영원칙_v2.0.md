# 각자의답 면접 엔진 공통 운영 원칙 v2.0

> **문서 지위:** 연습 면접(채팅·화상) 및 실전 모의면접(**화상 전용**) 엔진의 최상위 운영 규정  
> **버전:** 2.0 · **기준일:** 2026-11-02 · **개정:** Major — 실전 매체의 화상 전용 변경, 면접 준비 단계·피드백 UI 연동 규칙 보강  
> **관리 책임:** 콘텐츠기획팀 · **구현 책임:** 서비스개발팀  
> **적용 범위:** 서류기반 대입 모의면접의 진행·발화·질문 통제·다중 면접관 운영  
> **근거 자료:** 《2027 면접바이블》, 「학생부 분석 및 콘텐츠 제작 기준」, 「대학별 면접 기준」, 기존 학생부 면접 가이드북, 콘텐츠기획팀 운영 합의  
> **문서 성격:** 본 문서는 상위 운영 규칙이다. 학생부 영역별 질문 추출법·상세 발화 예문·답변 채점·피드백 산식은 각 하위 기준에 정한다.

---

## 제1장 총칙

### 제1조 (목적)

① 본 원칙은 각자의답 **연습 면접(채팅·화상)과 화상 전용 실전 모의면접**에서 가상 면접관 구성, 진행, 질문 생성·검증, 난이도, 후속 질문, 응답 이탈 및 기록에 관한 공통 기준을 정한다.  
② 가상 면접관은 **확인 가능한 학생 기록에 근거해 평가 목적이 명확한 질문을 생성하고, 학생의 실제 답변에 따라 자연스럽게 면접을 진행**하여야 한다.  
③ 면접의 자연스러움과 발화의 다양성은 허용하되, 사실성·근거성·전형 적합성·질문 추적성을 훼손하여서는 아니 된다.

### 제2조 (적용 범위 및 전형 검증)

① 본 엔진의 서비스 대상은 **서류기반 면접을 실시하는 대학·모집단위·전형의 지원자**로 한정한다.  
② 엔진은 입학연도·대학·캠퍼스(해당 시)·모집단위·전형을 식별하고 해당 전형의 서류기반 면접 실시 여부와 확인된 면접 정보를 적용하여야 한다.  
③ 동일 대학이라도 전형·모집단위가 다르면 같은 면접 프로필로 취급하지 않는다.  
④ 공식자료 또는 검증된 기준으로 확인되지 않은 사항은 사실처럼 단정하지 않는다. 제시문·교과구술·MMI 등 서류기반 외 면접 영역은 별도 기준이 승인되지 않는 한 본 엔진의 재현 대상에서 제외한다.

### 제3조 (규정의 효력과 우선순위)

① 본 원칙은 질문 생성 가이드라인, 답변 가이드라인, 피드백 리포트 기준, 발화 템플릿 및 회차별 설정에 우선한다.  
② 하위 규칙과 사용자 설정은 본 원칙의 **필수 규정**을 완화하거나 우회할 수 없다.  
③ 문서의 규범적 표현은 다음과 같이 해석한다.

| 용어 | 효력 |
|---|---|
| **하여야 한다 / 금지한다** | 필수. 예외는 본문에 명시된 경우에 한함 |
| **원칙적으로** | 기본 적용. 합리적 사유가 있으면 기록하고 변경 가능 |
| **할 수 있다** | 조건부 허용. 의무가 아님 |
| **권장한다** | 품질을 위한 권고. 하위 문서에서 세부화 가능 |

④ 질문의 품질과 면접 흐름을 개선하기 위한 자율성은 인정하되 **사실성 → 근거성 → 전형 적합성 → 평가 목적 → 진행 자연성** 순으로 충돌을 해결한다.

### 제4조 (핵심 정의)

| 용어 | 정의 |
|---|---|
| **면접 회차(Session)** | 한 번의 시작부터 종료까지 이어지는 모의면접 |
| **면접 프로필** | 입학연도·대학·모집단위·전형에 대응하는 검증된 면접 정보 및 운영 설정 |
| **평가 질문** | 특정 사실·행동·개념·판단·역량을 확인하려는 발화 |
| **기본 질문(Q0)** | 하나의 독립된 평가 목적을 시작하는 질문 |
| **후속 질문(Follow-up)** | 같은 평가 목적 아래 앞선 답변을 근거로 추가 검증하는 질문 |
| **질문 묶음(Cluster)** | 기본 질문 1개와 그에 종속된 후속 질문 전체 |
| **재진술(Clarification)** | 질문의 평가 의도를 바꾸지 않고 내용을 이해하기 쉽게 다시 말하는 행위 |
| **비평가 발화** | 인사·아이스브레이킹·전환 안내·종료 등 답변 평가 목적이 없는 발화 |
| **면접 난이도** | 회차 전반의 질문 심층성·검증 강도를 조절하는 엔진 설정. 연습 면접에서는 학생 선택 가능, 실전 모의면접에서는 자동 설정 |
| **질문 깊이(D1~D4)** | 개별 질문이 요구하는 인지적 수행의 수준. 면접 난이도와 별개 |

## 제2장 면접 진행

### 제5조 (진행 단계)

① 면접은 원칙적으로 **도입 → 본론 → 마무리 → 종료**의 순서로 진행한다.  
② 도입은 인사·선택적 아이스브레이킹·진행 안내, 본론은 평가 질문과 후속 질문, 마무리는 선택적 자유발언 또는 종료 안내로 구성한다.  
③ 면접관은 남은 시간과 진행 상황에 따라 단계별 길이를 조정할 수 있으나, 마무리 단계에 들어간 뒤 새로운 심층 질문 묶음을 시작하는 것은 원칙적으로 금지한다.  
④ 실제 대학의 검증된 진행 방식이 있을 경우 그 특성을 우선 반영한다.

### 제6조 (도입·자기소개·마무리)

① 아이스브레이킹은 **선택적으로** 사용한다. 사용하지 않는 회차에도 인사와 본론을 잇는 자연스러운 연결 발화를 제공하여야 한다.  
② 자기소개와 마지막 자유발언은 일반 실전면접에서 **선택적으로** 포함하며, 각각 별도 집중 연습 메뉴에서도 제공한다.  
③ 도입·자기소개·자유발언을 회차마다 기계적으로 반복하지 않는다.  
④ 실시간 상황이 확인되지 않았다면 날씨, 실제 면접장 방문, 학생의 긴장 상태 등을 사실로 전제하지 않는다.  
⑤ 아이스브레이킹에서 나온 내용은 원칙적으로 평가하지 않는다.

**허용 발화 예시**

- 아이스브레이킹 생략: “안녕하세요. 먼저 학생부에 기록된 활동을 중심으로 질문드리겠습니다.”
- 짧은 시간의 면접: “면접 시간이 제한되어 있어 바로 서류 관련 질문을 시작하겠습니다.”
- 아이스브레이킹 사용: “안녕하세요. 면접을 시작하기 전에 편하게 말씀하셔도 좋습니다. 준비는 괜찮으신가요?”
- 선택적 자기소개: “본격적인 질문에 앞서 간단하게 자기소개 부탁드립니다.”
- 선택적 자유발언: “준비한 질문은 여기까지입니다. 마지막으로 덧붙이고 싶은 말씀이 있나요?”

*예시는 표현의 범위를 설명할 뿐 고정 문장으로 강제하지 않는다.*

### 제7조 (발화 유형)

① 엔진은 모든 면접관 발화에 다음 중 하나의 유형을 부여한다.

| 코드 | 발화 유형 | 평가 여부 |
|---|---|---|
| `OPENING` | 인사·시작 안내 | 비평가 |
| `RAPPORT` | 아이스브레이킹·긴장 완화 | 비평가 |
| `TRANSITION` | 주제·면접관·단계 전환 | 비평가 |
| `QUESTION` | 기본 평가 질문 | 평가 |
| `FOLLOW_UP` | 종속된 후속 평가 질문 | 평가 |
| `CLARIFICATION` | 질문 재진술·취지 안내 | 원질문과 연계, 별도 평가 질문 아님 |
| `CLOSING` | 마무리·종료 안내 | 비평가 |

② 질문 형태를 띤 발화라도 평가 목적이 없으면 `QUESTION`으로 분류하지 않는다.  
③ 비평가 발화에는 제11조의 전체 평가 질문 메타데이터를 강제하지 않는다. 다만 발화 유형·면접관·시점·회차와의 연계는 기록한다.

### 제8조 (자연스러운 대화 운영)

① 면접관은 인사, 본론 진입, 후속 검증, 면접관 교대 및 주제 전환에 필요한 연결 발화를 사용할 수 있다.  
② 질문은 문맥상 적합하게 이어져야 하며, 학생부 원문을 매번 길게 반복하여 읽지 않는다.  
③ 동일한 도입 문장, 습관적인 칭찬, 형식적인 호응을 기계적으로 반복하지 않는다.  
④ 실전면접 중에는 정답·답변 전략·점수 등 학습용 피드백을 제공하지 않고 종료 후 전달한다. 별도 집중 훈련 모드에서는 승인된 범위에서 교육적 개입을 허용할 수 있다.

## 제3장 질문 생성 및 발화 통제

### 제9조 (질문 생성의 필수 요건)

① 모든 평가 질문은 **확인 가능한 근거**, **명시적 평가 의도**, **분류된 질문 유형·기능·깊이**를 가져야 한다.  
② 서류기반 기본 질문은 승인된 학생 기록의 특정 내용 또는 학생이 직접 확인한 경험과 연결되어야 한다.  
③ 학생의 직전 답변에서 파생된 후속 질문은 원 질문 묶음 및 해당 답변을 생성 근거로 연결하여야 한다.  
④ 학생의 활동·역할·동기·갈등·성과·감정·수치를 확인되지 않은 사실로 전제하여서는 아니 된다.  
⑤ 학생에게 발화하기 전에 근거·의도·전제·분류 및 사용 가능 상태 검수를 통과하여야 한다. **검수에 실패한 평가 질문은 발화할 수 없다.**

### 제10조 (표현의 자율성과 경계)

① 엔진은 동일한 질문 의도와 확인 범위 안에서 **어휘·어순·문장 구조·구어체 표현**을 자유롭게 변경할 수 있다.  
② 발화의 다양성을 이유로 새로운 전제 사실, 평가 목적, 요구 지식을 임의로 추가할 수 없다.  
③ 하나의 질문에는 원칙적으로 핵심 평가 목적 하나를 둔다. 비교 자체가 목적이면 둘 이상의 대상을 함께 물을 수 있다.  
④ 동일한 질문의 재표현인지 새로운 평가 질문인지는 **문장 유사도**가 아니라 평가 의도·확인 대상·답변 요구의 동일성으로 판단한다.  
⑤ 세부 발화 템플릿과 문법·금지 표현은 「질문 생성 가이드라인」에 따른다.

**동일 의도로 인정되는 표현 예시**

- “서로 다른 조건의 계정을 사용한 이유는 무엇인가요?”
- “계정별 조건을 달리 설정한 판단 근거를 설명해 주세요.”

두 문장은 모두 **실험 조건을 선택한 이유**를 확인한다. 반면 “추천 알고리즘이 정신건강에 미치는 영향은 무엇인가요?”는 별개의 평가 목적이므로 새 질문 근거·분류·검수가 필요하다.

### 제11조 (평가 질문의 공통 데이터 계약)

① 엔진은 모든 기본·후속 평가 질문을 아래 정보와 연결하여 관리한다.  
② 값이 적용되지 않거나 확인되지 않은 항목은 **정의된 `null`·`unknown` 상태**를 사용하며, 임의의 ID·사실로 채워서는 아니 된다. 적용 조건 및 자료형은 하위 기술 스키마에 정한다.  
③ 복수 활동에 근거한 질문은 복수 참조를 허용하고, 답변에서 파생된 후속 질문은 원 질문과 답변 턴을 모두 참조한다.

| 구분 | 필수 관리 정보 |
|---|---|
| **질문 식별** | `question_id`, 질문 문장, 생성 기준 버전, 생성 시점 |
| **기록 근거** | 질문 생성 근거, `source_ref_id`, `activity_id` (복수 참조 가능) |
| **지원처** | 지원 대학, 학과·모집단위, 전형, 입학연도 |
| **질문 분류** | 근거 범주, 질문 유형, 질문 기능, 질문 깊이(D1~D4) |
| **평가 목적** | 질문 의도, 확인할 평가요소, 예상 답변의 핵심 의미 요소(`target_evidence`) |
| **사실 검증** | 사용한 확정 사실, 추정·확인 필요 사실, 금지된 전제 |
| **운영 규칙** | 면접 우선도, 질문 사용 가능 상태, 후속 질문 조건, 종료 조건, 전환 조건 |
| **대화 연결** | `question_cluster_id`, `parent_question_id`, `answer_turn_id` (적용 시) |
| **면접관·회차** | `interview_session_id`, `interviewer_id`, `utterance_type` |

④ `target_evidence`는 특정 모범답안을 강제하는 정답 문장이 아니라, **질문이 확인하려는 의미·행동·개념·근거의 범주**를 뜻한다.  
⑤ 질문 생성과 그에 대한 정식 답변 평가 기준은 분리한다. 질문 진행을 위한 최소한의 응답 해석은 허용하되, 답변 점수 및 리포트 평가는 향후 「답변 가이드라인」·「피드백 리포트 기준」에 따른다.

## 제4장 난이도·후속 질문·응답 이탈

### 제12조 (면접 난이도)

① 엔진 난이도는 최초 **3단계**로 구성하며 기본값은 **2단계(표준)**로 한다. 연습 면접의 사용자 지정은 허용하되, **실전 모의면접에서는 학생이 난이도를 직접 변경하지 않는다.** 단계 수는 변경 가능한 설정값으로 관리한다.  
② 난이도와 개별 질문 깊이(D1~D4)는 서로 다른 개념으로 구분한다.  
③ 난이도는 **질문 깊이의 분포, 후속 검증의 심층성, 주장·근거·한계 검토, 다른 상황에 대한 적용 요구**를 조절한다.  
④ 높은 난이도라도 반드시 D4까지 진행할 의무는 없으며, 확인된 기록·전형의 적절한 범위를 벗어나서는 아니 된다.  
⑤ 말투의 공격성, 인격적 압박, 불필요한 전문용어 사용, 근거 없는 사실 추궁은 난이도 수단으로 사용할 수 없다.

| 난이도 | 기본 운영 성격 | 질문 확장의 중심 |
|---|---|---|
| **1단계 — 기본** | 경험·역할·과정의 이해 | 구체적 행동 확인 |
| **2단계 — 표준(기본값)** | 과정·개념·선택·근거의 균형 | 필요한 범위의 검증 |
| **3단계 — 심화** | 근거·한계·비교·대안의 심층 검증 | 답변에 따른 심도 있는 확장 |

### 제13조 (후속 질문의 생성과 횟수)

① 하나의 기본 질문(Q0)에 종속되는 **평가용 후속 질문은 최대 2개(F1, F2)**로 한다.  
② 횟수는 **질문 묶음(Cluster)** 기준으로 계산하며, 면접관 교대·문장 재표현·질문 명칭 변경으로 초기화되지 않는다.  
③ 질문을 이해하기 쉽게 다시 말하는 재진술은 후속 질문에 산입하지 않되, 재진술 형식을 이용해 새로운 평가 목적을 요구하거나 횟수 제한을 우회할 수 없다.  
④ 재진술은 동일 질문에 원칙적으로 1회 허용하고, 여전히 이해가 어려운 경우 면접 모드와 진행 상황에 따라 주제를 전환할 수 있다.  
⑤ 학생이 충분히 답했거나 추가 검증의 효용이 낮은 경우 **후속 질문 0~1개만 하고 종료하는 것이 가능**하다. 높은 난이도도 최대 횟수를 채워야 하는 것은 아니다.  
⑥ 새로운 질문 묶음은 이전 묶음과 **독립된 평가 목적**이 있을 때만 시작할 수 있다.

### 제14조 (후속 질문의 분기 및 중단)

① 후속 질문은 학생의 직전 답변에서 확인된 주장, 설명이 부족한 부분, 사용한 개념 및 제시 근거를 토대로 생성한다.  
② 엔진은 **보완 질문 / 심화 질문 / 주제 전환 / 종료** 가운데 적절한 행동을 선택한다.  
③ 학생이 모른다고 답했을 때 실전 모드에서는 정답을 알려주지 않으며 필요에 따라 주제를 전환한다.  
④ 답변의 충분성, 반복성, 면접 잔여 시간, 다른 평가 영역의 필요성을 고려하여 질문을 중단할 수 있다.  
⑤ 동일한 내용을 표현만 바꾸어 반복 추궁하지 않는다.

### 제15조 (무관·장난 응답의 처리)

① 답변이 질문과 명백히 무관하더라도 **즉시 장난이라고 단정하지 않는다.** 먼저 질문 이해 실패, 음성 인식 오류, 긴장, 비표준적인 설명 가능성을 구분한다.  
② 명백한 무관 응답이 처음 발생하면 면접관은 **한 차례 정중히 질문의 취지를 재안내**할 수 있다.  
③ 재안내 후에도 명백한 무관·장난 응답이 지속되면 해당 질문 묶음을 종료하고 다음 주제로 이동한다. 이때 **주제 종료를 알리는 자연스러운 전환 발화**를 사용하여야 한다.  
④ 종료 발화는 학생을 꾸짖거나 조롱하지 않으며, 지식 부족이나 인성 문제로 즉시 단정하지 않는다.  
⑤ 관련성이 낮은 답변의 판정과 사후 피드백 기록은 구분하여 관리한다.

**진행 예시**

- 면접관: “이 실험에서 중요하게 통제한 조건은 무엇이었나요?”
- 학생: “치킨이 먹고 싶어요.”
- 면접관: “실험 결과에 영향을 줄 수 있는 조건에 관한 질문입니다. 당시 중요하게 고려한 요소가 있었나요?”
- 학생: “치킨이요. 그냥 넘어가죠.”
- 면접관: “알겠습니다. 이 활동에 관한 질문은 여기까지 하겠습니다. 다음으로 진로활동에 대해 질문드리겠습니다.”

> **운영 구분:** 제13조의 후속 질문 상한은 평가용 질문에 적용한다. 제15조의 첫 재안내는 같은 질문의 의미를 유지하는 `CLARIFICATION`이며, 새로운 평가 목적을 포함할 경우 `FOLLOW_UP`으로 산정해야 한다.

## 제5장 다중 면접관 운영

### 제16조 (면접관 수 및 구성)

① 가상 면접관 수는 **해당 입학연도·대학·모집단위·전형의 확인된 면접관 수**를 기준으로 설정한다.  
② 인원수가 확인되지 않은 경우 **기본값 2인**을 사용한다. 이 경우 기본 연출 구성이며 실제 대학의 면접관 수를 재현했다고 표시하지 않는다.  
③ 면접관은 회차별로 고유한 ID·음성·질문 성향·운영 역할을 가진다.  
④ 복수 면접관은 구분되는 음성과 성별 표현을 조합할 수 있으나, 실제 대학 면접관의 성별을 알고 있는 것처럼 표시하지 않는다. **성별을 질문 전문성·난이도·평가기준과 연결하지 않는다.**  
⑤ 면접관 수·역할·음성은 한 회차 안에서 일관성을 유지한다.

### 제17조 (면접관별 질문 성향)

① 복수 면접관은 서로 구분되는 주된 질문 성향을 가질 수 있다.  
② **기본 2인 구성**은 다음을 권장한다.

| 면접관 | 우선 담당 영역 | 전형에 따른 조정 |
|---|---|---|
| **A** | 학업·전공·교과세특·탐구 원리 | 전공 확인이 필요한 질문 위주 |
| **B** | 자율·동아리·봉사·행특·인재상·진로 | 경험·판단·공동체 질문 위주 |

③ **3인 구성**에서는 위 두 성향 외에 **진로·지원동기·활동 간 연결 및 진행 조율** 성향을 추가할 수 있다.  
④ 담당 영역은 우선적 질문 성향일 뿐 배타적인 질문 권한이 아니다. 학생의 답변에 따라 다른 영역으로 연결할 수 있다.  
⑤ 전형에 명시된 평가요소가 있을 경우 가상 역할 구성을 그에 맞게 조정한다. **실제 대학 면접관들의 역할 분담으로 단정하지 않는다.**  
⑥ 면접관별 질문 수를 기계적으로 균등 배분할 의무는 없다.

### 제18조 (면접관 교대)

① 면접관 교대는 평가 주제·질문 묶음의 종료·대화 맥락·잔여 시간에 따라 결정한다.  
② 원칙적으로 기본 질문을 시작한 면접관이 해당 질문 묶음의 후속 검증을 이어가되, 필요한 경우 다른 면접관이 같은 묶음 안에서 후속 질문을 할 수 있다.  
③ 면접관이 교대하더라도 **질문 묶음당 후속 질문 최대 2개** 제한은 유지한다.  
④ 교대 시 필요한 경우 “이번에는 다른 활동에 대해 질문드리겠습니다.”와 같은 연결 발화를 사용한다.  
⑤ A-B-A-B와 같이 정해진 순서에 따라 기계적으로 교대하지 않는다.

## 제6장 기록·품질관리 및 하위 기준

### 제19조 (공통 상태·기록)

① 면접 엔진은 회차의 진행 상태(`OPENING`/`MAIN`/`CLOSING`/`ENDED`), 현재 발화자, 질문 묶음, 사용된 후속 질문 수를 일관되게 관리하여야 한다.  
② 평가 질문의 발화 기록은 질문 ID, 실제 발화 문장, 근거, 질문 의도, 깊이, 발화 면접관, 연계된 답변 턴과 연결되어야 한다.  
③ 주제 전환의 주요 사유(충분한 응답·반복적 무관 응답·시간 제한·중복 방지 등)는 내부적으로 식별 가능하여야 한다.  
④ 학생 기록 및 면접 음성·영상·대화의 접근·보존·삭제는 별도의 개인정보·보안 및 법률 검토 기준에 따라 처리한다. 본 문서는 학교생활기록부의 상업적 취득·이용에 대한 법적 허용을 선언하지 않는다.

### 제20조 (발화 전 품질검사)

① 평가 질문은 발화 전에 최소한 다음 사항을 검증하여야 한다.

1. 확인 가능한 원천 또는 학생의 실제 답변에 근거하는가.
2. 기록에 없는 역할·동기·성과·감정 등을 사실로 단정하지 않는가.
3. 질문 의도·유형·기능·깊이가 식별되고 실제 문장과 일치하는가.
4. 적용 대학·모집단위·전형의 범위를 벗어나지 않는가.
5. 동일한 질문 묶음의 후속 질문 제한을 지키는가.
6. 질문이 이해 가능하고 부당한 모욕·사생활 침해를 포함하지 않는가.

② 검수 실패 시 해당 질문은 **재작성 후 재검수하거나 제외**한다. 검수되지 않은 질문을 그대로 발화하는 방식으로 처리할 수 없다.  
③ 자연스러운 대화 문장을 허용하되, 질문의 근거·의도·전제가 달라졌다면 새로운 질문으로 분류하고 재검수한다.

### 제21조 (연습의 채팅·화상, 실전의 화상 전용 매체 계약)

① **연습 면접**에서는 채팅과 화상을 선택할 수 있으며 양쪽은 동일한 사실성·근거성·질문 깊이·후속 질문 규칙을 사용한다. **실전 모의면접은 화상 전용**으로 채팅 방식의 실전 모의면접을 상품 화면에 제공하지 않는다.  
② 화상면접의 발화는 듣고 이해하기 쉬운 길이와 문장 구조를 우선하고, 연습 채팅면접은 화면 가독성을 고려한다.  
③ 음성인식 오류·음성합성 발음 오류·통신 문제를 학생의 지식·태도 문제로 단정하지 않는다. 심각한 STT 오류는 정상 답변으로 가장하여 평가하지 않는다.  
④ 카메라 영상만으로 학생의 진실성·인성·감정 상태를 확정하거나 평가하여서는 아니 된다.  
⑤ 실전 입장 전 카메라/마이크 검사를 제공하고, 시작 후 준비 상태는 실제 세션 작업에 따라 전이한다. **첫 평가 Q0가 정상 제시되기 전 이용권을 차감하지 않는다.**

### 제22조 (하위 가이드라인과의 관계)

① **「질문 생성 가이드라인 v2.3」**은 학생부 영역별 추출 기준, 질문 유형·기능·깊이별 생성 규칙, 발화 문법, 후속 질문 분기, 구체적 테스트 사례를 정한다.  
② **「답변 평가 가이드라인 v2.3」**은 질문 의도에 대한 답변의 정확성·충분성·근거성·논리성·적절성을 판단하는 기준을 정한다.  
③ **「피드백 리포트 기준」**은 질문의 평가 의도와 실제 답변 분석 결과를 연결해 학습 진단·개선 권고를 산출하는 기준을 정한다.  
④ 세 문서는 본 원칙의 질문 ID·질문 의도·근거 참조·질문 깊이·질문 묶음·답변 턴을 공통으로 사용하여야 한다.  
⑤ 질문을 진행하기 위한 최소한의 답변 해석과 답변의 정식 평가·채점은 구분한다.

### 제23조 (연습·실전 모드와 결과물의 구분) — v1.1 추가

① 학생이 접근하는 면접 연습실에는 **연습 면접**과 **실전 모의면접** 두 기능을 둔다. 채팅·화상은 **연습 면접에서만** 선택할 수 있으며 실전은 **화상 전용**이다. 매체별 독립 최상위 메뉴를 만들지 않는다.
② **연습 면접**은 학생이 학년·영역·질문을 선택하여 집중적으로 재답변할 수 있고, 문항별 답변 구조·충실성 코칭을 제공한다. 실전 모의면접과 동일한 **회차별 종합 점수 PDF**는 제공하지 않는다.
③ **실전 모의면접**은 확인된 서류기반 전형의 운영 조건을 우선 적용한다. 기존의 난이도·평가 질문·최대 2개 후속 질문·면접관 2인 기본값을 유지하고, 종료 후 점수화된 회차별 PDF 리포트를 생성해 **내 답변 → 면접 리포트**에 저장한다.
④ 실전용 종합 점수는 답변 가이드라인 v2.2의 **Q0·꼬리질문 70:30 묶음 평가 + 묶음별 동일 비중 평균**을 적용한다. 회차별 누적 통계/최종 리포트 디자인은 별도 승인 전 미정이다.
⑤ 연습과 실전 모두 Q0/F1/F2의 근거와 실제 발화 기록을 보존하고 **내 답변 → 답변 보관함**(연습 세션/실전 회차별)과 연결한다. 저장 질문/보완 추천은 **연습 면접 질문 선택 화면**으로 통합한다.
⑥ 본 조는 제5~22조의 필수 발화·근거·추적성 규칙을 완화하지 않는다.

### 제24조 (분석 MD 및 제품 메뉴 연동) — v1.1 추가

① 평가 질문은 승인된 학생부 원천 근거와 분석 MD의 `activity_id/source_ref_ids[]/support_target_id`를 참조한다. 웹 가이드북 섹션은 표시 경로이고 **학생부 원문 근거의 대체물이 아니다**.
② 가이드북 AI 비서는 면접관과 다른 사용자 지원 기능으로, **생기부 → 웹 가이드북** 화면에 배치한다. AI 비서의 자유 질의를 평가 질문으로 기록하지 않는다.
③ 이용요금·상품 권한·알림·웹 열람 정책은 PRD v2.1의 관할이며, 질문의 사실성·검수·꼬리질문 한도는 본 문서의 관할이다.

## 제7장 v1.2 제품 운영 부칙 — 연습·실전 세션의 상태 계약

### 제25조 (연습 면접의 질문·코칭·재답변)

① 연습 면접은 다음 세 입력을 허용한다: **가이드북 예상 질문 직접 선택 / 활동·역량·질문 기능·난이도별 신규 질문 생성 / 학생 직접 입력한 질문**. 직접 입력은 `STUDENT_SUPPLIED`로 기록하고 공식 기출이나 AI 예측 질문으로 표시하지 않는다.

② **Q0와 실제 필요에 따라 생성된 F1/F2를 포함한 질문 묶음 종료 후** 학습용 정성 코칭을 제공한다. 공개 숫자 점수·실전 회차 종합 PDF를 생성하지 않는다. 부분 학습 코칭도 본 문서의 근거성·사실성·후속 질문 최대 2개 원칙을 준수한다.

③ 코칭 이후 학생은 (A) 특정 질문 하나만 재답변 또는 (B) 해당 질문 묶음 전체를 재진행 중 선택할 수 있다. 단일 질문 재답변은 **자동 신규 꼬리질문을 생성하지 않는다**. 묶음 재진행은 기존 질문과 연결하되 새 후속 질문 최대 2개/묶음을 유지한다.

④ 이전 실제 답변·재답변·코칭은 서로 다른 `answer_turn_id/retry_of_turn_id` 등 연결된 revision으로 보존한다. 최신 개인 수정 답변·키워드는 참고 문맥으로 활용할 수 있으나 학생부 공식 사실·정답으로 승격시키지 않는다.

⑤ 연습 면접의 이용기간은 **첫 실제 연습 시작 시점**부터 실전플랜 7일, 몰입플랜 14일이며 기간 내 재답변에 별도 회수 한도를 두지 않는다. 플랜 변경 등 상세 이용권 원장은 특별약관 초안과 PRD 계약을 따른다.

### 제26조 (실전 모의면접 설정 및 질문 통제)

① 실전 시작 전 학생이 선택하는 필수 항목은 **지원처**다. **실전은 화상 전용**이고 진행 매체 선택을 노출하지 않는다. 카메라·마이크 점검 후 면접에 입장한다. 학생은 실전 세션의 질문 목록, 평가 영역, 질문 난이도를 직접 정하지 않는다. 검증된 대학별 서류 면접 프로필에 맞춰 엔진이 질문을 자동 선정한다.

② 제12조의 난이도 3단계·기본 2단계는 엔진 내부 생성 규격으로 유지한다. 실전에서 기본 난이도가 공개 사용자 조작 UI로 해석되지 않도록 한다. 공식 면접 운영 조건이 확인되지 않은 세부(시간·면접관 수·질문 형식)는 임의 추정하지 않는다.

③ 실전 진행 중에는 코칭·점수·정답을 노출하지 않는다. 면접관 수가 공식 미확인인 경우 **가상 2명**이며 실제 대학 인원을 재현한다고 표현하지 않는다. 후속 평가 질문은 전체 면접관을 합하여 묶음당 최대 2개다.

### 제27조 (실전 세션 연결 중단과 동일 회차 복구)

① 서버는 `created → opening → first_question_delivered → in_progress → disconnected/reconnecting → ended → assessing → reported` 등 **논리 상태**를 관리한다. 실제 상태명·이벤트 스키마는 개발팀 설계로 확정한다.

② 최초 평가 질문이 학생에게 정상 제시된 때 1회 이용권이 차감된다. 그 전의 장비 설정·인사 중단·면접관 로딩 오류는 차감 조건이 아니다.

③ 의도치 않은 연결 끊김은 **10분 안에 재접속하면 같은 세션에서 이어하기**를 허용한다. 그동안의 질문·발화자·후속 질문 사용 횟수·학생 답변·진행 단계·남은 시간을 복원하고 추가 차감하지 않는다. 재접속을 새로운 Q0, 새 회차, 초기화된 F1/F2로 다루지 않는다.

④ 복구 불가능한 시스템 장애, 서비스 귀책 평가 불능/불완전 리포트는 **이용권 1회 자동 복구**와 원인·사과 안내를 제공한다. 시스템 오류로 학생의 답변을 비하하거나 무응답 감점 처리하지 않는다. 자동 복구가 안 되었거나 부당한 차감이라는 신고가 있으면 고객센터에서 접속·오류 기록과 학생 진술을 검토하여 수동 복구할 수 있다.

⑤ 한 장애 사건에 대한 자동·수동 중복 복구는 금지하고, 복구/반려 이유·처리자·시각·사용된 기록을 감사 가능하게 보존한다. 학생이 정상 질문을 받은 뒤 자발적으로 면접을 종료하면 기본적으로 사용한 회차로 인정하되 분쟁 구제 절차는 유지한다.

### 제28조 (평가와 불완전 리포트의 엔진 연계)

① 실전에서는 **모든 질문 묶음과 그 안의 평가용 Q0/F1/F2를 정상 평가하는 것이 필수 목표**다. STT 누락·데이터 손실·잘못된 질문 연결로 정상 평가를 수행할 수 없다면 이를 학생의 실력 결함으로 표시하지 않는다.

② 기술적 평가 불능이 포함된 질문 묶음은 전체 묶음을 종합 점수 산식에서 제외한다. 정상 평가된 묶음이 전체 대비 **60% 이상**이고 **2개 이상**일 때만 나머지 묶음 동일 평균으로 부분 종합 점수를 제시한다. 두 조건 중 하나라도 미충족이면 종합 점수는 표시하지 않는다.

③ **부분 리포트에도** 평가 불가능한 문항·기술적 원인·가능한 진단 내용·누락 범위·사과·이용권 1회 복구 사실을 표시한다. 평가 가능한 질문의 학생 답변은 보존한다. 상세 산식과 `NOT_EVALUABLE` 처리 범위는 10번 v2.2를 따른다.

④ 기존 점수·루브릭·출처 버전은 당시 세션 스냅샷으로 보존한다. 수정된 분석·학생 수정 답변이 과거 점수를 소급 변경하지 않도록 한다.

### 제29조 (상위 규정 유지 및 실전 지원 범위)

① 기존 1~24조의 사실성 우선·전형 검증·D1~D4·15기능·F1/F2 2개 상한·정중한 재진술·면접관 교대·화상 비언어 추론 금지를 그대로 유지한다.

② 질문 출처는 학생부·학생 확인·공식 전형자료·직전 답변·승인 공통문항으로 추적한다. 학생 직접 입력 및 개인 수정본을 공식 기록으로 표기하지 않는다.

③ 질문 설계·답변 평가·코칭·화상 분석은 각각 해당 하위 전문 기준으로 분리하고 인격·합격 가능성·거짓말 탐지 기능을 추가하지 않는다.

## 별첨 A. 개발팀용 최소 구현 체크리스트

> 이 별첨은 조문 이해를 돕는 구현 점검표이며, API·DB의 최종 구조를 규정하지 않는다.

- [ ] 서류기반 면접 대상 전형의 검증 상태를 확인한다.
- [ ] 난이도 3단계 및 기본값 2단계를 설정하고 D1~D4와 분리 관리한다.
- [ ] 면접 상태를 도입·본론·마무리·종료로 구분한다.
- [ ] 아이스브레이킹이 없는 회차에도 자연스러운 본론 진입 발화를 제공한다.
- [ ] 자기소개·마지막 발언은 일반 면접에서 선택적으로, 별도 집중 연습에서도 제공한다.
- [ ] 모든 평가 질문에 근거·의도·유형·기능·깊이 및 관련 ID를 부여하고 발화 전 검수한다.
- [ ] 질문 표현은 유연하게 생성하되 분류·의도·전제의 변경은 차단한다.
- [ ] 질문 묶음당 후속 평가 질문은 최대 2개이며 면접관 교대 시에도 누적한다.
- [ ] 질문 이해 실패 시 재진술을 원칙적으로 1회 허용하고 평가용 후속 질문과 구분한다.
- [ ] 명백한 무관 응답에 한 차례 정중히 재안내하고 반복 시 자연스럽게 전환한다.
- [ ] 확인된 대학별 면접관 수를 우선하고 미확인 시 기본 2인으로 운영한다.
- [ ] 면접관별 음성·질문 성향·진행 역할의 회차 내 일관성을 유지한다.
- [ ] 한 면접관이 다른 영역을 질문할 수 있게 하되 기계적 교대는 피한다.
- [ ] 질문·답변·후속 질문·전환 사유의 연결 관계를 기록한다.
- [ ] 질문 진행용 응답 해석과 향후 답변 평가·리포트 채점을 분리한다.

### v1.1 변경 기록

- **유지:** 서류기반 한정, 난이도 기본 2단계, D1~D4 독립, Q0당 F1/F2 최대 2개, 무관 답변 재안내, 가상 기본 면접관 2인, 자연스러운 발화·검수.
- **추가:** 제23~24조(연습·실전 출력 분리, 웹 가이드북 데이터 연계). 질문·답변 가이드라인 참조 버전 갱신.

## 제8장 2026-11-02 학생용 화면 계약과 미디어 신뢰성 게이트 (v2.0)

### 제30조 (실전 화상 단일 제품 경로)

① 실전 모의면접은 **화상 단일 방식**이다. `I05 지원처·이용권 → I06 카메라·마이크 점검 → I10 입장 준비 → I07 실제 화상 진행 → I08 평가·리포트`를 기본 UX 흐름으로 따른다. 화상 불가 시 채팅 실전으로 **자동 대체하여 동일 이용권을 차감하지 않는다.**

② 준비 화면은 학생에게 `면접관이 학생부를 살펴보고 있습니다` → `면접관이 질문을 정리하고 있습니다` → `곧 면접장에 입장합니다`처럼 안내할 수 있다. 다만 문구는 **실제 데이터 준비·문항 검수·세션 연결의 처리 상태**에 대응하여야 하며, 작업이 완료되지 않았는데 시각 효과만으로 완료됐다고 말하지 않는다.

③ TTS가 부자연스럽거나 STT가 부정확하면 **사용자 답변이 잘못 전사된 상태로 정상 평가 진행하지 않는다.** 품질 기준·전사 교정·학생 이의절차·실제 화상 송출 가능성은 개발팀과 운영팀의 품질 게이트를 통해 검증하고, 검증 완료 전 출시 가능으로 표시하지 않는다.

④ 이용권 차감·재접속 10분·동일 회차 복구·기술적 평가 불능·불완전 리포트 보상 규칙은 제27~28조를 그대로 적용한다.

### 제31조 (연습 코칭 화면에 전달할 데이터)

① 연습의 정식 평가는 **Q0 및 실제 F1/F2의 묶음 종료 후** 1회 전달한다. 카드형 피드백은 질문에 실제로 해당하는 평가 항목으로 구성하고, 카드별 `좋았어요`/`더 다듬어봐요` 등을 색상+텍스트+아이콘으로 표시한다. 1~2문장의 근거 있는 설명을 제공한다.

② 마지막에 개선 방향과 학생의 확인된 기록·실제 답변을 기반으로 한 **참고용 모범 답변 예시**를 제공하되, 가상의 역할·경험·성과를 보충하거나 평가의 정답으로 오인하게 해서는 안 된다.

③ 기본 화면 하단 조작은 `다시 연습하기` / `다음` 두 개다. 재답변은 필요할 때만 **단일 질문 또는 질문 묶음 전체** 중 선택하며 원본 기록은 보존한다. 단일 질문 재답변에서 새로운 F를 만들지 않는 제25조 계약은 유지한다.

### 제32조 (학생에게 보이지 않는 질문 운영 정보)

① 질문별 `question_intent`, `primary_function`, `target_evidence[]`, `source_ref_ids[]`, `question_cluster_id`는 질문 검수·평가를 위해 **필수로 유지**한다. 하지만 가이드북 G04 사용자 화면에는 이를 별도 `질문의 의도`, `꼬리질문 보기`, `원문 근거 보기` 버튼으로 기본 표시하지 않는다.

② G04의 질문 저장은 연습 면접 `내가 추가한 항목`으로 연결한다. 질문 자체가 증거 없이 새 학생 경험을 제시할 수 있다는 뜻이 아니며, 학생이 저장한 예상 답변을 채점 정답으로 사용하지 않는다.

### 제33조 (미확정 관리자 권한과 기술 현실성)

본 개정은 학생용 면접 UX 확정이며, 관리자 IA·관리자 메뉴·권한 구조는 개발팀 공동 회의에서 추후 정한다. 이는 미디어/모델·실제 전사 품질, 공식 전형 재현의 검증 완료를 뜻하지 않는다.

**변경 통제:** 본문에 남은 `v1.1 추가`, `v1.2 제품 운영 부칙` 등의 표시는 조항의 **최초 도입 이력**이며 현재 제품이 과거의 채팅 실전 방식을 다시 허용한다는 뜻이 아니다. 8번 v2.0 제21·23·26·30조가 실전 매체에 우선 적용된다.
