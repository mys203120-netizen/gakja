## 0. 핵심 의사결정과 용어

### 0.1 학생 UI 공통 원칙

1. **학습용 최상위 메뉴는 정확히 네 개:** `생기부 / 면접 연습실 / 내 답변 / 암기 훈련실`. 순서 고정.
2. **메뉴 카드 = 아이콘 + 명칭.** 메뉴 이름 아래 ‘이 메뉴는 ~하는 공간’식 설명문은 기본적으로 제거한다. 이름만으로 전달되지 않으면 문구가 아니라 네이밍을 개선한다. 단, `검수 중`, `잔여 3회`, `면접 하루 전 열려요`, `대학 정보 미확인`과 같은 **필수 상태 정보**는 허용한다.
3. 하나의 기능에 **대표 소속 화면 한 곳**을 배정한다. 이동 경로는 제공할 수 있지만 다른 메뉴에 동일 기능을 중복 구현하지 않는다.
4. 기본 화면에는 **실제 핵심 행동만** 보인다. 카드 전체 클릭 가능할 때 ‘입장’, ‘자세히’, ‘바로가기’ 버튼을 카드 안에 덧붙이지 않는다.
5. AI 비서는 **생기부 가이드북 내부 플로팅 패널**로 한정한다. ‘독립 AI 챗’, ‘오답노트’, ‘독립 암기 핸드북’, ‘대학·학과 최상위 메뉴’, ‘크레딧’ 명칭을 만들지 않는다.
6. 원본 학생부·검증된 분석·공식 대학자료·질문 생성 근거를 사용자 편집 가능 데이터와 구분한다. 사용자는 개인 답변·키워드·메모만 수정 가능하다.
7. 질문/답변/활동/지원처/면접 회차/출처·문서 버전은 내부 ID로 연결하고, 필요하지 않은 엔진 내부 코드(Q0/F1/F2 등)를 학생 화면에 전시하지 않는다.
8. **관리자 콘솔의 위계·메뉴·버튼·권한은 이번 승인 대상이 아니다.** 개발팀과 별도 회의 후 확정한다.

### 0.2 문서 ID 규칙

- `P` 공개 영역, `O` 가입·제작 흐름, `H` MY 홈, `G` 생기부, `I` 면접 연습실, `A` 내 답변, `M` 암기 훈련실, `U` 공통 계정 기능.
- 화면 ID는 **협업 식별자**이며 실제 라우트/컴포넌트/DB 테이블명으로 고정한 것이 아니다.
- `A05`(다시 준비할 질문 독립 메뉴)는 **폐기 ID**. `I10`(실전 입장 단계별 로딩)은 신규 추가 ID.

### 3.3 H01 MY 홈 배치

1. 전역 헤더 및 현재 지원처(정보를 반복 표시할 필요가 없으면 상단 선택기 활용).
2. 상태 카드: 학생부 미등록/플랜 미구매/분석 중/확인 요청/발행 완료 등. **현재 다음 행동이 필요한 경우에만 버튼 1개.**
3. **4개 학습 메뉴 카드**: 명칭+아이콘, **카드 전체 클릭**, 별도 `입장` 버튼 없음.
4. 이용 현황: 실전 면접 잔여 횟수, 연습 이용기간, 완료 회차 등. 기본적으로 읽기 전용.
5. 면접 일정: 학생 개인 확정일/대학 공개 참고일 구분, D-Day 조건부 표시.
6. 하단 정책·문의 링크.

| 상태 | 주행동 |
|---|---|
| 지원처 미등록 | 지원처 등록 |
| 상품 미구매 | 요금제 보기 |
| 학생부 미등록 | 학생부 등록 |
| 처리·검수 중 | 진행 상태 보기 |
| 추가 확인 요청 | 확인 요청 보기 |
| 처리 실패 | 다시 시도 |
| 가이드북 발행 완료 | 별도 CTA 없음; `생기부` 카드로 진입 |

**삭제:** 홈의 `바로 연습하기`, `실전 시작`, `AI 비서 시작`, `리포트 보기`, `학교·학과 분석`, `추천 질문`, `암기 핸드북 다운로드` 중복 진입 카드.

## 4. PART 3 — 생기부 웹 가이드북 (수정 후 확정)

### 4.1 6개 목차와 공통 탐색

1. **나의 면접 전략** — 지원 정보, 진로·학업 흐름, 핵심 키워드, 대표 활동, 면접 우선순위.
2. **학생부 분석** — 원문 전체를 학생부의 실제 항목·학년 순서대로 열람 + 원문에 대응하는 분석 정보.
3. **대학·학과 분석** — 대학·학과 이해, 인재상·평가요소, 면접 특성, 학생부 매칭, 강조 전략.
4. **예상 질문·답변** — 예상 질문·답변, **같은 화면에서 원문 전체 열람 및 근거 하이라이트**.
5. **실전 훈련** — 기억 구조화, 발화 훈련, 꼬리·돌발 대응법, 모의면접 활용법, 직전 점검 *콘텐츠*.
6. **부록** — 전체 질문 리스트, 사실 확인표, 전공·대학 핵심자료, 모의면접 기록지.

`가이드북 사용법`은 보조 안내이며 7번째 본문 목차가 아니다. AI 비서는 가이드북 내부에서만 호출. PC 좌측 목차, 모바일 목차 열기. 데이터가 필요한 장에서만 검색·학년/영역/우선도 필터를 노출하고, 무의미한 도구를 모든 장에 반복하지 않음.

### 4.2 G02 학생부 분석 — 원문 중심

- **학생부의 존재하는 원문 항목을 빠짐없이, 실제 원래 순서대로** 열람. 학적/출결/창의적 체험활동/교과학습발달·세특/독서/행동특성 등 해당 학생부에 있는 항목을 그대로 보여줌.
- 요약문으로 원문을 대체하지 않으며, 원문의 문장·수치·순서·영역 출처를 보존한다.
- 필요한 AI 분석은 원문과 시각적으로 구분하여 배치한다. 원문을 보려면 별도 팝업을 여러 단계 열도록 만들지 않는다.
- 원문·검증된 분석 직접 수정 불가. 인식·사실 오류는 상황에 맞춰 `정정 요청`으로 접수.

### 4.3 G04 예상 질문·답변 — 화면 핵심

**PC 권장 배치:** 왼쪽 `학생부 원문 전체(스크롤)` / 오른쪽 `현재 예상 질문 + 예상 답변`. 질문 선택 시 관련 원문 문장에 **형광펜처럼 자동 하이라이트**하고 해당 위치를 자연스럽게 찾도록 이동. 모바일은 동일 화면 내부의 `학생부 / 질문·답변` 전환으로 처리. 별도 원문 팝업·독립 페이지로 이동시키지 않음.

| 요소 | 동작·노출 |
|---|---|
| 예상 질문 | 선택한 질문의 자연어 본문 |
| 예상 답변 | 승인된 기본 예상 답변 + 학생 개인 수정본(구분 저장) |
| 원문 전체 | 같은 화면에서 열람, 현재 질문의 근거 범위 하이라이트 |
| `답변 수정하기` | 개인 답변 입력 모드, 편집 상태에서는 `저장`/`취소` 노출 |
| `질문 저장하기` | **연습 면접 → 질문 선택 → `내가 추가한 항목`**에 보관; 저장하면 동일 자리에서 `저장됨` 상태·취소 제공 |

**G04 기본 화면에서 삭제:** `원문 근거 보기` 버튼, `질문 의도` 설명, 미리보기 꼬리질문, `연습하기` 버튼, `다시 준비에 저장` 버튼, 암기 키워드 편집, 별도 답변 설계 절차, 기능·난이도·평가 코드 노출. 질문 의도/근거/후속 질문 정보는 엔진 내부 검수·생성 데이터에는 보존 가능하나 화면에서 장황하게 설명하지 않는다.

**중요한 데이터 계약:** 근거 하이라이트는 AI가 비슷한 문자열을 즉석 검색한 결과가 아니라 **학생부 원문 버전 + `source_ref_id`/`activity_id` + 정밀 위치(anchor/span)**에 기초해야 한다. 원문 근거가 없는 지원동기·공통/시사 질문은 학생부 문장에 임의 표시를 하지 않는다. 매칭 불확실 시 과장된 하이라이트 금지. 기존 승인 가이드북 질문은 원본 질문 ID를 보존; 학생 저장목록에만 상태 기록.

### 4.4 G01/G03/G05/G06 및 AI 비서

| 화면 | 핵심 기능/조작 | 삭제·제한 |
|---|---|---|
| G01 나의 면접 전략 | 핵심 전략·대표 활동·우선순위 읽기; 필요한 개인 키워드/메모 편집 | 별도 실전 실행 버튼·중복 지원처 변경 버튼 금지 |
| G03 대학·학과 분석 | 지원처별 공식/참고/미확인 자료 확인; 평가요소와 학생부 매칭 | 대학 공통 인재상을 미확인 학과 고유 인재상으로 변경 금지 |
| G05 실전 훈련 | 면접 준비방법·기억/발화/돌발 대응 콘텐츠 읽기 | 이 장 안에 또 다른 면접 엔진을 구현하지 않음 |
| G06 부록 | 질문·사실·핵심자료 열람, **선택 항목 인쇄/PDF** | 웹 가이드북 전체 PDF 기본 배포 금지 |
| G09 AI 비서 | 가이드북 문맥에서 질의응답; 플로팅 열기/닫기, 질문 보내기 | 다른 메뉴의 전역 챗 금지; 미구현 화면 조작을 수행했다고 말하지 않음 |

- AI 비서가 있기 때문에 매 단락마다 `자세히 설명`, `원문 근거 보기`, `연습 시작` 등을 반복 배치하지 않는다.
- 개인 답변·키워드·메모의 편집권은 유지하되, **정본 학생부 및 공식 대학자료는 수정 불가**.

## 5. PART 4 — 면접 연습실 (수정 후 확정)

### 5.1 I00 입구

카드 두 개만 노출: **`연습 면접` / `실전 모의면접`**. 카드 전체 클릭. `답변 기록`, `점수`, `리포트`를 별도 연습실 진입 메뉴로 만들지 않는다.

### 5.2 I01 연습 면접 설정

| 선택 | 내용 |
|---|---|
| `질문 선택` | **`내가 추가한 항목`**, `가이드북 전체`에서 승인된 질문 선택 |
| `AI 질문 생성` | 학년, 학생부 영역, 활동, 질문 기능, 난이도 등 유효한 조건으로 질문 생성·검증 |
| `직접 입력` | 학생이 질문을 입력, 출처는 학생 직접 입력으로 구분; 필요 시 `내가 추가한 항목` 저장 가능 |
| `보완 추천` | 과거 연습·실전 결과에서 재연습이 필요한 질문을 추천하는 **질문 선택 내부 목록**; A05 독립 메뉴 대체 |
| 진행 방식 | 연습 면접은 채팅/화상 선택 가능(실제 제공 품질 및 구현 검증 필요) |
| 주행동 | `연습 시작` |

- `내가 추가한 항목`은 G04에서 저장한 질문, 이슈픽에서 저장한 시사 질문, 학생이 저장한 직접 입력 질문 등을 **같은 저장소**로 조회하되 출처 ID로 구분.
- 질문 저장 행위는 연습을 즉시 시작하지 않는다. I01에서 시작.

### 5.3 I02 연습 진행

- Q0 최초 질문 + 필요 시 F1/F2 후속 평가 질문(최대 2개). 매번 한 질문에 하나의 주요 평가 목적, 학생부에 근거한 경우 정확한 출처 ID 유지.
- `답변 제출` 또는 매체에 맞는 `답변 완료`; `면접 종료` 제공.
- **질문 묶음 종료 전에는 피드백/점수/모범 답변 노출 금지**.
- 질문 의도·꼬리질문을 사전에 펼쳐 보는 UI 없음.

### 5.4 I03 연습 피드백 — 카드식 UI

- `잘한 점 / 보완할 점 / 개선 방향` 세 개의 긴 고정 문단 제거.
- 실제로 관찰된 항목만 **평가 관점별 카드**로 구성(예: 핵심 전달, 설명의 구체성, 답변의 논리, 학생부 정합성). 항목명은 이해하기 쉬운 자연어. 항목을 인위적으로 4/8개 채우지 않는다.
- 강점 카드는 민트 계열+긍정 아이콘, 보완 카드는 코랄 계열+보완 아이콘. **색상만으로 상태 전달 금지**. 설명은 카드당 1~2문장.
- 카드 아래 `이렇게 다듬어 보세요` + **`모범 답변 예시`**를 간결하게 배치. 학생이 하지 않은 경험·성과를 모범답안에 창작하지 않는다.
- **숫자 점수 없음**. 연습 이력/피드백 자동 저장.
- 하단 행동 **정확히 두 개:** `다시 연습하기` / `다음`.
- `다시 연습하기`를 누르면 필요할 경우 I04의 **간단한 2지 선택**으로 `이 질문만` 또는 `질문 묶음 전체`를 선택한다. 기본 피드백 화면에는 3번째, 4번째 버튼을 늘리지 않는다. 단일 질문 재답변에서는 새 꼬리질문을 만들지 않음. 과거 답변과 재답변 이력 별도 보존.
- `다음`은 다음 준비된 질문 진행, 마지막이면 I01 질문 선택으로 돌아감.

### 5.5 I05~I10 실전 모의면접 — **화상 전용**

| ID | 화면 | 필요한 조작 및 상태 |
|---|---|---|
| I05 | 실전 설정 | **지원처만 선택**, 잔여 실전 이용권·확인된 운영 조건 안내. 채팅/화상 매체 선택 UI 없음 |
| I06 | 입장 전 점검 | 카메라·마이크 점검, 차감 조건 안내, **`모의면접 시작`** |
| I10 | 단계별 입장 로딩 | 자동 진행 문구: `면접관이 학생부를 살펴보고 있습니다` → `면접관이 질문을 정리하고 있습니다` → `곧 면접장에 입장합니다` |
| I07 | 화상 면접 진행 | 실제 질문·음성·영상 응답; 필수 매체 조작·면접 종료만. 답변 도중 점수/코칭/모범 답안 표시 금지 |
| I08 | 종료/평가 | 평가 생성 중→완료 시 `리포트 보기` → A03/A04; 실패 시 정확한 오류·복구 상태 |
| I09 | 재접속 | 10분 이내 **같은 회차 이어하기**; 추가 차감 없음 |

**입장 로딩 규칙:** 실제 학생부 로드·질문 생성 검증·미디어 세션 준비 상태와 문구를 매핑한다. 긴장감을 이유로 무의미하게 기다리게 하거나 작업 중이지 않은 단계가 진행되는 것처럼 묘사하지 않는다. 정상 준비 완료 시 자동 입장, 실패 시 오류 상태로 전환. 입장 단계 전/장비 검사 실패를 정상 Q0 전달로 착각해 이용권을 차감하지 않는다.

**실전 세션 규칙:**

- 실전은 학생이 질문·난이도·꼬리 개수·평가 역량을 직접 지정하지 않는다. 검증된 대학·전형별 운영조건 사용; 면접관 수 미확인 시 ‘가상 기본 2인 시뮬레이션’으로 정확히 구분.
- Q0가 **정상적으로 제시된 순간** 이용권 1회 차감. 오류로 면접 평가 불능이면 기존 이용권 복구 원칙 준수.
- Q0만: 100%; Q0+F1: 70/30; Q0+F1+F2: 70/15/15. 유효 질문 묶음은 동일 가중치로 평균.
- 플랫폼 오류로 무효 처리한 질문 묶음은 0점으로 간주하지 않는다. 부분 종합 점수는 **유효 비율 ≥60% 및 유효 묶음 ≥2**일 때만 제공. 부분/오류 상세 표시는 전문 엔진 규칙을 준수.
- STT/TTS/카메라 품질이 부족할 때 채팅 실전을 동일 상품으로 몰래 대체하지 않는다. **화상 전용 출시 가능성은 개발팀 기술 검증 게이트**로 별도 관리.
- 회차별 결과는 A03/A04에서 조회. 실제 대학의 공식 합격 가능성으로 표기 금지.

## 6. PART 5 — 내 답변 (수정 후 확정)

### 6.1 A00 입구

아이콘+명칭 카드 **세 개:** `답변 보관함 / 면접 리포트 / 면접 직전 요약`. 메뉴 카드 설명 문구 없음. `다시 준비할 질문`을 독립 메뉴에서 삭제.

### 6.2 A01/A02 답변 보관함

**첫 화면은 ‘연습 면접 / 실전 모의면접’ 두 탭만. `전체보기` 없음.** 낱개 질문을 첫 화면에 길게 펼치지 않고 묶음 우선.

| 항목 | 연습 면접 | 실전 모의면접 |
|---|---|---|
| 첫 목록 | **연습 세션별** 카드(날짜, 주제/지원처, 질문 개수) | **실전 회차별** 카드(날짜, 지원처, 평가 완료 시 점수) |
| 1차 필터 | 지원처별(대학 지정 없는 질문은 `공통`) | 회차 정렬, 필요하면 지원처 필터 |
| 2차 필터 | 질문 유형별(학생 친화적 이름: 탐구·학업/지원동기/인성·협업 등) | 불필요한 유형 필터 기본 제외 |
| 상세 | 세션의 실제 Q0/F1/F2와 답변, 연습 피드백 | 회차의 실제 질문·답변 기록, 점수/평가 상태 |
| 기록 보존 | 당시 답변 불변, 재답변 revision 보존 | 당시 답변·출처·회차 불변 |

**대표 답변 지정:** 답변 상세에서 **별 아이콘 등 단일 조작 `대표 답변으로 지정`**. 동일 질문 및 지원처 맥락에서 하나를 대표 답변으로 관리하고 새 답변 선택 시 기존 대표 해제. 이 동작은 원본 답변 자체·기존 면접 평가·점수·기록을 변경하지 않는다. 학생이 선택한 답변이지 공식 모범 답안이라고 표기하지 않는다.

### 6.3 A03/A04 면접 리포트

**A03 목록 상단:** 짧은 수치 요약을 우선 표시(예: 평가 완료 회차, 평균 점수, 최근 점수) + 점수 변화 차트(실제 데이터가 충분한 경우). 아래는 **회차별 펼치기** 목록. 기본적으로 모든 질문을 펼치지 않는다.

- 누적 평균·추이는 **정상 평가 완료 회차**를 기준으로 계산. 부분 평가/평가 불능/취소된 회차는 무심코 섞지 않고 별도로 표시.
- 타 대학·전형의 점수가 하나의 ‘성장 점수’인 듯 오인되지 않도록 **현재 지원처 범위가 명확해야 함**. 전체 지원처 통합 집계 여부/비교 조건은 별도 QA 승인 대상.
- 상세 리포트를 펼쳤을 때의 시각화·평가 텍스트·PDF 구성은 **미확정**. IA에서는 펼침 컨테이너, 회차 점수·날짜·평가 상태, `PDF 다운로드` 진입만 결정.
- 리포트 구성 A/B/C 및 반올림·부분 통계 규칙은 별도 후속 결정.

### 6.4 A05 폐기 / 보완 추천 흡수

- `다시 준비할 질문` 독립 메뉴 **삭제**. 질문 저장 데이터가 사라지는 것은 아님.
- 학생이 G04에서 저장하거나 M04 이슈픽에서 저장한 질문은 **I01 `내가 추가한 항목`**에 보인다.
- 연습/실전에서 보완이 필요하다고 나온 질문은 **I01 `보완 추천` 목록**에 노출. 기록 이력은 A01/A03에 보존.
- `내 답변`에 동일 질문 목록을 추가로 복제하지 않음. ‘오답노트’ 명칭 금지.

### 6.5 A06 면접 직전 요약

- 내 답변의 세 번째 카드로 노출하되 개인 확정 면접일 이전에는 **`면접 하루 전 열려요`** 잠금/준비 상태.
- 학생 개인이 확인·등록한 면접일을 기준으로 **D-1부터 공개**. 대학 공개 참고 일정만으로 개인 면접일을 확정하거나 자동 해제하지 않는다.
- 공개 후 카드 항목: **핵심 활동 / 필수 예상 질문 / 반복 보완 사항 / 사실 확인 / 지원처 유의사항**.
- 정확한 공개 시각, 시간대, 다중 지원처 중복, 면접일 변경·지난 면접일, 자료 부족/아직 가이드북 미발행 때의 UX 및 실제 생성 방식은 **미확정 후속 검토**.

## 7. PART 5 — 암기 훈련실 (수정 후 확정)

### 7.1 M00 입구·이름

메뉴 카드 정확히 세 개: **`퀴즈 / 지식한입 / 이슈픽`**. 기존 `시사 코너` 명칭은 **`이슈픽`으로 변경**. 설명문 없는 아이콘+명칭 카드.

### 7.2 M01/M02 퀴즈

- 학습 목적에 맞는 문제 유형: **단일 선택 / 복수 선택 / 순서 배열 / 짝 연결 / 빈칸 완성**. 실제 항목별 정답·부분 정답·난이도 판정 세칙은 QA 후 결정.
- **오답 가중 반복학습**: 문항별 정오답, 누적 오답, 최근 풀이일, 연속 정답을 기록. 반복 오답 개념은 후속 퀴즈에서 높은 빈도로 재노출하고, 반복 정답 개념은 출제 가중을 낮추되 신규/다른 문항도 섞음.
- 같은 문항만 기계적으로 반복하지 않고 **동일 개념을 다른 유형으로 재확인**할 수 있도록 문항-개념 ID 분리 권장.
- 기본 버튼: `시작하기 → 답 확인 → 다음 → 끝내기`. `오답노트` 독립 메뉴, 장황한 보조 컨트롤 미제공.
- 가중치·반복 간격·문항 개수·채점 규칙·콘텐츠 검수 방식은 기획 방향 확정과 별개로 **기술/콘텐츠 세칙 미정**.

### 7.3 M03 지식한입

- 단순 텍스트 정의를 넘어 **학생부, 특히 세특·탐구활동과 직접 연결된 신뢰 가능한 외부 학습자료** 제공.
- 영상·강의·보고서·논문·공공/대학 자료 등. **실제 썸네일**을 크게 노출해 제목을 읽지 않아도 자료 형태·내용을 파악하게 함.
- 카드 주요 요소: 썸네일 / 제목 / 자료 유형 / 검증 가능한 출처 / **학생 개인 관련 중요도** / **즐겨찾기 별 아이콘**.
- `내 학생부 관련 / 전체 자료 / 즐겨찾기` 등 최소 탭을 상황에 맞게 사용 가능. 자료를 선택하면 검증된 원본 제공 페이지 또는 이용권한 있는 원문으로 연결. 불필요한 중간 상세 페이지는 배제.
- 중요도는 조회수/유명도가 아니라 학생의 활동·학과·면접 우선도와 연계해서 판정. 실제 평가 기준은 후속 정의.
- 출처 신뢰성·저작권/임베딩 허용·링크 생존·자료 갱신/추천 알고리즘은 **별도 추가 기획**. 가짜 썸네일·검증 안 된 출처/논문 제공 금지.

### 7.4 M04 이슈픽

- 전공·사회 이슈를 썸네일 중심 카드로 제공. 카드에서 제목·출처·발행일·중요도 및 **즐겨찾기 별** 확인.
- 클릭 시 `쟁점 요약 / 배경 / 주요 관점 / 면접에서 생각해 볼 질문`을 가볍게 제공.
- 질문이 실제로 있는 항목에는 **`질문 저장하기`** 제공 → I01 `내가 추가한 항목`으로 저장. 해당 질문은 학생부 근거 질문이 아니면 근거 있는 개인 활동처럼 표시하지 않음.
- `즐겨찾기`(자료를 다시 읽기 위한 저장)와 `질문 저장하기`(면접에서 연습하기 위한 질문 저장)는 서로 다른 데이터·행동.
- 신뢰 가능한 원문, 발행일·갱신일, 판권·검수 기준이 정해지기 전에는 `오늘 최신` 등 최신성 보장 문구 사용 금지.

### 7.5 접근권한

`암기 훈련실` 기본 제공: **실전플랜·몰입플랜**. 준비플랜은 포함하지 않음. 메뉴를 완전히 숨기기보다 현재 플랜 범위 안내 후 필요 시 `요금제 보기` 하나만 제공. 준비플랜도 가이드북 내 답변·키워드·메모 편집은 가능.

## 8. PART 6 — 공통 계정·지원처·고객지원 (확정)

### 8.1 프로필 메뉴

`지원처 관리 / 내 요금제 / 면접 이용권 / 결제 내역 / 계정 설정 / 고객센터 / 로그아웃`.

- 학생부 정정·재분석은 관련 자료 또는 계정 기능에서 접근하는 **문맥 기능**이지 별도 전역 메뉴가 아님.
- 회원 탈퇴는 `계정 설정` 내부. 고객센터의 오류 신고는 문의하기 흐름에 통합.

### 8.2 U01 지원처 관리

| 행동 | 구분 및 규칙 |
|---|---|
| `선택하기` | 이미 등록한 지원처로 현재 컨텍스트 전환, 무료 |
| `변경` | 기존 지원처의 대학·학과·전형 변경. 가이드북 발행 전 무료, 발행 후 최초 1회 무료·이후 14,900원 내부 정책(횟수 귀속 기준 후속 확인) |
| `지원처 추가` | 기본 3곳. 4번째부터 1곳당 14,900원 |
| `면접일 등록·수정` | 학생이 개인 면접일을 확인해 등록, 홈 D-Day 및 A06 D-1의 기준으로 활용 |

- 학교·캠퍼스·모집단위·전형·입학연도 정확히 매핑. 대학 2027 JSON은 **검증 상태를 표시한 데이터 후보**이고, 미확인 전형·날짜를 공식 확정으로 노출하지 않음.
- 등록된 지원처로 단순 전환할 때 ‘변경 수수료’가 발생해서는 안 됨. 이전 응시 기록은 기존 지원처와 데이터 버전 보존.
- 발행 후 변경 무료 횟수 및 여러 지원처 중 일부만 발행된 상황의 결제/환불 경계는 기존 미확정사항과 연계.

### 8.3 U02 내 요금제

| 플랜 | 내부 합의 가격 | 가이드북·AI 비서 | 연습 면접 | 기본 실전 | 암기 훈련실 |
|---|---:|---|---|---:|---|
| 준비플랜 | 39,000원 | 포함 | 기본 미포함 | 0회 | 미포함 |
| 실전플랜 | 99,000원 | 포함 | 최초 이용일로부터 7일 무제한 | 10회 | 포함 |
| 몰입플랜 | 169,000원 | 포함 | 최초 이용일로부터 14일 무제한 | 30회 | 포함 |

- 현재 플랜 상태·실제 연습 이용기간 표시. 업그레이드 주행동은 `플랜 업그레이드` 하나.
- 내부 차액: 준비→실전 60,000원; 실전→몰입 70,000원; 준비→몰입 130,000원. 사용한 기본 제공 회차 반영, 추가 구매권 보존. 실제 약관/PG 승인 전 외부 결제 실행 금지.

### 8.4 U03 면접 이용권

- 기본 제공 잔여 / 추가 구매 잔여 / 합산 잔여 / 이용·차감·복구 내역 / `이용권 추가 구매`.
- 모든 플랜에서 실전 모의면접 1회 7,900원 추가 구매 가능. **기본 제공권·추가 구매권 유효기간 없음**.
- 최초 정상 Q0 전달 시 차감, 재접속 이중 차감 금지, 시스템 장애 복구 내역 원자적 기록.
- UI 용어는 **`실전 모의면접 이용권`**. `크레딧` 금지.

### 8.5 U04 결제 내역

- 주문·상품·금액·날짜·결제 상태, 클릭 시 상세 영수증.
- 구매 실행 위치는 각 기능 소유 화면: 플랜 업그레이드(U02), 이용권(U03), 지원처 추가(U01). 결제 내역에 불필요한 복수 구매 버튼을 중복하지 않음.
- 환불·청약철회·무기한 권리 처리 등은 특별약관 v1.0과 법무 승인 전 미확정.

### 8.6 U05/U08 계정 설정·로그아웃

- `내 정보 / 알림 설정 / 회원 탈퇴`. 프로필 하단 별도 `로그아웃`.
- 개인정보·민감한 학생부 정보 처리, 미성년자 동의, 보관·삭제·계정 탈퇴는 별도 보안/법률 규칙에 따름. 발송 제공사/채널이 검증되지 않은 알림 옵션은 활성화 금지.

### 8.7 U06 학생부 정정·재분석 (문맥 기능)

- `정정 요청`: 학생부 원문 OCR 또는 분석 결과 오류 접수, 원문 직접 편집 불가.
- `새 학생부 재분석`: 새 원본 제출 후 전체 분석. 원본 교체 최초 1회 무료 내부 정책, 후속 유료 가격 미정.
- 요청/발행 버전·출처 ID 보존, 과거 실전 회차의 학생부 버전은 소급 변경하지 않음.

### 8.8 U07 고객센터

`자주 묻는 질문 / 문의하기 / 문의 내역`. 문의 유형: 이용, 결제·이용권, 학생부·가이드북, 면접/STT/TTS/화상 오류, 기타. 오류 화면에서 접수 시 가능한 범위에서 세션·오류 ID 자동 연결, 민감정보 최소 수집.

## 10. 접근·오류·검증 상태 공통 UX

| 조건 | 표시와 1차 행동 |
|---|---|
| 기록 없음 | ‘아직 기록이 없어요’; 불필요한 3~4개 버튼 없음 |
| 가이드북 미발행 | 실제 제작 상태·필요 시 `진행 상태 보기` |
| 기본 플랜 기능 제한 | 현재 이용 불가 안내 및 `요금제 보기` 하나 |
| 이용권 0회 | `이용권 추가 구매` (실제 결제 승인 조건) |

## 14. UX 북극성 및 의사결정 규칙

### 14.1 북극성: Quiet Confidence / 학습에 집중하는 조용한 자신감

- **1화면 1주요 목적(One Primary Job):** 같은 수준의 CTA 2개를 경쟁시키지 않는다. 내용 탐색 화면은 카드 자체를 클릭; 입력 완료 화면은 저장/제출이 주행동. 예외: 연습 피드백은 승인된 `다시 연습하기 / 다음` 두 행동을 동등하게 제공.
- **Recognition over Recall(기억보다 인지):** 사용자가 기억해야 할 정보(현재 지원처, 선택된 질문, 출처 상태)는 화면 맥락에서 보여주되, 설명문을 남발하지 않는다.
- **Progressive Disclosure(점진적 공개):** 진입화면은 간단하게, 실제로 선택한 뒤 필요한 설정만 노출. 상세 정보는 기본적으로 숨기되 중요한 비용·권리·데이터 오류는 숨기지 않는다.
- **Context Preservation(맥락 유지):** 질문 선택, 필터, 스크롤 위치, 지원처, 개인 답변 초안, 면접 세션을 실수로 잃지 않도록 한다.
- **Honest Status / Faithful Feedback(정직한 상태 표시):** 실제 처리·성공·실패 상태만 표시. 가짜 진행률·가짜 사용자 수·가짜 카운트다운 금지.
- **Action–Outcome Clarity(행동과 결과의 일치):** `질문 저장하기`는 저장만, `연습 시작`은 연습만. UI 이벤트와 백엔드 결과를 일치시키고 성공을 선표시하지 않는다.
- **Source First(근거 우선):** 학생부 원문과 질문 근거, 대학 공식/참고/미확인을 명확히 구분. 틀린 문장을 매력적인 UI로 포장하지 않는다.
- **Quiet Motion(절제된 모션):** 모션은 상태·공간 관계를 설명할 때만, 집중을 흐리는 과장된 애니메이션은 배제한다.
- **Essential Wording(필수 문구만):** 메뉴 하단 ‘이 기능은 무엇을 하는 곳’ 설명문 삭제. 상태·오류 해결·권리·출처 문구는 예외적으로 필수다.
- **No Feature Leakage(기능 소속 유지):** G04에서 실전으로 바로 뛰지 않음, 내 답변에 반복 연습 엔진을 복제하지 않음, 관리자 UI를 학생 화면에 섞지 않음.

### 14.2 UI 결정 우선순위

1. 사실·권리·안전·데이터 무결성(사용자의 잘못된 대학 정보, 평가, 결제 방지)
2. 목적 달성의 명확성(다음 행동이 하나로 이해되는가)
3. 실수 예방·복구(입력 손실·결제 중복·면접 중단)
4. 사용성·접근성(키보드/스크린리더/터치/좁은 화면)
5. 시각적 세련됨·모션(위 조건을 저해하지 않는 범위)

| AI | **Agent Steps** | 조건부 | 실전 입장 및 가이드북 발행 실제 상태 | 실제 상태값과 연동되며 단계마다 별도 버튼 필요 없음 |
| 심리 | **Default Effect** | 신중 | 올바른 접근성/필수 설정 기본값 | 고가 플랜·선택 동의·추가구매를 미리 선택하지 않음 |
| 심리 | **Peak-end Rule** | 절제 | 연습 피드백 마지막 ‘다음’·실전 종료 | 과장된 칭찬 대신 명확한 성취·다음 단계 |
| 심리 | **Framing** | 절제 | 실전 점수를 성장 코칭 맥락으로 설명 | 합격 확률을 암시하거나 수치를 좋게 보이게 왜곡 금지 |
| 심리 | **Choice Overload** | 적극 회피 | 모든 화면 | 기본 선택지 2~3개, 심화 조건은 필요 시만 노출 |
| 다크패턴 | **Roach Motel / Hidden Costs / Forced Continuity / Fake Scarcity / Fake Countdown / Confirmshaming / Nagging / Sneak into Basket / Pre-checked Consent** | **전부 금지** | 전 화면 | 해지/탈퇴/환불 방해, 허위 한정, 추가 금액 은닉, 자동결제 오인 유발 금지 |

### 15.1 채택 패턴 우선순위

- **필수 품질군:** Searchable Select, Tabs/Segmented, Skeleton, Inline Error, Loading Button, Toast, Confirmation Dialog, Empty State, Responsive Navigation, Evidence Highlight, 카드 전체 클릭, 상태 배지, 접근 가능한 폼.
- **차별화 품질군:** G04 원문 하이라이트, I10 정직한 3단계 입장, I03 역량별 피드백 카드, A01 세션·회차 묶음, M02 오답 반복, M03/M04 썸네일·별 즐겨찾기.
- **미채택군:** 허위 진행·과한 효과음·가짜 긴박감·자동결제 오인·두 번 탭 숨은 기능·무조건 애니메이션·분리된 중복 CTA.

## 16. 디자인 시스템 권고안 (Design Tokens / Component Contracts)

> 이 절의 수치는 **제안 토큰**이다. 기존 브랜드 정체성을 존중하되 개발 컴포넌트로 통일하기 위한 기준이며, 기획팀의 실디자인 검토에서 조정할 수 있다. ‘법/웹표준 인증 완료’를 뜻하지 않는다.

### 16.1 Visual Language

| 항목 | 권장값·규칙 | 이유 |
|---|---|---|
| Brand Primary | 딥민트/틸 계열 예: `#178D78` (추천 초안) | 민트 아이덴티티, 강조/상태에 사용. 본문 색으로 사용 전 대비 확인 |
| Brand Pale | `#E8F6F1` | 선택·강조의 약한 배경. 성공 알림 범람 방지 |
| Text Primary | `#1C2624` | 저자극 고대비 |
| Text Secondary | `#5F6A67` | 날짜·출처·보조 메타데이터. 메뉴 설명문 용도로 남발 금지 |
| Canvas | `#F7FAF8` 또는 밝은 중립톤 | 조용한 학습 공간 |
| Surface | `#FFFFFF`, Border `#E0E9E4` | 콘텐츠/입력 경계 명확화 |
| Positive | 민트 + 체크 아이콘 + ‘잘했어요’ | 연습 피드백 강점 표현 |
| Needs improvement | 코랄 + 향상 아이콘 + ‘보완해 봐요’ | 적색 경고와 학습 코칭 구분 |
| Error/Danger | 별도 적색 + 문구 | 결제/입력/연결 실패에만 사용, 학습 약점을 ‘오류’로 취급하지 않음 |
| Source highlight | 낮은 채도의 노란 계열 + 텍스트 대비 유지 | 형광펜 은유. 배경 하이라이트만으로 근거를 전달하지 않음 |
| Typography | 본문 약 16px, 보조 약 14px, 카드제목 16~18px, 큰 제목 24~32px | 읽기 쉬운 웹 가이드북. 작은 글씨를 기본값으로 남용하지 않음 |
| Spacing | 4px 기반: 4/8/12/16/24/32/48 | 한눈에 보이는 여백 규칙 |
| Radius | 버튼 10~12px, 카드 16~20px, 패널 20~24px (초안) | 과도한 둥근 모서리 회피 |
| Elevation | 카드 기본은 테두리, 떠 있는 패널에만 작은 그림자 | 장식적 그림자 경쟁 방지 |
| Icon | 선형 아이콘 20~24px, 한 기능 한 아이콘, 라벨 동반 | 아이콘 단독 의미 불명확 문제 최소화 |
| Max content width | 일반 1040~1200px, 읽기 전용 본문 680~760px | 가이드북 장문 가독성, G04 2열은 예외 |
| Mobile breakpoints | `≤767px` 단일열, `768–1199px` 중간, `≥1200px` 2열/넓은 화면 (권고) | 실험용 기준. 실제 데이터 길이로 브레이크포인트 테스트 |
| Touch target | 기본 목표 **44×44 CSS px 이상**, 구현 최소 WCAG 조건 별도 점검 | 작은 아이콘 탭 실수 방지 |

- `color.semantic`은 `brand`, `text`, `surface`, `positive`, `improve`, `error`, `warning`, `source` 등을 역할 중심으로 저장. `teal-500`처럼 외관만 뜻하는 명칭을 UI 코드에 직접 남발하지 않는다.
- 카드 제목이 길어지더라도 핵심 명칭을 임의로 ‘…’ 처리해 기능을 숨기지 않는다. 좁은 화면에서 줄바꿈 허용.
- 입력값·면접 질문·학생부 텍스트는 **실제 한국어 긴 문장**으로 테스트. 카드가 영문 한 단어일 때만 예쁘게 보이는 디자인 금지.

### 16.2 Layout & Navigation / 공통 레이아웃

| 조건 | 설계 계약 |
|---|---|
| 데스크톱 | 상단 헤더 4메뉴+지원처+계정, 본문 영역 최대폭, 긴 목차 화면만 좌측 서브내비 |
| 모바일 | 4개 하단 탭 + 상단 로고/지원처/계정. **면접 진행 중에는 하단 탭 숨김**으로 이탈 방지(종료 버튼은 유지) |
| 태블릿 | 4개 탭이 무리 없이 들어가면 상단, 아니면 모바일 구조; 끊긴 레이아웃 금지 |
| 스크롤 | 목록 → 상세 → 뒤로 복귀 시 원래 필터·스크롤 유지; 외부 자료 링크는 새 맥락 구분 |
| 긴 콘텐츠 | 제목/목차 고정은 필요할 때만, `scroll-margin-top`으로 앵커 제목 가림 방지 |
| 정보 밀도 | 최초 뷰에서 현재 목적과 다음 행동이 확인되면 충분. 가짜 KPI·장식 배지는 제거 |
| 메타 정보 | 출처·일시·상태 정보는 관계 있는 항목 근처만 노출; 장황한 부제 방지 |

### 16.4 Motion Tokens / 모션 가이드

| 종류 | 제안 타이밍 | 허용 위치 | 금지 |
|---|---|---|---|
| Hover/press feedback | 80~150ms | 메뉴 카드·아이콘 | 과도한 스케일/요동 |
| Fade/opacity transition | 120~200ms | 탭 콘텐츠·알림 등장 | 화면 전체 반복 페이드 |
| Drawer/Sheet transition | 180~260ms | 모바일 목차·지원처 | 제스처 필수 이동 |
| Star/Bookmark feedback | 120~180ms | 대표 답변·즐겨찾기 | 축포/효과음 남용 |
| Step change | 180~260ms | I10 실전 입장 상태 변화 | 실제 처리와 무관한 지연 연출 |
| `prefers-reduced-motion` | 움직임 최소/제거 | 전 화면 | 정보 전달을 애니메이션에만 의존 |

**미세상호작용(Microinteraction) 규칙:** hover는 보너스일 뿐, 터치와 키보드로 동일 기능을 제공. 클릭 반응은 가볍게, 실제 완료는 서버 확정 후 표시.

## 17. 화면별 UX 상세 명세 — 공개 사이트·가입·MY 홈

**읽는 법:** `Layout`은 주요 화면 구조, `Pattern`은 개발자가 이해할 UX 용어, `Action`은 사용자 조작, `States`는 필수 화면 상태. 이 절에서 정의한 상세 조작은 새 메뉴를 추가하는 것이 아니며 IA v1.0의 화면 ID를 그대로 사용한다.

### 17.1 P01 메인 홈페이지

- **Layout:** [브랜드 히어로] → [4개 기능의 가치] → [이용 절차] → [실제/가상 명시된 샘플] → [요금제] → [FAQ] → [푸터]. 긴 목록에 모든 문장과 아이콘을 채우지 않는다. 상단 Sticky Header는 스크롤에 따라 높이만 줄고, 중요 콘텐츠를 덮지 않는다.
- **Pattern:** Scannable Hero, Section Anchor Navigation, Disclosure/Accordion FAQ, Semantic Feature Card, Responsive Stack, Lazy Loading(이미지).
- **Action:** 상단 `로그인`, `시작하기`. 기능 소개 카드는 클릭 불필요하면 버튼처럼 보이지 않게 한다. 요금제는 명확한 상품 선택 구역으로 이어짐.
- **Motion:** 히어로 배경의 움직임 필수 아님. 첫 뷰의 움직임은 한 차례 미세 페이드 정도. Carousel 강제 자동 재생 금지.
- **Copy:** `나의 기록에서, 나의 답으로` 등 브랜드 승인 문장 중 하나 사용. `합격 보장`, `합격률 상승 확정` 금지.
- **States:** 이미지 실패 시 텍스트로 대체, 요금제 데이터 로드 실패 시 잘못된 가격 대신 정보 일시 불가 표시.
- **Mobile:** 핵심 문장 → 시작 CTA 순서, 4개 기능은 2열 또는 1열 카드. 끝없는 설명문 대신 실제 콘텐츠 미리보기를 활용.
- **QA:** `시작하기` 경로 한 개, 중복/모호 CTA 0개, 키보드/화면읽기 목차 정상.

### 17.2 P02 서비스 이용 방법·샘플

- **Layout:** 4~5단계의 세로 Stepper(모바일) 또는 가로 프로세스(PC); 각 단계에 실제 산출물의 익명화 예시 1개. 설명은 짧은 제목+실제 화면 예시로 대체.
- **Pattern:** Process Stepper, Progressive Disclosure, Image Caption, Demo Disclosure.
- **Action:** 섹션 내 필요 시 `시작하기` 1개. 샘플 자세히 보기 클릭은 동일 콘텐츠 확장(별도 판매/결제 유도 모달 금지).
- **States:** 샘플은 `예시 화면`, `실제 학생 자료 아님` 등을 명확히 표기. 가짜 수치·가짜 대학 기록 금지.
- **Mobile:** 단계마다 카드 하나씩 선형 순서 유지, 전환 슬라이더 필수 아님.

### 17.3 P03 요금제

- **Layout:** 3플랜 Side-by-side Comparison(PC), Stack(모바일). 상품명·금액·제공 기능·시간 기준·면접 이용권 수·추가 구매 조건을 같은 시야에 둔다.
- **Pattern:** Comparison Cards, Radio Selection, Sticky Price Summary(모바일 결제 검토용), Honest Pricing.
- **Action:** 플랜 선택 → O03 결제. 선택된 카드의 Outline+Radio는 시각/보조기술에 모두 전달. `추천` 강조는 근거 없는 최상위 상품 유도 문구 대신 실제 사용자 용도 기반일 때만.
- **States:** 결제 미지원/법무 대기면 구매 버튼 비활성화와 이유 공개. 포함권/별도권 구분. 숨은 할인·허위 타이머 없음.
- **QA:** `준비플랜도 실전권 추가 구매 가능`, `실전권 무기한`, `연습 최초 시작 시점부터 기간` 등을 반드시 확인.

### 17.4 P04 FAQ

- **Layout:** 주제별(가입/가이드북/면접/결제/개인정보) 묶음, 하위 질문은 Disclosure/Accordion. 한 번에 하나만 열어야 한다는 강제 규칙 없음.
- **Pattern:** Accordion with Accessible Button, Inline Search(FAQ가 충분히 많을 때만).
- **Action:** 질문 누름→내용 펼침. `문의하기`는 FAQ 하단 1곳 또는 공통 고객센터로 통일.
- **States:** 결과 없음 → `해당 질문을 찾지 못했어요` + 문의 경로(정말 필요할 경우).

### 17.5 P05 약관·정책

- **Layout:** 문서형 읽기 뷰, 시행일·버전·제공 주체와 조항 목차가 상단에 보임. 필요 시 인쇄 가능.
- **Pattern:** Document Navigation, Anchor Links, Legal Versioning.
- **Action:** 목차 선택·해당 조항 이동. 법적 문서를 동의 전 토스트/툴팁 안에 숨기지 않음.
- **States:** 아직 승인 안 된 약관은 공개용 최종약관으로 둔갑시키지 않는다.

### 17.6 P06 로그인·회원가입

- **Layout:** 단일 집중 폼, `로그인`과 `회원가입` 경로 분리. `이메일/비밀번호` 등 실제 인증 수단을 기준으로 항목 결정(인증 제공사 미확정이면 임의로 소셜 로그인 버튼 생성 금지).
- **Pattern:** Focused Form, Explicit Labels, Password Visibility Toggle, Inline Errors, Accessible Authentication.
- **Action:** `로그인` / `회원가입`; 비밀번호 재설정은 지원되는 인증 방식일 때만.
- **States:** 오류는 `이메일과 비밀번호를 확인해 주세요` 등 정보 노출을 최소화한 문구; 실패 후 이메일 입력값 유지. 계정/비밀번호 존재 여부를 악의적으로 열거하는 위험 완화.
- **Mobile:** 키보드 때문에 주버튼이 화면 밖에 가려지지 않게, 입력별 적절한 키보드 타입.

### 17.7 O01 계정·동의

- **Layout:** 필수 입력 → 동의 묶음(필수/선택 구분) → `동의하고 계속`. 선택 동의는 **기본 미체크**; 전체 동의를 사용하더라도 필수와 선택을 명확히 펼쳐볼 수 있어야 한다.
- **Pattern:** Checkbox Group, Inline Legal Links, Error Summary when submitted.
- **Action:** 필수 체크 누락 시 어떤 동의가 빠졌는지 바로 알려주기. 미성년자 법적 처리/동의 체계는 법무 검증 전 임의 구현 금지.
- **States:** 진행 중 저장, 제출 실패 시 선택값 유지, 중복 가입 방지.

### 17.8 O02 지원처 최초 등록

- **Layout:** `입학연도 → 대학 → 캠퍼스(해당 시) → 모집단위 → 전형` 순서의 Cascading Combobox. 이전 필드가 선택되기 전 다음 선택지는 비활성화하되 이유를 바로 이해할 수 있도록 배치.
- **Pattern:** Dependent Select, Searchable Combobox, Single-Choice Dropdown, Inline Validation.
- **Action:** 검색으로 대학 선택, 목록에 없으면 임의 가상 대학 생성 대신 `해당 지원처를 찾을 수 없어요` + 지원 문의 경로. `지원처 저장`은 정확히 한 번 처리.
- **States:** 자료 수집 중/검색 결과 없음/모집단위 적용 근거 미확인/저장 실패. `공식 확인`과 `참고`는 데이터별 표시.
- **Mobile:** 각 Dropdown은 Full-screen Picker 또는 Bottom Sheet, 검색 입력 위에 고정, 뒤로 가도 선택 유지.
- **QA:** 학교/캠퍼스/전형 매핑 혼선 0, 학교만 변경 시 이전 학과 값 초기화 여부 안내.

### 17.9 O03 요금제 선택·결제

- **Layout:** 선택한 상품명 + 포함 항목 + 결제 금액 + 추가 비용 여부 + 약관·취소 조건을 `결제 진행` 바로 앞의 Order Summary에 배치. 비회원 요금제와 가격 일치.
- **Pattern:** Order Review, Explicit Consent, Transaction Idempotency, Pending Payment State.
- **Action:** `결제 진행` 한 번 누르면 Loading Button; 중복 결제 방지. 결제 완료는 서버 검증된 결과일 때만 표시.
- **States:** 완료/취소/승인 실패/확인 중/중복 요청/PG 응답 지연. 결제 확인 중에는 '실패'나 '완료'로 조급하게 단정하지 않음.
- **Anti-dark:** 옵션 사전 체크 없음, 비용·유효기간·반복 청구 여부 숨김 없음, 가짜 마감시계 없음.

### 17.10 O04 학생부 등록

- **Layout:** 드롭존(Dropzone) + `파일 선택` + 파일 이름/용량/형식 표시 + `학생부 제출`. 드래그앤드롭은 보조 수단, 반드시 클릭 업로드 가능.
- **Pattern:** File Upload, Preflight Validation, Determinate Transfer Progress, Safe Retry, Privacy Notice.
- **Action:** 유효 PDF를 선택하면 기존 파일 교체 전 확인(초안 있을 때). 전송률은 **실제 업로드 바이트 진행률**일 때만. 서버 처리(O05)는 별도 상태.
- **States:** 파일 없음/형식 오류/크기 제한/암호 PDF/네트워크 실패/업로드 중/업로드 완료/처리 접수. `100% 업로드` ≠ `가이드북 완성`.
- **Mobile:** 파일 선택 OS 제공, 드롭존 강제하지 않음. 학생부 민감정보 노출/수집 범위 명확히.

### 17.11 O05 가이드북 제작·검수 상태

- **Layout:** 현재 상태 카드 + 실제 단계(접수 → OCR → 분석 → QA/검수 → 발행). 단순한 Linear Stepper. 복잡한 운영 내부 코드 미노출.
- **Pattern:** State-based Stepper, Status Banner, Polling/Push Update, Skeleton of Preview only if real preview exists.
- **Action:** 정상 처리 중 주요 버튼 없음 또는 `진행 상태 보기`(MY 홈에서 접근할 때). 추가 확인 요청이면 `확인 요청 보기`, 실패면 `다시 시도` 등 상황에 맞는 하나.
- **States:** `접수 완료` / `내용 확인 중` / `검수 중` / `추가 확인 필요` / `발행 완료` / `처리 실패`. 각 단계 실제 작업과 매핑. 실측 소요시간/정확한 백분율을 모르면 표시 안 함.
- **Error copy:** `학생부를 읽는 중 문제가 발생했어요. 파일을 다시 확인해 주세요.`와 같이 사용자 행동 제시. 내부 STT/OCR 용어를 꼭 알 필요는 없음.

### 17.12 O06 가이드북 발행 완료

- **Layout:** 짧은 확인 패널(Confirmation Page) + 하나의 CTA `가이드북 보기`. 진행 장표를 과도하게 반복하지 않음.
- **Pattern:** Confirmation State, Single CTA, Completion Message.
- **States:** 발행 완료와 읽기 권한이 실제로 연결됐을 때만 노출. 열람 실패 시 발행 완료처럼 보이는 거짓 완료 금지.

### 17.13 H01 MY 홈

- **Layout:** 전역 헤더 → 문맥 상태 카드(필요 시) → **4개의 큰 메뉴 카드** → 간략 이용 현황(숫자) → 면접 일정. 기본 모듈 순서 고정, 정보 부족하면 빈 카드로 채우지 않음.
- **Pattern:** Dashboard with Low Density, Status-driven Primary Action, 2×2 Feature Grid(PC), Responsive Stacked Cards(모바일), Conditional Badge.
- **Action:** 메뉴 카드는 **전체 클릭**하고 별도 `입장하기` 없음. `면접일 수정`은 U01에서만 실행, H01에는 현재 일정 정보만.
- **States:** 무지원처 → `지원처 등록`, 미구매 → `요금제 보기`, 미제출 → `학생부 등록`, 분석 중 → `진행 상태 보기`, 확인 요청 → `확인 요청 보기`, 실패 → `다시 시도`, 발행 완료 → **새 CTA 없음**.
- **D-Day:** 학생 본인의 면접일이 확인된 지원처에만. 남은 기간 계산은 한국 시간/입력한 면접일 기준, 대학 공개 참고일을 개인 확정일로 가장하지 않음.
- **Numbers:** `잔여 실전 면접`은 실시간 이용권 원장; `연습 7일`이 아니라 **현재 실제 남은 기간 또는 시작 전** 표시.
- **Anti-clutter:** 4개 카드 + KPI + 상태만. 실전 시작·답변 보기·AI 챗 아이콘을 홈에 반복 배치하지 않음.
- **QA:** 개인 데이터 없는 신규 학생도 문제없이 보이고, 가상 점수/성취 통계 자동 노출 0.

## 18. 화면별 UX 상세 명세 — G01~G09 생기부 가이드북

### 18.1 공통 Guidebook Shell / 읽기 시스템

- **PC:** 좌측 고정 목차(Side Navigation) + 본문(Content Pane) + AI 비서 플로팅 트리거. G04만 본문을 원문/질문 패널로 나눈 **Master–Detail Split View**.
- **모바일:** 목차는 `목차` 버튼의 Side Drawer, 한 화면 한 주요 작업. G04에서만 `학생부 | 질문·답변`을 Segment/Tabs로 전환, 선택한 질문/하이라이트 위치 유지.
- **탐색:** 좌측 목차에서 G01~G06 이동. `G07 사용법`은 도움 보조 화면(첫 방문 1회 가벼운 안내 가능). AI 비서는 모든 장에서 동일 패널.
- **검색:** 가이드북 전체 검색은 상단 1개. 필터(학년/영역/우선도)는 관련 질문/학생부 목록에서만. 검색 결과는 장/학생부 위치를 함께 표시.
- **Reading UX:** 가이드북 내용은 형광색 강조·강조 블록의 범람 없이 구조화. 긴 본문 1줄 폭 제한, 텍스트 선택/복사/브라우저 확대 가능.
- **Interaction:** 목차 전환 시 수정 중 답변이 있으면 저장/취소 여부 확인. 저장이 완료됐으면 과도한 모달 없이 Toast.

### 18.2 G01 나의 면접 전략

- **Layout:** 전략 요약 → 진로·학업 흐름(학년별 Timeline) → 대표 활동(우선도 S/A/B/C/F 목록) → 핵심 키워드 → 우선순위. 한꺼번에 모든 카드를 2열로 채우기보다 읽는 순서를 세로로 유지.
- **Pattern:** Editorial Content, Compact Timeline, Priority Chip, Collapsible Detail(필요할 때만).
- **Action:** 개인 메모/키워드 `수정 → 저장`. 공식 분석 우선도는 사용자가 임의로 바꾸지 못함.
- **States:** 대표 활동 없음/분석 필요/지원처별 우선도 미완료이면 `자료 확인 중` 또는 해당 분석 부족 상태. 텍스트를 억지로 채우지 않음.
- **Mobile:** Timeline 가로스크롤보다 학년별 세로 스택, 키워드 칩 줄바꿈.

### 18.3 G02 학생부 분석 — Full Source Document

- **Layout:** 원문 목차 → 학년/영역 순서 그대로의 **읽기 전용 원문 전문**. 필요한 분석은 원문 옆의 약한 Inline Annotation 또는 원문 아래 별도 분석 블록. 원문이 주인공.
- **Pattern:** Document Viewer, Anchor Navigation, Sticky Section Index(PC), Text Highlight for annotations only, Progressive Rendering(대규모 문서일 때).
- **Action:** 항목 목차 클릭 → 원문 해당 섹션으로 이동. 오류일 때만 맥락형 `정정 요청`; 원문 조각마다 `더 보기`, `질문 보기` 반복 금지.
- **Preserve:** 문단·수치·띄어쓰기·단락 구분·원래 순서를 보존. 실데이터가 없는 항목은 `해당 기록 없음` 정도로 표현, AI 요약문을 원문처럼 표시 금지.
- **States:** 원문 파싱 실패/일부 페이지 누락/원본 버전 변경 → 경고 + 검수 절차. 원문 중 민감한 내용 표기/공유 제한은 별도 데이터 정책.
- **QA:** 1학년/2학년/3학년, 교과/세특/창체 등 긴 문서에서 스크롤 위치·목차 이동·검색 정상, 원문 OCR 누락 검증.

### 18.4 G03 대학·학과 분석

- **Layout:** 대학·학과 요약 → 공식 평가요소/면접 운영 조건 → 인재상 → 학생부 매칭 → 강조 전략. 정보 출처의 **상태를 필드 근처에 최소 크기 라벨**로 표시.
- **Pattern:** Structured Facts, Source Status Labels, Evidence Provenance Link, Progressive Disclosure of citations.
- **Action:** 공식 원문 URL이 있을 때만 `출처` 텍스트 링크 제공; 허위 확정 숫자/날짜/전형명 생성 금지.
- **States:** 대학 공통 인재상만 확인/학과 미확인/면접 운영 조건 일부만 확인/참고 일정. 각각 별개 상태 유지; `정보 없음 = 면접 미실시`로 잘못 표현하지 않음.
- **QA:** 대학 JSON의 `official`, `third-party`, `null` 필드를 UI에서 섞지 않음.

### 18.5 G04 예상 질문·답변 — Evidence-linked Master–Detail

- **PC Layout:** 왼쪽 **학생부 원문 전체 스크롤 패널**(읽기 전용), 오른쪽 **예상 질문·예상 답변** 패널. 질문 목록/선택기는 오른쪽 상단 또는 최소한의 내비게이션으로 통합; 설명 많은 사이드바 세 번째 열 금지.
- **Mobile Layout:** `학생부 | 질문·답변` 탭. 기본은 질문·답변; `학생부` 탭에서는 현재 질문의 원문 근거가 노란 하이라이트로 보이고 해당 위치로 이동. 복귀해도 개인 답변 초안·질문 선택 유지.
- **Pattern:** Linked Scrolling, Source Span Highlight, Master–Detail, Contextual Anchor, Inline Editing, Stateful Save Toggle.
- **Question change:** 질문 A→B 선택 시 이전 하이라이트 해제 후 B의 검증된 원문 위치 **해당 부분만** 강조. 위치가 먼 곳이면 부드러운 스크롤(사용자가 원하면 즉시 점프, reduced-motion 반영), 본문 상단 제목 유지.
- **Evidence accuracy:** `student_record_version_id + activity_id + source_ref_id + normalized_span(start,end)` + 원문 해시/텍스트 검증. 여러 원문 조각에 출처가 걸칠 때 anchor array 지원. 탐색 실패 시 무표시+`근거 위치 확인 중` 같이 진실된 상태; 문자열 유사도로 엉뚱한 문장 하이라이트 금지.
- **Initial view:** 질문 본문 + 예상 답변, 원문은 그대로. **표시 제외:** 질문 의도/생성 함수명/평가 코드/꼬리질문 미리보기/즉시 연습 버튼/중복 근거보기 버튼.
- **Answer edit:** `답변 수정하기` → 기존 개인 답변 있으면 해당 버전 편집, 없으면 기본 예상 답변을 참고자료로 보여주되 **기본 답변을 사용자가 작성한 것처럼 오인시키지 않음**. 편집 상태에서 `저장 / 취소`, 저장 중 버튼 잠금, 실패 시 내용 보존. 입력이 길면 편집기만 내부 스크롤 대신 적절히 확장.
- **Save question:** `질문 저장하기` → 성공 시 동일 위치 `저장됨`(선택 가능 시 해제), I01 동일 원본 질문 ID와 지원처 문맥·출처 구분. 저장 완료 판정은 서버 확인 후(오프라인 데모는 데모 명시).
- **Empty/error:** 해당 학생부 근거 없는 `공통/시사` 질문은 근거 형광펜을 만들지 않음. 원문 누락/버전 충돌이면 질문 본문만 유지하고 근거 부정확한 상태를 숨기지 않음.
- **Accessibility:** `<mark>` 의미와 프로그램적으로 연결된 `현재 질문의 근거` 안내, 대비가 되는 강조 색, 키보드 질문 전환 시 독자가 맥락을 잃지 않도록 포커스 처리.
- **QA:** 동일 문장이 두 학년에 존재해도 정확한 원문 1곳 또는 승인된 복수 위치만, 답변 저장 중 이동 시 초안 보호.

### 18.6 G05 실전 훈련 — 학습 콘텐츠

- **Layout:** '기억 구조화 / 발화 / 돌발 대응 / 모의면접 활용 / 직전 점검' 간단한 장 목차 + 읽기 자료. 과도한 Interactive Training Widgets 금지.
- **Pattern:** Editorial Modules, Disclosure for long examples, Checklist only when user action meaningful.
- **Action:** 링크가 꼭 필요할 때만 면접 연습실로 이동(이 장에서 또 다른 면접 화면을 만들지 않음); 버튼 없이 읽는 것이 기본.

### 18.7 G06 부록

- **Layout:** 질문 전체/사실 확인/자료/기록지 섹션; 선택적 체크 상태가 있는 내용 목록(인쇄 대상 선택 시에만 체크박스 표시).
- **Pattern:** Selective Export, Print Preview, Batch Selection Scoped to Section.
- **Action:** `선택 인쇄·PDF`는 콘텐츠를 고른 뒤 열림, 선택 항목·분량 확인. 전체 가이드북 1클릭 다운로드는 없음.
- **States:** 선택 0개일 때 인쇄 버튼 비활성화 + 이유, 팝업 차단/생성 실패 안내, 민감 기록의 다운로드 주의.

### 18.8 G07 가이드북 사용법

- **Layout:** 최초에 필요한 2~3개만 소개: 목차 탐색/질문 저장/AI 비서. **Dismissible Coach Mark** 또는 작은 도움 화면. 필수 가입 단계로 강요하지 않는다.
- **Pattern:** Contextual Onboarding, Progressive Tips, Dismiss and Revisit.
- **Action:** `알겠어요` 한 번, 이후 도움 아이콘에서 재열람 가능.

### 18.9 G09 AI 비서

- **Layout:** 우하단 단일 플로팅 트리거 → Side Panel(PC)/Bottom Sheet 또는 Full-height Sheet(모바일). 기존 가이드북은 그대로 유지, 닫으면 읽던 위치로 복귀.
- **Pattern:** Scoped Assistant Panel, Suggested Prompt Chips(최초 2~3개 이내), Streaming Response, Thinking Indicator, Source Anchors, Inline Error.
- **Action:** 입력→`보내기`(텍스트 공백이면 비활성), 응답 중에는 입력/취소 정책에 맞게 제어. 제안 칩은 ‘이 활동의 핵심은?’ 같은 문장으로 제한; 학생부 근거가 없는 내용을 추측하게 하는 예시는 금지.
- **States:** 답변 중 / 답변 완료 / 출처 불확실 / 응답 실패 / 서버 제한. 응답 실패 시 학생 메시지 유지, 필요하면 `다시 시도`.
- **Citations:** 가이드북 근거가 있는 발언은 짧은 `관련 기록` 연결(누르면 이미 있는 원문 위치로 이동, 별도 원문 팝업을 만들지 않음). 공식 자료/학생부 미확인 내용은 단정 금지.
- **Safety:** AI 비서가 학생의 대답 원문을 보정하거나 사용자 권한 없이 학생부를 수정하지 않음. `답변 수정됨` 등 실행하지 않은 행동을 완료로 보고하지 않음.
- **Accessibility:** 새 메시지 수신 시 포커스를 강제로 빼앗지 않음, 실시간 텍스트 누적에 과도한 알림 방지, 전송 버튼·닫기 키보드 사용 가능.

## 19. 화면별 UX 상세 명세 — I00~I10 면접 연습실

### 19.1 I00 면접 연습실 진입

- **Layout:** `연습 면접` / `실전 모의면접` **카드 딱 2개**, 둘 다 명칭+아이콘. 메뉴별 장황한 설명·예상 질문 미리보기 카드 금지.
- **Pattern:** Binary Feature Choice, Whole-card Click, Clear IA.
- **Action:** 카드 선택 → I01 또는 I05. 실전은 **화상 전용**; `채팅 실전`처럼 언뜻 보이는 경로는 없음.
- **States:** 연습 기간 미시작/기간 종료/준비플랜/이용권 부족 등 권한별 조건을 다음 화면으로 진입했을 때 명확히 안내. 숨긴 구매 버튼으로 오인 유도 금지.

### 19.2 I01 연습 질문 선택·설정

- **Layout:** 상단 `질문 선택 | AI 질문 생성 | 직접 입력` **3개 탭**; `질문 선택` 탭 내부의 가벼운 분류 `내가 추가한 항목 | 가이드북 전체 | 보완 추천`(필요할 때만). 하단 `연습 방식`(채팅/화상) + 주행동 `연습 시작`.
- **Pattern:** Segmented Tabs, Nested Filter(두 번째 단계는 칩/필터), Progressive Disclosure, Dependent Filter, Sticky Bottom CTA(모바일에서만).
- **Action:** 질문 하나 선택하거나 입력/생성 → 출처와 질문을 확인 → `연습 시작`. AI 질문 생성 중에는 `질문을 준비하고 있어요`; 생성 후에는 검증 통과 질문만 노출.
- **Complexity control:** 엔진의 `15개 질문 기능`, Q0/F1/F2 내부 코드, 기술 난이도 D1~D4 등을 학생에게 한꺼번에 보이지 않는다. '질문 유형', '학년/영역', '난이도'는 학생이 실제로 이해 가능한 선택지만; 고급 조건은 `조건 더 보기` 같은 단일 Disclosure(정말 필요 시).
- **Save integration:** G04/M04의 `질문 저장하기`가 I01 `내가 추가한 항목`으로 유입. 이미 저장된 질문을 다시 불러왔을 때 중복 생성하지 않음.
- **State:** 저장 질문 없음→ `저장한 질문이 없어요`; AI 생성 실패→ 생성 탭에서 간단한 재시도; 직접 입력 공란→ `연습 시작` 비활성; 연습 기간 종료→ 권한/상품 정책 안내.
- **Mobile:** 첫 탭 3개가 좁으면 좌우 잘림 없이 적합한 Segmented/Tab 스크롤(현재 위치 인지), 하단 `연습 시작`은 가상 키보드 위로 안전하게 배치.
- **QA:** 탭 간 전환 시 직접 입력 초안 보존, 필터 변경 시 선택 질문을 조용히 바꾸지 않음.

### 19.3 I02 채팅/화상 연습 진행

- **Layout:** 질문 메인 카드/면접관 영역 → 학생 답변 영역 → `답변 제출` 또는 음성 완료 버튼. 상단에는 **`면접 종료`만** 부가 조작.
- **Pattern:** Focused Conversation, Turn-based Interaction, Loading Button, Single Clear Action, Session-safe Autosave.
- **Action:** 답변 제출 → 서버 확인 중 중복 제출 차단 → 필요 시 F1/F2가 자동 등장 → 질문 묶음 완료 후 I03. 질문 마다 하나의 평가 목적, 후속 최대 2개.
- **Feedback isolation:** 질문 묶음 종료 전 점수/피드백/모범 답변 절대 노출 금지. Q0/F1/F2 코드도 일반 학생 뷰에서 숨김.
- **Media:** 채팅은 Enter/Submit의 의미를 명확히(줄바꿈 입력 가능); 화상은 마이크 권한/기기 상태·음성 전달 표시. STT 신뢰도가 낮을 때는 오인식 답변을 학생 탓으로 평가하지 않는 복구 조건을 개발팀과 검증.
- **States:** 질문 준비 중, 답변 제출 중, 중복 제출 방지, 사용자가 닫음(종료 확인), 장애로 내용 전송 실패(입력 보존), 연결 복구.
- **Motion:** 화려한 면접관 등장/추임새 애니메이션 금지. 질문 바뀔 때 짧은 Crossfade 정도.

### 19.4 I03 연습 피드백 — 평가 카드·모범 답변

- **Layout:** 제목 `이번 답변 피드백` → 실제 관찰된 평가 관점별 카드(2열 PC/1열 모바일) → `이렇게 다듬어 보세요` → `모범 답변 예시` → 고정 하단 `다시 연습하기 | 다음` 두 버튼.
- **Pattern:** Feedback by Dimension, Sentiment Semantics, Low-Cognitive-Load Card, Worked Answer Example, Dual End-of-Task Actions.
- **Card taxonomy:** 카드 제목은 `핵심 전달`, `설명의 구체성`, `답변의 논리`, `학생부 정합성` 등 자연어. 엔진 내부 채점 지표와 대응하는 항목만 표시하고, 매번 억지로 4개를 채우지 않음.
- **Positive state:** Mint + 체크 + `좋았어요` / **Improve state:** Coral + 수정/상향 아이콘 + `더 다듬어봐요` 또는 `확인이 필요해요`. 금지: '역량 탁월' 같은 검증 없는 절대 평가나 색만으로 평가 표시.
- **Copy:** 카드당 1~2문장. 먼저 사용자가 실제로 한 설명을 짚고, 개선 필요 시 **어떤 한 가지 사례를 추가하면 되는지** 명시. 모범 답변은 '실제로 확인된 학생부/대화 사실만' 조합, **가상 경험 절대 생성 금지**.
- **Action:** 기본 버튼 두 개 정확히 유지. `다시 연습하기` → I04 필요 시 범위 선택, `다음` → 다음 질문 또는 I01. 별도 `피드백 저장` 버튼 없음(자동 저장).
- **States:** 평가 생성 중에는 Skeleton 대신 `피드백을 정리하고 있어요` + 실제 상태, 생성 불가 시 빈 칭찬문을 생성하지 않고 실패/복구 안내. 점수 0~100 등 숫자 미표시.
- **Accessibility:** 색채 구별 어려운 사용자도 문구/아이콘으로 강약 이해, 장문은 적절한 줄 간격, 버튼 Tab 순서 논리적.

### 19.5 I04 다시 연습하기 범위 선택

- **Layout:** 작은 **Dialog(PC) / Bottom Sheet(모바일)**에 `이 질문만` / `질문 묶음 전체` 2개 선택지. 기본적으로 I03에 더 많은 버튼을 만드는 대신 필요한 순간에만 등장.
- **Pattern:** Action Sheet, Radio/Single Choice, Contextual Confirmation.
- **Action:** `이 질문만`은 선택 질문 재답변(추가 F 생성 없음), `질문 묶음 전체`는 Q0부터 다시. 중단하려면 `취소`/닫기. 취소 시 I03 유지.
- **States:** 본 기록이 Q0만이면 불필요한 범위 선택 단계 생략해 즉시 재연습할 수 있음(권고); 각 재연습 결과는 과거 답변 Revision을 덮어쓰지 않음.

### 19.6 I05 실전 모의면접 설정

- **Layout:** 지원처 1개 선택 → 공식 확인된 면접 시간/면접관 정보(있을 때만) → 잔여권 안내. `다음` 1개. **면접 방식 선택 없음**.
- **Pattern:** Focused Single Choice, Information Hierarchy, Explicit Access State.
- **Action:** 지원처 선택 후 다음으로 이동. 등록 안 된 지원처를 갑자기 추가하는 중첩 팝업보다 U01 경로를 안내(맥락 유지).
- **States:** 잔여 0회→ 추가 구매 단일 경로, 해당 정보 미확인→ `가상 시뮬레이션 조건` 표시, 발행 미완료→ 실제 진행 가능 여부 정책대로 차단/안내.
- **QA:** '실전=화상' 규칙 위반하는 채팅/음성만 진행 대안 없음. 모든 플랜에서 7,900원 추가권 구매 정책 일치.

### 19.7 I06 입장 전 장비·차감 확인

- **Layout:** 카메라 미리보기 → 마이크 입력 레벨(실측) → 장치 상태(아이콘/짧은 문구) → 이용권 차감 기준 → `모의면접 시작`.
- **Pattern:** Preflight Device Check, Permission Prompt in Context, Capability Detection, Explicit Cost Disclosure.
- **Action:** 시작 전 카메라/마이크 권한은 실제 이용을 설명한 후 요청. 장비가 준비 안 된 상태에서는 시작 비활성화 + `장치 다시 확인` 같은 복구 행동.
- **Privacy:** 카메라/마이크 권한만으로 녹화·저장에 동의했다고 가정하지 않는다. 저장/처리/보유 정책은 승인된 고지대로.
- **States:** 장치 없음/권한 거부/지원 안 되는 브라우저/네트워크 저하/마이크 입력 없음/장치 정상. 무조건 '문제 없음' 녹색 상태 표시 금지.
- **Business:** Q0 정상 제시 전 이용권 차감 없음. `시작` 누르고 장치 실패 시 권리 차감 없어야 함.

### 19.8 I10 실전 입장 3단계 — Truthful State-based Stepper

- **Layout:** 1개 중앙 패널, 한 번에 단계 하나의 문장, 아래 단순 3단계 진행 상태. 사용자 버튼 없음.
- **Stage mapping:** `student_record_loading/validated` → `면접관이 학생부를 살펴보고 있습니다`; `question_planning/validated` → `면접관이 질문을 정리하고 있습니다`; `media_room_ready` → `곧 면접장에 입장합니다`.
- **Pattern:** Indeterminate Stage Progress + Stepper, Staged Feedback, Semantic Status Announcements. **고정 대기시간·가짜 백분율 없음**.
- **Motion:** 단계 교체 시 150~200ms Fade. 배경은 조용한 움직임, 학생을 압박하는 카운트다운/박동·시계 효과 금지.
- **States:** 단계가 실제로 건너뛰어 완료되면 자연스럽게 다음 상태로; 준비가 안 되면 현재 상태 유지하되 일정 시간 이상 지연 시 `준비에 시간이 걸리고 있어요`처럼 실제 경고. 실패하면 오류 화면(서버 상태 저장)으로 전환.
- **Observability:** UI 단계 ID·시작/완료/실패 시각을 서버 로그에 저장, 측정 가능한 QA 이벤트 제공. 학생에게 가짜 `'면접관이 ...'` 의인화를 해 작업 중인 것처럼 속이지 않음.
- **QA:** 2번째 단계 실패와 재시도를 재현, 첫 Q0 미제시로 이용권 미차감 확인.

### 19.9 I07 실전 화상 면접 — Immersive Room

- **Layout:** 면접관 비디오/아바타 또는 실제 기술로 제공 가능한 영상 표시 영역(미구현 기능을 영상처럼 연출 금지) + 질문 텍스트(접근성) + 학생 본인 카메라 미리보기(필요 시 작게) + 최소 장치 상태 + `면접 종료`.
- **Pattern:** Immersive Focus Mode, Video Call Controls, Captions/Question Transcript, Network Recovery Banner, Controlled Exit.
- **Action:** 기본 질문/답변 흐름은 AI가 주도. 필수 마이크/카메라 조작이 있을 경우 장치 상태와 결과를 명확히 표시. 수동 답변 종료가 있는 구현이라면 `답변 완료` 하나만 표시(자동 턴 종료와 중복 노출 금지).
- **Navigation:** 면접 중 상단 4메뉴와 모바일 하단 4탭 숨기기. 화면 이탈/새로고침/종료는 사용자 혼란 최소화. 중요한 종료는 Confirm Dialog.
- **A/V quality:** TTS 질문, STT 최종 전사, 원본 음성/세션 ID 사이 추적성 확보(실제 원본 저장 범위는 개인정보 정책 준수). STT 신뢰할 수 없는 상태는 답변자의 잘못으로 점수화하지 않음.
- **Fault:** 네트워크 끊김→ `연결이 끊어졌어요. 이어서 진행할 수 있어요` + 복구 경로. 장애가 길면 부정확한 점수 대신 무효/부분/이용권 복구 판정.
- **Timer:** 공식 면접 시간과 시뮬레이션 시간을 구분. 불필요한 초 단위 카운트다운은 압박과 오인을 키우므로 실제 시간 제한이 정책상 필요할 때만.
- **Accessibility:** 질문 자막/원문 보조(면접 형식 훼손하지 않는 범위), 키보드 미디어 버튼, 라벨, reduced motion, 카메라 미리보기 숨김 선택 등은 기술 검증에 포함.

### 19.10 I08 종료·평가 진행

- **Layout:** `면접이 종료됐어요` → `평가 결과를 정리하고 있어요` → 완료 시 `리포트 보기`. 정상 상태에서 불필요한 2차 저장 버튼 없음.
- **Pattern:** Processing State → Result State, Honest Async Feedback, Single CTA.
- **States:** 정상 완료/평가 처리 중/부분 평가/평가 불능/서비스 장애 복구. 무효 묶음을 0점처럼 표시 금지. 정확한 기준은 8·10번 면접 엔진 MD 적용.
- **Action:** 완료에서만 `리포트 보기`, 미완료는 상태 재확인/고객센터 중 필요한 하나.

### 19.11 I09 10분 재접속 복구

- **Layout:** 상단 `면접이 잠시 중단됐어요` + 동일 회차 정보 + `이어하기`. 남은 연결 복구 시간을 보여줄 경우 **서버 기준 실제 시각**으로 계산(가짜 타이머 금지).
- **Pattern:** Session Recovery, Single CTA, Preserved State, Idempotency.
- **Action:** 10분 이내에 현재 질문/진행 상태 복원, 이용권 중복 차감 절대 금지. 10분이 지난 경우 기존 정책에 따른 유효 질문·서비스 귀책/복구 판정.
- **QA:** 브라우저 새로고침, 다른 탭, 통신 오류에서 새 회차 생성 0, 과거 문답 보존.

## 20. 화면별 UX 상세 명세 — A00~A06 내 답변

### 20.1 A00 진입

- **Layout:** `답변 보관함 / 면접 리포트 / 면접 직전 요약` 3개 아이콘+명칭 카드. 이외 설명 부제 없음. A05 독립 메뉴 삭제 유지.
- **Pattern:** Feature Cards, Low Visual Density.
- **Action:** 전체 카드 클릭, 보조 `열기` 버튼 금지. 면접 직전 요약은 D-1 전에는 잠금 상태만 표시.

### 20.2 A01 답변 보관함 — 세션/회차 우선

- **Layout:** 최상단 `연습 면접 | 실전 모의면접` Segmented Tabs(전체보기 없음). 연습→ **세션별 목록**, 실전→ **회차별 목록**. 질문 낱개를 첫 화면에 나열하지 않는다.
- **Pattern:** Tabbed Records, Grouped Session Cards, Contextual Filter Row, Paging/Load More, Persistent Query State.
- **연습 필터:** `지원처`(선택한 대학 + 공통) / `질문 유형`(학생 친화적 분류). 필터는 목록 상단 2개까지만 기본 노출, 나머지는 `필터` 시트로 이동(정말 필요한 경우).
- **실전 목록:** 회차명·날짜·해당 지원처·평가 상태·확정 점수(있을 때만)만 간결하게 표시; 회차 누르면 해당 회차의 질문/답변 기록. 점수 미확정/무효에 가짜 숫자 사용 금지.
- **States:** 기록 없음→ `아직 연습 기록이 없어요` 또는 `아직 실전 기록이 없어요`; 필터 결과 없음→ `조건에 맞는 기록이 없어요` + 필터 초기화 1개; 검색 실패→ 재시도.
- **Navigation:** 상세→뒤로 시 탭/필터/스크롤 유지. 실전 회차 상세는 이미 A03 리포트가 있다면 명확히 ‘답변 기록’이라는 목적에 집중(점수 상세 UI 이중 구현 금지).
- **QA:** `공통` 표기가 대학 미선택을 의미, 한 세션 내 여러 질문이 있을 때 목록 1개 카드로 표시.

### 20.3 A02 답변 상세 — 대표 답변

- **Layout:** 상단 면접 종류·지원처·날짜(메타데이터) → 실제 질문 → 실제 답변 → 실제 후속 질문/답변(있을 때만) → 연습 피드백(연습일 때만). 질문별 대표 지정 아이콘은 답변 가까이에 1개.
- **Pattern:** Detail View, Read-only Record, Star Toggle / Single Representative, Comparison by Revision(탭/타임라인일 때만).
- **Action:** 별 아이콘 탭하면 `대표 답변으로 지정` 상태 토글. 같은 `canonical_question_id + target_context_id`에서 대표 답변 1개만 가능. 변경 시 원본 기록은 불변.
- **Feedback:** 성공 시 별이 채워지고 `대표 답변으로 지정했어요` 짧은 Toast. 실패 시 별 원상복구 + 오류. *이 답변이 정답으로 선정됐다*고 표현 금지.
- **History:** 새로 연습한 답변은 과거 답변의 Revision으로 보존; 과거 점수·시간·STT 확정본은 수정 불가. 기록 제거/수정 기능을 넣지 않음.
- **Accessibility:** 별 아이콘만 두더라도 `aria-label="대표 답변으로 지정"/"대표 답변 해제"`, 상태는 `aria-pressed` 등으로 전달.

### 20.4 A03 면접 리포트 — 누적 결과 중심

- **Layout:** 상단 집계 기간/지원처 범위 → `완료 회차 / 평균 점수 / 최근 점수` 간결한 3개 Statistic Cards → **점수 추이 Line Chart**(실제 유효 데이터가 2회 이상일 때만) → 아래 회차별 Accordion.
- **Pattern:** KPI Summary, Progressive Disclosure, Accessible Line Chart, Scope Selector(필요 시), Accordion.
- **Stats:** 정식 완료·유효 점수만 집계. 부분 평가/실패/취소 제외는 **분모와 제외 조건**을 코드와 화면 상태에 함께 적용. 다른 지원처 점수 합산 시 사용자가 범위를 혼동하지 않게 표시.
- **No fabricated progress:** 자료가 1회면 차트 대신 `첫 면접 점수가 기록됐어요` 같은 상태. 데이터가 없으면 큰 숫자 0.0점 표시하지 않음.
- **Interaction:** 회차 헤더 전체 클릭(펼침/닫힘), 한 번에 기본 1회차만 펼침(권장). 회차는 접근 가능한 `aria-expanded`.
- **Mobile:** 3KPI는 가로 스크롤 강제보다 2열/1열 또는 3열 균형 배치, 차트 가로 확대를 강요하지 않도록 축 레이블/텍스트 요약 병행.

### 20.5 A04 회차별 리포트 상세 — **미확정 경계 유지**

- **확정 가능한 껍데기만:** 회차·지원처·응시 시각·평가 완료/부분/무효 상태·평가 점수(유효할 때만)·`PDF 다운로드` 진입. 상세 카테고리, 그래프 종류, PDF A/B/C 레이아웃은 **TBD**.
- **Pattern:** Accordion Body Container, Print/Download Action, Stable Document Version.
- **실행 규칙:** 리포트 실제 생성 완료 전에는 PDF 버튼을 보이지 않거나 비활성 이유를 명시. 다운로드와 화면 미리보기 점수가 불일치하지 않도록 동일 report_version 사용.
- **주의:** 경쟁사 이미지의 8개 역량과 3단계 배지를 각자의답 공식 평가 항목이라고 자동 채택하지 않는다.

### 20.6 A06 면접 직전 요약 — D-1 Lock/Unlock

- **Locked State:** 메뉴 카드는 표시하되 열림 전 `면접 하루 전 열려요` 한 문장 + 자물쇠. 개인 확정 면접일이 없으면 `면접일을 등록하면 열리는 날짜를 알려드려요` + U01 일정 등록 경로.
- **Unlock:** 학생 개인 확정 면접일 기준 하루 전. 정확한 시각/타임존/다중 지원처 정책은 TBD로 두고, 구현 확정 전 하드코딩 금지.
- **Layout after unlock:** `핵심 활동 / 필수 예상 질문 / 반복 보완 사항 / 사실 확인 / 지원처 유의사항`의 **작은 읽기 카드**. 무조건 같은 카드 개수 채우지 않음.
- **Pattern:** Time-gated Content, Conditionally Locked Card, Summary Tiles, No False Countdown.
- **States:** 날짜 변경/기한 경과/원문 부족/일정 미확인/요약 생성 실패. D-1 공개를 가짜 '마감 압박'으로 연출하지 않음.

## 21. 화면별 UX 상세 명세 — M00~M04 암기 훈련실

### 21.1 M00 진입 및 권한

- **Layout:** `퀴즈 / 지식한입 / 이슈픽` 3개 카드, 아이콘+이름만. 준비플랜은 메뉴를 보이되 접근 시 조건 안내. 구독 유도를 위해 기능이 실제 제공되는 것처럼 미리 데이터를 채우지 않음.
- **Pattern:** Feature Grid, Permission State with a Single CTA.
- **Action:** 카드→해당 기능. 미포함 시 `요금제 보기` 1개.

### 21.2 M01 퀴즈 시작

- **Layout:** 질문 주제/학습 범위의 간단한 선택(진짜 사용자 선택이 필요할 경우만) → `시작하기`. 내부의 문항 기능·채점 규칙까지 전면 노출하지 않음.
- **Pattern:** Focused Quiz Setup, Sensible Defaults(비용/동의와 무관), Session Start.
- **States:** 생성/검증 완료 문항 부족→ 문제 없이 학습자료로 돌아갈 수 있는 안내. 오답 가중은 기존 기록이 충분할 때만 활성화.

### 21.3 M02 퀴즈 문제·해설

- **Type UI:** `단일 선택`=Radio, `복수 선택`=Checkbox, `순서 배열`=Drag-and-Drop + 키보드/위아래 버튼, `짝 연결`=Pair Matching + 터치/키보드 대체, `빈칸`=Text Input.
- **Layout:** 진행 문항수(실제 총 문항수 알려진 경우) → 질문 본문 → 답 입력 → `답 확인` → 짧은 정답/해설 → `다음`/마지막 `끝내기`.
- **Pattern:** Immediate Corrective Feedback **after explicit answer**, Error-based Spaced Repetition, Gentle Motion, Answer Lock after Check.
- **Spaced repetition state:** 문항 `question_id`, 개념 `concept_id`, 회차/최근 풀이 시각, 정오답, 연속 정답, 누적 오답. 다음 출제는 `틀렸던 개념 ↑ / 여러 번 맞힌 개념 ↓ / 신규 문제 일정 비중`을 반영(수치 가중치/간격 TBD).
- **Fairness:** 단순 철자 차이·순서 배열의 근거 부족으로 '틀림' 판정하지 않도록 문제 유형별 채점 세칙이 필요. 문제 정답은 출처가 검증된 데이터만.
- **Accessibility:** 드래그 필수 금지; 시각적 빨강/초록 외 `정답이에요`/`다시 확인해요` 문구. 타이머로 학습 압박 금지.
- **States:** 제출 없음/정답/오답/부분정답(정책 승인 시)/문항 서버 오류/문제 종료.

### 21.4 M03 지식한입 — 썸네일 리소스 라이브러리

- **Layout:** 상단 간략 `내 학생부 관련 | 전체 자료 | 즐겨찾기` 분류 → **Media-first Resource Cards**. 각 카드에는 `[16:9 썸네일] [제목] [자료 유형] [출처] [나에게 중요도] [별]`만.
- **Pattern:** Visual Browsing, Thumbnail Aspect-Ratio, Progressive Image Loading, Favorite Toggle, External Resource Links, Filter Chips.
- **Action:** 카드 본문 클릭 → 검증된 실제 제공 페이지. 별 아이콘은 **즐겨찾기 토글만**; 별을 누르면 카드 열기가 발생하지 않도록 이벤트 분리.
- **Personalization:** 세특·탐구활동 `activity_id`와 `topic_id`, 대학/학과 맥락을 연결해 개인 추천, 중요도는 **연계 강도**이지 대학교 출제 확률이나 공식 점수가 아님. `먼저 보기/관련 자료` 같은 정성 라벨부터 권장.
- **Sources:** 대학/공공기관/논문/저작권 허용 영상 등 실제 검증. 원본 링크·발행처·검증일·열람 가능 여부. 이미지 없는 자료는 파일 유형 아이콘/기관명 사용; 다른 자료 썸네일 재사용 금지.
- **States:** 링크 만료/썸네일 실패/추천 부족/즐겨찾기 없음/권한 없는 외부 원문. 내부 앱에서 사용자 학생부 정보가 외부 사이트 URL 쿼리에 노출되지 않도록.
- **Mobile:** 1열 카드 또는 2열 썸네일 그리드(제목 길이에 따라 선택), 별 타깃 충분히 확보.

### 21.5 M04 이슈픽 — 시사 아티클·질문 라이브러리

- **Layout:** 지식한입과 같은 카드 문법/썸네일. 상세에서 **짧은 이슈 요약 → 주요 관점 → 면접에서 생각해 볼 질문**. 출처·발행일·확인일 표시.
- **Pattern:** News/Knowledge Card, Short Editorial Summary, Distinct Favorite vs Save Question, Source Credibility Display.
- **Action 1:** 별 = **해당 콘텐츠 즐겨찾기**(이슈픽 내부); 토글 시 `즐겨찾기에 추가했어요`.
- **Action 2:** `질문 저장하기` = 질문을 I01 `내가 추가한 항목`에 등록. 저장 완료는 서버 확인 후 `저장됨`. 별과 서로 영향을 주지 않음.
- **States:** 원문 없음/기사 링크 갱신/질문 없는 자료(이때 저장 버튼 숨김)/출처 불명(제외)/시사 업데이트 지연(‘최신’ 주장 금지).
- **Caution:** 의견 균형을 위해 반대 관점을 무조건 같은 비중으로 허위 균형 처리하지 않고, 검증 가능한 사실과 논쟁 중인 관점을 분리.

## 22. 화면별 UX 상세 명세 — U01~U08 계정·공통 관리

### 22.1 공통 Account Menu

- **Pattern:** Popover/Menu Button(PC), Bottom Sheet(모바일). 정확히 `지원처 관리, 내 요금제, 면접 이용권, 결제 내역, 계정 설정, 고객센터, 로그아웃`.
- **Interaction:** 열림 시 포커스 첫 항목/트리거와 연결, ESC·바깥 클릭으로 닫힘(환경별 접근성 맞춤), 현재 화면을 바꾸지 않고 메뉴 열기만.

### 22.2 U01 지원처 관리

- **Layout:** 현재 선택된 지원처 상단, 나머지 등록 지원처 카드, 하단 `지원처 추가`. 카드에서 `선택하기`와 `변경`을 명확히 분리. 개인 면접일 편집은 해당 카드의 날짜 입력.
- **Pattern:** Context Selector, Distinct Actions, Searchable School Selector, Confirm Dialog for Paid Change, Date Picker.
- **Actions:** `선택`=무료 문맥 전환; `변경`=기존 슬롯의 학과·전형 등 교체; `추가`=4번째 이후 별도 14,900원. 세 동작을 UI에서 같은 `수정` 아이콘으로 표현하지 않는다.
- **Price boundary:** 발행 후 변경 유료 조건에 도달했다면 **변경 실행 전** 금액/대상/되돌릴 수 있는 범위를 확인. 사전 고지 없이 결제 화면으로 보내거나 학생부 분석을 삭제 금지.
- **Date:** 날짜 입력은 Date Picker + 직접 입력 대체. 확정일 저장 시 출처가 '학생 직접 확인/입력'임을 명확히 표시. 대학 JSON 참고 날짜는 개인 확정으로 자동 저장 금지.
- **States:** 슬롯 남음/기본 3개 모두 사용/추가 구매 가능/등록 학교 없음/학교 변경 전/가이드북 발행 후 변경 제한/지원처 전환 중/면접 진행 중 전환 불가.
- **QA:** 완료된 회차 지원처·학생부 버전 불변. 전환 버튼에 결제 팝업이 연결되지 않음.

### 22.3 U02 내 요금제

- **Layout:** 현재 플랜 명칭 → 포함 기능 표의 짧은 비교 → 실제 연습 기간(시작 전/이용 중/만료) → `플랜 업그레이드`.
- **Pattern:** Membership Summary, Usage Period Status, Single Upgrade CTA, Explicit Price Difference.
- **States:** 준비/실전/몰입, 미구매, 업그레이드 가능/최상위, 기간 만료. 몰입플랜에는 업그레이드 버튼을 관성적으로 표시하지 않음.
- **Anti-dark:** 차액과 이미 사용한 기본권 계산을 명확하게, 불필요한 할인 압박 금지.

### 22.4 U03 면접 이용권

- **Layout:** 합산 잔여 수치 1개를 크게, 기본/추가 잔여는 작은 행, 아래 이용 내역 Accordion, `이용권 추가 구매` CTA 1개.
- **Pattern:** Numeric Dashboard, Transaction Ledger, Expandable History, Quantity Stepper (구매 수량), Idempotent Action.
- **Actions:** 추가 구매 클릭→수량·단가(7,900원/회)·총액 → 결제 승인. 이용권 원장 승인 이후 잔여 수치 변경.
- **States:** 0회/잔여 있음/구매 처리 중/환불·복구/차감 오류. `만료까지 X일`은 **무기한 이용권에 절대 표시하지 않음**.
- **QA:** 재접속/장애 복구 시 차감/복구 중복 없음.

### 22.5 U04 결제 내역

- **Layout:** 최신 주문 카드(상품, 날짜, 금액, 상태), 클릭하면 거래 상세/영수증. 구매 버튼은 배치하지 않음.
- **Pattern:** Transaction History, Status Label, Receipt Detail.
- **States:** 결제 확인 중/완료/취소/환불/실패. 실패 거래도 고객 문의가 가능하도록 기록 유지(개인정보 최소화).
- **Anti-dark:** 할인/원가/합계 부정확하게 표시 금지. 결제 관련 중요 메시지를 몇 초짜리 토스트만으로 통지하지 않음.

### 22.6 U05 계정 설정

- **Layout:** `내 정보 / 알림 설정 / 회원 탈퇴` 간결한 행 목록. 각 항목 자체가 내비게이션. `로그아웃`은 프로필 메뉴에서만.
- **Pattern:** Settings List, Switch for Immediate Binary Preference, Inline Form, Destructive Confirm.
- **States:** 변경 저장 중/완료/실패, 동의 없는 수신 설정 금지, 발송 채널 미구현이면 설정 노출 금지.
- **Withdrawal:** 회원 탈퇴는 복구/삭제 범위/보유 이용권·면접 기록 영향 안내 → 확인 단계. 사용자에게 불필요한 여러 단계 방해/죄책감 메시지 금지.

### 22.7 U06 학생부 정정·재분석

- **Entry:** G02 오류 맥락 또는 계정/관리 경로에서 진입. 독립 최상위 메뉴 생성 금지.
- **Pattern:** Issue Report Form, Source-linked Anchor, Review-before-Reprocess, Version Tracking.
- **Action:** 정정 요청은 대상 원문 위치/실제 오류 설명을 붙여 제출. 재분석은 새 원본 등록을 받은 뒤 비용/영향/기존 버전 유지 여부 명시하고 실행.
- **States:** 요청 접수/검수 중/정정 완료/추가 확인/재분석 실패. 공식 원문을 사용자가 직접 고치게 하지 않음.

### 22.8 U07 고객센터

- **Layout:** `FAQ / 문의하기 / 문의 내역` 3개 간결한 카드. 문의 폼은 유형→내용→확인→제출. 별도 최상위 `오류 신고` 메뉴는 없음.
- **Pattern:** Focused Support Form, Contextual Diagnostics(세션 ID 자동 첨부, 승인된 범위), Error Validation, Confirmation Receipt.
- **Action:** 제출 중 버튼 로딩/중복 차단, 완료 시 `접수됐어요` + 문의 번호, 문의 내역으로 진입.
- **Privacy:** 음성 파일·학생부 원문은 필요한 경우만 동의를 받아 최소 범위로 첨부(자동 전체 첨부 금지).
- **States:** 등록 안 된 문의/답변 대기/처리 중/답변 완료/첨부 오류/서버 오류.

### 22.9 U08 로그아웃

- **Pattern:** Direct Session Termination for ordinary logout, Context-sensitive Unsaved Changes Guard.
- **Action:** 일반 상태는 즉시 로그아웃. 개인 답변 편집 중 미저장 데이터가 있으면 확인. 진행 중 면접은 별도 종료/복구 정책 우선.
- **Anti-dark:** 로그아웃을 마치 유료 탈퇴처럼 다루는 강제 설문/죄책감 메시지 없음.

## 23. 예외·상태 설계 — Page States / Recovery Contracts

모든 화면이 `happy path`만 구현되면 실제로는 불완전하다. 아래는 전역에서 재사용하는 표준 **상태 전이(State Machine)** 및 UX 처방이다.

| 상태 ID | 발생 조건 | 권장 패턴 | 사용자 화면에 보일 문구(예시) | 주행동 | 하지 말 것 |
|---|---|---|---|---|---|
| S00 Initial | 첫 화면 접속 | Stable Layout | 정보 표시 | 해당 화면 행동 | 시작부터 불필요한 스피너 |
| S01 Loading Short | 짧은 API 응답 | Loading Button/Inline Spinner | `저장 중…` | 클릭 잠금 | 전체 화면 차단 |
| S02 Loading Structured | 목록·카드 로드 | Skeleton | 실데이터와 비슷한 크기의 빈 모양 | 없음 | 가짜 내용 삽입 |
| S03 Processing Multi-step | OCR·실전 입장 | Actual Stepper | 현재 실제 처리 단계 | 보통 없음 | 임의 백분율/카운트다운 |
| S04 Empty First Use | 아직 기록 없음 | Empty State | `아직 연습 기록이 없어요` | 필요할 때만 1개 | 가짜 통계·샘플 기록 |
| S05 Empty Filter | 필터 결과 없음 | No-results State | `조건에 맞는 기록이 없어요` | `필터 초기화` | 무조건 새로 등록 유도 |
| S06 Success Lightweight | 저장/즐겨찾기 성공 | Toast + persistent UI state | `질문을 저장했어요` | 상태 토글 | 성공 전 토스트 선표시 |
| S07 Success Transaction | 결제/발행/접수 완료 | Confirmation Page/Panel | `결제가 완료됐어요` | `내역 보기` 등 하나 | 성공 상태를 짧은 Toast로만 안내 |
| S08 Error Field | 양식 값 오류 | Inline Error + Error Summary | `면접일을 다시 확인해 주세요` | 입력 수정 | 입력값 삭제/추상 오류 |
| S09 Error Recoverable | 네트워크·임시 장애 | Inline Banner + Retry | `연결이 불안정해요` | `다시 시도` | 무의미한 5개 버튼 |
| S10 Error Non-recoverable | 서버 오류·권리 영향 | Dedicated Error State | `서비스 문제로 면접을 이어갈 수 없어요` | `고객센터` 또는 자동 복구 경로 | 사용자 탓/유효 점수 조작 |
| S11 Restricted by Plan | 기능 권한 없음 | Permission Panel | `현재 플랜에 포함되지 않아요` | `요금제 보기` | 결제 압박/허위 잠금 혜택 |
| S12 Awaiting Verification | 학생부/대학 정보 검증 중 | Status Label/Banner | `정보를 확인하고 있어요` | 기다림 또는 정정 경로 | 미확인을 0/면접 없음으로 표현 |
| S13 Unsaved Edits | 편집 상태 이탈 | Save/Discard Dialog | `수정 중인 답변이 있어요` | `계속 수정 / 저장하고 이동 / 저장하지 않음` | 조용히 내용 파기 |
| S14 Time-gated | D-1 이전 | Locked Card | `면접 하루 전 열려요` | 없음 | 가짜 남은 초/강제 알림 허용 |
| S15 Service Fault Recovery | 실전 시스템 장애 | Status + Explicit Compensation | `면접을 완료하지 못했어요. 이용권 복구 상태를 확인해 주세요` | 재접속/복구 경로 | 0점 채점, 이중 차감 |
| S16 Offline/Background | 탭 이탈·오프라인 | Preserved State | `연결을 확인하고 있어요` | 복구 필요 시 1개 | 무작정 자동 새 세션 생성 |

### 23.1 상태별 문구의 3요소

**What happened? → What can I do? → What remains safe?** 가 필요한 곳에서만 짧게 제공한다.

- 문맥이 분명한 성공: `저장됐어요` 한 문장으로 충분.
- 학생의 데이터/권리가 걸린 오류: `모의면접 연결이 종료됐어요. 이번 회차는 복구 상태를 확인하고 있어요. 이용권이 추가 차감되지 않도록 처리 중입니다.` 등 확인된 상태만.
- 증빙 없는 낙관적 문구 `걱정 마세요, 다 복구됐어요` 금지.
- 미확인 대학 정보: `확인된 공식 자료가 없어요`(숫자 0이나 면접 미실시 표시 금지).

### 24.2 버튼 의미 체계 / Button Hierarchy

- **Primary Button:** 한 화면의 목적을 완료하는 행동 `학생부 제출 / 연습 시작 / 모의면접 시작 / 결제 진행`.
- **Secondary Button:** 보조 선택 `취소 / 다시 확인`; 연습 피드백만 승인된 `다시 연습하기 / 다음` 동등한 두 개.
- **Tertiary/Text Button:** 회피/탐색 `출처 / 필터 초기화 / 도움`(실제 필요할 때만).
- **Icon Button:** 의미가 단일하고 반복적인 토글(별, 닫기, 목차)만. `대표 답변 지정`은 hover tooltip/접근성 이름이 필수.
- **Destructive Button:** `면접 종료 / 회원 탈퇴 / 등록 정보 교체`는 실제 영향에 비례한 확인 단계. 배경을 전부 빨갛게 해 공포감을 주지 않는다.
- **Disabled Action:** 이유가 명확하면 `아직 질문을 선택하지 않았어요`처럼 맥락 상태를 근처에 표시; 의도가 불명확한 영구 비활성 버튼 방치 금지.

### 24.3 저장 정책 / Autosave & Explicit Save

| 대상 | 저장 방식 | 완료 표시 | 되돌리기/이력 |
|---|---|---|---|
| G04 개인 예상 답변 | **명시적 저장**(기본) | 서버 완료 후 `저장됐어요` | 취소·버전/수정 기록 |
| G04 질문 북마크 | 토글 저장 | `저장됨` 상태 | 다시 선택 시 해제(과거 이력 영향 없음) |
| A02 대표 답변 | 토글 지정 | 별 채움+`대표 답변으로 지정했어요` | 새 지정 시 이전 대표만 해제 |
| M03/M04 즐겨찾기 | 즉시 토글(Optimistic는 서버 롤백 조건 구현 시만) | 별 채움+짧은 Toast | 재탭 취소 |
| I02 연습 답변 | 명시적 제출 + **서버 기록** | 제출 확인 후 다음 턴 | 이전 답변 불변, 재연습은 새 기록 |
| I07 실전 답변 | 세션·원장·평가 무결성 보장된 확정 | 다음 질문은 서버 확정 턴 기준 | 과거 회차 불변, 기술 장애 구분 |
| O04 학생부 업로드 | 서버 수신 완료 → 처리 접수 분리 | `접수 완료` | 업로드 실패 재시도; 기존 자료 무음 교체 금지 |
| O03 결제 | PG 승인 + 서버 검증 | `결제 완료` | 결제 취소/환불은 별도 정책 |

### 24.4 전역 키보드·보조기술 동작

- Tab은 화면의 의미 순서대로 순회, Shift+Tab 역순. 포커스는 항상 눈에 보여야 한다.
- 모달 열기 시 포커스 이동, 내부 순환, 닫힘 후 트리거로 복귀. 모바일 스크린리더도 실제 라벨/상태를 인식해야 한다.
- Tab 패턴은 WAI-ARIA Tabs에 맞춰 선택/현재 패널 연결; 단순 필터는 `button`/`checkbox` 등 실제 의미로 구현.
- 아코디언 항목은 `button`+`aria-expanded`+`aria-controls` 규칙, 접힌 내용은 키보드 초점에 남지 않도록.
- 토스트는 `role=status` 등 적절한 비방해 알림; 중요한 오류는 실제 화면 텍스트로 유지.
- 하이라이트만으로 질문 근거 설명하지 않고 보조기술용 연결 상태를 추가한다.

## 25. 가독성·접근성·성능 요구 (QA Baseline)

### 25.1 접근성 Acceptance Target

- 목표: **WCAG 2.2 AA** 수준을 내부 품질 기준으로 설정(외부 적합성 인증을 취득했다는 뜻 아님).
- 일반 본문 최소 대비 **4.5:1**, 큰 글씨 **3:1**, 주요 그래픽·상호작용 구성요소의 대비도 관련 기준대로 점검.
- WCAG 2.2 AA의 Pointer Target Size 최소 조건은 **24×24 CSS px 및 예외 규정**으로 정의됨. 각자의답 자체 디자인 목표는 더 여유로운 **44×44 CSS px**를 기본으로 권장한다.
- 확대 200%, 좁은 너비 320px 및 실제 한국어 장문, 브라우저 확대·시스템 큰 글씨에서 주요 기능 손실 없는지 확인.
- Reduced Motion(운영체제/브라우저 설정) 준수. 애니메이션을 꺼도 진입 단계·상태 변화 이해 가능.
- 키보드만으로 `지원처 선택 / 질문 저장 / 답변 편집 / 면접 피드백 다음 / 대표 답변 / 퀴즈 배열 대체 조작 / 고객센터 제출` 가능해야 함.
- ARIA 라벨만 붙여 ‘접근성 완료’로 처리 금지. 실제 키보드 사용·스크린리더 탐색 검사 필요.
- 모든 미디어/썸네일에 의미 있는 alt나 무의미할 경우 적절한 장식 이미지 처리. 화상 면접 음성 대체/자막 정책은 실전 환경의 기술 및 공정성 검증을 병행.

### 25.2 성능 UX 가드레일 (제안 목표, SLA 아님)

| 상황 | UI 규칙 |
|---|---|
| 매우 짧은 로딩 | 깜빡이는 스피너를 무조건 띄우지 않음. 버튼 내부 진행 표시 필요 시만 |
| 1초 안팎 응답 | 주요 인터랙션 클릭 반응 즉시 보여주되 **성공 결과 선표시 금지** |
| 목록 로딩이 길 때 | 실제 콘텐츠 배치에 맞는 Skeleton, 스크롤 점프 방지 |
| 업로드 | 실제 네트워크 전송의 바이트 비율만 Determinate Progress |
| OCR/가이드북 생성 | 단계별 서버 상태만. 평균 예상 시간·진행률 계산 근거 없다면 퍼센트/분 단위 보장 표시 금지 |
| 실전 입장 | 단계별 상태 + 장비/연결 검사, 실제 준비 끝나면 자동 입장 |
| 결과 계산 | 실제 평가 완료/진행 중/무효/부분에 따라 화면 전환 |
| 썸네일 | 이미지 lazy-load, 실제 원본 비율 유지, 실패 시 문서 유형 대체 아이콘 |
| 저장 버튼 | 동기 실행 중 이중 요청 차단, 장애 시 원래 내용/버튼 복구 |

### 25.3 내용 UI 품질

- 공통 **메뉴명 밑 설명문 0건 원칙**, 단 권리·상태·출처·오류에 필요한 필수 문구 예외.
- 같은 행동에 서로 다른 표현 사용 금지: `저장`/`저장하기`를 상황별 사용하되 `보관`, `찜하기`, `추가` 등이 같은 API를 가리키면 통일.
- `대표 답변`과 `모범 답변`은 **서로 다른 개념**. 전자는 학생 선택, 후자는 AI가 실제 사실을 바탕으로 제안한 예시.
- `즐겨찾기`와 `질문 저장하기`도 서로 다른 개념. 별 토글은 콘텐츠 재열람, 질문 저장은 연습 면접용.
- `공식 확인`과 `학생 개인 확정 일정`은 동일 의미가 아니다. D-Day의 출처를 별도로 취급.
- 숫자 없는 평가요소는 `비율 미확인`. 0%로 표시하지 않는다.
- 도움말 문장은 `Tooltip`에 숨겨도 되는 **보조 정보**만. 결제 금액·기록 파기·면접권 차감 등 필수 조건 숨기지 않음.

## 27. 개발 전달용 데이터·상태 계약 (UI ↔ API, 권장 예시)

> 다음 필드는 **구현 대화용 권장 DTO**, 기존 DB 스키마의 확정 명칭이 아님. 실제 프레임워크와 관계없이 프런트/백엔드가 **같은 의미**로 전달해야 할 최소 상태를 표현한다.

### 27.2 G04 원문 근거 하이라이트

```ts
interface SourceEvidenceAnchor {
  studentRecordVersionId: string;
  sourceRefId: string;      // 승인된 근거 ID
  activityId?: string;     // 활동이 있는 경우
  spanStart: number;       // 정규화 본문 내 위치: 단위/인코딩 별도 확정
  spanEnd: number;

  targetContextId?: string; // 공통 질문은 null 가능
```

**세부 확인:** span이 Unicode code point인지 UTF-16 offset인지, 원문 OCR 정규화 전후 매핑을 어떻게 할지는 개발팀과 합의. UI는 근거 위치를 재검증하지 못할 때 하이라이트 표시하지 않는다.

### 27.3 면접·답변·권리

```ts
interface InterviewSessionView {
  sessionId: string;
  targetContextId: string;
  mode: 'practice' | 'scored_mock';
  media: 'text' | 'video';  // scored_mock이면 video만 허용
  status: 'setup' | 'preparing' | 'active' | 'reconnectable' | 'evaluating' | 'completed' | 'partial' | 'invalid';
  currentClusterId?: string;
  firstQ0DeliveredAt?: string; // 이용권 차감의 정확한 기준 이벤트
  recordVersionId: string;
  reportId?: string;
}
interface AnswerRepresentativeView {
  answerRecordId: string;
  canonicalQuestionId: string;
  targetContextId?: string;
  isRepresentative: boolean; // 한 컨텍스트에서 유일 제약
}
```

- 면접권 차감·복구는 **server-authoritative ledger**로 처리. 클라이언트가 로딩 단계를 세 번 지났다고 자동 차감하지 않는다.
- `firstQ0DeliveredAt`의 의미는 '정상 전달'이며 단순 질문 생성 완료·WebSocket 이벤트 송신 시각과 다를 수 있다. 실체적 정상 전달 판정 기준은 엔진/개발 QA로 검증.
- `representative`는 학생 선호 표시이며 공식 모범 정답·면접 성적 계산에 반영하지 않는다.

## 28. UX Writing / Microcopy 문구 정본 초안

### 28.1 레이블과 상태 문구

| 상황 | 권장 문구 | 사용하지 않을 문구 |
|---|---|---|
| 저장 전 | `질문 저장하기` | `찜`, `퀵 세이브`, `수집하기` 등 혼합 |
| 질문 저장 성공 | `저장됨` / Toast `질문을 저장했어요` | `연습을 시작했어요` |
| 대표 답변 지정 | `대표 답변으로 지정` / `대표 답변` | `모범 답변 지정` |
| 학생부 근거 미확인 | `근거 위치를 확인하고 있어요` | `근거 없음 = 질문 거짓` 단정 |
| 대학 공식 수치 없음 | `공식 수치 미확인` | `0분`, `면접관 0명`, `0%` |
| 가이드북 분석 중 | `학생부를 확인하고 있어요` | `67% 분석 완료`(측정 근거 없을 때) |
| 업로드 완료 | `파일이 접수됐어요` | `가이드북 완성` |
| 연습 피드백 긍정 | `좋았어요` | `완벽해요!`(실제 결함 있는데) |
| 연습 피드백 보완 | `더 다듬어봐요` | `역량이 부족합니다` |
| 실전 입장 1단계 | `면접관이 학생부를 살펴보고 있습니다` | `가상 분석 중(99%)` |
| 실전 입장 2단계 | `면접관이 질문을 정리하고 있습니다` | `질문 확정!(실제로 미검증)` |
| 실전 입장 3단계 | `곧 면접장에 입장합니다` | `무조건 5초 후 입장` |
| 면접권 부족 | `사용 가능한 실전 모의면접 이용권이 없어요` | `지금 결제하지 않으면 기회를 잃어요` |
| D-1 이전 | `면접 하루 전 열려요` | `잠금 해제를 위해 결제하세요` |
| 네트워크 오류 | `연결이 끊어졌어요. 다시 연결해 주세요` | `치명적 시스템 오류!` |
| 자료 즐겨찾기 | `즐겨찾기에 추가했어요` | `질문을 저장했어요`(잘못된 목적) |
| 빈 답변 기록 | `아직 연습 기록이 없어요` | 샘플 질문을 실제 기록처럼 보여줌 |
| 결제 확인 중 | `결제를 확인하고 있어요` | 결제 승인 전 `구매 완료!` |

### 28.2 UX 문구 스타일

- **간결·사실·행동 중심:** 일반 상태는 1문장, 중요한 오류/권리는 상황 설명+조치 문구.
- **과장·죄책감·공포 방지:** `뒤처지고 있어요`, `다들 구매했어요`, `이대로면 불합격` 금지.
- **학습자 존중:** 부족함을 인격/성격으로 평가하지 않고 실제 답변의 구체적 개선점으로 표현.
- **공식성 레이블:** `대학 공식`/`공식 확인`은 근거가 실제 존재하는 경우에만. 학과 고유 인재상과 대학 공통 인재상 혼합 금지.
- **영어 사용 원칙:** 개발/디자인 문서에서는 `Master–Detail`, `Stepper`, `Toast` 등의 영어 병기 허용. **학생 화면에는 이해하기 쉬운 한국어**를 우선하며, 브랜드 이름 등 특별한 이유 있을 때만 영어.

## 30. UX 원칙과 외부 참고자료 (Normative vs Design Guidance)

아래는 **UI 선택의 근거를 확인하는 외부 표준/설계 참고자료**이며, 원래 서비스 MD의 상품·면접 엔진 정책을 대체하지 않는다.

1. **W3C WCAG 2.2** — 색상 대비, 포커스, 타깃 크기, 입력 도움, 움직임·시간 제한 등 접근성 기준. https://www.w3.org/TR/WCAG22/ (이 문서에서 채택한 AA 목표는 내부 품질 기준이며 인증 주장 아님)
2. **W3C WAI-ARIA Authoring Practices** — Tabs, Accordion, Dialog, Menu Button 등 접근 가능한 상호작용 구현 패턴. https://www.w3.org/WAI/ARIA/apg/patterns/
3. **GOV.UK Design System** — 사용자가 고칠 수 있는 입력 오류는 해당 필드 인근에 구체적 원인과 해결 행동을 표시하고 입력값 보존. https://design-system.service.gov.uk/components/error-message/ 및 https://design-system.service.gov.uk/patterns/validation/
4. **GOV.UK Design System Components** — Accordion, Select, Button, File Upload, Error Summary, Status Tag 등 재사용 가능한 컴포넌트 원리. https://design-system.service.gov.uk/components/
5. **각자의답 기존 브랜드/IA 정본** — `2. 브랜드_정체성_v1.1.md`, `3. 웹가이드북_목차_콘텐츠배치_v2.0.md`, `4. 서비스_PRD_v2.1.md`, `5~10번 엔진/데이터 MD`, **본 문서 PART A의 IA v1.0 승인사항**. 현 문서는 UI 패턴을 위한 부록이며 이들의 보안·정책·근거 로직을 자동 개정하지 않는다.

### 기획팀

### 32.2 AI에 화면 제작을 지시할 때 붙일 공통 제약

1. **공식 IA와 화면 ID 우선:** 본 문서에 없는 메뉴·기능·가격·혜택·버튼을 임의 추가하지 말 것.
2. **화면 목적 하나:** 카드 제목의 의미를 살리고 메뉴명 아래 설명문을 반복하지 말 것. 중요한 데이터 상태와 출처는 예외.
3. **상태별 구현:** 초기·로딩·빈 상태·성공·실패·제한·모바일을 디자인하고, 에러/잠금/복구를 빼먹지 말 것.
4. **컴포넌트 용어 유지:** Tab, Segmented Control, Bottom Sheet, Modal Dialog, Skeleton, Toast, Inline Error, Source Highlight, Master–Detail, Sticky Header 등 정확한 역할로 선택할 것.
5. **데이터 정확성:** 학생부 원문/실제 면접 답변/지원처 정보/리포트 점수/결제권 원장은 가짜 내용으로 성공 상태를 연출하지 말 것.
6. **실전 면접 화상 전용:** 채팅 실전 폴백을 동일 상품으로 구현하지 말 것. 입장 3단계는 실제 서버 상태와 연결할 것.
7. **반응형·접근성:** 좁은 화면/긴 한국어/큰 글씨/키보드/스크린리더/색약/reduced-motion을 포함할 것.
8. **개발 완료 증명:** 구현한 화면 ID와 테스트 ID, 실패·미구현·임시 데이터 경계를 기록할 것.

### 32.3 화면 완성 정의 (Definition of Done)

한 화면을 ‘완료’로 인정하려면 아래 여섯 조건이 충족되어야 한다.

- **IA Fidelity:** 화면 위계·진입 경로·버튼 의미가 승인된 IA와 일치한다.
- **UX Semantics:** 상호작용 패턴이 실제 목적에 맞다(탭은 탭, 체크박스는 복수선택, 모달은 고위험 확인).
- **Data Integrity:** 실제 학생부·질문·출처·면접 기록·이용권·결제 상태가 정확히 연결된다.
- **State Completeness:** 최소 일반/로딩/빈 상태/오류/권한 상태가 검증된다(해당 없는 상태는 명시적으로 N/A).
- **Responsive & Accessible:** PC·모바일·키보드에서 주목적 달성이 가능하다.
- **Evidence of Working:** 데모 이미지만이 아니라 클릭 동작, 서버 반영, 재접속·오류 복구 등 해당 테스트 결과가 남는다.

**별도 기술 게이트:** 실전 화상 STT/TTS, 생성 질문의 사실 정합성, 실제 이용권 원장, 개인정보 보호, 결제는 이 디자인 명세를 충족하더라도 **실제 작동·품질 증빙이 없으면 출시 승인 불가**.

---

> **정리:** 각자의답 UX는 ‘많은 효과를 보여주는 UI’가 아니라 **학생이 질문과 자기 경험에 집중하도록 불필요한 화면 행동을 줄이고, 정말 중요한 상태와 근거를 정확히 보여주는 UI**를 지향한다. 이 문서에서 애니메이션·카드·색상·팝업은 그 목적에 맞을 때만 사용한다.

## 34. 디자인·개발 전달 시 기능 경계 유지

- **G02:** 원문 전체를 열람한다. 활동 카드만 나열하는 `분석 대시보드`로 대체 불가.

## 36. UX 용어 사용 제한

`Stepper`는 **실제 작업 단계가 있을 때**, `Skeleton`은 콘텐츠 구조가 예상되는 경우, `Inline Error`는 입력 필드 오류, `Toast`는 되돌릴 필요 없는 경미한 완료 안내, `Dialog`는 이용권 차감/중단/탈퇴처럼 돌이키기 어려운 행동 확인, `Bottom Sheet`는 모바일의 가벼운 목록 선택에 한정한다. `Fake countdown`, `Hidden costs`, `Confirmshaming`, `Forced continuity`와 근거 없는 가짜 진행률은 사용하지 않는다. `Skeleton`/3단계 로딩으로 실제 STT/TTS 성능 실패를 은폐하는 것도 금지한다.

**변경 규모:** v1.1 → **v1.2 Minor**. 승인한 학생용 IA와 PART B의 1,592줄 원문 구조는 그대로 두고 정본 간 충돌 차단·실제 구현 확인 항목만 추가하였다.
