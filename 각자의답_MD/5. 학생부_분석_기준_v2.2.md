# 0. 이 문서의 역할

이 문서는 학생마다 달라지는 학생부와 지원 대학을 **같은 제작 방법론으로 처리하기 위한 정본**이다. 목적은 ‘학생부를 예쁘게 요약하는 것’이 아니라 다음 연결을 일관되게 구현하는 것이다.

**학생부 원문 → 활동 → 사실 확인 → 분석 → 지원 대학 맥락 → 면접 우선도 → 대표 활동 → 예상 질문 → 답변 설계 → 답변 발화본 → 암기 키워드 → 실전 훈련**

[면접바이블]은 면접의 비언어 요소, 답변 원칙, 준비 단계, 주요 질문 답변법, 학생부 영역별·계열별 서류기반 질문 예시, 대학별 면접 분석을 제공한다. 특히 서류기반 실전 예시는 반복적으로 **학생부/교과 기록 예시 → 면접 질문 → 답변 예시 → 추가 질문 → 관련 학과 → 면접 키워드**의 생산 단위를 사용한다. 본 기준은 이 구조를 각자의답의 데이터 모델에 맞게 일반화한다.

# 1. 제작의 최상위 원칙

## 1.1 사실 우선

[프로젝트 확정]
- 학생이 하지 않은 행동을 만들지 않는다.
- 학생이 느끼지 않은 감정을 확정하지 않는다.
- 확인되지 않은 성과를 사실처럼 쓰지 않는다.
- 학생부와 학생의 정정이 충돌하면 원문을 덮어쓰지 않고 별도 이력으로 남긴다.

[면접바이블]
- 서류기반 면접에서는 자신이 기록한 활동을 정확하게 이해하고 기억하는 것이 우선이다.
- 기억하지 못하는 내용을 억지로 지어내는 것보다 모르는 부분을 솔직하게 처리하는 것이 낫다.
- 답변은 기록의 사실과 자신의 실제 경험을 기반으로 해야 한다.

[운영 규칙]
모든 답변 문장 또는 핵심 주장(claim)은 다음 중 하나로 분류한다.
1. `학생부 사실`
2. `학생이 확인한 경험`
3. `해석과 연결`
4. `학생의 생각·계획`
5. `확인 필요`

`확인 필요`가 핵심 의미를 좌우하면 발화본 확정을 보류한다.

## 1.2 평가보다 준비 우선

면접 우선도는 활동 자체의 우수성이나 학생의 능력 전체를 평가하는 등급이 아니다. **해당 지원처의 면접에서 얼마만큼 준비가 필요한가**를 나타낸다.

따라서:
- 짧은 기록도 지원동기나 핵심 서사를 설명하면 S가 될 수 있다.
- 긴 기록도 다른 활동과 중복되거나 면접 활용성이 낮으면 B/C/F가 될 수 있다.
- F는 ‘나쁜 활동’이 아니라 별도 집중 훈련을 유보하는 활동이다.

## 1.3 질문은 ‘기록을 확인하는 질문’과 ‘기록에서 확장하는 질문’을 구분

[프로젝트 확정]
- 근거 범주: `서류기반 질문` / `확장 질문`
- 질문 속성: 활동 질문, 전공 질문, 인재상 질문, 가치관 질문, 대학 및 학과 질문, 공통 질문, 시사 질문, 꼬리질문

하나의 질문은 여러 속성을 가질 수 있다. 예를 들어 “이 실험에서 오차가 발생한 이유와 다시 설계한다면 바꿀 점을 설명해보세요”는 `서류기반 + 활동 + 전공 + 꼬리질문`일 수 있다.

## 1.4 답변은 문장 암기가 아니라 의미 복원이 목표

[면접바이블]
- 답변은 간결하고 핵심이 분명해야 한다.
- 결론을 앞에 두고 구체적인 근거를 제시하는 습관을 권한다.
- 지나치게 외운 티가 나는 답변보다 질문 의도에 맞게 자연스럽게 설명해야 한다.
- 추상 표현보다 구체적 경험·행동·근거가 중요하다.
- 불필요한 군더더기·습관어를 줄인다.

[프로젝트 확정]
- 가이드북은 웹 기반 분석·이해·답변 설계용이다.
- 암기 훈련실은 기억·회상·지식 학습용이다. 별도 암기 핸드북 발행은 종료했으며 키워드·요약 데이터는 웹 가이드북과 암기 훈련실에서 재사용한다.
- 문장 일치 여부만으로 개인 경험 답변을 정오 판정하지 않는다.

## 1.5 대학별 차이는 공통 기준 위에 추가

모든 학생에게 공통적으로 적용하는 학생부 구조화 기준과, 대학·전형별로 달라지는 면접 평가 기준을 분리한다.

- 공통층: 학생부 사실, 활동 단위, 역할, 과정, 결과, 배운 점, 질문 깊이
- 계열층: 인문/사회/자연/공학/예체능/의약/교육의 질문 경향
- 대학층: 실제 대학·전형의 면접 방식, 평가요소, 반영비율, 제시문 여부, 서류기반 여부

# 2. 면접바이블에서 추출한 공통 면접 기준

## 2.1 비언어·발화 요소

[면접바이블, PDF p.14~25]

### 시선 처리
- 면접관을 피하지 않는다.
- 한 사람만 계속 응시하지 않고 복수 면접관에게 자연스럽게 시선을 배분한다.
- 지나친 응시는 부담을 줄 수 있으므로 자연스러운 시선 이동을 사용한다.
- 시선은 관심·신뢰·자신감의 인상을 형성하는 요소로 본다.

### 미소
- 억지 웃음이나 과도한 미소보다 상황에 맞는 자연스러운 표정이 중요하다.
- 무표정·경직도 피한다.

### 고개 끄덕이기
- 질문을 듣고 이해하고 있다는 신호로 활용할 수 있다.
- 반복적·자동적 끄덕임은 피한다.

### 자세
- 허리를 펴고 안정적으로 앉는다.
- 다리 꼬기, 몸 흔들기, 과도한 움직임, 구부정한 자세를 피한다.

### 입장·인사·손동작
- 입장부터 퇴장까지가 면접의 일부다.
- 인사는 명확하고 자연스럽게 한다.
- 손동작은 설명을 돕는 범위에서만 사용하며 과도한 제스처를 피한다.

### 복장
- 면접 상황에 맞는 단정함을 우선한다.
- 외형을 개성 표현보다 면접의 목적·상황에 맞춰 판단한다.

### 목소리
- 충분한 음량, 또렷한 발음, 안정된 호흡이 기본이다.
- 자신의 자연스러운 목소리를 유지한다.
- 빠르기·강세·끊어읽기를 조정한다.

**각자의답 반영:** 이 항목은 학생부 분석 점수에 넣지 않는다. `실전 훈련/면접 리포트`의 발화 관찰 항목으로 별도 관리한다.

## 2.2 대학에서 반복적으로 권하는 면접 준비 습관

[면접바이블, PDF p.27~32]
- 계획을 세우고 면접 준비를 시작한다.
- 예상 질문과 답변을 준비한다.
- 모의면접을 반복한다.
- 자신감 있는 태도를 유지한다.
- 질문의 의도를 파악한다.
- 핵심·결론 중심으로 말하고 근거를 논리적으로 붙인다.
- 추상적 표현보다 구체적 표현을 쓴다.
- “음…”, “어…” 등 습관어를 줄인다.
- 활동과 활동, 활동과 지원동기, 활동과 학업계획 사이의 연결을 이해한다.
- 외운 문장을 그대로 재생하기보다 자기 이야기로 설명한다.
- 연습 기록을 남기고 피드백 후 재연습한다.

## 2.3 면접 준비 단계

[면접바이블, PDF p.31~32]
1. 면접 준비 계획 수립
2. 지원 대학의 면접 방식·평가요소 분석
3. 예상 질문과 답변 준비
4. 모의면접
5. 피드백과 반복 연습

**각자의답 대응:**
- 1단계 → `01. 나의 면접 전략`
- 2단계 → `03. 대학·학과 분석`
- 3단계 → `04. 예상 질문·답변`
- 4~5단계 → `05. 실전 훈련`, 연습 면접(채팅·화상)·실전 모의면접(화상 전용), 면접 리포트

## 2.4 면접 절차·형식

[면접바이블, PDF p.33~40]
- 대기 → 면접실 입장 → 인사 → 질문·답변 → 마무리 인사 → 퇴실의 전체 흐름을 준비한다.
- 대면/비대면, 제시문형, 개인면접, 다대일, 다대다 등 형식에 따라 준비 방식이 달라진다.
- 제시문 면접은 자료 해석·논리 전개·교과 개념 적용이 추가된다.
- 서류기반 면접은 학생부 사실, 활동의 이유·과정, 학생의 실제 역할을 재확인하는 비중이 높다.

# 3. 학생부 구조화 표준

## 3.1 기본 엔티티

학생부를 바로 질문으로 바꾸지 않는다. 최소 단위는 다음 순서를 따른다.

`학생부 원문(source_ref) → 활동(activity) → 활동 분석(activity analysis) → 질문(question) → 답변 설계(answer design) → 발화본(answer script) → 암기 항목(memory item)`

## 3.2 원문 참조 source_ref

필수 필드:
- `source_ref_id`
- 출처 종류: 학생부/학생 확인/대학 공식자료/면접바이블/기타 승인자료
- 학년
- 학생부 영역
- 과목명(해당 시)
- 페이지/위치
- 원문 발췌
- 자료 revision
- 확인 상태

원칙:
- 원문은 해석문과 섞지 않는다.
- 같은 활동이 여러 영역에 등장하면 여러 source_ref를 하나의 activity에 연결한다.
- 학생이 정정해도 학생부 원문 자체는 수정하지 않는다.

## 3.3 활동 activity 필수 필드

- 안정적 `activity_id`
- 활동명
- 학년
- 학생부 영역
- 과목/교과(해당 시)
- 원문 참조 ID
- 활동 요약
- 핵심 주제
- 실제 확인된 행동
- 학생 역할
- 과정
- 결과/산출물
- 배운 점/변화
- 핵심 키워드
- 사실확인 상태
- 관련 활동 ID
- 진로·학업 흐름 내 위치
- 지원처별 면접 우선도
- 우선도 이유
- 전공 연계 설명
- 인재상 태그와 근거
- 대표 활동 여부
- 예상 질문 ID

# 4. 활동 단위 분리·통합 기준

## 4.1 활동의 정의

[운영 규칙]
`활동`은 학생이 특정한 목적·문제·관심을 바탕으로 수행한 하나의 의미 있는 경험 단위다. 단순 문장, 키워드, 교과목명은 활동이 아니다.

## 4.2 하나의 활동으로 묶는 기준

다음 조건이 다수 충족되면 하나의 활동으로 묶는다.
- 동일한 탐구 목적이나 문제의식이 이어짐
- 독서 → 조사 → 실험 → 발표처럼 단계가 연결됨
- 같은 결과물/발표/보고서를 향함
- 역할과 참여 맥락이 지속됨
- 학생이 하나의 경험으로 설명하는 것이 자연스러움

예시:
`기후위기 관심 → 관련 도서 탐독 → 탄소중립 자료조사 → 교내 발표`는 목적이 연속적이면 하나의 활동으로 묶고 단계로 저장한다.

## 4.3 분리하는 기준

다음에 해당하면 별도 활동으로 분리한다.
- 탐구 질문이 새롭게 바뀜
- 별도의 목표·역할·산출물이 존재함
- 같은 주제라도 시기·맥락·수행방식이 독립적임
- 하나로 묶을 경우 학생 역할이나 질문 근거가 모호해짐
- 지원처 평가에서 별도 경험으로 보는 편이 더 정확함

## 4.4 중복 기록 처리

같은 경험이 자율활동과 세특, 진로활동 등에 반복될 수 있다.
- activity는 하나로 유지한다.
- source_ref만 복수 연결한다.
- 각 원문이 추가하는 사실을 구분한다.
- 반복 기재 자체는 활동의 질을 자동으로 높이지 않는다.
- 다만 여러 시기·교과로 확장된 흔적은 `지속성/확장성` 근거가 될 수 있다.

## 4.5 활동명 작성 규칙

좋은 활동명:
- 학생이 무엇을 했는지 구별 가능
- 주제와 행동을 함께 드러냄
- 지나친 평가어 없음

예: `수소에너지와 SMR 비교 탐구`, `미세플라스틱 검출 실험`, `학급 갈등 조정 경험`

피해야 할 활동명:
- `훌륭한 리더십 활동`
- `전공적합성이 매우 높은 탐구`
- `진로 활동 1`

# 5. 학생부 영역별 분석 기준

## 5.1 기본정보·출결·수상·자격

### 확인 항목
- 학적 변화와 설명 필요 사항
- 출결 특이사항 및 사실관계
- 수상/자격이 현재 면접에서 활용 가능한지
- 학생부 기재 제도상 대입 제공 여부와 별개로 학생이 실제 경험을 설명할 필요가 있는지

### 질문화 원칙
- 사실 확인 필요가 없는 항목을 억지로 질문으로 만들지 않는다.
- 특이사항이 지원 서사·책임감·지속성에 직접 연결될 때만 주요 질문으로 승격한다.

## 5.2 창의적 체험활동·봉사활동

### 자율활동
주로 확인할 것:
- 참여 배경/목적
- 실제 역할
- 학교/학급 문제에 대한 행동
- 기획·운영·조정 과정
- 구성원과의 협업
- 결과와 변화

질문 축:
`왜 참여했나 → 무엇을 맡았나 → 실제로 무엇을 했나 → 문제가 있었나 → 어떻게 해결했나 → 무엇을 배웠나`

### 동아리활동
주로 확인할 것:
- 동아리 선택 이유
- 본인이 제안한 주제
- 탐구·실험·제작 과정
- 팀 내 역할
- 결과물
- 실패/오차/수정
- 다음 탐구로의 확장

특히 자연·공학·의약은 개념/실험 설계/오차가, 인문·사회는 주제 선정/자료 근거/관점 비교가 중요하다.

### 진로활동
주로 확인할 것:
- 진로가 형성·변화한 이유
- 탐색 방법
- 전공 이해가 깊어진 계기
- 대학·학과 선택의 근거
- 단순 체험 참가와 자기주도적 후속 활동의 차이

### 봉사활동
주로 확인할 것:
- 반복성·지속성
- 실제 수행 내용
- 대상자/공동체 이해
- 시혜적 표현이 아닌 역할·배운 점
- 면접을 위해 의미를 과장하지 않는지

## 5.3 교과 성적·세부능력 및 특기사항

### 성적 분석
- 학년/학기 추이
- 전공 관련 교과 흐름
- 진로선택 과목
- 과목 선택 이유
- 특정 과목의 상승/하락 원인: 확인 가능한 경우에만
- 활동 내용과 실제 성취의 연결

성적 하락을 곧바로 부정 요소로 규정하지 않는다. 질문 가능성이 있을 때 사실에 기반한 설명 준비 여부를 판단한다.

### 세특 분석
세특은 다음 순서로 읽는다.
1. 교과 맥락
2. 교사가 기록한 핵심 행동
3. 학생이 선택한 탐구 주제
4. 사용한 개념/자료/방법
5. 수행 과정
6. 결과/결론
7. 추가 탐구·확장
8. 다른 교과/진로와의 연결

[면접바이블] 교과세특 예시는 거의 모든 계열에서 `교과세특 예시 → 질문 → 답변 → 추가질문 → 관련학과 → 면접키워드`를 반복한다. 따라서 각자의답도 **세특 원문을 단순 요약하지 말고 질문 가능한 요소를 분해**한다.

## 5.4 독서활동·행동특성 및 종합의견

### 독서
확인 항목:
- 실제 읽은 책/자료
- 선택 이유
- 기억하는 핵심 주장/개념
- 자신의 생각과 동의/비판
- 이후 활동과의 연결

책 제목만으로 내용을 추정해 학생 경험으로 확정하지 않는다.

### 행동특성 및 종합의견
행특의 평가어를 그대로 학생의 자기소개 문장으로 옮기지 않는다.

예: `책임감이 강함`이라는 교사 기록이 있다면:
- 어떤 행동이 근거였는가?
- 학생이 기억하는 사례가 있는가?
- 다른 학생부 영역에서도 같은 행동이 확인되는가?

를 거쳐 경험 근거로 전환한다.

## 5.5 학생부 종합 흐름

개별 활동 분석 후 반드시 종합 흐름을 만든다.

필수 축:
- 관심의 시작
- 반복 주제
- 심화/확장
- 교과 간 연결
- 학년 간 변화
- 진로 변화와 이유
- 대표적인 탐구 방식
- 공동체에서 반복되는 행동
- 강점 근거
- 설명이 끊기는 지점
- 사실 확인 필요 지점

# 6. 계열별 분석·질문 기준

[면접바이블, 서류기반 면접 실전 PDF p.64~187]

## 6.1 인문계열

핵심 질문 관점:
- 텍스트/작품/사상/언어의 의미를 정확하게 설명하는가
- 자신의 해석에 근거가 있는가
- 시대·사회·문화적 맥락을 이해하는가
- 두 관점이나 작품을 비교할 수 있는가
- 자신의 관점을 과장 없이 표현하는가

질문 생성 축:
- 왜 이 작품/주제를 선택했는가
- 핵심 내용을 자신의 말로 설명해보라
- 특정 표현/개념의 의미는 무엇인가
- 다른 작품/사상과 어떤 차이가 있는가
- 본인의 해석을 뒷받침하는 근거는 무엇인가

## 6.2 사회계열

핵심 질문 관점:
- 사회 현상을 개념·제도로 설명하는가
- 자료/통계/사례를 근거로 주장하는가
- 이해관계자와 복수 관점을 고려하는가
- 정책 대안의 장단점을 비교하는가
- 시사 이슈를 사실과 의견으로 구분하는가

질문 생성 축:
`현상 설명 → 원인 → 자료 근거 → 이해관계 → 정책 대안 → 한계/부작용 → 자기 관점`

## 6.3 자연계열

핵심 질문 관점:
- 과학 개념과 원리를 정확히 설명하는가
- 실험의 독립/종속/통제 변수를 이해하는가
- 데이터와 결론의 관계가 적절한가
- 오차·한계를 이해하는가
- 후속 실험을 설계할 수 있는가

질문 생성 축:
`원리 → 가설 → 변수 → 방법 → 결과 → 오차 → 개선 → 적용`

## 6.4 공학계열

핵심 질문 관점:
- 해결하려는 문제를 명확히 정의하는가
- 설계 선택의 이유가 있는가
- 작동 원리/알고리즘/구조를 이해하는가
- 제약조건과 trade-off를 설명하는가
- 실패 원인과 개선안을 제안하는가
- 기술을 현실에 적용할 때의 한계를 이해하는가

질문 생성 축:
`문제 정의 → 요구조건 → 설계 → 구현 → 시험 → 문제 → 개선 → 현실 적용`

## 6.5 예체능계열

핵심 질문 관점:
- 작품/경기/표현의 의도
- 준비·연습 과정
- 사용한 기법과 선택 이유
- 피드백 수용과 수정
- 실제 수행에서의 자기 역할
- 결과에 대한 자기평가

## 6.6 의약계열

핵심 질문 관점:
- 생명·의학 기초 개념의 정확성
- 과학적 근거와 한계
- 환자·안전·윤리 관점
- 공중보건/사회적 맥락
- 연구·실험 결과의 과도한 일반화 여부
- 직업 이해와 지원동기

질문 생성 축:
`의학/생명 원리 → 근거 → 위험/안전 → 윤리 → 환자/사회 → 한계 → 대안`

## 6.7 교육계열

핵심 질문 관점:
- 학습자 이해
- 교육 방법 선택의 이유
- 교실 상황 문제 해결
- 의사소통과 공감
- 교직 윤리
- 교육관/교사상
- 교육 현안에 대한 균형 있는 관점

질문 생성 축:
`상황 → 학습자 관점 → 교사 판단 → 행동 → 이유 → 예상 효과 → 한계/대안`

# 7. 면접 우선도 S/A/B/C/F 판정 기준

## 7.1 고정 정의

| 우선도 | 정의 | 기본 준비 수준 |
|---|---|---|
| S | 학생의 핵심 서사나 지원 이유를 설명하는 데 필수인 활동 | 답변 발화본과 꼬리질문까지 준비 |
| A | 지원 전형의 평가요소를 설명하는 중요한 활동 | 핵심 답변과 주요 검증 질문 준비 |
| B | 다른 활동을 보완하거나 특정 질문에 활용할 활동 | 내용·본인 역할·배운 점 정리 |
| C | 기본적인 사실 확인에 대비할 활동 | 무엇을 했는지 정확히 기억 |
| F | 별도 집중 훈련을 유보할 활동 | 원문과 최소 설명 유지 |

## 7.2 판정 요소

숫자 총점으로 자동 판정하지 않는다. 다음 근거를 조합해 서술형으로 판단한다.

### 지원 맥락
- 해당 대학/전형의 평가요소와 직접 연결되는가
- 모집단위/전공과 연결되는가
- 대학별 기출·면접 경향상 질문 가능성이 높은가

### 학생 서사
- 지원동기/진로 형성의 핵심 경험인가
- 학년 간 흐름을 설명하는 전환점인가
- 다른 활동의 출발점 또는 정점인가

### 경험 품질
- 학생의 실제 역할이 명확한가
- 과정이 구체적인가
- 질문에 답할 충분한 기억과 근거가 있는가
- 결과보다 과정에서 설명할 내용이 있는가

### 중복성
- 같은 역량/주제를 더 잘 설명하는 활동이 이미 있는가
- 다른 대표 활동이 없는 독특한 역할을 하는가

### 검증 위험
- 기록이 강하지만 학생이 기억하지 못하는가
- 개념 설명이 필요한데 이해가 부족한가
- 사실관계가 불명확한가

검증 위험이 높다고 무조건 우선도를 내리지 않는다. 오히려 면접에서 물을 가능성이 높다면 S/A인 채로 `사실확인 필요`를 별도 표시한다.

# 8. 대표 활동 선정 기준

대표 활동은 ‘가장 화려한 활동’이 아니라 **학생의 면접 서사를 적은 수의 경험으로 설명할 수 있는 조합**이다.

## 8.1 대표 활동 후보 조건
- 지원동기 또는 진로 형성을 설명함
- 전공/탐구 역량을 설명함
- 학업 방식이나 문제해결을 설명함
- 공동체 행동/인성을 실제 사례로 설명함
- 학생의 변화·성장을 설명함
- 다른 활동과 겹치지 않는 역할이 있음

## 8.2 포트폴리오 원칙
대표 활동 전체가 같은 종류의 경험으로만 구성되지 않게 한다.

가능한 균형:
- 전공·탐구
- 학업
- 공동체·인성
- 진로 전환/가치관

학생에게 해당 경험이 없다면 인위적으로 균형을 맞추지 않는다.

## 8.3 대표 활동 제외/보류
- 학생이 실제 수행을 기억하지 못함
- 원문은 길지만 학생 역할이 거의 없음
- 사실확인이 되지 않음
- 지원처와 연결 이유를 설명하기 어려움
- 다른 활동의 반복으로 추가 정보가 없음

단, 질문 가능성이 높으면 대표 활동에서 제외하더라도 대비 질문에는 남긴다.

# 9. 전공 연계도·인재상 태그

## 9.1 전공 연계도

[운영 규칙]
숫자 점수보다 `무엇이 어떻게 연결되는가`를 저장한다.

전공 연결 근거 유형:
- 전공 개념을 직접 탐구
- 전공과 관련된 문제를 해결
- 전공 연구 방법/도구를 사용
- 전공 관련 사회문제를 탐구
- 관련 진로/직업을 구체화
- 전공 기초 교과 역량을 보여줌
- 직접 전공은 아니지만 학문적 태도/방법이 확장 가능

나쁜 표현: `전공 연계도 높음`
좋은 표현: `수소 생산 방식의 효율과 한계를 비교하면서 화학·에너지공학의 공정 및 에너지 전환 문제로 탐구를 확장함.`

## 9.2 인재상 태그

대학의 추상적인 인재상 단어를 활동에 억지로 붙이지 않는다.

태그 부여 조건:
1. 대학/전형의 공식 평가요소 또는 인재상 표현이 존재
2. 학생 활동에서 그 요소와 연결되는 실제 행동이 확인됨
3. `연결 이유`를 한 문장으로 설명 가능

예:
- `협업` 태그 근거 = 팀원 의견 조율, 역할 재배분, 공동 결과물 완성
- 단순 `팀 활동에 참여`만으로 협업 우수성을 확정하지 않는다.

# 10. 질문 제작 기준

## 10.1 질문 생성의 기본 단위 (세부 명세는 질문 가이드라인 v2.2 우선)

모든 핵심 질문은 가능하면 다음 필드를 갖는다.
- `question_id`
- 질문 문장
- 질문 의도
- 근거 범주: 서류기반/확장
- 질문 유형(복수)
- 연결 activity_id
- 연결 support_target_id
- 연결 source_ref_id
- 평가요소 연결
- 질문 깊이
- 답변 요소
- 후속/꼬리질문
- 사실확인 상태

## 10.2 활동에서 질문을 만드는 12개 축

[면접바이블 예시 전반을 구조화한 운영 규칙]

1. **사실 설명**: 무엇을 했는가
2. **동기**: 왜 했는가
3. **역할**: 본인이 맡은 부분은 무엇인가
4. **과정**: 어떻게 진행했는가
5. **선택 이유**: 왜 그 방법/자료/주제를 선택했는가
6. **개념**: 핵심 원리·용어를 설명할 수 있는가
7. **근거**: 어떤 자료/데이터로 판단했는가
8. **결과**: 무엇을 얻었는가
9. **한계/오차**: 무엇이 부족했는가
10. **개선/대안**: 다시 한다면 무엇을 바꿀 것인가
11. **비교/적용**: 다른 사례에 적용하거나 비교할 수 있는가
12. **연결**: 전공·대학·가치관·진로에 어떻게 이어지는가

## 10.3 질문 깊이 4단계

[프로젝트 확정]

### D1 사실 설명
- 무엇을 했나요?
- 어떤 책/실험/프로젝트인가요?
- 본인의 역할은 무엇인가요?

### D2 과정과 이유
- 왜 선택했나요?
- 어떤 과정으로 진행했나요?
- 가장 어려웠던 점은 무엇이었나요?

### D3 개념 적용·비교
- 사용한 원리를 설명해보세요.
- 다른 방법과 비교하면 어떤 차이가 있나요?
- 배운 개념을 다른 상황에 적용한다면?

### D4 한계·대안
- 이 탐구의 한계는 무엇인가요?
- 결과를 일반화해도 될까요?
- 다시 한다면 무엇을 바꾸겠습니까?
- 반대 근거가 있다면 어떻게 판단하겠습니까?

S/A 활동일수록 D1~D4까지 질문 트리를 준비한다.

## 10.4 꼬리질문 제작

꼬리질문은 직전 답변을 구체화·검증하기 위해 만든다.

좋은 꼬리질문:
- “직접 했다고 한 부분을 구체적으로 설명해보세요.”
- “그 결론을 내린 근거가 무엇인가요?”
- “다른 방법을 고려하지 않은 이유가 있나요?”
- “그 과정에서 본인의 판단이 바뀐 지점은?”

피해야 할 꼬리질문:
- 단순히 더 어려운 전공지식을 과시하는 질문
- 원문과 무관한 지엽적 암기문제
- 학생의 인격을 공격하는 질문

## 10.5 압박 질문

[프로젝트 확정]
압박은 `공격적 표현`이 아니라 **근거·모순·한계 검증**으로 구현한다.

- 주장과 근거 불일치
- 역할 과장 가능성
- 결과와 원인 사이의 비약
- 반대 사례
- 한계 인정 여부

# 11. 질문 유형별 제작 규칙

## 11.1 활동 질문

최소 준비 요소:
`활동 한 문장 설명 → 동기 → 역할 → 핵심 행동/과정 → 결과 → 배운 점`

핵심은 ‘동아리에서 무엇을 했는가’보다 **본인이 무엇을 판단하고 수행했는가**다.

## 11.2 전공 질문

학생 기록에서 출발한 개념을 우선한다.
- 기록에 등장한 용어를 설명
- 탐구에 사용한 원리를 설명
- 전공 관점에서 한계/확장

기록과 무관한 고난도 전공지식을 무작정 붙이지 않는다.

## 11.3 인재상 질문

추상적 “나는 협업형 인재다”가 아니라 행동 근거를 묻는다.

`상황 → 역할 → 행동 → 상대/팀과의 상호작용 → 결과 → 배운 점`

## 11.4 가치관 질문

개인의 선택 기준이 드러나는 실제 사례를 우선한다.
- 갈등
- 책임
- 실패
- 윤리적 선택
- 타인과의 차이

답변을 ‘좋은 사람처럼 보이는 정답’으로 만들지 않는다.

## 11.5 대학 및 학과 질문

[면접바이블]
지원동기·학업계획은 실제 학과 교육과정과 본인의 관심을 연결해야 한다.

필수 확인:
- 왜 이 전공인가
- 왜 이 대학인가
- 어떤 교육과정/학습 기회를 알고 있는가
- 자신의 과거 경험이 어떻게 이어지는가
- 입학 후 무엇을 배우고 싶은가

## 11.6 공통 질문

### 자기소개
- 자기소개 전체를 학생부 요약으로 만들지 않는다.
- 자신을 설명하는 핵심 특징 1~2개를 구체적 경험과 연결한다.
- 과도한 MBTI/성격유형 의존을 피한다.

### 지원동기
권장 흐름:
`과거 관심/경험 → 전공 선택 이유 → 해당 대학과의 연결 → 앞으로의 학습 방향`

### 학업계획
- 실제 대학 교육과정/과목을 확인한다.
- 과목명을 나열하기보다 왜 배우고 싶은지 설명한다.
- 현재 경험에서 입학 후 계획으로 이어진다.

### 마지막으로 하고 싶은 말
- 앞 답변을 길게 반복하지 않는다.
- 짧고 명확하게 남기고 싶은 메시지를 말한다.
- 면접 막판에 새로운 거대한 성과를 갑자기 추가하지 않는다.

## 11.7 시사 질문

[면접바이블, PDF p.54~55]
준비 순서:
1. 이슈의 기본 사실과 용어
2. 발생 배경/원인
3. 주요 이해관계자와 관점
4. 장점/문제점 또는 찬반 논거
5. 자신의 입장
6. 근거
7. 전공과 연결 가능한 경우 연결

시사 답변에서 사실과 의견을 구분한다.

# 12. 답변 설계 기준

## 12.1 답변 설계 필수 필드 (세부 평가는 답변 가이드라인 v2.2 우선)

- 질문 의도
- 사용 활동/경험
- 핵심 메시지
- 필수 의미 요소
- 답변 구조
- 사실/해석/생각 구분
- 답변 발화본
- 암기 키워드
- 예상 꼬리질문
- 확인 필요 사항

## 12.2 활동 질문 기본 구조

권장 기본형:

`결론/활동 정의 → 동기 → 본인 역할 → 핵심 과정 → 결과 → 배운 점/연결`

질문에 따라 필요한 요소만 사용한다. 모든 답변에 여섯 요소를 기계적으로 다 넣지 않는다.

## 12.3 설명형 질문

`핵심 정의 → 원리/근거 → 활동 속 적용 → 의미`

## 12.4 비교형 질문

`비교 기준 제시 → A → B → 차이/공통점 → 자신의 판단`

## 12.5 문제해결형 질문

`문제 → 원인 → 시도 → 선택 이유 → 결과 → 한계/개선`

## 12.6 가치관/인성 질문

`입장 → 실제 사례 → 행동 → 이유 → 배운 점`

## 12.7 지원동기

`관심의 시작 → 관련 경험의 누적 → 전공 선택 → 대학의 구체적 요소 → 앞으로의 목표`

## 12.8 답변 발화본 작성 원칙

- 첫 문장에서 질문에 답한다.
- 한 문장에 정보를 너무 많이 넣지 않는다.
- 교사 서술형 표현을 학생 말투로 바꾼다.
- “~역량을 함양했습니다” 같은 보고서식 문장을 최소화한다.
- 역할을 주어로 드러낸다: `저는 ~했습니다.`
- 결과만 말하지 않고 핵심 행동을 포함한다.
- 사실과 해석 사이를 명확히 한다.
- 대학 공식 표현을 외운 문구처럼 반복하지 않는다.
- 30~40초 기본형을 우선 설계하고, 필요 시 60~90초 확장형을 둔다.

## 12.9 답변에서 금지/주의할 것

- 하지 않은 활동 생성
- 감정 생성
- 수치·성과 임의 생성
- 읽지 않은 책을 읽었다고 표현
- 실험결과/통계 임의 보완
- 대학 교육과정/인재상 사실 왜곡
- 어려운 전문용어로 내용의 빈틈을 가리기
- 학생부 원문을 그대로 문어체로 낭독하는 발화본

# 13. 사실 확인 표준

## 13.1 확인 트리거

다음은 학생 확인을 요청한다.
- 실제 역할이 원문에서 불명확
- 동기/감정이 원문에 없음
- 결과물의 구체적 내용이 없음
- 조사 대상/표본/수치가 필요
- 팀 활동에서 개인 기여도가 불명확
- 책/논문/자료를 실제로 얼마나 읽었는지 불명확
- 실험 과정/변수/오차를 설명해야 함
- 기록과 학생 진술이 다름

## 13.2 확인 상태
- `confirmed_from_record`
- `confirmed_by_student`
- `needs_confirmation`
- `student_says_different`
- `cannot_confirm`

## 13.3 확인 실패 처리

확인되지 않는 요소를 빼도 답할 수 있으면 발화본을 수정한다.
핵심 경험 자체가 확인되지 않으면 발화본 확정을 보류하고 사실확인 질문으로 전환한다.

# 14. 생기부 OCR MD 및 분석 MD — 정본 데이터 계약

## 14.1 두 데이터의 법적·기능적 경계

- **생기부 OCR MD**는 허용된 입력 경로에서 생성한 학생부 원문 전사본이며, 학년·영역·과목·원문·페이지 위치를 보존한다. 어떠한 AI 평가·해석·면접 우선도도 원문 안에 삽입하지 **않는다**.
- **생기부 분석 MD**는 OCR 정본을 참조하여 활동 단위, 근거, 지원처별 우선도, 인재상, 전공 연결, 질문/답변 설계, **가이드북 여섯 장으로의 콘텐츠 투영**을 저장한다.
- 원문 법적 확보와 상업적 처리의 적법성은 **별도 승인 조건**이다. 이 문서는 수집·AI 입력의 허가서가 아니다.
- 분석 MD는 가이드북 목차에 맞아야 하지만 `activity_id` 정본을 장마다 중복 복사하지 않는다. 가이드북 섹션은 정본 활동·질문·답변 ID를 **참조**한다.

## 14.2 필수 식별·버전 필드

| 데이터 | 필수 식별값 | 관계/검사 |
|---|---|---|
| student | `student_id` | 학생별 데이터 완전 분리 |
| support_target | `support_target_id`, `admission_year`, `university`, `department`, `admission_track` | 전형별 분석 개별화 |
| OCR 문서 | `record_revision`, `ocr_revision`, `source_document_id`, `processing_status` | 원문 개정/전사 버전 구분 |
| OCR 위치 | `source_ref_id`, `grade`, `area`, `subject?`, `page?`, `text`, `verification_status` | 원문 발췌 및 위치 추적 |
| 활동 정본 | `activity_id`, `source_ref_ids[]`, `title`, `grade`, `area`, `actual_actions[]`, `fact_status` | 중복·비근거 활동 차단 |
| 지원처별 분석 | `support_target_id`, `activity_id`, `priority`, `priority_reason`, `ideal_trait_links[]` | S/A/B/C/F 사유 증명 |
| 질문 | `question_id`, `activity_ids[]`, `source_ref_ids[]`, `question_intent`, `primary_function`, `depth` | 질문 v2.1 계약 참조 |
| 가이드북 투영 | `guidebook_section_id`, `content_refs[]`, `display_order` | 여섯 목차 참조 무결성 |
| 발행 | `analysis_revision`, `guidebook_revision`, `publication_revision`, `published_at?` | 제작 완료와 실제 열람 구분 |

**필수 상태:** `created / needs_review / approved / blocked / published / superseded`는 **제안 상태 집합**이다. 실제 DB enum·승인 주체는 PRD와 제작 프로세스의 합의 필요사항에 맞추고, 위 단어를 확정 구현 값으로 간주하지 않는다.

## 14.3 OCR의 원문 불변성

① 원문 전사 오류는 원본을 대조해 정정하며 **이전 OCR revision과 대조 로그**를 남긴다. 원문 그 자체와 학생의 정정 진술을 혼합하지 않는다.
② 원문 누락·페이지 뒤바뀜·교과·학년 오분류·중복 변환을 검사한다.
③ OCR 검증이 미완료된 근거는 확정 질문·개인 발화본에 사용하지 않는다.
④ 학생이 추가 사실을 제공한 경우 원문을 덮어쓰지 않고 `student_confirmations` 등 별도 기록에 남긴다.
⑤ OCR 수정 시 해당 `source_ref_id → activity_id → question_id → guidebook_section_id`의 영향 범위를 검사한다.

## 14.4 분석 MD의 필수 논리 구조 (예시)

```yaml
student_id: STUDENT_ID
analysis_revision: "revision-placeholder"
ocr_revision: "revision-placeholder"
support_targets:
  - support_target_id: "TARGET-ID"
    admission_year: 2027
activities:
  - activity_id: ACT-001
    source_ref_ids: [SRC-001]
    title: "학급 방송 개선 활동"
    grade: 2
    area: "자율활동"
    actual_actions: ["방송 퀴즈 기획"]
    fact_status: confirmed_from_record
priority_assignments:
  - activity_id: ACT-001
    support_target_id: TARGET-ID
    priority: S
    priority_reason: "지원처 평가관점과 확인된 문제해결 행동의 연결"
    ideal_trait_links:
      - trait: "문제해결"
        evidence_ref_ids: [SRC-001]
guidebook:
  sections:
    - guidebook_section_id: strategy
      title: "나의 면접 전략"
      content_refs: [ACT-001]
    - guidebook_section_id: record_analysis
      title: "학생부 분석"
      content_refs: [ACT-001]
```

**주의:** 위 값은 필드 관계를 보여주는 가상 예시다. 필드 이름·enum의 최종 JSON Schema는 개발팀과 콘텐츠기획팀이 단일 버전으로 승인해야 한다. YAML 예시 자체가 실행 스키마는 아니다.

## 14.5 가이드북 여섯 목차 매핑

| 정본 섹션 ID(제안) | 화면 목차 | 필수 연결 데이터 |
|---|---|---|
| `strategy` | 나의 면접 전략 | 지원정보·학업흐름·핵심 키워드·대표활동·우선도 |
| `record_analysis` | 학생부 분석 | 활동 정본·원문 근거·학년/영역/과목·종합 흐름 |
| `university_major` | 대학·학과 분석 | 검증 전형 프로필·평가요소·활동 매칭 |
| `qa` | 예상 질문·답변 | 질문·의도·답변 설계·발화본·키워드·활동 참조 |
| `practice` | 실전 훈련 | 기억 구조·발화 방법·면접/피드백 활용 안내 |
| `appendix` | 부록 | 전체 질문·사실 확인표·핵심자료·기록지 |

`00. 가이드북 사용법`은 탐색 안내를 위한 보조 섹션으로 관리한다. 사용자에게 노출되는 주요 여섯 목차는 위와 같다.

## 14.6 필터 및 검색 정합성

- 최소 필터: 학년(1/2/3), 영역(자율/동아리/진로/봉사/교과세특 등), 우선도(S/A/B/C/F). 해당 값이 없는 비활동 섹션은 별도의 적용/미적용 처리.
- 검색은 활동·질문·근거 발췌·목차를 연결하고 결과의 실제 위치로 이동할 수 있어야 한다.
- `activity_id`를 복수 섹션에서 표시해도 통계·질문 출제 시 하나의 활동으로 집계한다.
- 원문을 표시하지 않는 사용자 옵션이 있어도 내부 근거 링크와 권한·검수 조건은 유지한다.

# 15. 제공물과 학습 데이터의 관계

① 웹 가이드북은 분석 MD를 렌더링한 **기본 제공물**이다. 단독 PDF 교재 중심 제작은 기본 파이프라인이 아니다.
② 암기 훈련실의 퀴즈·지식한입·이슈픽는 공식 메뉴로 확정되었으나, 각 콘텐츠의 생성·채점·갱신 기준은 미정이다.
③ 과거 **암기 핸드북**의 `동기 → 역할 → 과정 → 결과 → 배운 점 → 연결 키워드` 압축 방식은 분석 자산으로 유지하되, **독립 핸드북 DOCX/PDF 발행은 종료**한다. 필요한 키워드·학습 항목만 웹 가이드북과 암기 훈련실에 전달한다.
④ 개인별 답변 발화본과 암기 키워드는 동일한 `question_id` 및 `activity_id`를 사용한다. 예시답안은 학생 확인 없는 내용을 사실로 만들 수 없다.
⑤ 면접 질문 생성과 답변 평가는 각각 9번 v2.1, 10번 v2.1을 우선 참조한다. 본 문서의 과거 질문·답변 관련 서술은 **분석·콘텐츠 설계 참고 원칙**이며 정식 면접 운영 제약을 변경하지 못한다.

| 활동 구조화 | 활동 누락/중복/억지 병합, 모든 source_ref 연결 | 수정 후 재검수 |
| 우선도 | 지원처별 S/A/B/C/F 사유와 과도한 평가어 | 사유 보완/재검토 |
| 인재상 | 공식 평가요소/일반 인재상 구분, 행동 근거 | 태그 보류 |

**조건부 자동 발행 확정:** 다섯 가지 중대 오류가 없고 자동 QA를 통과한 일반 건은 자동 발행할 수 있다. 중대 오류가 발견된 건은 발행 보류→콘텐츠기획팀 원인 수정→자동 재검증→콘텐츠기획팀 최종 승인 후 발행한다. 실제 자동 QA 신뢰도를 확보하는 시험·운영 기준은 별도 기술 검증이 필요하다.

# 17. 변경 관리 및 우선순위

- 원문 OCR revision이 변경되면 영향을 받는 활동/질문/가이드북 투영을 검사하고 영향 받은 객체만 새 revision으로 다시 승인한다.
- 대학 공식 전형 프로필 갱신은 지원처별 분석 재검토 사유다. 참고 교재의 예시로 입학연도 정보를 덮어쓰지 않는다.
- 분석 정본이 발행 후 바뀌더라도 이전 면접 기록과 피드백은 당시 사용한 `analysis_revision`, `question_version`, `rubric_version`과 함께 보존한다.
- 질문의 발화와 답변 평가 실행 기준은 **공통 운영 원칙 v1.1 > 질문 가이드라인 v2.2 > 답변 가이드라인 v2.2** 순으로 해석한다. 학생부 분석의 원문·활동·우선도 판정은 본 문서에서 관리한다.

# 18. v2.1 추가: 사실성 QA의 강제 수준 및 학생 수정 데이터 계약

## 18.1 원천의 신뢰 계층과 발화 금지

| 데이터 계층 | 값 예 | 사용 가능 범위 | 금지 |
|---|---|---|---|
| 원본 PDF/검증 OCR 원문 | `RECORD_CONFIRMED` | 사실 서술·근거 인용 | OCR 불일치 무시 |
| 학생이 확인한 별도 경험 | `STUDENT_CONFIRMED` | ‘학생이 확인한 경험’으로 답변 소재/질문 사용 | 학생부 공식 원문으로 표시 |
| 학생이 자유 편집한 답변/키워드 | `STUDENT_CLAIM_UNVERIFIED` 포함 가능 | 최신 참고 문맥·학습 개인화 | AI 수정본을 학생부 확정 사실·정답으로 승격 |
| 해석/연계 | `AI_INFERENCE` | 후보·설명·우선도·활동 매칭 | 실제 학생 행위를 단정 |
| 지원처 검증 정보 | `ADMISSION_VERIFIED` | 해당 입학연도+모집단위+전형에 한한 운영 사실 | 전년도·일반 인재상·참고서 문구를 현행 면접 규칙으로 단정 |

**원본 불변 조건:** `record_ocr.revision`과 `source_ref.id`는 수정 이력과 함께 관리한다. 잘못된 OCR은 검증된 새 revision으로 정정하되 원본 업로드를 조용히 덮어쓰지 않는다. 학생 자유 편집은 `user_answer_revision`, `user_keyword_revision`, `personal_note_revision`의 별도 계층에 보관한다. 공식 분석 데이터의 수정은 정정 요청 승인 흐름을 사용한다.

## 18.2 발행 차단 5대 중대 오류의 정밀 정의

| 코드 | 검출 예시 | 차단 범위 | 검수의 증명 자료 |
|---|---|---|---|
| `CRIT-OCR` | 학년·성적·도서명·숫자·활동의 핵심 원문 누락/오인식, 원문-위치 대응 실패 | 영향을 받은 지원처 발행 작업 | PDF 대조한 OCR 위치·정정 diff |
| `CRIT-FACT` | 학생이 하지 않은 활동·역할·성과·감정을 ‘했다’고 확정, source_ref 부재 | 해당 콘텐츠 및 의존 발행 전체 | claim 목록·source_ref·확인 상태 |
| `CRIT-ADMISSION` | 확인하지 못한 면접 시간·면접관·평가요소·전형을 공식 사실로 안내하거나 서류기반 여부 불명인데 확정 재현으로 표기 | 해당 지원처의 허위 확정 콘텐츠 발행 | 입학연도·전형 식별자·공식 출처/검증 상태 |
| `CRIT-CONTENT` | 필수 6장/대표 활동·주요 질문·핵심 분석 링크 누락 | 해당 지원처 발행 | 생성 매니페스트·필수 장 완전성 |
| `CRIT-RELATION` | activity ID 참조 끊김, source-ref 잘못 연결, 다른 지원처 우선도 혼입, 질문-답변 연결 오류 | 교차 참조 영향 범위 | ID 무결성/버전 그래프 검사 |

- **전부 차단:** 중대 오류가 하나라도 있으면 전체 자동 발행 경로로 전환할 수 없다. 경미한 문체·스타일 문제는 사전 정의된 다른 QA 등급으로 처리하되, 사실 오류를 경미한 오류로 강등하지 않는다.
- **미확인 사실:** ‘질문으로 확인할 수 있는 미확인 소재’와 ‘검증 없이 사실로 문서에 확정된 문장’은 구분한다. 후자는 반드시 발행 차단한다.
- **검증 미완료와 허위 확정의 구분:** 대학 면접관 수·시간이 공식 미확인인 사실을 **미확인으로 표시하고** 승인된 가상 기본 설정과 명확히 구분하는 것은 허위 확정과 다르다. 다만 서류기반 면접 실시 여부 자체가 불확실하면 실제 대학 실전 재현이 가능한 것으로 판매/발행하지 않는다.
- **사람 승인:** 보류된 건은 콘텐츠기획팀이 원본 대조·수정→자동 재검증→최종 승인자 서명/시각 기록을 모두 완료해야 발행한다. 재검증 통과만으로 자동 발행하는 경로 금지.
- **학생 확인:** 원본/공식 근거를 기획팀이 우선 대조하고 자체 해결이 불가능할 때만 학생에게 설명 또는 재업로드를 요청한다. 학생 확인을 원문 필드에 덮어쓰지 않는다.

## 18.3 안정적 ID·재분석과 영향 그래프

1. 같은 실제 활동이면 새로운 분석 revision에도 동일 `activity_id`를 유지한다. 기존 활동을 분리/병합할 필요가 있을 때는 `supersedes_activity_ids[]/merged_from[]/split_from_id` 등 **명시적 관계표(논리 필드 예시)**와 승인 사유를 남기고 원 ID를 무단 재사용하지 않는다.
2. 활동의 우선도는 `activity_id + support_target_id + analysis_revision` 단위의 **지원처별 판정**이다. 같은 활동이 다른 지원처에서 S와 B를 받을 수 있고, 그 사유가 모두 설명되어야 한다.
3. 오류 정정은 영향 그래프 `source_ref → activity → activity_priority → question → answer_design → guidebook_section → memory_item`을 따라 재평가한다. 영향을 받지 않은 개체는 무작정 재생성하지 않는다.
4. 과거 실전 모의면접의 질문·발화·학생 답변·당시 rubric/분석 버전/리포트는 변경하지 않는다. 새 내용은 새로운 revision과 관련성을 표시한다.
5. **비용 정책:** 발행 후 서비스 오류는 무료 수정, 학생부 교체에 따른 전체 재분석 1회 무료·이후 유료라는 내부 합의가 있다. 결제/법적 표기는 특별약관 승인 이후로 한다.

## 18.4 생성·검수 예시 (가상 데이터)

```yaml
student_id: example_student
support_target_id: example_2027_uni_dept_track
record_revision: 4
analysis_revision: 7
activity:
  activity_id: ACT-001
  source_ref_ids: [SRC-003, SRC-013]
  fact_status: confirmed_from_record
  user_claims: []  # 개인 자유 수정 주장과 분리
priority:
  activity_id: ACT-001
  support_target_id: example_2027_uni_dept_track
  label: S
  reason: "공식 평가요소와 검증된 활동의 연결에 근거한 준비 우선도" # 가상 예시
quality_gate:
  critical_errors: []
  automated_check_status: passed
  has_ever_been_blocked: false
  staff_final_approval_required: false
  publishable: true
```

보류 건은 `has_ever_been_blocked: true`이면 `staff_final_approval_required: true`와 실제 승인 이벤트를 요구한다. QA 상태 필드명·자료형은 **개발 설계 예시**이지만 상태 의미와 승인 순서는 제품 합의다.

## A. 승인 원문과 UI 투영의 엄격한 구분

본 문서 1~마지막 장의 **활동 추출·평가 기준·S/A/B/C/F·질문 도출 방법·실제 사례·참고문헌은 변경하지 않는다.** 다음 규칙은 기존 `source_ref → activity → question` 연결을 UI에서 **오인 없이 보여주기 위한 추가 계약**이다.

1. `G02 학생부 분석`은 모든 공개 권한이 확보된 원문 항목을 **문서의 실제 순서/학년/영역/과목 그대로 렌더링**한다. AI 활동 분석만 보여주거나 중요한 활동만 추려 표시하여 원문 완전 열람 기능을 대체하지 않는다.
2. OCR/원본 대조 데이터에는 **학생별 존재하는 항목**, 표 셀 좌표, 줄바꿈/문단 경계, 원본 페이지, 원문 내 순서, `record_revision`과 `source_ref_id`를 보존한다. 일부 원본이 법적으로 노출 금지라면 비공개 처리 이유와 범위를 별도로 관리한다.
3. 동일 문구가 여러 과목/학년에 반복되어도 문자열 검색만으로 질문 근거를 **형광펜 처리하지 않는다**. 각 질문 근거는 `source_ref_id + record_revision + anchor_range/structured_location`으로 연결하며 복수 근거를 허용한다.
4. 원문 위치가 OCR 재처리·학생부 교체·재발행으로 어긋나면 **불일치 감지→강조 중단→대조/재검증 요청**. 잘못된 문구를 대강 강조하여 질문의 출처인 것처럼 표시하지 않는다.
5. `G04`에서는 실제 학생부 전체 원문과 **예상 질문·예상 답변만 기본 노출**, 질문의 평가 의도·숨은 평가 근거·후속 질문 설계는 계속 **내부 정본에 저장**하되 별도의 `질문의 의도`/`꼬리질문 보기` 버튼으로 기본 전시하지 않는다. 학생의 수정 가능한 답변은 원문과 분리한다.
6. `COMMON_APPROVED` 등 특정 학생부 문장으로 직접 추적할 수 없는 공통 질문은 **근거 하이라이트 없음**. 빈 위치에 거짓 형광펜을 표시해서는 안 된다.
7. `G04 질문 저장하기`는 `question_id`, `support_target_id?`, `source_ref_ids[]`, `saved_at`을 연결하고 연습 면접 `내가 추가한 항목`에서 재사용한다. 질문/원문을 별도 DB 행으로 복제하지 않는다.

## B. 관련 검증 케이스

- **SA-UX-01:** 문서의 모든 공개 대상 항목이 G02에서 항목별 누락 없이 보임.
- **SA-UX-02:** 중복 문자열 두 곳 중 지정된 문장만 G04에서 강조됨.
- **SA-UX-03:** 재OCR로 페이지/줄 위치가 바뀌어도 잘못된 하이라이트를 표시하지 않음.
- **SA-UX-04:** 1개 활동의 복수 `source_ref_ids[]`가 각 원문 위치에 올바르게 매핑됨.
- **SA-UX-05:** 학생 개인 수정 예상 답변이 원본·분석 MD·기존 면접 기록을 덮어쓰지 않음.

학생부·지원처의 **원천 데이터 규칙은 본 문서**가 정본이고, 화면 패턴·문구는 `12. 학생용_IA및UX_정밀설계_v1.2.md`에 따른다. 원문 인식 성능이나 보안 검증 완료를 뜻하지 않는다.
