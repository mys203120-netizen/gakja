# 각자의답 웹 가이드북 통합 제작·검수·발행 프로세스 v2.2

- **기준:** 2026-10-29 통합 회의록, 2026-11-02 승인 학생용 IA 및 용어집 v2.2, 학생부 분석 기준 v2.2, 질문 생성 v2.3, 답변 평가 v2.3
- **변경 규모:** Minor — 기존 OCR→분석→가이드북 제작·승인 구조 보존, G02/G04 원문 전체·질문 근거·학습 연결 출력을 보강
- **대상:** 콘텐츠기획팀·서비스개발팀·운영 담당자
- **상태:** 조건부 자동 발행·예외 사람 승인·독립 핸드북 종료 확정; 기술 검증 세칙은 제안/미확정 구분

## 제1장 목적과 최고 원칙

### 제1조 (제작 목표)

① 승인된 학생 자료와 검증된 지원처 기준으로 개인별 웹 가이드북을 생성하고, 면접 엔진·암기 훈련·AI 비서가 일관된 정본 데이터를 참조하도록 한다.
② 모든 분석 결과는 근거의 위치와 콘텐츠 버전을 추적할 수 있어야 한다.
③ 동일 활동을 다양한 목차·질문·학습 기능에서 활용하더라도 정본 활동을 복제하지 않는다.

### 제2조 (사실·해석·의견 분리)

① 학생부 원문(OCR MD)은 사실 근거이며, 활동 우선도·전공 연계·인재상은 분석 MD의 해석이다.
② 학생이 명시하지 않은 동기·기여·감정·수치·성과를 확정적인 학생 경험으로 생성하지 아니한다.
③ 학생의 확인·정정은 원문 덮어쓰기가 아니라 별도 확인 기록과 revision으로 관리한다.
④ 외부의 대학 참고 교재는 특정 입학연도의 공식 모집요강을 대체할 수 없다.

### 제3조 (참조 우선순위)

- 학생부 분석의 판정: **5번 학생부 분석 기준 v2.2**.
- 대학·전형 정보: **6번 대학별 면접 기준 v1.3** + 검증된 공식 입학연도 자료.
- 질문의 내용·문법·꼬리질문: **8번 공통 원칙 v2.0, 9번 질문 가이드라인 v2.3**.
- 답변 분석·표준 프레임·전략 코칭: **10번 답변 가이드라인 v2.3**.
- 웹 목차·메뉴·권한: **1번 용어집 v2.2, 3번 목차 v3.0, 4번 PRD v3.0, 12번 IA/UX v1.2**.

**주의:** 학생부의 취득·저장·전송·상업적 활용 허용 여부는 별도 법적 검토와 적법한 운영 설계가 선행되어야 한다. 이 문서는 수집 허가가 아니다.

## 제4장 제작 단계 및 품질 게이트

### STEP 0. 제작 건 등록

**입력:** 지원처, 학생 계정·권한, 적법한 입력자료. **작업:** 학생/지원처 분리, `production_job_id` 생성, 정책 버전 기록. **검수:** 접근 권한·입학연도 및 서류기반 전형 여부.

**실패 처리:** 잘못된 지원처·권한 불일치·처리 근거 부재 시 생성 보류. 추측으로 대학 프로필을 만들지 않는다.

### STEP 1. 생기부 OCR MD 생성

**작업:** 학년·영역·과목·원문 발췌·페이지 근거를 그대로 전사. 원문에 AI 평가 문구를 끼워 넣지 않는다.

**Gate 1 — 원문 검증:** OCR 누락, 숫자/도서명/고유명사 오류, 영역 혼합, 과목 매핑 실패, 중복 텍스트를 대조한다. 오류 발생 시 `needs_review`로 관리하고 관련 하위 생성 진행을 차단한다. **자동 QA 통과 일반 건은 자동 발행, 차단 건은 콘텐츠기획팀 최종 승인**.

### STEP 2. 활동 구조화·분리·통합

**작업:** 목적과 맥락이 이어지는 기록을 동일 활동으로 묶고 독립 경험을 분리. `activity_id`를 부여하고 복수 `source_ref_ids[]`를 연결한다.

**Gate 2 — 활동 완전성:** 주요 활동 누락·중복·잘못된 병합 여부를 검수한다. 중복 기록 자체를 활동 여러 개로 집계하지 않는다.

### STEP 3. 학생부 분석 MD 생성

**작업:** 모든 활동에 역할·방법·결과·키워드·사실 상태를 붙이고 지원처별 S/A/B/C/F와 판정 사유, 인재상 태그와 행동 근거, 학년/교과 간 연결을 산출한다.

**Gate 3 — 해석 QA:** 원문 사실과 AI 추론 혼입, 지원처 외부자료 오인, 인재상 과잉 태그, 기준 없는 S 등급, 활동 누락을 검수한다. 실제 결과에 영향이 큰 미확인 사실은 차단한다.

### STEP 4. 사실 확인 요청 관리

**작업:** 학생이 실제 맡은 역할·선택 동기·갈등·측정값·독서 범위 등을 확인할 필요가 있으면 별도 목록 생성. `학생 확인 필요 / 확인 완료 / 확인 불가 / 사용 금지` 등 상태 구분.

**Gate 4 — 사실 확인:** 미확인 사실을 확정 발화본·평가 질문의 허위 전제로 사용하지 않는다. 확인이 필요한 내용은 질문으로 여는 것은 가능하지만 수행 사실처럼 단정하지 않는다.

### STEP 5. 개인별 질문·답변 및 학습 콘텐츠 설계

**작업:** 질문 v2.2의 `primary_function`, `question_intent`, `target_evidence[]`를 부여하고 질문 ID와 정본 활동을 연결. 답변 v2.2의 표준 구조·예시 발화본·키워드를 생성한다.

**Gate 5 — 질문·답변 QA:** 기록에 없는 역할·성과·감정·기출·면접시간·전형 조건의 허위 확정이 있으면 발행 금지. 질문은 Q0와 F1/F2 상한을 유지하고, 답변 예시를 유일한 정답으로 만들지 않는다.

### STEP 6. 웹 가이드북 6개 장으로 투영

**작업:** `나의 면접 전략 / 학생부 분석 / 대학·학과 분석 / 예상 질문·답변 / 실전 훈련 / 부록`으로 인덱스 구축. `00. 가이드북 사용법`은 보조 안내. 동일 활동은 같은 ID로 여러 장에서 재사용.

**Gate 6 — 웹 품질 QA:** 섹션 누락/정렬 오류/원문-활동-질문 끊긴 링크/검색 위치/필터·접기/펼치기 실패 점검. `가이드북`이 `분석 리포트`라는 이름으로 노출되지 않도록 검사.

### STEP 7. 승인·웹 발행

**작업:** 검증 완료 데이터의 발행 버전 고정, 학생별 접근·소유권 확인, 웹에서 실제 열람 가능 상태로 전환.

**Gate 7 — 최종 발행:** 미검증 자료 노출 차단, 개인정보 접근 격리, 외부 링크 공개 방지, 이전 발행본·세션 이력 보존을 점검한다. **중대 오류 이력 없는 일반 건은 자동 QA 통과 후 발행 가능**. 한번이라도 Critical로 보류된 건은 **재검증 통과 + 콘텐츠기획팀 최종 승인 필수**.

### STEP 8. 완료 알림

**트리거:** **OCR MD 생성이 아니라, 학생의 웹 가이드북이 실제 열람 가능한 발행 완료 시점**이다.

**방향:** 회의에서 `솔라핏`이라고 언급된 메시징 API 경유 카카오 알림톡 또는 SMS. 정확한 서비스·발신 자격·템플릿·채널 우선순위·실패 재시도는 **개발 검증 전**이며 발송 성공을 미리 표시하면 안 된다.

### STEP 9. 사후 수정·버전·재발행

**작업:** 학생 확인·OCR 정정·전형 공지 변경 시 영향 받는 `source_ref → activity → priority → question → guidebook`을 추적하고 재검토한다.

**필수:** 이전 문항과 리포트 기록을 새 데이터로 몰래 덮어쓰지 않는다. 회차별 사용 질문·루브릭·분석 버전을 보존한다. 완료 알림의 중복발송·재발행 안내 정책은 미정으로 관리한다.

## 제5장 화면·훈련과의 데이터 연결

- **생기부:** 발행한 웹 가이드북 6개 목차를 개인에게만 표시하고, 필터·검색·선택적 표시를 동일 ID로 구현한다.
- **AI 비서:** 가이드북 안의 우측 하단 플로팅 호출. 사용자 권한에 따라 승인된 데이터만 참조하고 출처를 표시한다. 화면 필터 자동 조작 범위는 별도 합의.
- **연습 면접:** 가이드북 질문 선택, 조건별 신규 생성, 학생 직접 입력을 지원한다. Q0와 필요한 F1/F2 묶음 종료 시 **숫자 없는 정성 코칭**을 제공하고 단일/묶음 재답변을 허용한다.
- **실전 모의면접:** 학생은 **지원처만 선택하며 실전은 화상 전용**이다. 카메라/마이크 점검과 실제 서버 준비 상태 3단계 이후 진입한다. 대학 프로필과 엔진이 질문을 자동 구성한다. 10번의 평가 계약에 따라 회차별 점수 PDF를 내 답변에 저장하며 평가 불능 시 부분 리포트·사과·이용권 복구 이벤트를 처리한다.
- **암기 훈련실:** 퀴즈(복수 유형·오답 가중 반복학습)·지식한입(세특 연계 실자료/썸네일/출처/즐겨찾기)·이슈픽(검증 시사/출처/즐겨찾기/질문 저장). 별도 암기 핸드북 발행 없음.
- **내 답변:** `연습 면접/실전 모의면접` 구분의 **세션·회차별 답변 보관함**과 대표 답변 지정, 정상 평가 회차를 우선 집계한 **누적 수치·회차별 펼침 리포트**, **개인 면접일 D-1 면접 직전 요약**. 저장 질문/AI 보완 추천 목록은 **연습 면접**으로 통합한다.

## 제6장 상태 및 버전 계약 (구현안)

```text
production_job: registered → ocr_processing → ocr_review → analyzing
   → analysis_review → content_generating → guidebook_review
   → publish_ready → published → notification_pending → notified

예외: failed / blocked / needs_student_confirmation / needs_operator_approval
```

- **상태명 자체는 개발 제안**, 단 일반 자동 발행/중대 오류 건의 사람 승인이라는 전이 조건은 확정 정책이다.
- `published`는 학생의 계정에서 웹 가이드북이 실제로 열람된다는 뜻이다. 알림 전송 여부와 분리한다.
- 각 작업은 `production_job_id`에 `student_id`, `support_target_id`, `ocr_revision`, `analysis_revision`, `guidebook_revision`, `policy_versions`, `published_at`, `notification_status`를 기록하도록 제안한다.
- 동일 `production_job_id` 재시도는 결과를 중복 발행하지 않아야 한다. 외부 알림의 멱등성 키와 재시도 큐는 기술 설계에서 확정한다.

## 제7장 개발팀 인수 조건

1. 학생 A의 `student_id`를 바꿔 요청해도 B의 자료나 OCR·분석 내용을 열람할 수 없다.
2. OCR 원문 누락이 발견되면 자동 분석·발행 경로가 차단되고 오류 상태가 기록된다.
3. 하나의 활동이 여러 영역에 나타나더라도 `activity_id` 1개·`source_ref_ids[]` 복수로 저장된다.
4. S/A/B/C/F는 지원처별로 다른 사유를 가질 수 있고 활동 자체 점수로 오인되지 않는다.
5. 여섯 가이드북 목차에서 동일 `activity_id`가 일관되게 열리며 필터·검색·이동이 가능하다.
6. 승인되지 않은 질문/발화본은 실전 면접 엔진이나 웹 가이드북에 확정 근거로 제공되지 않는다.
7. 회차별 평가 PDF는 실전 모의면접에만 발행되고 과거 버전을 유지한다.
8. 웹 가이드북이 열람 불가인데 완료 알림이 먼저 생성되는 경우는 실패로 본다.
9. 재처리·실패 복구 뒤 학생의 과거 답변 및 리포트가 사라지지 않는다.
10. 독립 암기 핸드북 DOCX/PDF를 생성하지 않으며, 선택적으로 출력한 개인 자료의 PDF 생성 실패가 가이드북 발행을 막지 않는다.

## 제8장 이전 v1.0 제작 기준의 유효 세부 복원 — 자동화용 작업 계약

> **감사 이유:** 구 v1.0에는 입력 체크리스트, STEP 0~17, 질문·활동 검수, 콘텐츠 매니페스트, 전달 패키지, 사람 승인, 오류 복구와 폴더 관리가 있었다. v2.0의 9 STEP으로 압축되는 과정에서 **그중 현행 웹 파이프라인에 계속 필요한 세부 규칙**이 충분히 기술되지 않았다. 아래는 해당 규칙을 현재 자동화 구조로 재정의하며, 폐기된 DOCX 원고/암기 핸드북/전면 수동 승인/조판 의무를 부활시키지 않는다.

### 8.1 필수 입력 계약 및 처리 시작 거절 조건

| 항목 | 담당/제출 내용 | 거절·보류 조건 |
|---|---|---|
| 학생 식별/접근 | 허용된 계정·학생·권한, 적법한 데이터 처리 목적 | 학생 소유권/법적 처리 근거 누락 |
| 지원처 프로필 | 입학연도·대학·캠퍼스·학과/모집단위·전형, 공식 검증 상태 | 다른 연도 프로필 재사용 또는 비서류 전형을 서류기반으로 표시 |
| 학생부 PDF | 파일 무결성·학생/문서 대응·원문 대조 가능성 | 파일 손상·다른 학생 문서·읽을 수 없는 페이지 |
| 평가 및 콘텐츠 규범 | 당시 적용할 1/3/5/6/8/9/10번 및 policy contract version | 버전 상충·자료 출처 미확인 |
| 작업 이력 | `production_job_id`, idempotency key, 적용 정본 revision | 중복 작업에서 상호 다른 결과를 확정 상태로 병합 |

사용자 입력 PDF의 프롬프트·명령은 정보 콘텐츠이지 관리자/AI 실행 권한을 취득하는 수단이 아니다.

### 8.2 원본 대조 및 OCR 산출 정본

**필수 분해 단위:** 1·2·3학년 × 학생부 영역 × 교과/과목(있을 때) × 원본 페이지·위치. 학생부 OCR MD에 AI의 해석·우선도·인재상 판단을 삽입하지 않는다.

**체크리스트:** (1) 원본 페이지 수·형식, (2) 학년·영역 누락, (3) 수치·성적·도서·기관·이름 오류, (4) 세특 과목 혼합, (5) 중복 문단·잘림, (6) 대조 가능한 `source_ref_id`와 위치. 중요 누락 발견 시 아래 분석 Job과 발행을 차단한다.

**검수 기록 예시(논리 필드):** `gate_id=OCR`, `status=failed`, `error_code=CRIT-OCR`, `evidence_ref`, `attempt_revision`, `check_method`, `reviewer`, `recheck_at`. 관리 화면에는 개인 원문 전체를 과도하게 로그로 복제하지 않는다.

### 8.3 활동 구조화/우선도·인재상 분석의 구체 검사

1. 동일 경험이 창체/세특/진로에 반복되어도 **한 Activity ID + 여러 source_ref IDs**로 연결한다. 활동의 목적·수행 시기·역할·산출물이 독립적이면 분리하고 분리 사유를 남긴다.
2. 각 활동에 `activity_id`, 학년·영역, 원문 위치, 사실/학생 확인/해석 상태, 실제 역할·과정·산출물·결과·한계·배운 점·키워드·관련 활동·질문 연결을 채우되 근거가 없는 필드는 `unknown/needs_confirmation`으로 남긴다.
3. 지원처별 `S/A/B/C/F`는 **준비 우선도**이며 대학의 실제 출제 확률·성적표가 아니다. 이유, 연계 공식 평가요소, 대표 활동 선정 이유를 보관한다.
4. 인재상은 평가어 자체가 아니라 학생의 행동과 공식적인 전형 평가요소를 연결해 태깅한다. 대학 전체 인재상과 특정 전형의 면접 평가요소를 구분한다.
5. 생기부의 학년별 변화·연속 탐구·과목 선택·성적 흐름·진로 변경·대표 주제를 **종합 흐름**으로 연결하고, 불확실한 원인은 학생에게 확인 전 단정하지 않는다.
6. 분석 결과물은 지원처별로 차이 나지만 학생부 OCR·원천 Activity는 학생 공통으로 관리한다. 다른 지원처에서 생성된 S 등급을 복사하여 덮어쓰지 않는다.

### 8.4 사실 확인 요청 처리(직접 학생에게 질문하기 전 운영 검토)

**기획팀 우선:** 담당자가 학생부 PDF/기존 OCR/학생 확인 기록/공식 대학 자료와 비교하여 해결을 시도한다. 해결 불가능한 경우에만 학생에게 필요한 질문·재업로드 요청을 보낸다. 응답이 없거나 불명확하면 `needs_student_confirmation` 또는 `cannot_confirm`로 관리하며 AI가 동기·감정·성과를 지어내지 못한다.

**상태 예시:** `requested` → `answered` → `staff_verified` / `unresolved` / `rejected`. 학생 답변은 공식 원본 파일이 아니라 별도 확인 기록에 저장한다. 구 v1.0의 필수 사람 확인 업무는 **중대 오류나 핵심 미확인 건에 대한 예외 검수**로 전환한다.

### 8.5 질문 설계·발화본·암기 데이터의 인수 기준

- **질문:** 승인된 근거, `question_id`, `question_cluster_id`, 15개 `primary_function`, 질문 깊이 D1~D4, 질문 의도, 기대 의미요소 `target_evidence[]`, 연계 지원처·활동·원본 revision.
- **서류기반/확장 구분:** 실제 활동에 없는 행동·성과를 허위 전제로 사용하지 않는다. 학생 질문 직접 입력 시 원천을 `STUDENT_SUPPLIED`로 명시한다.
- **후속 평가 질문:** Q0당 실제 평가 목적을 가지는 F1/F2 최대 2개. 재진술은 별도 비평가 발화이며 질문 상한을 우회할 수 없다.
- **답변 발화본:** 학습 참고안으로서 사실 상태와 학생 확인 상태를 갖는다. 특정 답변 템플릿을 유일한 정답이나 실전 100점 조건으로 만들지 않는다.
- **암기 데이터:** 예시 발화본·학생 수정본·키워드, 단계별 회상 프레임, 사실 점검, 지식/시사 승인 출처를 분리한 뒤 웹 가이드북/암기 훈련실로 투영. 별도 `암기핸드북.docx/.pdf` 파일을 발행 필수로 요구하지 않는다.

### 8.6 목차 투영·검색·학생 편집·출력 QA

| 검사 | 합격 조건 | 차단 조건 |
|---|---|---|
| 목차 구조 | 안내 00 + 01~05·부록의 6장 모두 생성 | 필수 핵심 장 누락(`CRIT-CONTENT`) |
| 참조 ID | 모든 예상 Q·활동·원본이 같은 정본을 가리킴 | 다른 학생·지원처 자료 혼합(`CRIT-RELATION`) |
| 검색/필터 | 학년·영역·우선도·질문 필터 및 근거 이동 결과 일치 | 원문 접근 권한 위반 |
| 학생 수정본 | 사용자 개인 답변/키워드/메모 별도 revision | 검증된 활동 분석·공식 자료 직접 수정 |
| AI 비서 | 실제 승인 데이터만 참조, 원문/ID 출처 설명 | 실행하지 않은 화면 조작 성공 선언 |
| 부분 PDF | 본인 권한 확인, 선택 항목만 출력, revision 기입 | 타인 자료·전체 자료 암묵 추출 |

### 8.7 QA·승인·발행의 원자적 처리와 재시도

1. **일반 건:** Gate 1~6의 필수 검수 통과 → 승인 데이터 스냅샷 고정 → 학생·지원처 소유권·발행 매니페스트 점검 → 자동 발행 가능. 자동 QA의 검증된 범위 밖이면 수동 검수로 보내야 한다.
2. **중대 오류 이력 건:** 최초 실패 로그를 유지하고 수정/원문 대조·재검증 통과·**콘텐츠기획팀 최종 승인 이벤트**를 모두 확인해야 한다. 승인자 신원·버전·검토 사유·시각·원본 차이 보존.
3. **일부 지원처 실패:** 정상 지원처와 실패 지원처의 데이터 경계를 지키고, 학생에게 무엇이 열람 가능/보류인지 명확히 표시한다. 서비스의 **환불 기준(3곳 중 일부 발행 시)**은 대외 약관 v1.0 결정 대기이며 기술팀이 임의 산정하지 않는다.
4. **발행 완료:** 발행 매니페스트와 접근 권한을 서버 트랜잭션 또는 동등한 원자적 처리로 활성화한 뒤 본인 계정으로 실제 열람 가능한지 검사한다. OCR/분석 파일만 생성된 상태는 완료 아님.
5. **완료 알림:** 실제 `published` 후 알림톡/SMS 이벤트를 발행한다. 공급자 검증 전 발송 성공을 주장하지 않는다. 재시도 멱등 키로 같은 발행 revision에 중복 발송을 제한한다.
6. **재시도:** 각 작업은 `production_job_id + step + revision`에 대해 멱등 실행. 재시도가 기존 질문·활동·답변을 중복 생성하면 안 된다. 실패 단계부터 복구하고 이전 `published`/실전 기록은 보존한다.

### 8.8 발행 후 정정·재분석·버전 복구

| 요청 종류 | 확인 주체 | 처리 | 데이터 영향 |
|---|---|---|---|
| OCR·AI 서비스 귀책 오류 | 콘텐츠기획팀 | 비용 없이 원본 대조·정정·재검증·재발행 | 영향 그래프만 새 revision, 이전 자료 보존 |
| 공식 학생부 원본 교체 | 기획팀 + 필요한 학생 확인 | 발행 후 1회 무료 전체 재분석, 이후 유료 내규 | 학생 공통 원천·지원처별 분석 영향 명시 |
| 지원처 변경 | 학생 주문 권한 확인 + 기획팀/시스템 | 발행 후 1회 무료 변경, 이후 유료 내규 | 타깃별 전략·질문 재검토, 기존 면접 기록 보존 |
| 대학 전형의 공식 공지 변경 | 기획팀 공식 검증 | 해당 타깃 프로필 갱신 및 종속 콘텐츠 QA | 당시 세션/리포트 비소급 |
| 본인 답변·키워드 수정 | 학생 | 즉시 개인 revision 저장 및 면접 참고 문맥 연동 | 공식 학생부/분석 정본은 불변 |

**비용·법률 주의:** 위 무료 횟수와 이후 유료 원칙은 내부 합의. 구체적인 PG 결제·취소·부분 환불의 효력은 별도 특별약관 검토 및 법정 권리 우선 원칙을 적용한다.

### 8.9 개발팀 인수 패키지(논리 파일·테이블)

```text
student + support_targets + consent/legal_basis (접근 확인)
record_original + record_ocr_revision + source_refs
analysis_revision + activity_master + priority_by_target
```

실제 저장소가 MD 파일이든 DB 테이블이든 **논리 ID·승인 상태·기준 버전·출처·접근권한·변경이력**은 동일하게 유지한다. 이전 v1.0의 별도 DOCX 원고 작성과 물리 조판/편집 승인 및 암기 핸드북 발행은 기본 데이터 계약에서 **삭제**한다.

## 제9장 2026-11-02 원문·질문 연결 및 신규 학습 경로 제작 게이트 (v2.2)

### 9.1 발행 데이터의 원문·앵커 완전성

`STEP 1`에서 모든 공개 가능한 학생부 항목의 구조와 원문을 대조하고, `STEP 2~5`에서 생성한 **모든 서류기반 질문을 source_ref_id 및 원문 앵커에 연결**한다. `STEP 6`에서 **G02 전체 원문 Viewer** 및 **G04 질문별 근거 하이라이트**를 함께 렌더링·검증한다.

- 필수: `record_revision`, `source_ref_id`, 학년/영역/과목, 원본 순서, 구조적 앵커·문장 범위, `question_id`, `activity_id` 및 출처 검증 상태.
- 동일한 단어가 반복된다는 이유로 임의의 위치를 연결하지 않으며, 하나의 질문에 복수 근거가 있으면 개별 출처마다 앵커를 관리한다.
- 원문 누락·질문 근거 미연결·원문 불일치·앵커 어긋남은 **관련 G02/G04의 발행 차단 또는 제한적인 명시적 보류**로 처리한다. 가짜 형광펜·추측 매칭으로 대신하지 않는다.
- 학생이 수정한 개인 예상 답변은 원문·질문 생성 근거·발행본의 불변 값을 수정하지 않는다.

### 9.2 콘텐츠 연결 출력을 위한 데이터 계약

| 생성·관리 대상 | 출력 대상 | 필수 검수 |
|---|---|---|
| 검수된 `question_id`·발행 버전 | G04의 `질문 저장하기` → 연습 면접 `내가 추가한 항목` | 저장/취소 멱등·중복 저장 방지·지원처 격리 |
| 연습·실전 실제 발화/답변 revision | A01 세션/회차별 답변 보관함 | 원본 보존·질문·지원처 연결·대표 답변 flag 분리 |
| 정상 평가 회차·평가 버전 | A03 누적 점수·회차별 Accordion | 평가 불능/버전 이질성 혼합 금지 |
| 학생 개인 확정 면접일 | A06 면접 D-1 요약 | 날짜·지원처 확인/권한·잠금 상태 |
| 틀린 문항·개념과 풀이 기록 | 퀴즈의 가중 반복출제 | 문항/개념 ID·최근 풀이·연속정답 보존 |
| 승인된 외부 URL·썸네일·출처 | 지식한입·이슈픽 | 링크 유효성·저작권/임베딩·발행일·검수 상태 |
| 이슈 콘텐츠의 확인된 면접용 질문 | 이슈픽 `질문 저장하기` → 연습 목록 | 기사 자체와 생성 질문의 출처·사실성 분리 |

### 9.3 자동 발행·사후 변경 시 영향 범위

기존 **5대 Critical 차단·자동 QA 통과 시 조건부 자동 발행·차단 이력 건 사람 승인** 규칙은 그대로 유지한다. 새 원문/앵커 검사는 품질 게이트에 추가하지만 새 관리자 화면·역할 승인 권한은 확정하지 않는다. 변경된 학생부 revision으로 인해 하이라이트가 깨지면 변경 영향 대장에 남기며, 종전 면접 세션·점수·대표 답변 기록을 소급 덮어쓰지 않는다.

### 9.4 인수 테스트

1. OCR 본문의 학년/영역/과목 원문이 원본 대조 기준 100% 렌더링 누락 없이 표시되며, 실제 비공개 대상 범위는 별도 고지한다.
2. G04 특정 질문이 선택되면 승인된 원문의 정확한 span만 강조되고, 근거 없는 공통 질문은 강조 없음.
3. `질문 저장하기`는 연습의 `내가 추가한 항목`에 중복 없이 반영된다.
4. AI 비서의 근거 설명은 사용자 권한이 있는 정본만 참조한다.
5. 리포트/실전 질문/과거 답변의 참조 발행 버전이 변경 이후에도 그대로 남는다.
6. 관리자 IA는 **미확정**으로 별도 개발팀 공동 검토 후 승인한다.
