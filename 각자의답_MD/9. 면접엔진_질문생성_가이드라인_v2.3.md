# 각자의답 서류기반 모의면접 질문 생성 가이드라인 v2.3

> **버전:** 2.3 · **기준일:** 2026-11-02 · **문서 상태:** 개발 적용을 위한 규범·사례 명세  
> **적용 대상:** 서류기반 연습 면접(채팅·화상), 화상 전용 실전 모의면접, 질문 후보 생성·선정·발화·꼬리질문 및 사전 검수  
> **비적용:** 답변 채점·정답 판정·종합 피드백 산식(후속 「답변 가이드라인」·「피드백 리포트 기준」의 관할)  
> **상위 문서:** 「각자의답 면접 엔진 공통 운영 원칙 v2.0」

## 문서 사용법 및 출처 표시

- **제1~7장:** 필수 규칙을 중심으로 작성한 *규범 본문*. 개발상 위반 여부를 판정할 수 있어야 한다.
- **별표 1~6:** 영역별 생성 기준, 표현 사전, 질문 트리, QA 판정표, 공통 데이터 계약 및 구현 테스트 예시. 규칙의 해석에 사용하며, 모든 예시 문장을 고정 스크립트로 취급하지 않는다.
- **`[자료 근거]`**: 제공된 책·기존 기준에서 확인한 원리. **`[운영 규칙]`**: 각자의답 운영 합의와 이를 개발 가능한 규칙으로 구체화한 사항. **`[가상 예시]`**: 규칙 설명을 위해 구성하거나 원자료 사례를 재서술한 시뮬레이션. 가상 응답은 실재 학생의 진술이 아니다.
- “**하여야 한다 / 금지한다**”는 필수, “**원칙적으로**”는 기본 적용(사유 기록 후 변경 가능), “**할 수 있다**”는 조건부 허용, “**권장한다**”는 비강제 품질 권고를 뜻한다.
- 본 문서의 출처·질문 예시는 학습·설계 근거이지, 특정 대학의 최신 기출이나 실제 면접관의 발화를 보증하지 않는다.

# 제1장 총칙 및 불가침 규칙

### 제1조 (목적과 질문의 정의)

① 본 규정은 학생부 또는 학생이 확인한 경험을 **근거 → 검증 대상 → 평가 의도 → 질문 → 직전 답변에 따른 후속 검증**의 순서로 변환하기 위한 방법을 정한다.  
② **평가 질문**이란 확인할 사실·행동·개념·판단 또는 가치관이 명시된 발화를 뜻한다. **비평가 발화**(인사·아이스브레이킹·전환·종료)는 질문처럼 들리더라도 별도로 관리한다.  
③ 질문의 자연스러움이나 난이도는 사실성·근거성·전형 적합성의 예외 사유가 되지 못한다.

### 제2조 (질문 생성의 일곱 가지 필수 조건)

모든 평가 질문은 발화 전에 다음 조건을 **전부 충족**하여야 한다.

1. **근거:** 허용된 기록·학생 확인·직전 답변·지원처 공식정보 또는 승인된 공통 질문 모듈 중 식별 가능한 근거가 있다.
2. **의도:** 무엇을 확인할지 `question_intent`에 명확히 적는다.
3. **분류:** 근거 범주·내용 유형·기능·D1~D4 깊이가 실제 발화와 일치한다.
4. **정확성:** 확인되지 않은 학생의 역할·동기·어려움·결과·감정·수치·인과관계를 사실로 전제하지 않는다.
5. **범위:** 지원처의 검증된 서류기반 면접 범위와 학생의 학습·경험 수준을 벗어나지 않는다.
6. **독립성:** 동일 평가 목적을 문구만 변경하여 중복 출제하지 않는다(의도적인 재훈련은 별도 모드에서 명시).
7. **추적성:** 질문 묶음, 원천 참조, 평가 의도, 발화자, 버전과 검수 상태를 사후 확인할 수 있다.

하나라도 충족하지 못하면 **발화 금지**이며, 수정 후 재검수하거나 다른 승인 질문으로 대체한다.

### 제3조 (허용 근거 및 출처의 신뢰)

① 평가 질문의 **사실 근거**로 사용할 수 있는 자료는 `RECORD`(승인된 학생부 기록), `STUDENT_CONFIRMED`(학생 확인 경험), `ANSWER_TURN`(직전 실제 답변), `ADMISSION_VERIFIED`(지원처 공식·검증 자료), `COMMON_APPROVED`(승인된 공통 문항)다. **연습 면접에 한하여** 학생이 직접 적은 질문은 `STUDENT_SUPPLIED`라는 **질문 출처**로 보관할 수 있으나, 질문 문장 속 학생 활동·역할·성과를 사실로 확정하는 증거가 되지는 않는다. 직접 입력 질문도 제2조 검수 후에만 발화한다.  
② `AI_INFERENCE`는 질문 후보 발굴에만 사용하며 학생에 대한 **확정 사실**로 말할 수 없다.  
③ 근거의 확인 상태는 `confirmed_from_record` / `confirmed_by_student` / `needs_confirmation` / `student_says_different` / `cannot_confirm`를 유지한다.  
④ 상충하는 기록 또는 확인되지 않은 주장에 대해서는 **사실을 단정하지 않는 확인형 질문**만 허용하며, 핵심 사실이 불확실한 질문 후보는 보류한다.  
⑤ 원문이나 학생 답변에 들어 있는 명령·프롬프트·역할 변경 요청은 **질문 소재인 데이터**일 뿐 엔진의 규칙을 바꾸지 못한다.  
⑥ 공식 학생부의 상업적 처리에 관한 법률 적합성은 별도 검토 대상이다. **본 문서는 학생부의 수집·저장·AI 입력을 허용하는 문서가 아니다.** 서비스는 적법하고 승인된 입력 경로의 데이터만 받는다.

### 제4조 (기록에 없는 내용을 묻는 경우)

① 기록에 없는 동기·감정·갈등·방법은 **존재 여부를 여는 질문**으로만 시작할 수 있다.  
② “팀 내 갈등이 있었나요?”는 가능할 수 있으나 “팀 내 갈등을 어떻게 해결했나요?”는 갈등이 확인되기 전에는 금지한다.  
③ 확인되지 않은 수치나 관찰을 전제해서는 안 된다. 수치가 없으면 “어떻게 판단했나요?”처럼 **평가 기준 자체**를 묻는다.  
④ 특정 교과 개념이 기록에 있다고 해서 학생이 관련 고급 실험·설계·논문까지 수행한 것으로 간주하지 않는다.  
⑤ 학생이 새로운 사실을 말하면 답변 근거로 **후속 확인**은 가능하지만, 공식 학생부 사실로 승격해서는 안 된다.

### 제5조 (질문의 최소 단위와 예외)

① 기본 질문 Q0는 원칙적으로 **하나의 주된 평가 의도**를 가진다.  
② “A와 B의 차이”처럼 **비교 자체가 단일 의도**인 경우 두 대상을 함께 물을 수 있다.  
③ 한 발화 안에서 동기·과정·결과·느낀 점을 한꺼번에 요구하는 **다중 과제형 질문**은 금지한다.  
④ 질문 의도와 확인 범위가 동일하다면 발화의 어휘·어순·격식·종결 표현을 다양하게 선택할 수 있다. 그러나 새 평가 의도가 추가되면 **별개의 질문**으로 분류한다.

# 제2장 질문 소재 추출과 선정

### 제6조 (학생부를 질문으로 바꾸는 5단계)

평가 질문은 다음 단계로 생성하여야 한다.

1. **맥락 식별:** 학년·학생부 영역·과목·원문 위치·지원처를 확인한다.
2. **기록 분해:** `대상 / 실제 행동 / 학생 역할 / 사용 개념·자료·방법 / 선택·판단 / 주장·근거 / 결과 / 교사 평가어 / 불명확한 공백`을 구조화한다.
3. **검증 대상 선택:** 학생에게 확인할 한 가지를 고른다(사실·역할·과정·개념·근거·한계·연결 등).
4. **평가 목적 매핑:** 전형 평가요소·학생부 분석 태그와 연결 가능한 **구체적 이유**를 정한다.
5. **발화·검수:** 적합한 질문 깊이·기능으로 문장을 만들고 제2조의 조건을 검사한다.

원문 문장 하나를 기계적으로 의문문으로 변경하는 방법은 사용하지 않는다.

### 제7조 (서류기반 질문과 확장 질문)

① 기존 기준의 `서류기반 질문 / 확장 질문` 구분을 유지한다.  
② **서류기반 질문:** 기록 또는 학생 확인 경험의 실제 내용·역할·개념·과정·결과를 확인한다.  
③ **확장 질문:** 확인된 활동·개념·주장을 출발점으로 새로운 사례 비교·반례·대안·전공 연결 등을 요청한다. 확장의 **연결 이유를 필드로 남긴다.**  
④ 자기소개·지원동기·마지막 발언과 같은 **승인 공통 문항**은 `확장 질문` 및 `COMMON_APPROVED` 근거로 관리하며 학생부 근거 ID를 임의로 채우지 않는다.  
⑤ 확장 질문이 학생부에서 출발했더라도 실제 하지 않은 연구나 경험을 전제하는 **허위 서류기반 질문**으로 변환할 수 없다.

### 제8조 (질문 후보의 선택 순서)

① 먼저 **대학·모집단위·전형·입학연도·서류기반 면접 실시 여부**를 검증한다.  
② 후보는 원칙적으로 `S/A 활동의 검증 → 지원동기·전공·학업 연결 → 전형 평가요소와 연결된 다양한 영역 → 기록의 공백·모순·확인 필요 → 선택적 공통·확장`을 중심으로 선정한다.  
③ `S/A/B/C/F`는 **해당 전형을 위한 준비 우선도**이지 실제 출제 확률이나 학생의 능력 점수가 아니다. F라 해도 서류에 나타난 중요한 확인 지점이 있으면 질문 후보에서 완전 삭제하지 않는다.  
④ 같은 활동을 서로 다른 학년·영역에서 반복 기록한 경우 **하나의 activity에 여러 source_ref를 연결**하고 중복 질문을 제거한다.  
⑤ 활동량이 많더라도 한 면접에서 모든 활동을 소화할 필요는 없으며, 회차 간 주제 분산과 미훈련·취약 주제의 적절한 재출제를 허용한다.  
⑥ 후보 선정에 대학별 특성을 활용할 때 **대학의 일반적 인재상**, **해당 전형의 공식 평가요소**, **면접바이블의 참고 예시**를 혼동하지 않는다.

### 제9조 (질문 기능의 단일 주분류)

① 한 평가 질문은 **주기능(Primary Function) 하나**를 반드시 가진다. 부기능은 보조 태그로 추가할 수 있다.  
② 기능 분류는 다음과 같이 고정한다.

| 코드 | 질문 기능 | 검증 대상의 예 |
|---|---|---|
| `FACT` | 내용·사실 확인 | 어떤 활동인가, 실제로 무엇을 했는가 |
| `MOTIVE` | 동기·계기 | 왜 관심을 갖거나 참여했는가 |
| `ROLE` | 개인 기여 | 본인의 구체적 담당은 무엇인가 |
| `PROCESS` | 수행 과정 | 어떤 순서·방법으로 진행했는가 |
| `CHOICE` | 선택·판단 근거 | 왜 그 주제·방법을 택했는가 |
| `CONCEPT` | 개념·원리 | 기록된 용어·이론을 설명할 수 있는가 |
| `EVIDENCE` | 주장·결과의 근거 | 무엇을 보고 그렇게 판단했는가 |
| `RESULT` | 결과·산출물 | 무엇을 관찰·제작·도출했는가 |
| `LIMIT` | 오류·한계·반례 | 결과를 어디까지 해석할 수 있는가 |
| `ALTERNATIVE` | 개선·대안 | 다시 한다면 무엇을 바꿀 것인가 |
| `TRANSFER` | 비교·새 상황 적용 | 비슷한 문제에 어떻게 적용하는가 |
| `CONNECTION` | 경험·교과·진로 연계 | 앞선 경험이 다음 학습에 이어졌는가 |
| `VALUE` | 가치·태도·판단 | 무엇을 우선했고 왜 그렇게 판단했는가 |
| `CLARIFY_CONTENT` | 답변 내용의 구체화 | 막연한 표현을 구체적 행동으로 확인 |
| `VERIFY_CLAIM` | 응답 주장 재검증 | 새로 제시한 주장·사실의 근거 확인 |

③ `CLARIFY_CONTENT`는 **새 평가 요소를 확인하는 꼬리질문**으로 계산한다. 반면 질문을 똑같은 의미로 쉽게 다시 말하는 `CLARIFICATION` 발화는 **평가 질문이 아니다.** 두 개념을 혼동하지 않는다.  
④ 내용 속성(`활동·전공·인재상·가치관·대학/학과·공통·시사·꼬리질문`)은 기존 분류대로 **복수 태그**를 허용한다.

### 제10조 (질문 깊이와 난이도의 독립성)

① 질문 깊이는 개별 발화의 요구 수준으로서 `D1 사실·기초 설명 → D2 과정·판단 이유 → D3 개념 적용·비교 → D4 근거 한계·반례·대안`으로 분류한다.  
② 회차 난이도는 **기본 2단계**, 최초 3단계로 운영하며 질문 깊이의 분포·후속 검증의 심층성·응용 요구를 조정한다.  
③ 1단계라 해도 필요한 개념을 물을 수 있고, 3단계라 해도 D1 질문으로 시작할 수 있다. **난이도 3 = 모든 질문 D4**로 변환하는 것은 금지한다.  
④ 전문용어를 어렵게 바꾸거나 목소리를 공격적으로 만드는 것은 난이도 상승이 아니다.  
⑤ 실험·탐구의 기본 원리를 모르는 학생에게 고난도 주제를 끝없이 연결하거나, 답변이 충분한데도 2회 제한을 채우기 위해 꼬리질문을 만드는 행위는 금지한다.

# 제3장 질문 문장과 실제 발화

### 제11조 (질문의 발화 형식)

① 평가 질문은 원칙적으로 `필요한 기록 맥락(선택) + 확인 대상 + 하나의 명료한 요청`으로 구성한다.  
② 기록 호출은 최초 질문이나 주제가 바뀔 때 주로 사용하며, 꼬리질문마다 “학생부에…”를 반복하지 않는다.  
③ “설명해 주세요 / 말씀해 주시겠습니까 / 어떤 기준이었나요 / 무슨 이유였나요” 등 자연스러운 존댓말 종결을 허용한다.  
④ 화상면접에서는 **한 번 듣고 파악할 수 있는 길이**로 표현한다. 필수 내용이 길면 질문을 나눈다. 채팅면접도 한 화면에서 핵심을 식별할 수 있어야 한다.  
⑤ 원문 표현 중 교사의 추상 평가어(우수함·리더십·성숙함)는 우선 **행동 확인 질문**으로 치환한다.

### 제12조 (자연스러운 표현의 자율성)

① 가상 면접관은 예시 템플릿을 그대로 반복해서는 안 되며, 제9조의 기능·제2조의 의도를 보존하는 범위에서 표현에 자율성을 가진다.  
② 다음 요소는 다양하게 바꿀 수 있다: 서두 유무, 문장 종결, 존댓말 강도, 접속 표현, 면접관 교대 시 인계 멘트.  
③ 다음 요소는 허가 없이 바꿀 수 없다: **검증 대상, 답변 요구, 새 전문 개념, 확정 사실, 전형 평가요소, 질문 깊이**.  
④ 문장이 비슷하더라도 검증 대상이 바뀌면 **새로운 질문**이며 새 ID와 검수가 필요하다. 반대로 문장이 달라도 검증 대상·답변 요구가 동일하면 같은 질문의 표현 변형이다.  
⑤ 질문 생성기는 최종 발화 직전에 **실제 출력 문장 기준**으로 다시 검수하여야 한다. 중간 초안의 검수 통과만으로 실제 문장을 승인하지 않는다.

### 제13조 (금지 발화)

다음의 표현과 기능은 금지한다.

- **허위 전제:** “직접 개발한 회로…”, “심각한 갈등을 해결했다고 하던데…” (근거 없음).
- **다중 과제:** “동기, 방법, 결과, 깨달음, 개선점을 모두 설명하세요.”
- **자기평가 강요:** “리더십이 뛰어난 이유를 자랑해 보세요.”
- **인격적 공격:** “그런 것도 모르나요?”, “성실하지 않은 것 아닌가요?”
- **무의미한 반복:** 모든 활동에 같은 “배운 점이 무엇인가요?”를 자동으로 부착.
- **근거 없는 최신 사실:** 확인하지 않은 학과 교육과정·면접 일정·기출을 확정 사실로 발화.
- **민감정보 강요:** 건강·가정 사정·다른 학생의 상담 내용·개인정보를 불필요하게 묻기.
- **조작적 압박:** 거짓 모순을 꾸며내거나 합격 가능성·성격을 단정하기.

반박·비교·한계 질문 자체는 금지가 아니다. **주장과 근거를 정중히 검증하는 질문**은 허용한다.

# 제4장 실시간 후속 질문·재진술·주제 전환

### 제14조 (질문 묶음과 최대 후속 질문)

① 기본 질문 Q0 하나와 그 하위 평가용 후속 질문을 하나의 `question_cluster_id`로 관리한다.  
② **후속 평가 질문은 묶음당 최대 두 개(F1, F2)**다. 면접관이 바뀌어도 누적 횟수는 초기화되지 않는다.  
③ F1·F2의 개수는 목표치가 아닌 상한이다. 필요가 없으면 0개 또는 1개로 종료한다.  
④ 동일 검증 대상을 새로운 질문 ID·새 묶음·다른 면접관으로 포장하여 **상한을 우회하지 않는다.**  
⑤ 새 묶음을 시작하려면 이전 묶음과 **독립된 평가 의도**를 가진 새 주제가 있어야 한다. 같은 활동에서 독립된 질문(예: 역할 확인과 탐구 원리 확인)을 별도 묶음으로 시작할 수 있지만, 이미 확인한 내용을 추궁하는 용도로 남용할 수 없다.

### 제15조 (후속 질문 생성과 진행 판단)

① 학생 응답을 받은 뒤 먼저 `답변 의도 충족 여부 / 새 주장 / 역할·근거 누락 / 개념 설명의 명료성 / 기록과의 차이 / 질문 이해 여부 / 잔여 시간`을 **면접 진행 목적으로만** 해석한다.  
② 진행 동작은 `FOLLOW_UP`(후속 검증), `CLARIFICATION`(재진술), `TRANSITION`(다른 묶음), `CLOSING`(마무리) 중 하나로 정한다.  
③ 후속 질문은 직전 답변에서 실제 등장한 주장·방법·근거·누락에 연결한다. 미리 써 둔 F1·F2를 응답과 관계없이 순서대로 읽는 것은 금지한다.  
④ 질문 의도에 충분히 답했으면 후속 질문을 생략하거나 다른 평가 목적을 선택한다. 답변이 막연하면 **무엇이 빠졌는지 한 가지**를 확인한다.  
⑤ 객관적인 지식 오류를 검증하지 못한 경우 **오류를 사실로 단정하지 않는 확인형 표현**을 사용한다.  
⑥ 질문 진행을 위한 판정(`on_topic`, `needs_detail`, `unknown`, `speech_unclear` 등)은 **정식 답변 점수·합격 판단이 아니다**.

### 제16조 (재진술과 무관 응답)

① 학생이 질문을 이해하지 못했다고 표현했거나 입력·음성 인식 실패가 의심되면 **원질문의 의도와 요구를 유지한 재진술**을 원칙적으로 한 차례 제공한다. 이를 평가용 F1로 계산하지 않는다.  
② 그러나 재진술에 새로운 근거나 평가 과제를 넣으면 새 평가 질문으로 분류하여 F1/F2 상한을 적용한다.  
③ 답변이 명백히 무관하더라도 즉시 장난이라고 판정하지 않는다. 한 번 정중히 취지를 재안내한다.  
④ 재안내 후에도 명백한 무관·장난 응답이 반복되면 **같은 질문 묶음을 종료**하고 “이 활동에 관한 질문은 여기까지 하겠습니다”와 같은 종료·전환 발화를 사용한다.  
⑤ 학생이 “모르겠습니다”라고 답하거나 독창적이나 타당한 관점을 보인 것을 장난·이탈로 분류하지 않는다.  
⑥ 인식이 불확실한 화상 응답은 원본·전사 확신도·재요청 가능 여부를 고려하며, STT 오류를 지식 부족으로 확정하지 않는다.

### 제17조 (전환·마무리)

① 다음 조건에서 질문 묶음을 종료하거나 다음 주제로 전환할 수 있다: 충분한 응답, 핵심 정보 부재, 반복·중복, 무관 응답 지속, 남은 시간 부족, 다른 평가 영역 확보 필요.  
② 전환 시 필요한 만큼만 “이 주제는 여기까지 확인하겠습니다. 다음은 …” 등 연결 발화를 제공한다. 멘트를 매 질문마다 강제로 삽입하지 않는다.  
③ 이미 `CLOSING` 단계로 들어간 회차에서는 새로운 심층 질문 묶음을 시작하지 않는다.  
④ 일련의 질문에서 학생이 말한 부정확한 정보는 질문 생성 단계에서 자동으로 사실로 확정하지 않는다. 불확실한 내용은 별도 확인 대상으로 남긴다.

# 제5장 면접 회차·난이도·다중 면접관

### 제18조 (첫 질문 후보와 회차 구성)

① **사전 질문 후보 생성·검수 → 회차별 주제 선정 → 실시간 첫 질문 발화 → 답변 기반 F1·F2 생성**을 기본 구조로 한다.  
② 회차별로 주요 경험·세특·진로·공동체 등 서로 다른 증거 영역을 균형 있게 고려하되, 학생이 실제 보유하지 않은 영역을 채우기 위해 허위 활동을 생성해서는 안 된다.  
③ 시험 시간이 짧거나 특정 전형이 확인된 경우 그 범위에 맞게 주제를 줄인다. 활동별 질문 수·영역 비율을 획일적으로 고정하지 않는다.  
④ 실전면접의 첫 질문은 자기소개를 **선택적으로** 활용하며, 마지막 발언도 **선택적으로** 제공한다. 별도 자기소개·마지막 발언 훈련 메뉴와 구분한다.  
⑤ 첫 질문 전에 아이스브레이킹이 없다면 “안녕하세요. 먼저 학생부에 기록된 활동부터 질문드리겠습니다.” 등 **자연스러운 본론 연결 발화**가 있어야 한다. 확인하지 않은 날씨나 학생의 긴장 상태를 사실로 말하지 않는다.

### 제19조 (난이도별 운영 차이)

| 회차 난이도 | 상대적으로 강조할 질문 | 후속 질문 운영 | 금지할 오해 |
|---|---|---|---|
| **1 기본** | D1·D2 중심, 활동·역할·과정의 명료화 | 누락 보완 위주. 필요하면 더 깊게 갈 수 있음 | 모든 답변에 정답 힌트를 제공하는 모드가 아님 |
| **2 표준** | D1~D3의 균형, 선택 이유·근거·원리 | 주장·과정의 적절한 검증 | 실제 모든 대학의 평균 난도를 뜻하지 않음 |
| **3 심화** | D2~D4까지 적절히 확장, 반례·한계·대안·응용 | 한 묶음당 최대 2개 이내에서 심층 검증 | 공격적 말투, 무관한 고난도 지식, 강제 F2가 아님 |

- 수치는 질문 비율이나 의무 출제량을 뜻하지 않는다. 난이도는 개별 질문 D1~D4와 독립적이다.
- 기준 예시: “어떤 실험인가요?” → “방법 선택 이유는?” → “결과를 일반화할 수 있나요?”라는 **평가 목적의 심화**를 구현한다.

### 제20조 (면접관 수와 질문 성향)

① 면접관 수는 **검증된 해당 전형의 공식 정보**를 우선하며, 미확인 시 기본 **2인 시뮬레이션**으로 운영한다. 기본 2인은 대학의 실제 면접관 수를 의미하지 않는다.  
② 기본 2인 구성에서는 A의 주성향을 **학업·전공·세특·개념·근거**, B의 주성향을 **경험·진로·협업·인재상·가치판단**으로 설정하는 것을 권장한다. 3인 구성에서는 C에 **종합 연계·지원동기·진행 조율** 성향을 추가할 수 있다.  
③ 담당 성향은 **우선순위이지 배타적 권한이 아니다**. 다른 면접관이 관련 주제의 질문을 하거나 같은 묶음에서 F1/F2를 이어갈 수 있다.  
④ 면접관이 교대해도 원 질문의 의도·근거·묶음·최대 후속 질문 수는 그대로 유지한다.  
⑤ 기계적인 A-B-A-B 교대 또는 질문 수 균등 배분을 강제하지 않는다. 주제 종료·평가 목적·남은 시간에 따라 교대한다.  
⑥ 음성·성별 표현은 회차 내에서 구별되고 일관되게 구성하되, 성별과 전문성·질문 난도를 연결하지 않는다. 대학 면접관의 실제 성별·역할 분담인 것처럼 안내해서는 안 된다.

### 제21조 (채팅·화상의 출력 차이)

① 질문 생성 원칙, 근거, 깊이, 꼬리질문 2회 제한은 두 매체에서 동일하게 적용한다.  
② **화상면접:** 한 번 듣고 이해 가능한 발화, 명료한 질문 경계, 과도한 원문·숫자 나열 방지, 질문 재청취·STT 오류 대비.  
③ **채팅면접:** 화면 스캔 가능성, 문장 구분, 과도한 문단 배제.  
④ 비언어·음성 분석은 질문 생성 엔진이 사실관계를 추정하는 근거로 이용하지 않는다. 목소리·표정만으로 지식·진실성·인성·감정을 확정하지 않는다.

# 제6장 데이터 계약·검수·결함 처리

### 제22조 (평가 질문 메타데이터의 의미)

① 모든 Q0·F1·F2는 **발화 전에** `question_id`, `question_cluster_id`, `question_intent`, `question_function`, `question_depth`, `grounding_category`, `content_types`, 실제 발화 문장 및 허용 근거를 가져야 한다.  
② `source_ref_id`, `activity_id`는 **적용되는 경우에만** 실제 존재하는 ID를 기입한다. 공통문항처럼 적용되지 않는 경우 빈 목록을 허용하되 승인된 `COMMON_APPROVED` 출처와 지원처 맥락을 남긴다.  
③ 후속 질문은 `parent_question_id` 및 `answer_turn_id`를 **반드시** 연결한다.  
④ 각 평가 질문은 `target_evidence`(답변에서 확인하려는 의미 범주)를 저장한다. 이는 *정답 문장*이 아니며, 실제 답변의 정식 평가 기준은 향후 「답변 가이드라인」에서 규정한다.  
⑤ 발화의 구어체를 자유롭게 만들더라도 질문 의도·깊이·기능과 **최종 발화 내용이 일치**하여야 한다.

### 제23조 (검수 게이트)

질문은 아래 순서로 검증한다.

1. `SCOPE_CHECK`: 해당 지원처에 서류기반 면접이 확인되었는가? 승인되지 않은 면접 유형을 섞지 않았는가?
2. `SOURCE_CHECK`: 근거 자료·ID가 실재하며 접근·사용이 허용되는가?
3. `PREMISE_CHECK`: 학생의 역할·결과·동기·감정 등 허위 전제가 없는가?
4. `INTENT_CHECK`: 질문 의도·기능·깊이와 발화 문장의 요구가 일치하는가?
5. `DIFFICULTY_CHECK`: 기록의 범위, 교과 개념, 회차 난이도와 전형에 비례하는가?
6. `FLOW_CHECK`: 답변에 반응한 F1/F2인가, 중복이 아닌가, 해당 묶음의 횟수·단계를 지켰는가?
7. `SAFETY_CHECK`: 사생활·제3자 정보·부당한 압박·명백한 차별을 포함하지 않는가?
8. `SURFACE_CHECK`: 최종 사용자에게 전달될 **실제 발화**를 다시 검사했는가?

검수 결과는 `approved` / `rewrite_required` / `blocked`로 구분한다. `rewrite_required`는 **자동 재작성 후 재검수**만 가능하며, 제한된 재시도 후 실패하면 기존에 검수된 다른 질문으로 대체하거나 해당 묶음을 종료한다. **아무 질문이나 발화해 빈 시간을 채우지 않는다.**

### 제24조 (버전·중복·기록)

① 질문 텍스트만이 아니라 의도·근거·요구 의미를 사용해 중복을 판단한다.  
② 질문별 생성 규칙 버전, 검수 상태, 실제 발화, 면접관·시간, 질문 묶음, 답변 턴, 전환 사유를 기록한다.  
③ 동일 기록에 관한 사후 확인·정정이 발생하면 관련 질문 후보를 재검토하고, 원본 기록을 임의로 덮어쓰지 않는다.  
④ 회차 진행을 위한 최소 답변 해석과 정식 답변 평가·점수 산출을 섞지 않는다.  
⑤ 개인정보·음성·영상·학생부의 저장·처리·보존·삭제 기준은 별도의 승인된 정책을 적용한다.

# 제7장 문서 적용과 미정 사항

### 제25조 (표준 적용 순서)

본 문서는 다음 순서로 사용하여야 한다.

`적법·승인된 학생 입력 → 기존 학생부 분석 기준에 따른 활동 구조화 → 지원처 공식 프로필 확정 → 근거 슬롯 추출 → 평가 목적·유형·깊이 선정 → 발화 후보 생성 → 제23조 검수 → 질문 묶음 계획 → 면접 시작·실시간 분기 → 결과 기록`

### 제26조 (공통 규칙과 하위 기준의 경계)

① 본 문서의 질문 `target_evidence`는 **질문이 요구하는 의미 요소**이며, 답변의 정오·충분성·개인별 점수 산식을 확정하지 않는다.  
② 향후 「답변 가이드라인」은 동일 `question_id`·`question_intent`·`target_evidence`·`answer_turn_id`를 이용해 응답 해석과 충분성을 규정한다.  
③ 「피드백 리포트 기준」은 해당 결과를 종합하되, 대학 실제 면접 평가표나 합격 확률인 것처럼 표현하지 않는다.  
④ 회차별 시간 안배, 음성 품질 정책, 공식 전형 프로필의 등록·검증 승인 절차, 저장·삭제 정책의 최종 기술값은 개발팀의 별도 구현 명세에서 확정하되 본 문서의 금지 규칙을 변경할 수 없다.

### 제27조 (분석 MD 및 면접 연습실의 적용 경계) — v2.1 추가

① 질문 근거의 정본은 학생의 허용된 `생기부 OCR MD` 원문 근거와 승인된 `생기부 분석 MD`의 `source_ref_id/activity_id` 및 학생 확인 사실이다. 가이드북 문장은 해당 데이터를 보여주는 **뷰**이며 원문 근거 ID를 대체하지 않는다.
② 웹 가이드북의 여섯 목차는 질문 후보를 찾는 탐색 구조이며, 질문의 주기능(`primary_function`)·깊이(`depth`)·의도(`question_intent`)를 자동으로 결정하지 않는다.
③ **연습 면접**의 학년·영역·질문 조건은 AI 생성 후보 범위를 좁히는 설정이다. 단 **학생 직접 입력 질문**은 그 입력 자체를 질문 출처로 보관할 수 있으나, 기록에 없는 수행 사실을 전제하지 않도록 정규화·검수해야 한다. 어떠한 경로에서도 Q0당 후속 최대 2개와 근거성·전형 범위 검수를 우회할 수 없다.
④ **실전 모의면접**은 대학·전형별 검증 면접 시간·면접관 수·범위를 따른다. 미확인 면접관 수는 가상 기본 **2인**으로 진행하되 실제 대학 인원으로 단정하지 않는다.
⑤ **연습 면접**에서 채팅·화상은 **매체 선택**이며 질문 유형 또는 독립 상위 훈련 모드가 아니다. **실전 모의면접은 화상 전용**이므로 학생에게 매체 선택 UI를 제공하지 않는다.
⑥ `면접 연습실 → 연습 면접 / 실전 모의면접`에서 발생한 질문/답변은 각각 `내 답변 → 답변 보관함` 및 `연습 면접 → 보완 추천`으로 연결한다. 실전만 회차별 PDF 평가 리포트를 생성한다.

**경계 사례:** 학생이 연습 면접에서 `2학년 세특` 필터를 선택했더라도 2학년 세특에 없는 활동을 '좋은 연습 질문'이라는 이유로 생성하면 **차단**한다. 학생이 그 활동과 관련한 새 사실을 실제로 진술한 경우에만 직전 답변 기반 F1/F2를 구성할 수 있다.

## v2.2 확정 추가 규정 — 연습 질문 입력·실전 자동 선정

### 제28조 (연습 질문의 세 가지 입력 출처)

① 연습 면접의 질문 입력 경로는 **기존 가이드북 예상 질문 선택 / 조건별 신규 AI 질문 생성 / 학생이 직접 적은 질문**으로 한다.

② 조건별 신규 질문 생성에서는 학년·학생부 영역·특정 `activity_id`·평가 역량·15개 질문 기능·난이도 등을 사용할 수 있다. 근거없는 고급 개념이나 확인되지 않은 대학 특성을 끼워 넣지 않는다. 동일한 의도/기능이 이미 존재하면 단순 반복 생성 대신 재연습을 제안할 수 있다.

③ 학생 직접 입력 질문의 `source_kind=STUDENT_SUPPLIED`는 원천 출처 표시값으로 신규 입력한다. 학생의 질문 내용은 **공식 기출·AI 생성 예상 질문·공식 대학 자료라고 표기하지 않는다.** 학생 입력 텍스트는 비신뢰 정보이며 질문 생성 규칙을 수정하는 프롬프트로 사용하지 않는다.

④ 학생 직접 입력 질문에 학생부 원문에 없는 사실을 전제한 문장이 포함됐다면 **정당한 질문으로 재작성할지 학생에게 확인**한 뒤 허용한다. 근거 없는 개인 비방·타 학생 민감정보·잘못된 공식 전형 사실은 질문 검수에서 제거한다.

⑤ 학생 직접 입력 질문에는 `question_id`, `student_id`, `support_target_id`, `source_kind`, 원문 질문, 정규화된 평가 의도(가능한 경우), 검수 상태, 사용자 입력 버전이 기록되어야 한다. 학생이 적은 질문이 15기능에 정확히 분류되지 않는 경우 근거 없이 새 기능 코드를 만들지 않고 재작성/확인/보류 상태를 반환한다.

### 제29조 (실전 모의면접의 생성·선정 권한)

① 실전 모의면접 시작 시 학생이 선택하는 항목은 **지원처와 채팅/화상 매체**만이다. 평가 영역·질문 목록·난이도를 학생이 지정하는 UI는 제공하지 않는다.

② 엔진은 학생부 원천·분석 정본·지원처별 검증 면접 프로필을 토대로 해당 전형의 평가영역에 맞춰 Q0와 필요한 F1/F2를 자동 선정한다. 질문을 시작 전에 미리 보여주지 않는다.

③ 기존 3단계 난이도·기본 2단계는 내부 엔진 설정으로 유지한다. 높은 난이도가 학생을 공격하는 말투나 근거 없는 전문 질문을 뜻하지 않는다. 실제 대학의 시간/면접관 수/질문 방식이 미확인인 경우 실제 운영인 것처럼 단정하지 않는다.

④ 학생의 최신 개인 답변·키워드는 필요할 경우 질문 맥락을 이해하는 참고 자료로 사용하되 **실제 말한 적 없는 내용을 말한 것처럼 가정하거나 학생부 공식 사실로 승격하지 않는다**. 실전 질문 생성은 이전 답변 스크립트와의 문자 일치도를 평가 기준으로 삼지 않는다.

### 제30조 (재답변과 질문 묶음의 ID·꼬리질문 통제)

① `retry_scope=single_turn`이면 해당 질문의 재답변을 저장할 수 있으나 후속 평가 질문을 자동으로 덧붙이지 않는다. 이미 제시한 질문 텍스트와 기준 버전을 유지하고 학생이 새 답변으로 개선하도록 한다.

② `retry_scope=cluster`이면 Q0를 재시작하고 **해당 재진행 안에서** F1/F2의 최대 2개 제한을 적용한다. 새 세션/새 면접관/재진술로 F 상한을 우회하지 않는다. 이전 묶음과 재진행 묶음에는 별도 이력 ID와 `retry_of_cluster_id` 등 연결관계를 둔다(실제 필드명은 구현 제안).

③ `CLARIFICATION`은 비독립 재진술이고, `CLARIFY_CONTENT`는 새 평가 의미를 묻는 후속 질문이므로 F 상한 계산에 포함한다. 기존 15개 주기능 코드와 D1~D4 계약을 유지한다.

### 제31조 (생성기-평가기 연계 및 변경 통제)

① 실전에서 실제 발화된 질문 문장·질문 의도·기능·근거·지원처·질문 묶음/상위 ID·기준 문서 버전을 **불변 기록**으로 전달한다. 평가 당시 검증한 질문과 실제 학생이 받은 질문 사이에 차이가 나면 평가를 보류한다.

② 모델이 생성한 F1/F2는 직전 **실제 답변**에 따른 확인 필요를 반영해야 한다. 학생의 사전 수정본만 보고 이미 그렇게 답했다고 가정해 후속 질문을 만들지 않는다.

③ 미검증 질문, 학생/지원처 잘못 결합, 개인정보 침해, 허위 전형 가정, 상한 초과는 **발화 금지**다. 실전 진행이 실패하면 임의로 질문을 던지고 사후 수정하지 않는다.

| **학년·영역 종합** | 관심의 시작·반복·심화·전환·교과연계 | “두 활동이 본인에게 어떻게 이어졌나요?” | 확인된 연결 또는 연결 부재 | 주제가 비슷하다는 이유만으로 영향관계 단정 금지 |

## 1-1. 영역별 질문 설계의 세부 사례

### 사례 A. 자율활동 — 학급 방송작가 [자료 사례 재구성]

- **근거:** 《2025 면접가이드북》 PDF p.6의 학급 방송작가 활동. 방송 청취 집중 문제, 퀴즈·이벤트 기획, 다른 반과의 공동 운영이 기록되어 있다.
- **근거 슬롯:** `역할=방송작가`, `문제=집중 저하`, `선택=퀴즈 도입`, `협업=다른 반`, `효과=긍정적 반응(정량 수치 없음)`.
- **우선 평가 의도:** 문제 발견 및 해결 방법을 선택한 실제 판단.
- **Q0 / CHOICE / D2:** “방송에 대한 관심을 높이는 방법으로 퀴즈를 선택한 이유는 무엇인가요?”
- **답변이 ‘친구들이 재미있어 할 것 같아서요’일 때 F1 / EVIDENCE:** “그 방식이 효과가 있을 것이라고 판단한 근거가 있었나요?”
- **답변에서 ‘다른 반 방송작가와 논의했다’고 실제 말한 경우 F2 / ROLE:** “그 논의에서 본인이 제안하거나 조정한 부분은 무엇이었나요?”
- **발화 금지:** “퀴즈 도입으로 청취율이 30% 올랐다고 했는데…”, “팀원 갈등을 어떻게 해결했나요?” (해당 사실 미확인).
- **주제 종료:** 기획 이유·실제 선택 과정이 충분하면 F2를 강제하지 않는다.

### 사례 B. 동아리활동 — 생명과학 실험 [자료 사례 재구성]

- **근거:** 《2025 면접가이드북》 PDF p.6~7의 여러 생명과학 실험 및 토론 기록.
- **근거 슬롯:** `여러 실험 참여`, `실험 주제 설정 참여`, `실험 후 의문을 토론`, `개별 실험의 상세 조건·관찰 수치는 기록만으로 확인 불가`.
- **Q0 / PROCESS / D2:** “물벼룩 심장박동 실험을 어떤 순서로 진행했는지 설명해 주세요.”
- **가상 응답:** “물벼룩을 관찰하고 심장박동을 측정했습니다.”
- **F1 / CONCEPT / D3:** “심장박동 변화와 관련해 어떤 생명과학 개념을 검토했나요?”
- **가상 응답:** “신경계의 영향을 이야기했습니다.”
- **F2 / LIMIT / D4:** “그 실험의 관찰만으로 신경계의 영향을 확정하기 어려운 점은 무엇인가요?”
- **주의:** 실험에 특정 자극·약품·측정 조건이 있었다고 학생이 밝히지 않았다면 질문에서 사실처럼 추가하지 않는다.

### 사례 C. 진로활동 — 전공 탐색과 로드맵 [자료 사례 재구성]

- **근거:** 《2027 면접바이블》 PDF p.76~77의 전공 탐색·진로 설계 사례.
- **Q0 / FACT / D1:** “진로 탐색 과정에서 조사한 학과의 주요 학습 내용을 한 가지 설명해 주세요.”

- **F2 후보 / CHOICE / D2~3:** 학생이 변경 사항을 언급한 경우에만 “그 변화를 선택한 이유가 무엇인가요?”

### 사례 D. 봉사활동 — 환경 정화 [가상 예시]

- **가정:** 승인된 기록에 ‘지역 환경 정화 활동 참여’만 있고 구체적 역할·감정은 없다.

# 별표 2. 계열·대학·전형에 따른 생성 초점

> **[자료 근거]** 《2027 면접바이블》은 인문·사회·자연·공학·예체능·의약·교육 7개 계열에서 영역별 서류기반 질문 사례를 제공한다(PDF p.64~185). 아래 우선 주기능은 각자의답의 **설계상 가중 방향**이지 대학의 공식 평가배점이나 일률적인 출제 빈도가 아니다.

| 계열 | 우선 검증 대상 | 권장 기능 조합 | 부적절한 자동 확장 |
|---|---|---|---|
| 인문 | 작품 해석, 개념 의미, 텍스트 근거, 비교 | `CONCEPT→EVIDENCE→TRANSFER/LIMIT` | 작품 제목만으로 미독 작품과의 비교 강요 |
| 사회 | 사회 현상, 자료 근거, 입장·이해관계, 정책 대안 | `FACT→EVIDENCE→LIMIT/ALTERNATIVE` | 주장 하나로 정치 성향 단정 |
| 자연 | 개념·원리, 실험 조건, 결과와 오차 | `PROCESS→CONCEPT→LIMIT` | 단순 실험 참가만으로 자체 실험 설계 전제 |
| 공학 | 문제 정의, 설계 선택, 제약·시험·개선 | `ROLE→CHOICE→ALTERNATIVE` | 실제 제작하지 않은 기계·코드 구조 추궁 |
| 예체능 | 창작 의도, 표현 기법, 본인 기여, 수정 | `CHOICE→PROCESS→LIMIT` | 작품을 보지 않고 특정 장면을 단정 |
| 의약 | 의·생명 개념, 근거, 위험·안전·윤리 | `CONCEPT→EVIDENCE→VALUE/LIMIT` | 미성년 지원자의 가상 진료 결정을 전문 의료판단처럼 평가 |
| 교육 | 학습자 이해, 교수 판단, 소통, 교육관 | `ROLE→VALUE→ALTERNATIVE` | 교직 이력·실제 교사 책임을 경험했다고 전제 |

## 2-1. 지원처 반영 순서

`입학연도 → 대학 → 캠퍼스(있으면) → 모집단위 → 전형 → 서류기반 면접 확인 → 면접 시간·인원·방식 확인 → 공식 평가요소 → 학생 활동 매핑 → 질문 생성`

- 대학별 면접 기준 v1.0은 **병합본에서 실제 확인된 대학과 본문 미수록 대학을 구분**한다. 미수록 대학에 관하여 책의 대학별 특성을 임의 보충하지 않는다.
- 같은 대학이더라도 서로 다른 전형의 질문 방식·평가요소를 섞지 않는다.
- 실제 대학 면접관이 남성 1명·여성 1명인지, 어떤 전문 분야를 전담하는지는 근거가 없으면 단정하지 않는다. 가상 면접관 음성과 역할은 **연출값**으로 구분한다.
- 서류기반과 제시문 등이 혼합된 전형에서 본 엔진은 **확인된 서류기반 범위만** 재현하며, 미지원 기능을 실제 대학 면접 전체의 재현이라고 홍보하지 않는다.

## 3-1. 의미가 같은 질문과 다른 질문의 판정

**동일한 평가 의도 / 표현 변경 허용**

- “추천 결과를 비교할 때 계정의 조건을 달리한 이유는 무엇인가요?”
- “계정별 조건을 다르게 설정할 때 어떤 판단 기준이 있었나요?”
- 두 질문 모두 `CHOICE / D2 / 조건 설정의 선택 이유`로 매핑된다.

**새 평가 목적 / 별도 질문으로 처리**

- “추천 결과가 달라진 이유를 어떻게 해석했나요?” → `EVIDENCE` 또는 `CONCEPT`, 검증 대상이 *선택 이유*에서 *원인 해석*으로 변경됨.
- “추천 알고리즘이 청소년에게 미치는 정신건강 영향은?” → 관련 전공·자료 근거가 없는 경우 원래 질문의 자유 변형으로 허용 **불가**.

## 3-2. 다중 과제형 질문의 분해

- **금지:** “이 활동을 선택한 이유, 수행 과정, 역할, 성과, 배운 점을 전부 이야기해 보세요.”
- **Q0:** “활동에서 본인이 직접 맡은 일은 무엇이었나요?”
- **F1(답변 후 필요 시):** “그 역할을 수행할 때 가장 중요하게 판단한 기준은 무엇인가요?”
- **F2(답변 후 필요 시):** “그 판단이 적절했는지는 무엇을 근거로 확인했나요?”
- 두 후속 질문은 **응답에 해당 판단과 결과가 실제로 등장한 경우에만** 생성한다. 반드시 F2까지 간다는 뜻이 아니다.

# 별표 4. 실시간 질문 분기·다중 면접관 실전 예시

> 본 별표의 학생 답변은 모두 **[가상 예시]**이며, 옳고 그름을 채점하는 정답지가 아니다. 각 질문과 예시 응답을 통해 *다음 질문을 생성해도 되는 조건*을 보여준다. Q0 이후 F1/F2를 **실제로 발화한 경우**에만 평가용 후속 질문 카운트를 올린다.

## 4-1. 동일한 첫 질문, 다른 학생 응답: 분기 비교

**사전 승인 Q0:** “학급 방송을 개선하기 위해 퀴즈를 도입한 이유는 무엇이었나요?”  
`source=2025 가이드북의 방송작가 사례를 재구성한 승인된 샘플`, `function=CHOICE`, `depth=D2`, `cluster=C-001`.

| 실제 답변 | 진행 판단 | 다음 허용 발화 | 이유·카운트 |
|---|---|---|---|
| “친구들이 방송에 귀 기울이지 않아서 관심을 높일 방법을 찾았습니다.” | 핵심 동기 충분, 추가 근거 확인 선택 가능 | “그 판단을 내리게 된 구체적 계기가 있었나요?” | F1=1, 근거 확인. 충분하면 전환 가능 |
| “그냥요.” | 이유 불충분 | “결정할 때 무엇을 가장 중요하게 고려했나요?” | F1=1, CHOICE 보완 |
| “저는 사회학을 전공하고 싶어요.” | 현재 질문과 연결 불명확 | “제 질문은 퀴즈를 선택한 이유에 관한 것입니다. 그 이유를 말씀해 주세요.” | `CLARIFICATION`, F=0 |
| “질문의 뜻을 모르겠습니다.” | 이해 실패 | “방송 방식을 바꿀 때 왜 하필 퀴즈를 쓰기로 했는지 여쭤본 겁니다.” | 같은 의미 재진술, F=0 |
| “참여율이 높아졌습니다.” | 선택 이유 대신 결과만 답함 | “결과는 알겠습니다. 그 방식을 선택한 이유가 무엇인가요?” | 핵심 질문의 재안내 또는 F1: 새 평가 요구 유무를 실제 문장으로 판정 |
| “처음에는 퀴즈가 아닌 영상 편집을 해 보려 했습니다.” | 새로운 선택 비교 주장 등장 | “두 방법 중 퀴즈가 더 적절하다고 판단한 기준은 무엇인가요?” | F1=1, 답변에서 새로 나온 대안 검증 |
| “청취율이 정확히 83% 증가했습니다.” | 새 정량 주장 등장 | “그 증가율은 어떤 방식으로 측정했나요?” | F1=1, 학생 답변의 수치 검증; **원문 사실로 자동 편입 금지** |
| “좋은 질문이네요. 그건 비밀이에요.” | 회피 가능성, 장난 단정 금지 | “설명하실 수 있는 범위에서 당시 선택 기준을 말씀해 주시겠습니까?” | 재안내 1회 후에도 반복되면 전환 |

### 실제 질문 하나에서 최대 2개 예시

- **A / Q0:** “퀴즈를 선택한 이유는 무엇이었나요?” (`followup_count=0`)
- **학생:** “학생들의 관심을 높이고 싶었습니다.”
- **A / F1:** “관심이 부족하다는 것을 어떤 상황에서 알게 되었나요?” (`followup_count=1`)
- **학생:** “청소 시간에 방송에 귀 기울이지 않는 모습을 봤습니다.”
- **B / F2:** “그렇다면 실제로 반응이 달라졌다는 것은 어떻게 확인했나요?” (`followup_count=2`, **동일 cluster**)  
  → **학생이 도입 후 반응을 실제로 확인했다고 말했거나 자료에 해당 결과가 기재된 경우**에만 이 질문을 허용한다.
- **학생:** “방송 이후 참여하는 친구가 늘어났습니다.”
- **B / TRANSITION:** “이 활동에 관한 질문은 여기까지 하겠습니다. 다음에는 진로활동을 확인하겠습니다.”
- **금지:** A가 동일 활동의 같은 평가 목적을 `C-002`로 다시 열어 “그런데 정말 늘어난 게 맞나요?”라고 F3를 우회하는 것.

## 4-2. 기본·표준·심화의 차이: 같은 기록, 다른 요구 수준

**기록:** LED와 광합성에 관하여 조사·발표함. **직접 회로 제작 여부는 미확인**.

| 단계 | 첫 질문 | 가상 응답 | 가능한 F1 | 가능한 F2 | 멈추는 조건 |
|---|---|---|---|---|---|
| 1 기본 | “LED를 활용하는 이유를 설명해 주세요.” | “필요한 빛을 조절할 수 있습니다.” | “빛을 조절하는 목적이 무엇인가요?” | 답변에서 설명이 부족한 경우만 구체화 | 핵심 원리 확인 시 전환 |
| 2 표준 | “LED의 빛 조건이 식물 생장과 어떤 관련이 있나요?” | “광합성에 영향을 줍니다.” | “빛의 파장에 따른 차이를 어떻게 설명할 수 있나요?” | 이해된 원리를 실제 사례와 연결(답변·교과 범위 확인) | 추가 검증의 실익이 낮으면 종료 |
| 3 심화 | “이 조사에서 빛의 파장이 중요한 이유를 설명해 주세요.” | “빛의 특성에 따라 광합성 반응이 달라집니다.” | “그 설명을 검토하려면 어떤 조건을 일정하게 유지해야 할까요?” | “관찰 결과가 다르다면 원인을 어떻게 구분할까요?”(학생이 실험 방법을 제안한 경우) | 기록·교육과정 밖으로 불필요하게 확장하지 않음 |

**핵심:** 심화 모드는 D4를 **요구할 가능성**을 높일 뿐, 모든 학생에게 D4와 F2를 강제하지 않는다.

## 4-3. 장난 응답과 이해 실패는 다른 상태

### 사례 1. 명백한 무관 응답 반복

1. **A / Q0:** “DNA 추출 실험에서 본인의 역할은 무엇이었나요?”
2. **학생:** “아무튼 축구가 제일 재밌죠.”
3. **A / CLARIFICATION:** “실험에서 실제로 맡으셨던 일을 말씀해 주시겠습니까?” (`followup_count=0`)
4. **학생:** “그냥 넘어가요. 축구가 최고예요.”
5. **A / TRANSITION:** “네, 이 활동에 관한 질문은 여기까지 하겠습니다. 다음 질문으로 넘어가겠습니다.”

**판정:** 주제 종료 허용. 불필요한 꾸중 금지. 답변 품질 점수는 미래 답변 기준에서 별도 판단.

### 사례 2. 질문의 개념을 모르는 경우

1. **A / Q0:** “탐구에서 통제변수를 어떻게 설정했나요?”
2. **학생:** “통제변수라는 말이 정확히 기억나지 않습니다.”
3. **A / CLARIFICATION:** “실험 결과에 영향을 줄 수 있어 일부러 같게 유지한 조건이 있었는지 여쭤본 것입니다.”
4. **학생:** “온도는 일정하게 유지했습니다.”
5. **A / F1:** “온도를 일정하게 유지할 필요가 있다고 판단한 이유는 무엇인가요?” (`followup_count=1`)

**판정:** 처음 응답을 장난으로 분류 금지. 재진술은 같은 의미, F1은 새로 검증할 선택 근거이므로 평가용 카운트 1.

### 사례 3. 화상 STT 전사 불확실

- **음성:** “상관관계와 인과관계는…”
- **전사:** “상관가계와 인간관계는…”
- **금지:** 전사문을 근거로 “상관관계를 모르시는군요”라고 추궁하기.
- **권장:** 인식이 불확실하다는 신호가 충분할 때 “마지막 말씀을 정확히 듣지 못했습니다. 한 번만 다시 말씀해 주시겠습니까?”라는 기술적 재요청. **학생의 지식 평가로 전환 금지**.

## 4-4. 기록과 답변이 충돌할 때

- **승인 자료:** “동아리에서 실험 결과를 정리해 발표함.”
- **학생:** “사실 저는 발표하지 않았고, 자료 정리만 했습니다.”
- **허용 F1 / VERIFY_CLAIM:** “기록에는 발표 참여로 되어 있는데, 실제로 맡은 부분을 다시 설명해 주실 수 있나요?”
- **금지:** “학생부가 맞으니 방금 거짓말한 거죠?”
- **후속 처리:** `student_says_different` 표시. 원문은 변경하지 않고 사실확인 절차에 연결. 학생이 확인되지 않은 새 사실을 말해도 즉시 기록의 정본으로 채택하지 않는다.

## 4-5. 질문 교대·연결 발화의 올바른 흐름

**면접관 A: 학업·전공 성향 / B: 경험·공동체 성향 / 음성은 서로 구별, 성별과 담당 역량 무관**.

```text
[OPENING / A] 안녕하세요. 지금부터 면접을 시작하겠습니다.
[TRANSITION / A] 먼저 학생부에 기록된 탐구활동에 대해 질문드리겠습니다.
[QUESTION Q0 / A] 2학년 정보 과목에서 추천 결과를 비교한 이유는 무엇이었나요?
[학생 답변]
[FOLLOW_UP F1 / A] 결과를 비교할 때 어떤 기준을 사용했나요?
[학생 답변]
[TRANSITION / B] 네, 이 주제는 여기까지 확인하겠습니다. 저는 공동체 활동에 대해 질문드리겠습니다.
[QUESTION Q0-2 / B] 3학년 동아리 프로젝트에서 본인이 맡은 역할은 무엇이었나요?
[학생 답변]
[...]
[CLOSING / A] 준비한 질문은 여기까지입니다. 면접을 마치겠습니다.
```

- 앞선 Q0에서 F2가 필요 없다면 **다른 면접관으로 넘어가기 위해 임의로 F2를 끼워 넣지 않는다**.
- 질문 하나를 다른 면접관이 이어받아도 `cluster_id`와 F1/F2 카운트는 **공유**한다.
- 선택적 아이스브레이킹·자기소개·마지막 발언은 상위 원칙을 따르며, 매번 필수로 실행하지 않는다.

# 별표 5. 공통 질문 데이터 계약 (예시 스키마 및 값의 의미)

> 이 별표는 **콘텐츠 계약의 의미와 필수 조건**을 정한다. 실제 DB·API 자료형, 별도 테이블 분리는 개발팀이 선택할 수 있지만 **동일한 의미·제약이 보존**되어야 한다. 아래 예시는 학습용 가상 데이터이며 학생부 원문을 포함하지 않는다.

## 5-1. 핵심 필드 계약

| 범주 | 필드 | 필수성·의미 |
|---|---|---|
| 식별 | `question_id` | 모든 평가 질문에 필수, 불변 ID |
| 문장 | `utterance_text` | 실제 발화 최종본. 초안이 아니라 출력 문장 |
| 근거 설명 | `grounding_rationale` | 왜 이 근거에서 이 질문을 묻는지 설명 |
| 원천 참조 | `source_ref_ids[]` | 서류기반 질문에서 최소 1개, 복수 허용. 공통문항에서는 빈 배열 가능 |
| 활동 참조 | `activity_ids[]` | 활동 기반 질문에서 최소 1개. 독립 공통문항은 빈 배열 가능 |
| 답변 파생 | `parent_question_id`, `answer_turn_id` | F1/F2에서는 둘 다 필수, Q0에서는 `null` |
| 지원처 | `support_target_id`, `admission_year`, `university`, `department`, `admission_track` | 모든 회차에 연결. 확인되지 않은 대학명 생성 금지 |
| 근거 범주 | `grounding_category` | 기존 `서류기반` / `확장` 이원 구분 유지 |
| 근거 종류 | `grounding_sources[]` | `RECORD`, `STUDENT_CONFIRMED`, `ANSWER_TURN`, `ADMISSION_VERIFIED`, `COMMON_APPROVED` 중 실제 사용 근거 |
| 내용 유형 | `content_types[]` | 활동·전공·인재상·가치관·대학/학과·공통·시사·꼬리질문 등 복수 태그 |
| 질문 기능 | `primary_function` | 제9조 코드 중 하나. 부기능은 `secondary_functions[]` |
| 깊이 | `depth` | `D1`, `D2`, `D3`, `D4` 가운데 하나 |
| 평가 목적 | `question_intent` | 구체적인 확인 목표 1개 |
| 답변 연결 | `target_evidence[]` | 해당 질문에서 확인하려는 의미 요소. **정답 텍스트 아님** |
| 평가요소 | `assessment_element_refs[]` | 검증된 전형 평가요소 ID 또는 별도 프로젝트 태그와 구분해 저장 |
| 사실 입력 | `confirmed_facts[]`, `uncertain_facts[]`, `forbidden_premises[]` | 사실·추론·금지 전제의 분리. 근거 없는 값 생성 금지 |
| 우선도 | `preparation_priority` | 기존 S/A/B/C/F. 출제 확률 점수와 다름 |
| 면접 묶음 | `question_cluster_id`, `followup_index` | Q0=0, F1=1, F2=2. 세 번째 평가용 F 금지 |
| 발화자 | `interviewer_id`, `session_id`, `utterance_type` | 회차·면접관·발화 종류 관리 |
| 운영 | `followup_triggers[]`, `stop_triggers[]`, `transition_triggers[]` | 다음 질문 결정 조건. 실제 응답에 따라 판단 |
| 검수 | `validation_status`, `validation_failures[]` | `approved/rewrite_required/blocked`; `approved`만 발화 가능 |
| 추적 | `rules_version`, `source_revision`, `generated_at` | 재현·버전·정정 검증을 위한 필드 |

**중요한 구현 규칙**

1. `source_ref_ids=[]`를 허용한다고 **근거 없음**을 허용한 것이 아니다. 예컨대 자기소개는 `COMMON_APPROVED`로 승인된 공통 모듈과 해당 지원처 프로필에 연결한다.
2. 모든 서류기반 Q0는 실제로 존재하는 `source_ref_ids` 또는 승인된 `STUDENT_CONFIRMED` 근거를 가져야 한다. `activity_ids`만 있고 원천 추적이 불가능한 경우는 보류한다.
3. `uncertain_facts`의 값은 질문 문장에 확정 서술로 삽입할 수 없다. 질문 자체가 이를 확인하는 목적이면 **개방형·조건형**으로 표현한다.
4. 복수 학생부 영역에 동일 활동이 기록된 경우 `activity_ids`를 중복 생성하지 않고 `source_ref_ids`만 필요한 만큼 연결한다.
5. 실제 화상 면접에서 STT가 불확실해도 전사 결과는 `ANSWER_TURN`으로 보관할 수 있으나, **불확실한 전사를 검증된 사실로 승격하지 않는다**.
6. `validation_status=approved`인 질문만 발화한다. 발화 직전 문장이 바뀌면 **최종 문장 기준 재검수**한다.

# 별표 6. 필수 인수 테스트·반례 및 품질 게이트

> 개발팀은 단순한 예문 일치가 아니라 **의도 보존·근거 검증·상태 전이**를 검증하는 테스트를 구현한다. 테스트 기대 결과는 `허용 / 재작성 / 차단 / 전환`으로 구분한다.

| ID | 입력 상황 | 기대 엔진 행동 | 필수 판정 |
|---|---|---|---|
| T01 | 원문 “실험에 참여함” | “어떤 역할을 했나요?” | **허용**. ‘실험 직접 설계’ 단정 시 차단 |
| T02 | 원문에 실제 역할 불명확 | “본인이 직접 담당한 부분은?” | **허용**. `needs_confirmation`을 확정 사실로 처리 금지 |
| T03 | 팀 활동 결과만 기록 | 팀의 성과를 개인의 성과로 묻는 질문 | **차단**, 실제 개인 기여 확인으로 재작성 |
| T04 | 기록 “친구들과 토론” | “갈등을 해결한 과정은?” | **차단**, 갈등 존재 확인 전제 누락 |
| T05 | 기록 “방송에 퀴즈 도입” | “청취율 30% 증가한 근거는?” | **차단**, 없는 수치 생성 |
| T06 | 같은 CHOICE 의도의 종결 표현만 변경 | 같은 질문의 다른 발화형 | **허용**, 새 평가 질문·새 묶음 아님 |
| T07 | CHOICE 질문에서 갑자기 정신건강 영향 요구 | 의도·요구 지식 변경 | **차단 또는 독립 질문으로 재검토** |
| T08 | Q0, F1, F2가 이미 발화됨 | F3 평가 질문 생성 요청 | **차단**, 면접관 교대 후에도 동일 |
| T09 | Q0·F1만 사용했고 학생 답변 충분 | F2 강제 생성 | **차단/전환**, 횟수는 최대치이지 할당량 아님 |
| T10 | 학생 “질문이 무슨 뜻이죠?” | 같은 의미로 한 차례 쉽게 재진술 | **허용**, 카운트 유지 |
| T11 | 재진술에 별도 실험 한계 검증 추가 | 사실상 새 평가 질문 | **새 F로 산정**, 상한 초과 시 차단 |
| T12 | 학생 첫 무관 답변 | 취지 한 번 정중히 재안내 | **허용**, 장난 단정 금지 |
| T13 | 같은 묶음에서 재안내 후 무관 답변 지속 | “이 활동 질문은 여기까지 하겠습니다” | **전환**, 설교 금지 |
| T14 | 학생 “모르겠습니다” | 필요시 다른 주제로 이동 | **허용**, 무관·장난과 분리 |
| T15 | 음성 전사 의미 불확실 | 재청취·재답변 요청 | **허용**, STT 오류를 지식 오류로 확정 금지 |
| T16 | 학생이 공식 기록과 다른 역할 설명 | 중립적 차이 확인, 정정상태 기록 | **허용**, 거짓말 단정 금지 |
| T17 | 2학년 알고리즘 + 3학년 영상제작 | “연결된 부분이 있나요?” | **허용**. 연결 사실을 전제하면 차단 |
| T18 | 특정 책 제목만 기록 | 책의 특정 장을 읽었다는 질문 | **차단**, 읽은 범위 확인으로 변경 |
| T19 | 봉사활동 참여만 기록 | “가장 감동한 순간은?” | **재작성**, 감정·강도를 전제하지 않음 |
| T20 | 단순 성적 수치에 0·결측 포함 | 전 학기 등급 평균 계산 질문 | **차단**, 결측·산식 점검 필요 |
| T21 | 확인되지 않은 전형 면접관 수 | 대학 실제 3인처럼 소개 | **차단**, 기본 2인 가상 연출만 허용 |
| T22 | 면접관 A가 F1, B가 F2를 발화 | B가 동일 내용 F3를 새 묶음으로 재개 | **차단**, cluster 상한 우회 금지 |
| T23 | 회차 첫 질문에 아이스브레이킹 생략 | 인사·자연스러운 본론 연결 멘트 | **필수 허용**, 질문만 돌연 시작하는 UX 피함 |
| T24 | 인사에서 실제 날씨 모름 | “오늘 무척 춥죠?” | **재작성**, 확인 불가능한 현황 단정 금지 |
| T25 | 학생 인적사항·사생활 정보 포함 | 실제 질문의 평가 목적과 무관한 추궁 | **차단**, 제3자 민감정보 질문도 차단 |

## 6-1. 질문 QA 루브릭: 필수 탈락 vs 개선 권고

### 필수 탈락(`blocked`)

- 승인되지 않은 근거를 바탕으로 질문 생성.
- 학생의 확인되지 않은 행위·감정·수치·인과관계 단정.
- 실제 전형과 다른 면접 범위 또는 공식 평가요소의 허위 연결.
- 데이터 계약의 필수 필드 누락·허위 ID.
- 같은 질문 묶음에서 평가용 F3 생성.
- 학생에게 부당한 개인정보·제3자 정보 노출 요구.
- 실전 모드에서 정답을 알려주거나 합격 여부·성격을 단정.

### 재작성(`rewrite_required`)

- 불필요하게 긴 문장.
- 한 질문에 여러 독립적 평가 목적이 결합.
- 같은 표현·서두 반복.
- 지나치게 추상적인 “역량·성장” 질문.
- 답변의 실제 내용을 듣지 않고 준비된 꼬리질문을 기계적으로 발화.
- 질문의 취지는 적절하지만 문법·존댓말이 어색함.

### 승인(`approved`)

- 근거·의도·유형·깊이·평가요소가 정확하게 연결됨.
- 한 번에 이해할 수 있으며, 학생이 답할 범위가 명확함.
- 질문의 답변 가능성과 심화 가능성을 갖추되 의무적인 꼬리질문을 요구하지 않음.
- 상위 규정·전형 설정·후속 질문 상한 및 발화 형식 준수.

## 6-2. 개발팀 인수 조건 (Definition of Done)

1. **메타데이터 선행:** 평가 질문의 구조화된 근거·의도·분류·검수 결과가 생성된 후에만 발화 가능.
2. **실제 문장 검수:** 모델이 최종적으로 자연스럽게 고친 발화 문장까지 QA 통과.
3. **후속 질문 상한:** 모든 면접관이 공유하는 cluster 상태를 통해 F1/F2 상한 강제.
4. **응답 분기:** 충분한 답변·불충분한 답변·모름·무관 응답·STT 불확실 응답에 대한 분리 동작 확인.
5. **자연스러운 흐름:** 아이스브레이킹 유무, 주제 전환, 다중 면접관 교대, 마무리 문장을 적절히 생성.
6. **대학·전형 검증:** 서류기반 여부·면접관 수·평가요소의 출처 및 확인 상태에 맞춰 운영.
7. **분리된 책임:** 본 질문 명세의 `target_evidence`를 임의로 합격 점수·정답 문장으로 사용하지 않음.
8. **시나리오 테스트:** T01~T34를 자동·수동 검수에 포함하며, 탈락 사례가 배포에서 발화되지 않음.
9. **기록·재현:** `rules_version`, 학생 입력 revision, 질문·답변·전환 사유를 통해 문제 재현 가능.
10. **데이터 보호:** 학생부 및 면접 기록은 법률·개인정보·보안 승인 범위에서만 접근·보존.

## 최종 확인 문장

> **각자의답의 평가 질문은 모두 ‘어디에서 왔는지, 무엇을 확인하려는지, 어떤 수준의 사고를 요구하는지’가 설명되어야 한다. 면접관은 그 제한 안에서 자유롭게 말할 수 있지만, 학생부의 사실을 만들어내거나 같은 질문을 무한히 추궁할 수 없다.**

# 제8장 2026-11-02 IA/UX 연동 규정 (v2.3 추가)

> 본 장은 질문 생성의 **15개 주기능, D1~D4, 7대 필수 조건, 질문 하나에 하나의 핵심 평가 목적, 학생부 근거 검증 및 F1/F2 최대 2개**를 변경하지 않는다. 전수 사례·예제 데이터도 보존하였다. 학생용 화면 연결과 매체만 갱신한다.

### 제40조 (실전 질문 생성 매체 — 화상 전용)

① 연습 면접만 채팅/화상 방식 중 선택할 수 있다. **실전 모의면접은 지원처만 선택하며 화상으로 진행**한다. 매체 종류는 질문의 사실성·평가 의도·근거 필수 검수조건을 완화할 수 없다.

② TTS 발화 품질이 부족하면 생성한 질문을 다수 결합해 짧게 만드는 등 평가 의도를 침해하는 임의 가공은 금지한다. 질문 텍스트와 TTS에 입력된 발화문, 실제 전사에 남은 질문 원문을 검증·기록한다.

### 제41조 (질문 근거 하이라이트를 위한 앵커 계약)

① 학생부 원문에서 도출된 Q0는 `source_ref_ids[]`, `record_revision`, `activity_id`, **원문 앵커 범위**와 연결한다. `G04 예상 질문·답변`에서 학생이 질문을 선택하면 `Full Source Document`의 **정확히 해당 근거만** 강조할 수 있도록 질문 생성 시 원문 위치를 보존한다.

② `COMMON_APPROVED` 공통 질문 또는 학생부 특정 문장에 직접 근거하지 않은 질문은 **하이라이트 근거 없음**을 정확하게 반환한다. 가상의 문장/위치 ID를 생성하지 않는다. 확장 질문이 학생부에서 출발한 경우에는 검증된 원천 참조만 연결한다.

③ 원문 재OCR/재발행 시 질문-근거 앵커 유효성 검사를 실시한다. 연결이 잘못되면 **문항 또는 강조를 보류**하고 잘못된 근거를 그럴듯하게 표시하지 않는다.

### 제42조 (예상 질문 UI와 실제 후속 질문 구분)

① 학생용 가이드북 G04의 기본 화면에는 **예상 질문/예상 답변 + 학생부 원문 하이라이트**를 표시한다. `질문의 의도`, `꼬리질문 보기`, `원문 근거 보기`, `연습하기`를 별도 버튼으로 표시하지 않는다. 이는 **엔진의 `question_intent`, F1/F2 후보 생성·검수 데이터를 제거하는 정책이 아니다.**

② G04 `질문 저장하기`나 이슈픽의 `질문 저장하기`는 **연습 면접 → 내가 추가한 항목**으로 귀속한다. 사용자 직접 입력 `STUDENT_SUPPLIED` 문항은 학생이 만든 질문이지 학생부 공식 근거가 아니므로 별도 출처 표시를 유지한다.

③ 연습 면접 `보완 추천`은 기존 실제 답변·평가가 확인한 취약한 질문을 **가중 추천하는 UI 목록**이며, 무조건 부정적 평가/실제 대학 출제 보장을 의미하지 않는다. 원 질문 ID·근거/평가 정보는 재사용한다.

### 제43조 (규범 검수 테스트 강화)

- **QG-UX-01:** 한 질문에서 동기·과정·결과 등 세 과제를 동시에 물을 경우 `BLOCKED` 처리.
- **QG-UX-02:** 지원처별 근거 없는 학생 활동 사실을 전제할 경우 발화 금지.
- **QG-UX-03:** Q0·F1/F2가 각각 단일 핵심 평가 의도를 가지며 동일 묶음 꼬리질문 2개 상한 유지.
- **QG-UX-04:** 원문 근거 ID/앵커 불일치 문항은 G04 형광펜을 오염시키지 않음.
- **QG-UX-05:** 공통 승인 문항은 원문 위치를 지어내지 않고 ‘하이라이트 없음’으로 처리.
- **QG-UX-06:** 사용자에게 `질문의 의도`가 보이지 않아도 생성·평가 서버는 `question_intent`를 완전하게 보존.

**현행 참조:** 8번 v2.0, 5번 v2.2, 6번 v1.3, 12번 학생용 IA·UX v1.2. 과거 테스트/예시의 `채팅 실전` 표현은 현재 제품 경로에서 제외하고, 연습 채팅/화상 예시는 보존한다.
