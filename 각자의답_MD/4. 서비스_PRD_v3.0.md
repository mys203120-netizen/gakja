# 1. 제품 정의와 원칙

**각자의답**은 학생의 기록을 지원 대학의 관점에서 분석하여 개인별 웹 가이드북과 반복 훈련을 통해 `나의 답`을 준비하는 **서류기반 대학입학 면접 대비 서비스**다. 브랜드 철학은 브랜드 정체성 v1.0을 따른다.

1. 학생 본인에게 확인되지 않은 동기·역할·성과·감정을 확정 사실로 만들지 않는다.
2. `생기부 OCR MD`(전사 정본)와 `생기부 분석 MD`(해석·구조 정본)를 구분한다.
3. 같은 활동·질문·답변을 가이드북, AI 비서, 훈련 및 리포트가 **공통 ID·발행 버전**으로 참조한다.
4. 지원 대학·모집단위·전형·입학연도 단위의 확인된 서류기반 면접 정보만 실제 대학 재현으로 표시한다.
5. 질문 완성도 점수와 활동 선택 전략 코칭, 표준 프레임 훈련, 화상 전달력 분석을 혼동하지 않는다.
6. 학생 자료·대화·음성·영상·리포트는 소유권을 검사한 비공개 경로에서 처리한다.
7. 웹 가이드북은 기본 제공물이고, 실전 면접 리포트는 **다운로드 PDF**로 구분한다.

## 2.2 명시적으로 폐기하거나 유지하지 않는 구 구조

- `MY / 자료 / 챗 / 훈련 / 기록`의 다섯 최상위 카테고리 IA.
- `학교·학과` 독립 메뉴; 해당 내용은 가이드북 `대학·학과 분석`에 둔다.
- 독립 `개인맞춤 챗` 상위 메뉴; **AI 비서**는 가이드북에서만 호출한다.
- `답변 만들기` 독립 메뉴 및 `기억 꺼내기`의 면접 연습실 소속.
- `기본·서류집중·꼬리질문·전공심화·대학맞춤·압박` 여섯 모드의 메뉴 구조.
- HTML 완성본을 외부에서 조판·업로드해 이를 유일한 웹 자료 원천으로 파싱하는 종전 기본 흐름.
- 일반 웹 가이드북을 최종 PDF 다운로드 중심으로 제공하는 방식.
- `오답노트`, `분석 리포트`(가이드북 의미), `크레딧` 등의 금지 네이밍.

**범위 외:** 제시문·MMI·실기·교과 구술을 서류기반 모의면접만으로 재현하지 않는다. 합격 확률·성격/거짓말 탐지·자동 입시 합격 보장 기능을 명세하지 않는다.

# 3. 사용자 여정 및 가입·상품

## 3.1 상태 전이

```text
비회원 메인(서비스/요금/시연 영상 소개)
 → '내 학생부 분석하기' → 가입·온보딩(목표 대학/학과/전형/일정)
 → MY 홈(미등록 상태: 학생부 등록 유도)
 → 학생부 등록 진입 → 요금제 비교·결제
 → 허용된 자료 등록 → 생성 진행/오류 상태
 → OCR 검수·분석·웹 가이드북 발행
 → 학생 전용 웹 열람 가능 → 외부 완료 알림(검증된 연동)
 → 생기부에서 학습 → 암기 훈련실/면접 연습실 → 내 답변에서 복습
```

- 가입 후 MY 홈 진입은 학생부 자료 발행 전에도 가능해야 한다.
- 학생부 미등록 상태에는 `아직 학생부가 등록되지 않았어요` 및 등록 유도 버튼을 제공한다.
- 서비스 완료 상태는 OCR·분석 파일 생성만으로 성립하지 않고 **학생에게 웹 가이드북 열람 권한이 부여된 경우**에 한한다.
- 등록·분석에 걸리는 실제 시간은 측정 전이다. **5분 보장** 문구를 확정 정책으로 쓰지 않는다.

# 4. MY 홈과 최상위 IA

```text
MY 홈
 ├─ 생기부
 │    └─ 가이드북 [나의 면접 전략 / 학생부 분석 / 대학·학과 분석 /
 │                 예상 질문·답변 / 실전 훈련 / 부록]
 │         └─ 우측 하단 AI 비서
 ├─ 면접 연습실
 │    ├─ 연습 면접
 │    └─ 실전 모의면접
 ├─ 내 답변
 │    ├─ 답변 보관함
 │    ├─ 면접 리포트
 │    └─ 면접 직전 요약 [개인 면접일 D-1 공개, 시간·예외 미정]
 └─ 암기 훈련실
      ├─ 퀴즈
      ├─ 지식한입
      └─ 이슈픽
```

- MY 홈은 지원처·면접 D-Day·가이드북 완료/준비 상태·연습 현황의 간결한 개요와 네 진입점을 제공한다.
- 홈은 **네 핵심 메뉴 카드를 동등한 진입점**으로 배치하며 설명형 부제·중복 CTA를 제거한다. 실제 아이콘·색상·화면 크기는 12번 IA/UX의 검토용 디자인 시스템에 따른다.
- 지원처 변경과 개인정보·알림·계정 설정은 필요에 따라 보조 화면에서 관리할 수 있으나 독립 기능 메뉴를 추가하는 근거가 아니다.
- **채팅/화상은 연습 면접에서만 선택할 수 있는 입력·출력 방식**이다. **실전 모의면접은 화상 전용**이며 매체 선택 단계 자체를 제거한다.

# 5. 기능 요구사항

## FR-01 생기부 등록·처리 상태

**입력:** 유효한 지원처 및 입력 권한, 해당 상품 권한, 허용된 학생 자료.

**처리:** 업로드 후 OCR MD 생성, 영역/학년 분리, 근거 검수, 분석 MD 산출, 목차별 콘텐츠 연결 및 웹 가이드북 발행. **5대 중대 오류가 없는 자동 QA 통과 건은 조건부 자동 발행**, 차단 건은 콘텐츠기획팀 수정·재검증·최종 승인 후 발행한다. 불명확 정보는 기획팀 우선 검토 후 필요할 때만 학생 확인을 요청한다.

**출력:** `미등록 / 처리 중 / 검토 필요 / 완료(열람 가능) / 처리 실패` 등 사용자가 이해할 수 있는 상태. 원인·재시도·문의 경로는 별도 확정.

**금지:** OCR 미완료·잘못된 권한·사실 충돌이 있는 콘텐츠를 정상 발행 완료로 표시하는 행위.

**개발 계약:** 5번 분석 기준 v2.1과 7번 제작 프로세스 v2.1의 `record_revision`, `analysis_revision`, `publication_revision`, `source_ref_ids[]`, `activity_id` 준수.

## FR-02 웹 가이드북

**필수 여섯 목차:** 나의 면접 전략 / 학생부 분석 / 대학·학과 분석 / 예상 질문·답변 / 실전 훈련 / 부록. `00. 가이드북 사용법`은 안내 영역.

**UI:** 여섯 목차의 문서 중심 탐색; 필요한 장에서만 목차 점프·접기/펼치기·학년/영역/S/A/B/C/F 필터·검색. **G02는 학생부 원문 전체를 항목별로 열람**, **G04는 같은 화면의 원문 전체와 예상 질문·예상 답변을 병렬/전환하며 정확한 근거 문장을 형광펜 표시**한다. `원문 근거 보기` 팝업·`질문의 의도`·꼬리질문 미리보기·즉시 `연습하기`는 G04 기본 화면에서 제거한다.

**동작 제약:** 필터 적용 결과에서 비해당 장의 표시방식은 UI 세부 합의 사항. 동일 활동이 여러 섹션에 있더라도 데이터를 복제하지 않으며 참조 ID로 연결한다.

**제공:** 개인 계정 인증 웹 렌더링이 기본. 학생은 **개인 답변·암기 키워드·메모**를 편집하고 필요한 영역만 선택적 PDF 저장/인쇄한다. 전체 가이드북 일괄 PDF 배포는 기본 정책이 아니고 독립 암기 핸드북을 제작하지 않는다. 실전 리포트 PDF와 혼동하지 않는다.

## FR-03 가이드북 플로팅 AI 비서

**위치:** 생기부 → 가이드북 화면 우측 하단 각자의답 캐릭터 아이콘. 아이콘 클릭으로 채팅 인터페이스 호출.

**대화 예:** “2학년 세특 중 S 활동만 보여줘”, “리더십 활동만 찾아줘”, “이 질문의 학생부 근거를 보여줘”.

**내부 계약:** 승인된 학생별 `activity_id/source_ref_id/question_id`와 현재 화면의 섹션·검색·필터 맥락을 사용한다. 자료에 없는 사실을 학생이 경험한 것처럼 답하지 않는다.

**구분:** 현재 화면에서 필터/검색 강조·스크롤을 직접 수행하는 범위, 화면 조작 권한 및 되돌리기 정책은 **추가 설계**. 비서가 성공하지 않은 화면 조작을 완료했다고 말하지 않는다. 다른 학생 자료 접근 차단.

## FR-04 연습 면접

**설정:** 등록 지원처·채팅/화상 매체, 학년(1·2·3), 학생부 영역(자율/동아리/진로/세특/행특 등), 기존 예상 질문, 활동·평가 역량·기능·난이도별 신규 질문 생성 또는 학생 직접 입력 질문 선택. 직접 입력은 학생 제공 출처로 분리한다.

**진행:** 사용자의 선택에 맞춘 Q0와 필요한 F1/F2(총 후속 평가 질문 최대 2개), 정중한 연결 발화, 연습 목적에 따라 승인된 교육적 재질문 허용.

**출력:** Q0와 필요한 평가용 F1/F2 **질문 묶음이 끝나면** 평가 항목별 **긍정(민트)/보완(코랄) 카드**로 핵심 설명 1~2문장, `이렇게 다듬어 보세요` 개선 방향, 확인 가능한 경험만 사용한 `모범 답변 예시`를 제공한다. **학생 공개 숫자 점수와 실전 종합 PDF는 없다.** 기본 하단 버튼은 `다시 연습하기` / `다음` 두 개. 다시 연습하기 내부에서는 **단일 질문 재답변 또는 질문 묶음 전체 재진행**을 선택할 수 있으며, 과거/재답변 revision을 각각 보존한다. 단일 질문 재답변에서는 신규 후속 질문을 만들지 않는다.

## FR-05 실전 모의면접

**목적:** 해당 입학연도 지원 대학·모집단위·전형에 확인된 서류기반 면접 운영 조건을 가능한 범위에서 반영.

**설정:** 학생은 **지원처만 선택**하고 실전은 **화상 전용**이다. 카메라·마이크 점검 후 하나의 `모의면접 시작`으로 진입한다. 난이도는 엔진 내부 3단계·기본 2단계를 적용하되 사용자 설정에는 노출하지 않는다. 대학별 검증된 시간/면접관 수/유형을 적용하며, 인원 미확인 시 **가상 기본 2인**으로 안내한다. 질문·난이도·집중 평가 영역은 학생이 정하지 않는다.

**진행:** 도입→본론→마무리→종료, 선택적 아이스브레이킹·자기소개·마지막 발언, 자연스러운 도입 안내, 질문 의도별 메타데이터 검증, Cluster당 꼬리질문 최대 2개, 무관 답변 반복 시 1회 정중한 안내 후 전환. 가상 면접관은 역할별 질문 성향을 공유하되 성별을 질문 능력과 연결하지 않는다.

**평가:** 면접 종료 후 개별 답변 100점 평가와 별도 전략·프레임·화상 전달 코칭을 구분한다. 질문 묶음 점수는 Q0/F1/F2 가중치(0개: Q0 100%; 1개: Q0 70%·F1 30%; 2개: Q0 70%·F1 15%·F2 15%)로 계산하고, 유효 질문 묶음을 동일 가중치 평균해 종합 점수를 산출한다. 서비스 오류로 일부 묶음이 평가 불능이면 해당 묶음은 제외하고 **유효 비율 60% 이상 및 최소 2개**일 때만 부분 종합 점수를 표시한다. 불완전 리포트는 오류 원인/사과 및 이용권 1회 복구 안내를 포함한다. **회차별 PDF 리포트**는 내 답변에 저장하되 상세 구성 A/B/C안은 미정이다.

**유의:** 실제 대학의 공식 점수/합격 가능성을 모사한다고 표시하지 않는다. 평가 점수는 내부 훈련 지표이며 전문가 라벨셋 검증 전임을 명시한다.

## FR-06 내 답변

### 답변 보관함

상단의 `연습 면접` / `실전 모의면접` **2개 탭만** 제공하며 `전체` 탭과 낱개 질문의 첫 화면 나열은 없앤다. 연습은 **세션별 묶음**과 지원처(미지정은 `공통`)·질문 유형 필터를 제공하고, 실전은 **회차별 묶음 + 리포트 획득 점수/평가 상태**로 표시한다. 상세에서 답변별 **대표 답변 별표 지정**을 허용하되 원본 실제 발화/전사·평가 기록은 바꾸지 않는다.

### 면접 리포트

실전 **누적 결과(평가 완료 회수·평균 점수·최근 점수·점수 변화)**를 간결하게 상단에 보여주고, 하단의 **회차별 Accordion(펼침)**에서 리포트를 확인한다. 평가 불능·기술적 불완전 회차는 정상 평균에 섞지 않는다. **회차 상세 내부 구성·PDF A/B/C안·지원처 간 비교가능성·최소 통계 회차는 미정**이다. PDF 다운로드 권한/버전 보존은 유지한다.

### 보완 추천 (독립 메뉴가 아닌 연습 면접 질문 목록)

`다시 준비할 질문` **독립 IA 메뉴는 폐기**한다. 가이드북·이슈픽에서 저장한 질문은 `연습 면접 → 내가 추가한 항목`, 실전/연습 기록에 근거한 재학습 질문은 `연습 면접 → 보완 추천`으로 노출한다. 질문 출처·저장 시점·추천 근거는 **하나의 질문 참조 데이터**로 구분 관리하고, `오답노트`·중복 보관함을 만들지 않는다.

### 면접 직전 요약

`내 답변 → 면접 직전 요약`은 **학생이 등록·확인한 개인 면접일의 D-1부터 공개**한다. 열리기 전에는 `면접 하루 전 열려요` 잠금 상태를 표시한다. 공개 후 주요 활동·필수 예상 질문·반복 보완 사항·사실 확인·지원처 유의사항을 간결한 카드로 제공한다. **정확한 공개 시각·시간대·일정 변경·복수 지원처·자료 부족 예외는 미정**이다.

## FR-07 암기 훈련실

- `퀴즈`: 학생부·전공 지식·표준 답변 프레임·회상 키워드로 **단일 선택/복수 선택/순서 배열/짝 연결/빈칸 완성** 등 목적에 맞는 유형을 사용한다. 문항별 오답 이력·최근 풀이·연속 정답을 관리하여 **오답 가중 반복출제**를 제공한다. 구체적 가중치·간격·채점 세칙은 미정.
- `지식한입`: 세특·탐구·전공과 관련된 **실제 영상/보고서/논문/공식자료**를 썸네일·검증 출처·학생별 관련성 중요도·즐겨찾기로 탐색한다. 자료 추천·검수·저작권 세칙은 미정.
- `이슈픽`: 시사·전공 이슈 카드에 **실제 썸네일·출처·발행일·즐겨찾기**를 제공한다. 면접에서 생각해볼 질문이 검증되어 존재할 때만 `질문 저장하기`로 `연습 면접 → 내가 추가한 항목`에 연결한다. 갱신 주기·콘텐츠 세칙은 미정.
- **실전플랜·몰입플랜**의 기본 제공 기능으로 확정되었다. 준비플랜은 웹 가이드북의 암기 키워드·답변 편집만 사용 가능하다.
- 별도 암기 핸드북 PDF·DOCX 발행은 종료되었다. 기존 암기 자산은 데이터 원천으로만 보존한다.

## FR-08 완료 알림

**발송 조건:** 웹 가이드북 실제 `published` 및 학생 열람 권한 활성화 이후.

**연동 방향:** 회의에서 `솔라핏`으로 언급된 메시징 통합 서비스의 API를 통한 카카오 알림톡 또는 SMS. 공급사의 공식명, API, 채널 우선순위, 템플릿 승인, 비용, 동의/수신거부, 오류 재시도는 **개발 검증 전**.

**안전성:** 고객에게 노출하는 알림 문구에 원문 학생부·성적·민감정보를 불필요하게 포함하지 않는다. 중복 발송 방지와 전송 상태를 기록한다.

# 6. 데이터·콘텐츠 계약

## 6.2 상태와 API (구현 제안)

**상태:** 미등록 → 업로드 확인 → OCR 검증 → 분석 생성 → 콘텐츠 QA → 발행 준비 → 발행 완료 → 알림 처리, 실패 시 재시도/보류 상태. **일반 건은 자동 QA 통과 시 조건부 발행**, Critical 이력이 있는 건은 수정·재검증·콘텐츠기획팀 최종 승인 없이 발행할 수 없다. 실제 상태명은 구현 제안이다.

**예시 리소스(경로 확정 아님):**

```text
GET /api/me/support-targets
GET /api/me/guidebook?target_id=...
GET /api/me/guidebook/search?target_id=...&query=...
POST /api/me/assistant/messages
POST /api/me/interview-sessions
POST /api/me/interview-sessions/{session_id}/turns
GET /api/me/answers
POST /api/me/review-questions
GET /api/me/interview-reports/{report_id}
GET /api/me/publication-status
```

각 API는 서버에서 실제 사용자의 소유권·구매권한·발행 버전을 검증한다. 외부에서 넘어온 `student_id`를 신뢰하지 않는다. 실제 미지원/추정 기능에 대해 성공 응답을 반환하지 않는다.

## 6.3 화면에서 쓰는 검색·필터 인덱스

- 공통 검색단위: Activity ID·Question ID·Source Ref ID·가이드북 섹션 ID. 원문을 숨긴 화면에서도 내부 근거 참조는 유지한다.
- 학년·영역·우선도 필터가 동일 자료에서 일관된 결과를 내도록 하나의 정규화 데이터 또는 인덱스를 사용한다.
- AI 비서가 필터 요청을 처리할 때 화면을 자동 변경했다면 실행 결과를 확인한 뒤 반영·실패를 안내한다.

# 7. 인증·권한·보안

- 역할은 `student / staff / admin`을 기본 논리로 구분하되 실제 역할·승인권 상세는 구현 설계에서 확정한다. 콘텐츠기획팀·서비스개발팀은 조직이며 로그인 권한 역할과 혼동하지 않는다.
- 학생·보호권자 승인 여부에 따라 허용된 학생 자료의 접근 범위를 최소화한다. 학생부 수집·상업적 처리는 **사전 법률 검토·적법한 처리 근거가 확보된 경우에만** 운영한다.
- 개인 자료·OCR·분석 MD·원문 발췌·AI 비서 대화·답변·녹화·리포트는 기본 비공개. 공개 URL, 공개 버킷, 정적 앱 리소스에 학생 내용을 배치하지 않는다.
- 모든 읽기·수정·PDF 다운로드·AI 검색·영상 접근에 계정 권한·발행권한을 검증한다. 관리자라는 이유만으로 모든 학생 대화 전문의 일반 열람 권한을 부여하지 않는다.
- 학생 계정의 user-supplied metadata를 관리자 권한 근거로 사용하지 않는다. 관리자/담당자의 권한과 변경이력은 별도 관리한다.
- OCR·음성·화상 처리에 대한 수집 고지, 보존 기간, 외부 위탁 및 목적 제한은 별도 정책 승인이 필요하다. 로그에 원문·이름·토큰을 무조건 기록하지 않는다.
- 화면 시선·표정만으로 성격·성실성·거짓말·합격 가능성을 추론하거나 점수화하지 않는다. 카메라 위치 차이에 따른 오판을 방지한다.

# 8. 기술 구성·운영 경계

**이전 PRD v1.2의 기술 선택:** Turborepo + Next.js + Expo + Supabase + Vercel, 별도 콘텐츠 제작 프로젝트, OpenAI API 모델명에 관한 서술이 있었다. **이번 회의록은 기술 스택의 유지·폐기를 확정하지 않았으므로**, 기존 사용 중인 기술은 개발팀이 현행 코드/계약을 확인한 뒤 확정한다.

특히 이전 PRD의 특정 모델명/API ID를 **동작이 검증된 현재 모델로 단정하지 않는다**. 모델 공급자·엔드포인트·응답 포맷·원가·용량·장애시 대체 처리 등은 구현 검증 대상이다.

공유되는 것은 승인된 `content_contract_version`·ID 체계·스키마·테스트 fixture 및 근거 정책이다. OCR/분석 생성기를 웹 서버에 직접 통합할지 별도 작업자로 운영할지는 기술 설계 결정 사항이며, **웹 가이드북 데이터 결과와 발행 게이트**는 어느 구현에서도 보존해야 한다.

# 9. 실전 리포트의 출력 정책

- **연습 면접:** 질문 묶음 종료 후 **평가 항목별 강점/보완 카드 + 개선 방향 + 사실 기반 모범 답변 예시**. 화면 하단 `다시 연습하기` / `다음`만 기본 제공. 내부의 질문 의도·충족/누락·프레임 정보는 평가·코칭 생성에 유지하되 카드로 과도하게 쪼개지 않는다. 숫자점수 공개와 실전 종합 PDF 금지.
- **실전 모의면접:** 10번 답변 기준 v2.2의 기능별 100점 산식, 70:30 질문 묶음 점수, 묶음별 동일 평균, 유효 묶음 60%·최소 2개 게이트를 적용한다. 통계적 표준편차, 점수 등급의 회차 집계 및 누적 리포트 차트/디자인은 **미정**이다.
- **화상 매체:** 발화 속도·반복어·명료성·시선처리는 기술적으로 신뢰 가능한 경우에 한해 별도 전달 코칭. **내용 점수에 자동 가감하지 않는다**.
- **PDF:** 실제 발생한 질문·학생 답변·근거·강점·보완점·표준 프레임·활동 전략 제안·재훈련 항목·사용 루브릭 버전을 포함하는 방향. 정확한 디자인/통계 규칙은 후속 보고서 기준으로 확정.
- **저장:** 세션의 가이드북·질문·평가 버전을 보존하고, 새 분석이 나와도 과거 리포트를 덮어쓰지 않는다.

## 13.2 전 과정 상태·권한 게이트

| 상태/이벤트 | 진입 조건 | 공개/과금·알림 제한 | 실패 처리 |
|---|---|---|---|
| `not_registered` | 학생부 없음 | 가이드북 열람/연습 활성화 불가 | 자료 등록 유도 |
| `upload_received` | 적법·허용된 입력과 학생/지원처 연결 | 완료 알림 금지 | 형식·권한 오류 안내 |
| `ocr_validating` | 전사 job 생성 | 사실로 안내 불가 | 원문 대조·재업로드 |
| `analysis_processing` | 원천 QA 통과 | AI 해석 미승인 사실은 비공개 | 작업 단위 재시도 |
| `needs_review` | 5대 중대 오류/불명확 핵심 데이터 | 해당 지원처 자동 발행 금지 | 기획팀 검수 큐 |
| `needs_student_confirmation` | 담당자 자체 해결 불가 | 미확인 학생 진술을 사실로 생성 금지 | 확인 요청·응답 기한 UX 추후 승인 |
| `ready_to_publish` | 모든 자동 QA 통과 또는 보류 건의 재검증+기획팀 승인 | 권한 검증 전 가이드북 미공개 | DB/스토리지 원자적 발행 처리 |
| `published` | 실제 본인 열람 가능 | 완료 알림 이벤트 발행 가능 | 접근 장애 시 완료 상태 철회/복구 |
| `notification_pending` | published 이벤트 | 발송 성공을 미리 표시하지 않음 | 공급자 실패·재시도 로그 |
| `correction_requested` | 학생 신고/서비스 오류/원본 교체 | 기존 발행본 유지 및 영향 관리 | 조사·새 revision·재발행 |

**5대 Critical 차단:** (C1) 원문 인식 누락·왜곡, (C2) 근거 없는 학생 활동·기여·성과 등 확정, (C3) 지원처 핵심 정보 미검증을 공식 사실로 서술, (C4) 필수 목차·핵심 분석 누락, (C5) 원문-Activity-질문-답변 간 ID·근거 충돌. 자동 검증에 하나라도 실패하면 `needs_review`로 전환한다. OCR/분석 처리 성공 자체는 `published`가 아니다.

**발행 승인:** 일반 건은 QA 통과로 조건부 자동 발행. 중대 오류 발생 건은 수정→동일 기준 재검증→콘텐츠기획팀 최종 승인이라는 세 조건을 모두 만족해야 발행. 자동 QA의 기술적 신뢰가 검증되기 전 실제 자동 발행 비중은 운영 승인 대상으로 유지한다.

## 13.3 학생 개인 편집·동기화·근거 오염 차단

1. 학생은 `user_answer_revision`, `user_memory_keyword_revision`, `personal_note_revision`만 생성할 수 있다. `record_ocr`, `activity`, `source_ref`, `admission_profile`은 직접 수정 불가.
2. 학생이 저장한 최신 답변/키워드를 질문 생성·코칭의 **허용 참고 문맥**으로 자동 연동하지만 원래 `answer_script_revision`을 덮어쓰지 않는다. 새로운 활동 사실이 포함되면 `STUDENT_CLAIM_UNVERIFIED`로 관리한다.
3. 실전 평가기는 **실제 해당 회차의 학생 발화·질문 의도**를 채점하며 사전 작성본과의 문자열 일치도로 감점·가산하지 않는다.
4. 두 기기에서 같은 답변을 동시 수정할 때 revision 충돌을 감지한다. 데이터 유실 없이 이전 revision 복원/변경 비교가 가능해야 한다.
5. 학생의 활동 분석 오류 신고는 공식 근거 정정 요청으로 처리한다. 서버는 학생의 개인 답변 저장 요청을 활동 분석 수정 권한으로 오인하지 않는다.
6. 원천 자료 교체 후 최초 1회 무료 재분석, 이후 유료 내규를 표시할 수 있으나 실제 결제/환불 규칙은 특별약관 승인 전 대외 확정으로 표현하지 않는다.

## 13.4 면접 세션과 이용권의 원자적 계약

- 최초 정상 평가 질문 Q0가 **학생 측에 정상 제시되었다는 서버 이벤트**(`first_evaluative_question_delivered`)를 기준으로 실전 이용권 1회를 차감한다. 세션 생성·장비 권한 확인·도입 인사에서는 차감하지 않는다.
- 실전 재접속은 **연결 끊김부터 10분 이내**면 같은 session ID, 실제 질문·답변·면접 진행 상태 및 남은 시간을 복원한다. 복원 과정의 중복 callback·retry는 추가 차감하지 않는다. 시간 경과에 따른 남은 시간 정지/감산의 기술 세칙은 별도 QA에서 승인한다.
- 복구 불가능한 서비스/시스템 오류 또는 서비스 귀책으로 평가 불능 묶음이 생긴 **불완전 리포트** 발생 시, 이용권 1회를 **한 번만 자동 복구**한다. 재시도·관리자 수동 처리와 중복 복구하지 않는다.
- 학생의 자발적인 면접 종료는 정상 개시 후라면 회차 사용으로 인정한다. 학생이 부당 차감을 주장하면 고객센터에서 접속·서버 오류·학생 설명을 검토하여 **구제 승인/반려 사유·담당자·이력**을 남기고 복구할 수 있다.
- 무기한 기본/추가 구매 면접 이용권은 지원처 전체에 공유된다. 사용기한이 없다는 사실은 서비스 제공 종료나 법정 환불 권리의 불변을 뜻하지 않는다. 이 경우의 구체적 정산 규칙은 **법률 검토/특별약관 v1.0 승인 전 미확정**이다.
- 연습 면접 사용기간은 첫 연습 면접 **실제 시작 이벤트**로 활성화하고 실전 7일/몰입 14일이다. 해당 기간 내 재답변은 무제한이지만 과다 요청 등에 관한 합리적 시스템 보호 기준은 별도 승인한다.
- 기존 사용횟수·플랜 업그레이드·추가 구매로 생긴 이용권은 **원장(ledger) 단위**로 기록한다. 동시 요청·중복 결제 콜백에서도 잔여가 음수가 되지 않아야 한다.

## 13.5 검색·AI 비서·지원처별 데이터 격리

1. 개인 검색·RAG의 선행 필터는 `account_id/student_id`, 발행된 `support_target_id`, 허용된 revision, 자료 상태다. **검색 뒤 화면에서만 타인 내용을 감추는 방식 금지**.
2. `source_ref_id/activity_id/question_id`로 인용 근거를 확인할 수 있어야 하며 출처 없는 학생 역할/성과를 AI 비서가 추가하지 못한다.
3. 사용자 문장·학생부 PDF·외부 문서에 포함된 권한 변경 지시·프롬프트는 **비신뢰 입력**이다. AI가 실행 권한을 취득한 것으로 처리하지 않는다.
4. AI 비서가 실제 검색·필터·강조·스크롤을 조작할 경우 명시적 허용 액션과 **성공 확인/실패/되돌리기** 계약이 필요하다. 현재 범위는 미확정으로, 실제 실행 전 성공 선언 금지.
5. 지원처 A/B/C의 활동 우선도는 공통 원천을 참조하더라도 **지원처별 판정값**을 사용한다. 실전 세션 시작 시 당시 지원처 공식 프로필 revision을 고정한다.

## 15.3 실전 화상 및 미디어 품질 게이트

- I05→I06(카메라/마이크 점검)→I10(실제 상태 기반 `면접관이 학생부를 살펴보고 있습니다` → `면접관이 질문을 정리하고 있습니다` → `곧 면접장에 입장합니다`)→I07 화상 면접으로 전이한다. 3단계는 **가짜 고정 타이머가 아니라 실제 작업·세션 준비 신호**로 진행한다.

- 최초 평가 Q0 정상 제시 시에만 실전 이용권 1회 차감; 10분 재접속 동일 회차 유지; 시스템 오류 복구와 60%/2클러스터 부분 평가 규칙은 변함없다.

## 15.4 답변 보관/리포트/반복 학습

- 답변 보관함의 `전체` 탭 금지, 연습은 세션별·지원처/유형 필터, 실전은 회차별·점수 표시. 원본 답변은 불변; 대표 지정은 별도 flag/관계로 관리한다.
- 실전 누적 통계는 **정상 완료된 평가에만 기본 집계**하고, `scoring_rules_version`/지원처가 다른 회차는 비교 조건을 명시한다. 부정확한 통합 평균은 금지한다. 세부 PDF 레이아웃은 미확정.
- 면접 직전 요약 공개는 개인 면접일 **D-1**. 잠금 문구는 `면접 하루 전 열려요`; 카드 콘텐츠는 핵심 활동·예상 질문·반복 보완·사실 확인·지원처 유의사항.
- 퀴즈의 유형/오답 가중, 지식한입·이슈픽 미디어 카드·즐겨찾기·연습 질문 저장은 제품 기능 방향으로 승인. **가중치 공식·외부 링크 검수·기사 갱신·저작권/임베딩·추천 모델은 미확정**.

## 15.5 추가 수용 테스트 (모두 제품 기능 점검, 디자인 완성이 아님)

- `UX-FR-01`: G02에서 학생부의 모든 승인 원문 항목·본문 순서·과목을 열람한다.
- `UX-FR-02`: G04에서 서로 같은 문자열을 가진 두 위치 중 **연결된 정확한 문장만** 강조한다.
- `UX-FR-03`: G04 저장한 질문이 `내가 추가한 항목`에 즉시 나타나며 선택 해제하면 사라진다.
- `UX-FR-04`: 가이드북에 질문 의도·원문 근거 보기·꼬리질문 보기·즉시 연습하기 버튼이 없다.
- `UX-FR-05`: 연습 피드백은 묶음 종료 후 **정성 카드/개선/참고 답변**을 표시하고 하단 버튼은 두 개다.
- `UX-FR-06`: 실전은 화상 전용. 미디어 권한 거부/장비 실패는 최초 Q0 전에 차감되지 않는다.
- `UX-FR-07`: 준비 시퀀스가 실제 작업 단계와 일치하고 실패 시 오류 화면으로 전환된다.
- `UX-FR-08`: 연습·실전 기록을 세션/회차별로 탐색할 수 있고 대표 답변이 원본 이력을 손상하지 않는다.
- `UX-FR-09`: 이슈픽·지식한입의 즐겨찾기와 이슈 질문 저장은 출처·권한·중복 저장 상태를 보존한다.
- `UX-FR-10`: 잠긴 직전 요약은 확정 개인 면접일 이전에 새어 나오지 않는다.
- `UX-FR-11`: 관리자 IA를 학생용 메뉴/개발 확정 범위에 임의 추가하지 않는다.

**우선 적용:** 기존 본문/구 PRD 복원표에 `시사 코너`, `다시 준비할 질문` 또는 `실전 채팅`이 **과거 표현·예시**로 남아 있으면 본 v3.0의 학생용 기능 계약을 적용한다. 구 방식의 참고 정보는 삭제하지 않고 역사 이력으로 관리한다.
