# 연속 시간축 영상 관측 구현

## 동작과 근거 범위

종료된 본인 면접의 동의된 `answer_recording`만 처리한다. 브라우저가 저장된 원본을 불러와 처음부터 끝까지 100ms 간격으로 디코딩한다. 최대 640px 프레임 한 장씩 같은 출처의 Worker로 전송하여 MediaPipe Face/Pose/Hand Landmarker의 VIDEO 모드로 순서대로 추적한다. 처리 속도에 맞춰 프레임을 버리지 않으므로 느린 기기는 시간이 더 걸린다. 원본 촬영의 모든 프레임을 분석한다는 의미는 아니며, 100ms보다 빠른 움직임은 관측 범위 밖이다.

정지 화면 6개를 외부 AI에 전송하던 신규 요청 경로는 로컬 추적으로 교체했다. 이전 결과는 별도 접기 영역에서 읽을 수 있다. 기존 유료 분석 함수의 이용량·실패비용 처리는 보존하며, 새 HTTP 경로는 호출하지 않는다. 새 추적은 OpenAI 키와 `NONVERBAL_ANALYSIS_ENABLED`에 의존하지 않고 유료 API 이용량을 발생시키지 않는다. GPT Live1은 사용하지 않는다.

얼굴은 변환행렬의 수직축 회전 근사값을 사용한다. 눈의 위치·동공·시선, 표정 계수, 감정, 태도, 능력, 합격률은 사용하거나 평가하지 않는다. 얼굴 방향 이탈은 25도 진입/18도 복귀의 히스테리시스와 300ms 지속 기준을 사용한다. 시작·복귀 중 하나가 영상 끝이나 누락으로 끊기면 구간만 표시하고 횟수에서 제외한다.

상체는 양 어깨 중심의 화면상 이동, 손은 같은 사람의 포즈 손목과 대응되는 손 랜드마크의 위치를 어깨 폭 단위로 정규화해 관측한다. 안정된 기준 위치에서 벗어났다가 복귀하는 완전한 왕복만 1회다. 상체 진입/복귀 반경은 화면 비율 0.065/0.022, 손은 어깨 폭 0.30/0.10, 왕복 길이는 700ms–8초다. 이는 명시적인 제품 집계 규칙이며 임상 검증된 행동 척도가 아니다. 카메라 움직임을 인물 움직임과 완벽히 구분하지 못하므로 원본 확인을 안내한다.

## 누락·신뢰·중복 집계

검출/존재/추적 모델 기준은 각각 0.75다. 포즈 관측 좌표는 visibility 0.75 이상을 요구한다. 손의 handedness 점수는 검출 신뢰로 오해해 사용하지 않으며 포즈 손목과의 공간 대응을 요구한다. 한 화면에 여러 얼굴 또는 포즈가 보이면 누구의 동작인지 추정하지 않고 모든 채널을 중단한다. 가림·낮은 신뢰·화면 밖·미검출·프레임 디코딩 실패가 나오면 해당 채널의 연속 상태를 초기화한다. 가림 전후를 이어 한 왕복으로 세지 않는다. 두 손은 별도 채널이며 두 값을 합쳐 사람의 전체 행동 횟수로 표시하지 않는다.

채널별 관측 비율은 계획된 100ms 시간 위치 중 모델 기준을 통과한 위치의 비율이다. 연속 실제 시간의 인식 확률이나 정확도 점수가 아니다. 화면에는 비율, 미관측 길이, 사유별 구간, 시작/복귀 확인 여부, 제한적 신뢰를 표시한다. 각 구간을 눌러 같은 원본 영상의 해당 시점으로 이동할 수 있다. 모두 미검출이면 관측 0%와 관측 불가로 표시한다.

## 저장·취소·지원 제한

서버는 학생 권한, 매체 소유권, 해당 면접·문항 연결, 종료 상태, 녹화 동의, 유효 문항을 확인한다. 시작 시 소유 매체에 lease를 생성하고 저장 직전에 다시 확인한다. 취소 또는 다른 lease로 교체된 결과는 저장하지 않는다. 45분 지난 lease는 재시작할 수 있다. 서버가 받은 숫자 신호와 원본 길이·순서·전체 시간축을 검증한 뒤 결과를 재계산한다. 임의의 평가 문장을 받지 않는다. 브라우저 결과가 원본에서 나왔다는 암호학적 증명은 아니므로 공적인 평가나 부정행위 판정에 사용하지 않는다.

프레임 이미지, 원본 얼굴 랜드마크, 음성은 새 분석 요청에 포함하지 않는다. 일시적인 방향/위치 신호는 서버 검증에 사용한 후 저장하지 않고, 관측 구간·횟수·누락·모델 버전 요약만 `media_assets.metadata.nonverbalTimeline`에 저장한다. 원본 영상과 과거 분석은 유지한다. 새 DB migration은 없다.

최대 20MB, 20분 영상이며 Worker, WebAssembly, OffscreenCanvas, createImageBitmap을 지원해야 한다. 최신 Chrome/Edge를 안내한다. 3개 모델은 메모리를 사용하므로 낮은 메모리 기기에서 실패할 수 있다. 모델 준비와 단일 프레임 타임아웃, 연속 디코딩 오류 중단, 명시적 취소와 재시도를 제공한다. 취소하면 Worker를 즉시 종료하고 객체 URL·캔버스·영상 버퍼를 해제한다. 완성 전 부분 결과는 저장하지 않는다.

## 배포와 검증

`npm run dev/build --workspace=@gakja/web`의 pre hook가 `scripts/prepare-nonverbal-assets.mjs`를 실행한다. npm의 정확한 `@mediapipe/tasks-vision@1.1.1` 런타임과 공식 revision 1 모델을 같은 출처의 정적 자산으로 제공한다. 모델 다운로드는 개발/빌드 때만 일어나며 SHA-256을 검증한다. 생성된 큰 자산은 Git에서 제외하고 준비 스크립트와 manifest를 관리한다. 운영 중 외부 CDN이나 외부 AI로 사용자 프레임을 보내지 않는다. 오프라인 빌드는 사전에 검증된 모델 파일을 준비해야 한다.

`tests/nonverbal-timeline.test.mts`는 전체 시간축, 불일치 입력, 중복 없는 왕복, 긴 대기 후 동작, 가림에서 상태 중단, 얼굴 경계 제외, 관측 0%, 다중인물/저신뢰, 소유권/종료/lease/취소/원본 보존을 확인한다. 이전 `nonverbal-analysis.test.mts` 회귀도 유지한다.

`tests/video-tracking-client.test.mts`는 순차 추출, 취소 후 프레임 중단/자원 해제, 브라우저 지원·크기 제한, 원본 길이 불일치, 연속 디코딩 오류를 검증한다. 세 파일의 집중 검사 18개가 통과했다. 다른 에이전트의 서버 lease·소유권·집계 경계 독립 코드 검토에서도 중대한 누락을 찾지 못했다.

브라우저 실측용 `.local/followup-qa-2026-10-23/nonverbal-preview.mjs`는 실제 컴포넌트/CSS와 추적기를 사용한다. 합성 캐릭터를 canvas로 6초 이동시켜 MediaRecorder WebM을 만들고 실제 프레임 디코딩·모델 추적을 수행한다. 기기 카메라·마이크·DB·외부 AI를 사용하지 않는다. 별도 결정적 좌표 예제는 반복 집계와 원본 시점 UI 확인용이며 실제 영상 검출 결과와 구분한다.

추가 공개 인물 fixture는 TensorFlow 공식 테스트에 포함된 Anna Shvets의 Pexels 4838220 운동 영상이다. 원출처·무료 사용 조건·5fps 변환 설명을 `.local/followup-qa-2026-10-23/public-video-source.md`에 기록했다. 제품 자산으로 배포하지 않으며 일반 면접에서의 정확도 보증이나 10fps 원본 검증이라고 표현하지 않는다.

2026-10-23 부모 에이전트의 CUA 실측에서 공개 영상의 130개 시간 위치 처리 완료를 확인했다. 상체 관측 비율 100%, 집계된 왕복 2개 구간(0.5–3.6초, 5.3–8.4초), 얼굴 0%, 왼손 16.9%, 오른손 73.1%였다. 두 번째 구간 버튼을 누른 원본 플레이어는 `currentTime=5.3`, 일시정지 상태였다. 합성 영상도 59개 위치 처리가 완료됐고 손은 0%로 표시했다. 이는 실제 디코딩·로컬 모델 실행·관측불가 처리·원본 시점 연결 확인이며, 별도의 사람이 주석한 정답 데이터와 비교한 정확도 평가가 아니다.

별도로 `http://localhost:3104`의 Next 개발 서버(`dev --webpack`)에서 실제 DB와 HTTP API를 검사했다. 기존 합성 계정의 완료 면접에 임시 메타데이터용 매체를 연결해 다른 소유자 거절, 중복/다른 lease 거절, 시간 위치 누락 거절, 취소 후 저장 거절, 재시도와 요약 영속 저장을 확인했다. 원본 바이트와 동의 메타데이터는 보존됐으며 숫자 프레임 배열은 저장되지 않았다. 임시 매체는 삭제했다. 이는 결정적 숫자 추적 fixture를 사용한 서버 검사이며 브라우저가 해당 DB 매체를 디코딩한 통합 검사는 아니다. 기록은 `.local/followup-qa-2026-10-23/api-flow-results.json`에 있다.

## 공식 자료

- [Face Landmarker Web](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js): VIDEO 모드, 변환행렬, 검출 기준, 동기 추론으로 인한 Worker 사용 근거.
- [Pose Landmarker Web](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js): 포즈 좌표·visibility, 영상 순차 처리와 옵션.
- [Hand Landmarker Web](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js): 손 좌표와 handedness의 구분, 영상 추적과 검출 기준.
- [공식 모델 목록](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker): Lite 모델 및 다운로드 경로. 얼굴·손 모델도 각 공식 task 문서에서 제공하는 revision 1을 고정했다.

모델 문서는 기능을 설명하며, 위 제품의 움직임 집계 규칙이나 정확도를 검증한 자료는 아니다.
