# 최종 가이드북 HTML 등록·발행

> 현행 계약·검증 갱신: 2026-10-14. [문서 적용 순서](document-authority.md)와 [서비스 PRD v2.2](../확정안/4.%20서비스_PRD_v2.2.md)를 따른다. [개선·검증 요약](learning-remediation.md)과 [후속 QA](../.local/learning-remediation-2026-10-14/report.md)·[화면 보고서](../.local/learning-remediation-2026-10-14/report.html)에 실제 API/저장값·학교 등록·같은 질문의 학습 연결 검증을 기록했다. 아래 이전 테스트와 화면은 당시 범위로 보존한다. 실제 OAuth·Live/STT·장기 회상·88교 전 학과 콘텐츠 품질·운영 보안은 후속 인수 게이트이며, 이번 결과가 모든 기능이나 실제 학습 효과의 완료를 뜻하지 않는다.

## 2026-10-14 현행 교재·학습 계약

신규 등록은 외부 검수된 FINAL 가이드북 HTML **한 파일**이다. 핸드북 두 파일이나 PDF 매니페스트 2.0을 현재 웹 발행의 필수 입력으로 요구하지 않는다. 과거 두 책 계약과 발행본은 호환·복귀를 위해 보존한다. 학생부 분석·활동 평가·원고 작성·조판·Quality Gate는 외부 제작 업무이며 웹에서 새 AI 원고로 대체하지 않는다.

지원처의 면접 단계 `interview_stage`는 선택 필드다. 알려진 값은 비어 있지 않은 문자열로 제공한다. 기존 교재의 누락/미정은 같은 대학·캠퍼스·학과·학년도·전형의 학습 연결을 끊는 변경 증거가 아니다. 양쪽에 확인된 다른 단계가 있을 때는 당시 맥락과 현재 준비를 구분하며 공식 학교 프로필의 적용 확인은 별도 검사한다.

발행본 질문·퀴즈·활동 평가가 앱 학습의 기준이다. 리포트 보완과제는 원래 질문·활동·지원처·버전·근거에서 생성하고 재발행/학교 변경으로 과거 답변을 재해석하지 않는다. 개인 경험의 자기 점검, 객관 개념의 승인 정답, 시도별 도움 기록을 구별한다. 미확인 사실을 발행된 모범 정답으로 바꾸지 않는다.

외부에서 학생부 구조화, 지원처별 활동 평가, 원고·편집 검수를 완료한 뒤 최종 HTML 한 파일을 등록한다. 제작 검수는 외부에서 수행하고 웹은 검증·미리보기·발행과 학습 데이터 연결을 담당한다.

## 관리자 작업

1. `/admin/imports/new`에서 학생과 연결된 제작 건을 선택한다.
2. 최종 가이드북 HTML 한 파일을 등록한다. 최대 5MB이며 핸드북은 필요하지 않다.
3. 학생·지원처·제작 건·목차·학습 데이터·외부 승인 참조·활동별 평가·질문/퀴즈 연결을 검사한다.
4. 발행 대기 버전의 교재 원본과 웹에서 읽는 구조를 미리 본다. 외부 승인 기록과 교재 본문, 학습 데이터의 내용도 대조한다.
5. 미리보기 확인을 기록한 뒤 발행한다. 확인 기록은 해당 파일·학습 데이터의 해시에 묶이며 다른 버전에는 재사용할 수 없다.

최종 HTML은 본문 `main[data-document-kind="guidebook"]`과 `application/json#gakja-learning-pack`을 포함한다. 제작자가 같은 승인 데이터에서 교재 본문과 JSON을 함께 출력해야 한다. 본문만 있는 HTML을 AI가 재분석해 문제·정답을 추정하지 않는다. 상세 계약은 `packages/content-contracts/README.md`, 데이터 타입과 목차는 `packages/content-contracts/src/index.ts`를 따른다.

원본 미리보기는 실행 권한 없는 sandbox iframe으로 표시한다. 학생도 본인에게 발행된 원본만 볼 수 있다. 실행 스크립트, 이벤트 핸들러, 외부 리소스, 중복 JSON은 등록 단계에서 거부한다.

## 활동별 평가와 학습 연결

- 공통 활동에는 안정적인 Activity ID, 학생부 원문 참조, 동기·역할·과정·결과·배운 점, 사실확인 상태를 저장한다.
- 교재에 포함한 지원처마다 S/A/B/C/F, 판정 사유, 근거 ID, 기준 버전을 기록한다. S/A/B/C/F는 해당 지원처의 면접 준비 우선도다.
- 지원처별 인재상 태그, 전공 연결, 대표 활동 후보·사유를 선택 필드로 제공한다. 명시적인 전공 연결 없음(null)을 다른 지원처의 값으로 대체하지 않는다.
- Activity ID → Question ID → Memory Item ID를 연결한다. 모의면접은 교재의 검수된 질문, 퀴즈는 제작자가 작성한 검수된 항목을 사용한다. 개인 경험은 자기 점검으로 처리하고 객관 개념만 승인 정답으로 판정한다.
- 최소 하나의 검수된 질문과 연결된 퀴즈가 있어야 등록할 수 있다. 모든 질문에 퀴즈가 있는 것처럼 표시하지 않는다.
- 활동·질문에서 연습을 시작할 때 선택 지원처와 개인 콘텐츠 버전을 함께 전달한다. 저장된 세션과 당시 근거는 이후 개정본에 맞춰 다시 해석하지 않는다.

## 개정과 기존 자료

동일 학생의 package_id를 유지하고 content_version을 올려 개정본을 등록한다. 같은 버전의 학습 데이터뿐 아니라 교재 원본이 달라져도 재등록을 거부한다. 같은 파일 재전송은 중복 버전을 만들지 않는다.

질문의 의도가 바뀌면 새 Question ID를 사용한다. 이전 버전에서 삭제했다가 재사용하는 ID도 모든 과거 버전의 의도와 비교한다. 학생 답변·녹음·퀴즈·면접·확정 리포트는 가져오기와 발행으로 덮어쓰거나 삭제하지 않는다. 발행된 과거 버전은 반려로 비공개 처리하지 않으며, 기존 두 책 버전으로의 복귀도 유지한다.

교재 발행과 버전 복귀는 학생의 학교 등록 정보와 개인 면접 일정을 덮어쓰지 않는다. 새 발행 시 계정의 현재 학교·캠퍼스·학과·전형·연도와 교재 정보를 다시 비교한다.

## API

- `POST /api/imports`: FormData studentId, productionJobRef, files(최종 가이드북 한 개). 발행 대기 버전 생성.
- `GET /api/imports/{versionId}/preview`: 관리자 또는 해당 학생의 review 권한 담당자에게 원본·구조·해시 반환.
- `POST /api/actions`: preview_confirm + payload(versionId,digest), 이후 publish + payload(versionId).
- `GET /api/documents?kind=guidebook&contentVersion=1`: 학생 본인의 발행본 원본 조회. contentVersion 생략 시 현재 발행본.
- 개인 퀴즈/면접의 sourceType=personal, sourceVersion은 승인된 교재 버전이다. 공통 학교 질문의 sourceVersion은 별도 학교 질문 revision이다.
