# 면접 바이블 반영안

점검일: 2026-10-12. 제공된 `2027_면접바이블_대학별정리_v1.0.md` 전체 10,818줄을 읽고 현재 학교 정보·일정·면접 문항 편성 코드를 대조했다. 원문은 88개 대학, 병합 PDF 188–419쪽을 포함한다. 이 문서는 제안이며, 대학 정보나 기출을 DB에 가져오지는 않았다.

**학교를 등록하면 면접 개요를 바로 보여주는 방향이 좋다. 다만 책에 있는 평가 비중을 질문 출제 비중으로 바꾸면 안 된다.** 공통 기출, 개인 활동 질문, 제시문 세트도 서로 다른 적용 조건이 필요하다.

## 가입부터 연습까지

`가입 → 지원 학교 선택 → 면접 안내 확인 → 공통 질문 첫 연습 → 생기부 연결 → 개인 질문 연습 → 약점 복습 → 재면접`

- 학교 선택은 **지원 학년도, 대학·캠퍼스, 전형, 모집단위**를 기준으로 한다. 모르는 항목은 미정으로 저장하고, 확정된 안내처럼 보여주지 않는다. 학과 대신 학부·자유전공을 지원하는 경우도 받는다.
- 등록 직후 면접 방식, 준비·응답 시간, 면접관·지원자 수, 평가 요소, 블라인드 유의사항을 한 화면에서 보여준다. 우선 출처가 있는 책의 개요를 제공하되 `제공 자료 기준 · 공식 확인 전` 상태와 해당 연도를 짧게 표시한다.
- 생기부를 아직 제출하지 않아도 해당 학교·전형에 적용 가능한 공통 질문으로 시작할 수 있게 한다. 학교에 공개 공통 기출이 없으면 `일반 연습`으로 구분한다. 없는 기출을 만들어 학교 기출로 표시하지 않는다.
- 생기부 분석이 끝나면 공통 연습 기록을 유지하면서 개인 활동 질문과 합친다. 독서·실험·협업 질문은 실제 활동 근거를 연결한다.
- 학교 안내는 `내 지원 학교 > 학교별 면접 안내`에서 다시 볼 수 있게 하고, 모의면접 시작 화면에서도 연결한다. 새 대메뉴를 늘릴 필요는 없다. 학교가 여러 곳이면 현재 선택한 지원처를 명확히 표시한다.

점검 시점에는 지원처 등록이 운영자 권한에 묶여 있고, 학생 계정 화면은 배정된 지원처를 읽기만 한다. 학생의 학교 선택 API를 따로 추가하되, 공식 정보 검수 권한은 운영자에게 유지해야 한다. 현재 면접 시작은 공개된 개인 질문 패키지를 요구하므로, 첫 공통 연습은 이 선행 조건을 분리해야 한다.

## 현재 구조에 연결할 데이터

| 정보 | 현재 구조와 반영 방법 |
|---|---|
| 학생의 지원처 | `support_targets`의 대학·캠퍼스·학년도·전형·모집단위를 유지하고, 학생이 검수된 목록을 선택할 수 있게 확장한다. |
| 대학의 면접 개요 | 현재 `school_profiles`는 학생·지원처별 검수 이력이다. 모든 학생에게 같은 자료를 복사하기보다 공용 대학 프로필과 그 버전을 참조하고, 필요할 때 학생별 보정값을 둔다. |
| 평가 요소 | `evaluation_weights`에 넣는다. 원문 단위가 비율인지 점수인지 함께 보존한다. 총점 400점이나 최종 전형 반영률 30%를 면접 내부의 100%로 오해하지 않는다. |
| 질문 주제 비중 | `question_distribution`과 평가 요소를 계속 분리한다. 책에 실제 문항 비중이 없으면 비워 둔다. 운영자가 만든 연습 비중은 `basis: training`으로 저장한다. |
| 공통 기출·예시·예상 질문 | 공용 문항 목록이 필요하다. 출처 유형, 출제 연도, 적용 학교·전형·모집단위, 원문/변형 여부와 검수 상태를 각각 보관한다. |
| 개인 활동 질문 | 사실을 고정한 문항 대신 템플릿을 둔다. 학생 활동의 ID·근거를 연결한 뒤 공개하고, 연결할 사실이 없으면 제외한다. |
| 제시문·MMI·집단 과제 | 자료, 주질문, 조건부 꼬리질문, 준비 시간, 진행 순서를 묶어 세트로 저장한다. 자료 없는 질문 한 문장으로 분해하지 않는다. |
| 출처 | 대학 공식 URL과 책의 로컬 문서 출처를 구분한다. 현재 `source_url`은 HTTP(S)만 받으므로 로컬 MD/PDF 경로를 넣을 수 없다. 문서 ID·해시·PDF 쪽·책의 인쇄 쪽을 별도 필드로 둔다. |
| 면접 일정 | 책의 월·기간은 참고 정보다. 공식 검수된 기간과 개인별 확정 일정을 구분하는 현재 `schedule` 규칙을 유지한다. 기간만으로 개인 D-day를 만들지 않는다. |

현재 `school_profiles`에는 `official_confirmed`, `historical_reference`, `sampled`, `training_configuration`, `needs_confirmation` 상태와 수정 이력이 있다. 책을 가져온 초기 상태는 **`historical_reference` 또는 확인이 필요한 자료**가 적절하다. 파일명이 2027이어도 수록된 기출은 2022–2026년, 예시·예상·후기가 섞여 있다. 공식 프로필에는 해당 학년도의 공식 출처와 검수 시점을 별도로 요구한다.

## 질문 비중과 반복 학습 편성

1. 학년도·대학·캠퍼스·전형·모집단위·면접 단계가 맞는 검수된 프로필과 문항만 후보로 받는다. 공식 기출, 책의 예시, 일반 연습을 구분한다.
2. 질문 주제 비중과 평가 요소를 별도 축으로 유지한다. 평가 태도 10%가 있다고 해서 태도 질문을 10% 출제하지 않는다. 답변 하나에 학업·진로·논리·태도를 함께 평가할 수 있다.
3. 질문 비중이 실제로 공표된 경우만 `official`을 사용한다. 기출 표본에서 계산하면 동일 전형·연도 범위의 **중복 제거한 주질문 수, 표본 크기, 분류 기준**을 함께 저장하고 `sample`로 표시한다. 책에 없는 비중은 `training`이다.
4. 문항 개수 기준 편성에는 현재의 최대 잔여 방식이 적합하다. 시간 기준 비중과 꼬리질문 포함 비중은 별도 알고리즘이 필요하다. 첫 지정 질문도 배정 수에 포함하고, 부족한 범주를 실제 편성 결과에 기록한다.
5. 비중을 계산하기 전에 전체 적격 문항을 확보한다. 현재 `interviewQuestions`는 먼저 최대 8개로 잘라서 동일 문항 반복과 범주 부족을 만들 수 있다. 전체 후보에서 범주를 배정하고, 범주 안에서 복습 시점·약점·미경험 문항·최근 출제 회피를 고려한다.
6. 개인 질문은 실제 학생 근거가 있을 때만 활성화한다. 근거가 없으면 질문을 제외하거나 사실을 전제하지 않는 질문으로 변형하고 `기출 변형`으로 기록한다. 제시문과 조건부 꼬리질문은 세트의 순서를 유지한다.
7. 면접을 시작할 때 프로필 버전·문항 버전·계획 비중을 고정하고, 리포트에는 실제 질문·꼬리질문·편성 부족을 저장한다. 이후 대학 안내가 수정되어도 과거 평가의 기준이 바뀌지 않아야 한다.

공통 기출의 재사용 기준은 “대다수에게 적용 가능”에 더해 **그 전형에 적용 가능하고, 사실을 새로 만들어내지 않는가**다. 예를 들어 `협업에서 갈등을 해결한 경험`은 공통 질문으로 가능하지만 `생기부에 적힌 특정 실험에서 본인의 역할`은 개인 기록 연결이 필요하다. 특정 활동을 했다는 전제를 지운 경우에는 원문 기출과 동일한 질문으로 표시하지 않는다.

## 데이터가 쌓일수록 달라져야 할 것

- 리포트의 약점은 평가 요소와 활동·주제로 나눠 쌓는다. `지원 동기가 약함`, `환경 개념 설명이 약함`, `근거를 빠뜨림`은 다음 행동이 다르다.
- 다음 학습은 `관련 지식한입 → 짧은 개념 퀴즈 → 같은 역량의 다른 질문 → 재면접`으로 연결한다. 동일 문장을 외우는 성공과 새로운 질문에 적용하는 성공을 구분한다.
- 학교를 바꿔도 공통 역량의 성장 기록은 유지하고, 학교별 평가 기준으로 다시 해석한다. 학교마다 다른 기준을 하나의 절대 점수로 비교하지 않는다.
- 면접관 반응의 5% 단계는 표현을 부드럽게 조절하는 내부 값으로 쓸 수 있다. 사용자의 창의적인 답이나 다른 견해를 터무니없음으로 판정하지 않는다. 자료와의 모순·질문 이탈·근거 없는 주장·회복 여부를 검수된 기준으로 보고, 모델 확신이 낮으면 중립 반응을 유지한다. 책의 오류 있는 예시를 반응 기준으로 쓰지 않는다.

## 우선순위와 확인 기준

**P0:** 학생의 학교 선택, 출처·연도가 보이는 즉시 개요, 공통 질문 첫 연습, 평가 비중/질문 비중 분리, 허위 개인 사실 방지.

**P1:** 공용 프로필·문항 목록, 전체 후보 편성, 최근 질문 회피, 약점·복습 시점 반영, 리포트에서 다음 학습으로 연결.

**P2:** 제시문 자료·준비 시간, MMI 순환, 제출형 영상, 집단 과제의 실제 진행 방식. 현재 엔진이 지원하는 서류 개인 면접과 구분해 단계적으로 구현한다.

**P3:** 공식 모집요강 대조와 연도별 갱신, 변경 이력·영향받는 지원처 알림. 공식 일정 검수는 P0 개요의 검수 상태와 별도로 운영한다.

출시 전 확인할 항목:

- 같은 대학의 다른 캠퍼스·전형·학년도가 섞이지 않는가.
- 점수/비율 단위와 평가/문항 비중이 구분되는가. 공개 비중이 없는 대학에서 임의 수치가 공식처럼 보이지 않는가.
- 사용자의 실제 활동 없이 특정 활동·결석·수상·독서를 전제하는 질문이 나오지 않는가.
- 생기부가 없는 신규 사용자도 공통 연습을 시작하고, 이후 개인 학습에 이력이 이어지는가.
- 문항을 추가하면 실제 편성 후보가 늘고, 최근에 한 문항을 계속 반복하지 않는가.
- 제시문 이미지·표·도표, 블라인드 규칙과 조건부 꼬리질문이 누락되지 않는가.
- 공개 기출이 없는 대학, 면접이 없는 전형, 현재 미지원 방식의 화면 표시가 정확한가.
- 기간 정보가 개인 확정 일정과 D-day로 바뀌지 않는가.
