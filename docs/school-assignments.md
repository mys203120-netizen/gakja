# 학교 질문 과제와 답변의 학습 축

> 현행 계약·검증 갱신: 2026-10-14. [문서 적용 순서](document-authority.md)와 [서비스 PRD v2.2](../확정안/4.%20서비스_PRD_v2.2.md)를 따른다. [개선·검증 요약](learning-remediation.md)과 [후속 QA](../.local/learning-remediation-2026-10-14/report.md)·[화면 보고서](../.local/learning-remediation-2026-10-14/report.html)에 실제 API/저장값·학교 등록·같은 질문의 학습 연결 검증을 기록했다. 아래 이전 테스트와 화면은 당시 범위로 보존한다. 실제 OAuth·Live/STT·장기 회상·88교 전 학과 콘텐츠 품질·운영 보안은 후속 인수 게이트이며, 이번 결과가 모든 기능이나 실제 학습 효과의 완료를 뜻하지 않는다.

## 2026-10-14 리포트 기반 보완과 도움 기록

리포트에서 만든 과제는 `assignment_create`의 `reportId`·`questionId`·`requestId`를 사용한다. 서버가 본인 리포트와 세션, 실제 답한 유효 턴 및 리포트 구간을 대조하고 당시 질문·개인 발행본/공통 출처 revision·활동·원문·지원처 스냅샷을 복구한다. 현재 교재에서 질문이 삭제됐더라도 당시 발행본을 사용할 수 있으면 그 기준으로 배정한다.

당시 승인된 개인 질문에 자기점검 카드가 없으면 그 질문·필수 의미 요소의 미채점 `short_speech` 과제를 만든다. 새로운 객관 정답이나 학생 경험은 생성하지 않는다. 당시 승인 질문·발행본을 확인할 수 없거나 생성된 꼬리질문이면 409로 이유를 알리며 현재 질문으로 대체하지 않는다. 부모 과제·재훈련은 원래 지원처·버전·근거를 복사한다.

과제의 자료/힌트 도움은 `assignment_help`와 `assignmentId,itemId,helpKind`로 기록한다. AI 비서의 과제 도움은 `assignmentId,assignmentItemId`를 서버가 검증하고 실제 완료한 응답과 함께 남긴다. 제출은 서버 도움 기록과 제출된 도움 표시를 합쳐 `assistance_recorded:true`, `assisted`, `hintUsed`, `helpKinds`를 보존하며 false 입력으로 기존 도움을 지우지 않는다.

정답 검증·자기 의미 체크·도움·확인 필요는 서로 다른 결과다. 후속 면접 링크도 과제의 당시 질문·지원처·개인 버전/공통 revision을 유지한다.

2026-10-13 구현. 생기부가 발행되기 전에도 등록한 학교·학과의 공개 질문으로 **실제 퀴즈 과제**를 만들고 시작·제출·재훈련할 수 있다. 자유 Q&A에 단순히 과제 이름을 붙이지 않는다.

## 생성 계약

`POST /api/learning`

```json
{
  "action": "assignment_create",
  "requestId": "새 UUID",
  "targetId": "내 지원처 ID",
  "questionIds": ["선택 학교에서 공개된 공통 질문 ID"],
  "activityId": "선택사항: 발행된 자료의 확인된 내 활동 ID"
}
```

`memoryItemIds`와 `questionIds`는 상호 배타적이다. 기존 개인자료 과제 계약은 유지한다. 학교 과제의 질문·공식 출처·판정 방식은 서버가 공개 질문 은행에서 확정한다. 클라이언트가 보낸 정답, 출처, 지원처 스냅숏은 신뢰하지 않는다.

학교 과제는 `package_id=null`, `content_version=0`, `source_kind=common`으로 저장한다. 개인자료 과제는 기존 `content_packages` 및 `(package_id,content_version)` 외래 키를 유지한다. PostgreSQL 제약은 두 유형을 구분하고 공개 질문의 자기점검 방식·실제 지원처 스냅숏·공통 질문 개정 번호·출처 묶음을 요구한다. 브라우저의 직접 DB 쓰기 차단과 학생별 조회 RLS는 유지된다.

## 동일한 질문의 연속성

- 등록한 **학교·캠퍼스·학과·입학연도·전형 + 질문 ID·개정 번호**를 기준으로 자유 Q&A와 동일한 학교 퀴즈 항목 ID를 사용한다.
- 제출 응답, 회상 기록, 학습 이벤트, 답변 변경 이력에 `target_id`, `target_snapshot`, `source_kind`, `source_type`, `common_revision`, `source_snapshot`을 저장한다.
- 기존 `assignment_start`, `assignment_submit`, `assignment_retry`로 실제 과제 상태가 바뀐다. 동일 요청 중복 제출은 한 건으로 처리한다.
- 완료 화면에서 공식 근거, 같은 질문의 모의면접, 답변 변화 리포트로 이어진다. 개인 경험·가치관 답변의 `correct`는 `null`이며 자기평가나 체크박스가 객관적 정답으로 바뀌지 않는다.
- 답변이 떠오르지 않은 학교 질문은 재훈련 대상으로 남긴다. 학생부 사실이 아니므로 사실 확인함에 임의로 넣지 않는다.

## 과거 기록 보호

지원처가 바뀌어도 이미 만든 과제와 재훈련 과제는 **당시 학교·학과·질문 출처**를 유지한다. 현재 지원처로 새 과제를 만들 때에는 해당 지원처의 최신 공개 질문만 허용한다. 공통 학교 질문의 과거 지원처가 현재와 다르면 당시 기준의 기록으로 보존하며 현재 학교 질문으로 변환하지 않는다. 개인 교재 질문은 원래 발행본·지원처의 기본 연습 경로를 유지하고 현재 공식 프로필/편성 비율을 덧씌우지 않는다.

선택 활동은 발행된 본인 자료의 확인된 활동만 허용한다. 활동 제목·내용과 실제 학생부 원문, 발행 번호를 과제에 고정해 이후 학생부 재발행으로 근거가 바뀌지 않는다. 공통 질문 은행의 동일 `(id,revision)` 출처는 변경하지 않고 새 revision으로 발행해야 한다.
