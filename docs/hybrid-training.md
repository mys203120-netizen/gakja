# 혼합형 면접 훈련

학생은 **오늘 훈련 → 준비 현황 → 내 기록**의 세 메뉴로 면접 준비를 이어갑니다. 기간을 7일이나 한 달로 고정하지 않습니다. 가입일, 선택한 학교·학과·전형의 실제 면접 일정, 날짜별 학습 가능 시간과 저장된 답변 관찰로 가까운 일정을 다시 만듭니다.

## 가입과 학습 시간

학교·학과·전형 등록 후 학습 시간 설정이 이어집니다. `/availability`에서 이후에도 수정할 수 있습니다.

- 평일·주말의 하루 시간: 각각 0~480분.
- 학습하지 못하는 날짜와 특정 날짜의 시간 예외.
- 준비 시작일은 서버의 가입 시각을 한국 날짜로 변환해 저장하며 설정을 수정해도 유지합니다.

시간 적용 순서는 **가입 전·학습하지 못하는 날 0분 → 날짜별 예외 → 평일·주말 하루 시간**입니다. 학습하지 못하는 날은 날짜별 예외보다 우선합니다. 수능 전후로 시간을 나누거나 수능일을 자동으로 제외하지 않습니다. 이전 형식의 설정은 이전 시점에 적용되던 평일·주말 시간을 현재 형식으로 가져옵니다. 설정의 revision을 검사해 다른 화면의 최신 변경을 덮어쓰지 않습니다. 저장 전 제안값을 실제 설정으로 취급하지 않습니다.

## 학교별 실제 일정

등록한 지원처의 연도·학교·캠퍼스·학과·전형과 연결된 저장 일정을 사용합니다. 개인 면접일, 정확히 연결된 공개일, 공개 면접기간, 직접 선택한 준비 목표를 구분합니다.

- **개인 확정일:** 학생이 등록한 개별 면접일을 우선합니다.
- **공개일:** 학교 공개 일정이며 개인 배정 확인이 필요하다고 표시합니다.
- **공개기간:** 기간을 그대로 보여주고 기간 시작 전의 준비 목표로 사용합니다. 시작일을 개인 면접일로 저장하거나 확정하지 않습니다. 화면에도 `준비 목표 D-X`로 구분합니다.
- **확인 대기·전형 불일치·면접 미실시·지원 범위 밖:** 다른 전형의 날짜를 가져와 자동 계획을 만들지 않습니다.

남은 가능 시간은 오늘부터 준비 마감 전날까지 날짜별 시간을 합한 값입니다. 여러 학교를 지원할 때 하루 시간은 학생 한 명의 공통 예산으로 나눕니다. 학교별 남은 가능 시간을 서로 더하면 안 됩니다. 데이터 출처·검증 범위는 [면접 일정 연동](admission-calendar.md)을 따릅니다.

## 하루 배분과 첫 진단

오늘 화면은 **누적 회상 또는 첫 진단 → 받은 과제·퀴즈·집중 보완 → 연결 면접 → 오늘 정리**를 순서대로 제시합니다. 퀴즈와 받은 과제는 집중 보완 예산의 일부를 사용하며 하루 시간 위에 더하지 않습니다. 시간에 따라 주제별 훈련을 여러 개 배치하며 설정한 시간은 학습 시간으로 사용합니다. 자동 휴식 과제를 계획이나 캘린더에 넣지 않습니다. 20분은 고정 하루 분량이 아닙니다.

오늘 훈련의 하위 메뉴는 **오늘 계획 / 자유 연습 / AI 비서**입니다. 자유 연습은 퀴즈·Chat 면접·Live 면접을 각각 한 번 노출하고 과제함은 보조 경로로 둡니다. 글·음성 답변이나 과제를 진행하는 화면에서는 탐색 탭을 숨기고, 현재 질문의 AI 도움창을 열어 같은 질문으로 돌아옵니다. 자유 연습을 방문했다는 사실만으로 특정 자동 차시를 완료하지 않습니다.

퀴즈는 기존 서버의 검수된 문항과 학교 질문 회상 풀을 재사용합니다. 검수된 객관식 개념과 자기 점검형 회상 질문을 구분합니다. 같은 지원처·자료 버전·문항 ID·계획 ID를 서버에서 검사하고, 해당 계획에서 시작한 실제 세션의 전체 제출로 완료를 확인합니다. 계획으로 다시 들어오면 진행 중인 퀴즈를 이어갑니다. 과제는 현재 학교·자료에 맞는 받은 과제를 공유 예산 안에 한 번 배치하고, 모든 항목의 유효 제출이 있어야 수행으로 인정합니다. 시간 안에 배치할 수 없는 과제는 경고와 과제함에 남깁니다.

계획에 연결된 퀴즈와 과제는 한 번 시작하면 실제 답변 화면으로 이어지고, 제출 뒤 다음 차시를 결과 상단에 제안합니다. 자유 연습의 기존 수동 시작과 다시 연습은 유지합니다. 차시의 분 표시는 권장 배분이며 실제 진행 시간을 측정한 값이 아닙니다.

연결 면접은 여러 본질문에 꼬리질문을 이어갑니다. 오늘 정리는 모든 지원 학교의 본질문 답변·퀴즈·과제·도움 사용·남은 보완을 원본 영수증으로 요약하고, 보완한 한 가지와 내일 다시 답할 질문을 저장합니다. 선택한 질문은 지원처·콘텐츠 버전이 고정된 유한한 재확인 요청으로 반영하며 다른 진단 요청을 지우지 않습니다. 새 정리 저장은 요약 버전을 한 번 갱신하고 같은 제출 재시도는 중복 요청이나 추가 버전 증가를 만들지 않습니다.

AI 도움은 해당 세션·본질문 또는 꼬리질문·미제출 초안의 맥락을 사용합니다. 도움창을 열어도 답변 편집기와 녹음은 유지하며, 진행 중인 Live 녹음은 일시정지합니다. 도움 사용은 원본 시도에 남기고, 도움 대화만으로 답변이나 차시를 완료하지 않습니다. 닫으면 같은 질문으로 돌아가며 기존 타이머·녹음은 학생이 계속하기를 선택해 재개합니다.

첫 진단은 현재 지원처와 같은 자료 버전에서 활동·전공·학교 연결 질문을 가능한 범위에서 골라 짧게 답하는 과정입니다. 관찰 대상은 실제 답변, 도움 사용, 시간 초과, 검수된 개념 문항의 결과와 학생이 다시 연습하겠다고 선택한 질문·영역입니다. 진단 완료를 실력 확인·합격 가능성으로 표시하지 않으며 아직 답하지 않은 내용은 **미확인**으로 남깁니다.

집중 보완은 확인된 보완점과 미확인 내용을 함께 다룹니다. 연결 면접에서는 다른 주제도 이어서 답합니다. 남은 기간의 긴급도와 학교별 연습 배분을 함께 고려하며 가까운 7일은 자세한 예정으로 보여줍니다. 7일은 전체 과정의 길이가 아닙니다.

## 글·음성·활동 기록

훈련 중 글·음성 입력을 전환해도 같은 질문과 활동에 답변을 남깁니다. 저장한 방식은 분리해 보존합니다.

- 실제 제출이 `text`이면 글, `recording`이면 음성으로 기록합니다. 영상 세션에서 글로 답해도 음성 수행으로 집계하지 않습니다.
- 본질문과 생성된 꼬리질문은 각각의 질문 ID를 유지합니다. 꼬리질문의 활동 연결만 저장된 본질문과 당시 자료에서 가져옵니다. 본질문의 평가 기준을 다른 꼬리질문에 적용하지 않습니다.
- 학생이 편집한 답변도 저장한 질문·자료 버전의 활동과 연결합니다. 재발행한 현재 자료로 과거 기록을 바꾸지 않습니다.
- 음성 원본·원전사·화면 정리·전사 정정과 새 답변 시도를 구분합니다. 도움 사용도 해당 시도에 남습니다.
- 학생이 직접 확인한 추가 사실은 활동 메모로 모읍니다. 학생부 원문과 과거 답변을 자동으로 덮어쓰지 않습니다.

준비 현황은 활동별 본질문·꼬리질문 답변, 글·음성 시도, 도움 사용, 학생 확인 메모와 보완점을 함께 보여줍니다. 내 기록에서 실제 시도와 답변을 비교할 수 있습니다. 준비 상태는 관찰한 내용이며 종합 실력 점수나 근거 없는 완료율을 만들지 않습니다.

## 보완 상태의 공통 판단 기준 — 1단계

오늘 훈련의 보완 배분과 준비 현황의 보완 표시는 같은 유효 기록과 같은 보완 상태 판정을 사용합니다. 화면마다 과거 도움 사용 횟수나 진단 선택값으로 보완 여부를 별도 계산하지 않습니다. 과거 도움 사용 횟수는 이력으로 보존하되, 이후 도움 없이 확인한 기록이 있으면 현재 보완 여부를 다시 판단합니다.

### 범위와 해결 조건

- 보완 요청은 학생 소유의 **지원처 ID와 학교·캠퍼스·학과·전형·지원학년도 식별값, 질문 또는 활동 ID, 콘텐츠 버전**에 연결합니다. 지원처 ID가 같아도 지원 정보나 질문의 의도가 바뀐 경우 이전 근거를 새 범위에 재사용하지 않습니다.
- 다른 지원처, 다른 질문·활동, 이전 콘텐츠 버전의 답변으로 현재 보완을 해결하지 않습니다. 공통 활동이라도 해당 지원처에서 요구한 확인 범위가 일치해야 합니다.
- 요청에는 요청 원인, 요청 시각 또는 시각 미확인 여부, 확인할 질문·활동, 해결 조건과 해결에 사용한 제출 근거를 남깁니다. `보완 필요 → 재확인 → 해결` 상태를 구분하며 해결 근거가 더 이상 유효하지 않으면 다시 보완 대상으로 판정합니다.
- 도움 없이 제출했다는 사실과 검증된 성공을 구분합니다. 검수된 개념 문항의 정답, 면접 답변의 도움 없는 재답변과 학생 확인 등 실제로 저장한 관찰만 사용합니다. 도움 사용 여부·결과가 없는 기록을 성공으로 추정하지 않습니다. 분야 전체의 요청은 정해진 재확인 과제로 풀어내며 한 질문의 답변을 분야 전체의 숙달로 표시하지 않습니다.
- 영역 보완은 요청 시 같은 범위의 대표 질문을 최대 두 개로 고정합니다. 질문별 재확인 완료를 먼저 반영하고, 두 질문을 모두 마쳐야 영역 과제를 해결합니다. 이후 질문이 추가되어도 완료한 과제를 자동 확장하지 않습니다. 면접에서는 도움 여부가 명시적으로 기록된 무도움·시간 내 본질문 재답변을 과제 완료로 인정하며, 숙달이나 정답 판정과 구분합니다. 퀴즈·회상은 검수된 문항의 확인된 정답이 있어야 합니다.
- 보완의 추가 우선순위는 해당 범위에 적용합니다. 한 요청 때문에 다른 학교의 실전 연습이나 면접 임박 배분이 계속 밀리지 않도록 합니다. `계속 집중하기`와 같은 지속적 학습 선호를 도입할 때는 해결 가능한 보완 요청과 별도로 다룹니다.

### 기존 선택값 이전

기존 `needsReviewQuestionIds`·`focusCategories` 선택값은 현재 지원처와 콘텐츠 범위에 맞는 재확인 요청으로 이전합니다. 과거 요청 시각을 알 수 없으면 **요청 시점 미확인**으로 보존하며 이전 시각을 실제 요청 시각처럼 만들지 않습니다. 범위나 버전을 확인할 수 없는 선택값은 현재 자료의 성공 기록으로 임의 해결하지 않고 재확인 대상으로 남깁니다.

시각 미확인 요청은 이전부터 존재한 성공 기록만으로 자동 해제하지 않고 재확인 과제로 연결합니다. 해당 요청과 연결된 새 확인 근거로 해결 여부를 판단합니다. 이전은 반복 실행해도 같은 요청을 중복 생성하지 않아야 합니다. 이전한 범위에서는 새 상태 체계만 배분에 사용하며 기존 선택 배열이 별도로 보완 가중치를 더하지 않습니다. 기존 선택과 진단 완료 이력 자체는 보존합니다.

### 근거 변경과 중복 제출

보완 상태는 원본 제출의 현재 유효성, 지원처·콘텐츠 범위, 도움 사용과 결과를 기준으로 재계산합니다. 해결 근거였던 답변이 무효화되거나 도움 사용·결과·연결 정보가 정정되면 해당 요청과 관련된 준비 현황 및 아직 시작하지 않은 계획을 다시 판정합니다. 다른 유효한 해결 근거가 남아 있으면 해결을 유지하고, 해결 조건을 더 이상 만족하지 않으면 재활성화합니다. 원본 이력은 삭제하거나 성공 기록으로 덮어쓰지 않습니다.

동일 제출의 네트워크 재시도나 재처리는 **제출 영수증 ID**를 기준으로 한 번만 집계합니다. 시각이나 답변 문자열이 다르다는 이유로 같은 제출을 새 수행으로 세지 않습니다. 학생이 의도적으로 다시 답한 별도 시도는 별도 영수증으로 남기며, 그 시도가 현재 요청의 해결 조건에 맞는지 다시 확인합니다.

### 1단계 완료 조건

**동일한 유효 기록으로 오늘 훈련과 준비 현황이 같은 보완 상태를 표시하고, 해결·재활성화가 모두 재현되어야 합니다.** 다음 검증을 포함합니다.

- 날짜가 있는 요청과 요청 시점 미확인인 기존 선택값을 각각 이전하며, 반복 이전과 기존 배열의 중복 가중치가 없습니다.
- 동일 범위의 유효한 후속 확인으로 해결하고, 다른 지원처·질문·활동·콘텐츠 버전의 기록으로는 해결하지 않습니다.
- 동일 제출 재시도는 수행 횟수와 해결 근거 수를 늘리지 않습니다. 별도 재답변은 별도 시도로 남습니다.
- 해결 근거의 무효화 또는 도움 사용 정정으로 재활성화하고, 남아 있는 다른 유효 근거가 있으면 해결을 유지합니다.
- 오늘 훈련과 준비 현황이 같은 판정 결과를 사용하며, 기록의 글·음성 방식에 따라 별도의 보완 상태가 생기지 않습니다.

## 재계획과 보존

새 답변, 진단 후 선택, 지원 정보나 가용 시간 변경을 반영해 아직 시작하지 않은 자동 계획을 다시 구성합니다. 지난 계획, 완료한 계획, 오늘 시작한 훈련과 직접 추가한 계획은 보존합니다. 다만 같은 지원처의 학과·전형 등 식별 정보가 바뀌어 더 이상 열 수 없는 미완료 훈련은 이력으로 보관하고 오늘의 고정 시간에서 제외합니다. 동일 지원 정보의 자료 재발행만으로 이미 시작한 훈련을 버리지 않습니다. 완료한 학습 시간은 계속 예산에 반영하며, 진행 중인 보완 질문이 있으면 새 보완 차시는 가능한 다른 질문을 우선합니다. 미완료 과제를 다음 날 전부 더하지 않습니다. 보존할 계획이 새 하루 가능 시간을 넘으면 추가 배치를 줄이고 확인 내용을 표시합니다.

자동 훈련은 계획과 실제 세션을 연결하며 실제로 제출·종료한 기록으로 수행 여부를 확인합니다. 오늘 정리는 학생의 명시적 마무리로 기록합니다. 이전 자동 휴식의 과거·시작한 기록은 보존하지만 새 자동 계획에는 넣지 않습니다. 직접 추가한 계획은 기존 자료·학습 주소를 유지하고 자동 세션으로 바꾸지 않습니다.

## 조회와 집계 분리

일부 질문만 답하고 종료한 진단은 오늘 훈련과 캘린더 모두 미완료로 남습니다. 퀴즈·과제 원본이 무효화되면 완료와 준비 현황도 다시 판단하며, 과제 제출의 복습 미러를 별도 수행으로 중복 집계하지 않습니다.

2026-10-21 적용: 공통 초기 조회, 커서 기반 목록·ID 상세, 전체 유효 이력의 재생성 가능한 요약을 분리했습니다. 응답 계약과 로컬 측정은 [학생 화면 조회 계약](student-record-read-contract.md)에 기록합니다.

앱 공통 조회는 계정·지원처·설정과 필요한 요약으로 제한합니다. 오늘 훈련과 준비 현황은 각 화면의 요약을 조회하고, 기록 목록은 제한된 개수로 조회하며 답변·리포트 본문은 상세 진입 시 불러옵니다. 목록의 이어 조회는 **생성 시각 + ID**의 안정적인 순서를 사용하며 첫 페이지 기준점과 다음 커서를 유지합니다. 동일 시각 기록, 조회 중 새 기록 추가, 학교 변경에서도 중복·누락 없이 이어지는지 검증합니다.

화면의 페이지 크기와 관계없이 준비 현황·보완 상태·계획은 전체 유효 이력을 반영합니다. 최근 기록만 보고 오래된 활동을 미학습으로 바꾸지 않습니다. DB 집계 또는 같은 의미의 요약 모델은 제출 중복 제거, 정정·무효화, 지원처·콘텐츠 버전 범위를 동일하게 적용해야 합니다. 원본 이력으로 요약을 재생성할 수 있어야 합니다.

학생별 원본 revision과 공통 질문 revision에 연결한 `student_read_models`를 사용합니다. 첫 생성과 원본 변경 뒤에는 전체 원본을 다시 접어 계산하고, 같은 revision의 화면 전환에서는 요약만 읽습니다. 오늘 훈련과 준비 현황은 같은 training projection의 보완 상태를 사용합니다. 목록의 30개 제한이 집계 근거를 제한하지 않습니다. 계획에는 최신 시도와 현재 질문별 상태만 전달하며, 누적 답변 수는 전체 유효 제출에서 계산합니다. 과거 답변 본문·전체 요청 이력을 이 요약에 복제하지 않습니다.

원본의 정정·무효화·삭제, 도움 여부 변경, 지원처·자료 변경은 DB 트리거로 요약을 무효화합니다. 소유자가 바뀌는 경우 이전·새 소유자 모두 갱신하며, 단순 초안 입력과 heartbeat는 학습 집계를 매번 다시 만들지 않습니다. 잠금과 revision 전후 확인으로 변경 중인 원본을 이전 요약으로 확정하지 않습니다. 캐시를 삭제해도 원본 기록과 보완 근거로 재생성할 수 있습니다. 원본 변경 후의 전체 집계 비용까지 이력 수와 무관한 상수라고 주장하지 않습니다.

성능 검증은 100개·1,000개·10,000개 규모의 합성 기록에서 응답 크기, DB 쿼리 수·반환 및 스캔 행 수, 서버 응답 시간의 중앙값·상위 지연을 함께 측정합니다. 공통 첫 응답과 기록 페이지의 반환 행 수는 고정 상한을 두고, 전체 이력 JSON을 다시 전송하거나 JS에서 반복 스캔하지 않습니다. 측정 환경과 전후 수치를 함께 기록하며 단순히 `LIMIT`이 있다는 이유로 서버 비용이 제한된 것으로 판단하지 않습니다.

답변·진단·시간·지원 정보가 바뀌면 관련 활동과 보완 요약을 갱신합니다. 계획 갱신은 답변한 학교 하나에 한정하지 않고 **여러 지원 학교가 공유하는 날짜별 하루 시간 예산**도 다시 계산합니다. 완료·시작·직접 추가한 계획의 보존 원칙은 유지합니다.

## CSS 소유권과 동작 보존

전역은 토큰·초기화·폰트·문서 기본값을 담당하고, 앱 틀은 헤더·사이드바·하단 네비게이션을 담당합니다. 페이지는 배치를, 공통 컴포넌트는 자체 상태와 모양을 담당합니다. 버튼·입력·토글·메뉴·툴팁의 상태 표현을 페이지 전역 선택자로 다시 덮어쓰지 않습니다. 기능 스타일은 해당 화면 또는 컴포넌트 범위로 이전하며 중복 규칙을 함께 제거합니다.

루트의 전역 CSS import 41개를 기본 CSS 1개로 줄이고 기능 규칙을 소유 영역별 CSS Modules로 옮겼습니다. 원래 DOM 훅은 테스트·행동 연결용으로 유지하고, 소유 모듈의 지역 클래스와 함께 사용합니다. 같은 선택자·조건 안에서 중복된 선언을 제거했습니다. 이는 소유권과 변경 영향 범위의 정리이며 CSS 전체 바이트가 줄었다는 주장은 아닙니다. 프로덕션 CSS의 애니메이션 이름도 실제 브라우저 기준으로 확인합니다. 구체적인 경계와 이전 검증은 [CSS 소유권](css-ownership.md)에 기록합니다.

영역을 하나씩 이전하기 전에 모바일·데스크톱의 모양과 동작을 기준으로 고정합니다. 특히 모바일 주 메뉴는 **아래로 스크롤할 때 표시하고, 마지막 표시 조건 이후 1.4초에 부드럽게 숨기는 동작**을 보존합니다. 위로 스크롤할 때 다시 나타나거나 즉시 깜빡이지 않아야 합니다. 키보드 포커스와 메뉴 접근성도 보존하며, 동작 줄이기 설정에서는 불필요한 이동을 줄이되 메뉴 사용 가능성과 상태 전환을 유지합니다.

직접 진입과 화면 간 이동 순서, 선택·호버·포커스·오류·로딩 상태, 동작 줄이기 설정을 실제 프로덕션 스타일 구성에서 확인합니다. 전역 import 개수 감소만을 완료로 보지 않고, 중복 소유권과 제거한 규칙을 확인합니다.

## 확인 범위와 검증

학생부 기반 준비가 현재 중심 범위입니다. 제시문 등 다른 면접 방식에 현재 배분의 적합성을 자동 보장하지 않습니다. 공개일·일정 확인 상태와 개인 배정일은 계속 확인해야 합니다. 계획의 분량은 예상 시간이며 실제 소요 시간·장기 학습 효과와 다릅니다. AI 피드백·추가 질문·음성 전사는 연결된 서비스의 실제 동작에 따라 확인해야 합니다.

아래 명령은 저장소 루트에서 실행합니다. 순수·렌더 검사는 외부 AI를 호출하지 않습니다.

```powershell
npm run typecheck
node --import tsx --test tests/hybrid-training.test.ts tests/training-availability.test.mts tests/training-evidence.test.ts tests/learning-workflow-activity.test.mts
node --import tsx --test tests/training-availability-api.test.mts tests/training-registration-onboarding.test.mts
node --import tsx --test tests/training-review.test.ts tests/training-review-evidence.test.ts tests/training-diagnostic-scope.test.ts
node --import tsx tests/app-navigation-render.mjs
node --import tsx tests/shell-ui-render.mjs
node --import tsx tests/app-shell-refresh.mjs
node --import tsx tests/training-hub-render.mjs
```

`tests/hybrid-training-api.mts`는 로컬 PostgreSQL의 격리된 합성 데이터로 설정·일정·계획·실제 세션 연결과 보존을 확인하는 통합 검사입니다. 실행 조건은 파일 첫 부분에 따릅니다. 검사 수를 실제 학생의 학습 효과나 모든 대학·기기의 검증 범위로 해석하지 않습니다.

`tests/training-review-api.mts`는 외부 AI를 끈 로컬 QA 서버에서 실제 등록·진단·재답변 API와 PostgreSQL을 사용합니다. `HYBRID_TRAINING_TEST_URL`로 해당 서버를 지정하며, 매 실행 생성한 정확한 합성 UUID 계정과 그 소유 데이터만 정리합니다. 기존값 이전, 중복 제출, 원본 근거 정정·무효화·대체 근거, 범위 격리, 새 진단의 선택 대체, 두 화면의 공통 판정과 여러 학교의 하루 시간 예산을 확인합니다.
