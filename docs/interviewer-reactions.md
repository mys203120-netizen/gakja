# 면접관 반응

> 현행 계약·검증 갱신: 2026-10-14. [문서 적용 순서](document-authority.md)와 [서비스 PRD v2.2](../확정안/4.%20서비스_PRD_v2.2.md)를 따른다. [개선·검증 요약](learning-remediation.md)과 [후속 QA](../.local/learning-remediation-2026-10-14/report.md)·[화면 보고서](../.local/learning-remediation-2026-10-14/report.html)에 실제 API/저장값·학교 등록·같은 질문의 학습 연결 검증을 기록했다. 아래 이전 테스트와 화면은 당시 범위로 보존한다. 실제 OAuth·Live/STT·장기 회상·88교 전 학과 콘텐츠 품질·운영 보안은 후속 인수 게이트이며, 이번 결과가 모든 기능이나 실제 학습 효과의 완료를 뜻하지 않는다.

## 2026-10-14 학습 피드백과의 경계

내부 5 단위·21단계는 가상 캐릭터의 표현 강도다. 학생의 실력·학교 적합성·성격·진실성·합격 가능성을 수치화하지 않는다. 실제 제출 답변과 허용 근거의 인용, 모델 확신·전사 불확실성을 확인하고 낮은 확신/실패에서는 중립을 유지한다.

현재 의미 반응은 제출 후의 질문별 피드백과 연결된다. 발화 중 실시간 의미 반응·Face/Pose 감정 판별을 구현·검증했다고 표시하지 않는다. 도움을 사용한 답변의 반응은 독립 답변 성공 증거가 아니며, 같은 질문의 새 무도움 답변과 비교해야 한다.

전사 정정에서 이전 반응을 이력으로 보존하고 현재 반응을 무효화하는 경계를 유지한다. 추가 의미 관찰을 적용하더라도 허용된 실제 답변 인용과 질문별 승인 요소·룰/모델 버전을 남기고 표정을 별도 정답 기준으로 쓰지 않는다.

면접관 반응은 학생의 합격 가능성이나 실력을 수치화하는 기능이 아니라, 제출한 답변에 대한 가상 면접관의 호응이다. 기존 SVG 캐릭터의 형태를 유지하고 눈썹·눈·입·고개만 바꾼다. 내부 표정 강도는 0~100의 5 단위로 구분한다. 화면에는 퍼센트 대신 집중·끄덕임·추가 설명·질문 복귀 같은 상태를 표시한다.

## 현재 구현

- 준비 화면과 진행 화면에서 `면접관 반응`을 켜면 기존 `질문마다 피드백`을 함께 사용한다. 기본값은 끔이다. 종료 후 피드백을 선택하면 반응도 꺼진다.
- 기존 질문별 피드백 또는 꼬리질문 Responses API 호출의 구조화 출력에 반응 필드를 함께 요청한다. 표정만을 위한 추가 호출·백그라운드 호출·타이머 호출은 없다. 반응을 켠 경우 기존 질문별 피드백 호출이 필요하다.
- 질문과 학생이 실제 제출한 답변을 기준으로 관련성·의미 연결·구체적인 근거를 살핀다. 답변 길이·금칙어·키워드 개수로 판정하지 않는다.
- 모델의 확신이 높고, 인용한 문구가 실제 제출 답변에 그대로 있으며, 신호와 강도 범위가 일치할 때만 반응한다. 잘못된 인용·낮은 확신·전사 오류 가능성·AI 미연결·API 실패는 중립이다. 이 검증은 모델 판단의 정확성을 보장하는 장치가 아니므로 표정은 코칭 표현으로만 사용한다.
- 답변 제출 후에 반응한다. 녹음 중에는 중립 표정과 듣기 모션만 제공한다. 분노·조롱을 표현하지 않는다. 모션 줄이기 설정을 따른다.
- 답변 턴에 반응, 근거 인용, 규칙 버전, 콘텐츠 버전, 모델, 프롬프트 버전, 시간, 원본 턴 ID를 보관한다. 전사 정정 시 이전 반응은 이력으로 보존하고 현재 반응을 중립으로 무효화한다. 잘못된 전사에서 파생된 꼬리질문의 반응도 같은 방식으로 무효화한다.

## 아직 구현하지 않은 실시간 의미 반응

현재 Live는 녹화 종료 → 비공개 저장 → `gpt-4o-mini-transcribe` 원전사 → `gpt-6-luna` 화면용 정리 → 학생의 답변 확인 → 답변 제출 순서다. 원전사와 화면용 정리를 분리하며 정리된 문장을 학생의 실제 발화 인용으로 자동 승격하지 않는다. 전사·정리 실패/불확실성은 반응 평가 근거로 확정하지 않는다. 상세 계약과 모델 전환 검증 상태는 [전사·화면용 정리](transcription-pipeline.md)를 따른다. 발화 중 의미를 읽어 즉시 표정을 바꾸는 스트리밍 기능은 없다.

후속 구현에서는 STT 확정 구간마다 질문과 전사의 연결을 점검하고, 전사 수정·발화 도중 끊김·불확실성에서는 중립을 유지해야 한다. 매 단어마다 API를 부르는 대신 의미가 완성된 구간과 간격 제한을 사용한다. 답변을 마치기 전에 단정적인 부정 반응을 주면 말하기를 방해하므로 듣기·관심·명료화 반응을 우선한다. 같은 구간에 연결한 반응을 정정할 수 있도록 전사 구간 ID와 반응 버전을 저장한다.

## 이전 기능 검증 기록

`node --import tsx --test tests/interviewer-reaction.test.ts`는 5 단위 양자화, 21개 형태, 실제 인용 확인, 낮은 확신·전사 불확실성의 중립 처리, 짧은 답변·부정적인 단어만으로 반응하지 않음, 잘못된 숫자·신호 차단을 검사한다. 유료 API는 호출하지 않는다.

`node --import tsx --test tests/interviewer-coach.test.mts`는 실제 `coach` 어댑터의 SDK 전송과 DB만 테스트 대역으로 바꿔, 반응과 피드백이 단 한 번의 요청을 공유하는지, strict schema가 적용되는지, 반응을 끈 기존 코칭 계약이 유지되는지, 인용을 검증하지 못해도 본문 피드백을 보존하며 중립 표정으로 돌아가는지 확인한다. 두 파일 합계 12개 테스트다. 실제 모델의 의미 판단 품질이나 마이크·스트리밍 지연까지 검증한 것은 아니다.

Structured Outputs는 기존 Responses API의 `text.format` strict JSON schema를 유지했다. 참고: [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
