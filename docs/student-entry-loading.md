# 학생 첫 화면과 진단 저장

2026-10-21. 학교 등록부터 오늘 훈련까지의 대기와 진단 완료 표시를 정리한다.

- 학생 레이아웃이 인증을 확인한 뒤 개인 bootstrap을 서버 렌더에 전달한다. HTML 수신 → 클라이언트 bootstrap 요청 → 화면별 요청으로 이어지던 첫 왕복을 없앤다. 인증 응답은 요청마다 생성하고 공용 서버 캐시에 보관하지 않는다. 계정 ID가 바뀌면 셸을 다시 마운트한다.
- 첫 렌더의 인증 ID로 해당 브라우저 탭의 메모리 캐시만 초기화한다. 같은 계정의 반복 초기화는 진행 중 요청을 취소하지 않는다. 다른 계정·로그아웃·401에서는 이전 결과를 폐기한다.
- 오늘 훈련과 준비 현황의 overview만 최대 3초 공유한다. 키에는 계정·지원처·지원 정보·교재 ID/버전·한국 날짜를 포함한다. 개별 계획 조회는 재사용하지 않는다. 저장과 명시적 셸 새로고침은 캐시를 무효화하고, 화면 복귀·자정·명시적 다시 조회는 최신 자료를 요청한다. 브라우저 HTTP·디스크 캐시는 쓰지 않는다.
- 학습시간 GET은 가입 시각과 학습시간 키만 한 번 조회한다. 모든 개인 설정·보완 이력을 가져오지 않는다. 저장의 revision 충돌 방지와 다른 설정 보존은 유지한다.
- 첫 진단은 글로 시작하고 음성을 선택할 수 있다. 면접관 무대는 일반 Live 연습에 남긴다. 종료한 방과 진단 완료를 구분한다. 고정 질문 목록의 모든 본질문에 유효한 제출이 있어야 완료하며, 무효화 시 다시 부분 완료로 판정한다. 글의 길이만으로 실력이나 준비 완료를 판정하지 않는다.
- 종료는 원본 답변·리포트 기본 자료의 저장을 먼저 확인한다. AI 리포트는 응답 뒤 처리하고, 중단된 요청은 소유 학생이 재요청할 수 있다. 과거 생성 결과는 이후 수정한 기록을 덮지 못한다.

학교별 조회와 원본 변경 시 캐시 처리 기준은 [학교 등록 성능](school-registration-performance.md), 실제 RTC 출력과 입 움직임은 [면접관 구현](realtime-live2d-implementation.md)을 따른다.

회귀: `app-shell-refresh.mjs`, `client-request-cache.mjs`, `training-hub-cache.test.mts`, `training-availability-api.test.mts`, `hybrid-training-api.mts`, `interview-completion-api.mts`, `interviewer-output-browser.mjs`. 실제 기기 마이크 권한·오디오 출력 환경 검사는 합성 음성 검사와 별개다.

운영 빌드·390px Chromium·임시 학생으로 등록한 지원처 응답을 일부러 대기시켜도 80개 대학이 표시되고 선택 가능한지 확인했다. 초기 `/api/bootstrap` 요청은 0회였다. 같은 로컬 환경의 마지막 실행에서 첫 목록 표시 약 559ms, 학교 검색·선택과 학과 메뉴 열기 약 366ms였으며 가로 넘침과 브라우저 오류는 없었다. 운영 성능 보장값은 아니며, 개발 서버의 최초 컴파일 시간과 분리한 작은 합성 표본이다. 임시 학생은 검사 후 삭제했다.
