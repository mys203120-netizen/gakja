# 학교 등록 조회와 면접 전형 범위

2026-10-21. 기존 80개 대학 ID·명칭·원본 로고 URL과 공시 학과 데이터는 유지한다. 학교 목록이 표시될 때까지 참고 교재·공통 질문·등록한 지원처를 함께 기다리던 의존성을 제거했다.

- 신규 등록은 `school-registration-summary.json`의 80개 요약을 즉시 표시한다. 이 파일은 선택 화면에 필요한 ID·학교명·로고 URL만 포함한다. 원본 디렉터리와 ID/로고 일치를 자동 검사한다.
- 등록·수정의 `GET /api/schools?scope=registration`은 로그인 학생 소유 지원처만 한 번 조회한다. 전체 학교 바이블·인재상·공통 질문을 반환하지 않는다. 지원처 로딩은 신규 학교 선택을 잠그지 않는다.
- 학과 조회의 `view=registration`은 선택한 학교의 학과 ID·명칭·캠퍼스·단과대·세부 전공만 보낸다. 실제 저장 시 학교 안에서 학과 ID를 다시 확인하고 공시 코드·캠퍼스를 서버 원본에서 결정한다.
- 학교에 포인터를 올리거나 키보드 포커스를 주거나 터치를 시작하면 상세를 미리 읽는다. 동일 학교의 요청은 공유하고 공개 정적 메타데이터만 최대 1시간 재사용한다. 로고 파일·맞춤 크기는 변경하지 않는다.
- 목록에서 학과·전형을 고르면 즉시 조회한다. 직접 입력 중에만 180ms 지연한다. 단일 전형이면 서버가 같은 원본에서 만든 별도의 서명된 `suggestedCalendar`를 제공하므로 자동 선택 후 두 번째 요청을 생략한다.

## 캘린더 원본 재사용과 정정

매 요청에서 공개 원본 두 판의 ID·확인 시각과 관리자 수정의 건수·revision 합·수정 시각만 확인한다. 같을 때는 88개 학교의 JSON 읽기·날짜 검증·공식 보완·관리자 수정 합성을 재사용한다. 변경되면 다시 읽고 합성한다. 최대 4개 합성 결과만 보관하며 실패한 생성 요청은 캐시에서 제거한다. stale/재시도 가능 여부는 현재 시각으로 다시 계산한다.

화면의 동일 선택 미리보기는 30초 동안 재사용하고 명시적 재조회는 이를 지운다. 최종 저장에서는 서버가 현재 원본으로 다시 만든 fingerprint를 대조한다. 관리자 변경 직전의 화면을 보더라도 과거 확인으로 변경된 전형을 저장할 수 없다. 원본이나 관리자 수정 내역을 변경하지 않는다.

## 전형 선택 규칙

현재 학년도·학교에서 면접 실시가 확인된 전형을 후보로 사용한다. 정확한 모집단위·허용된 별칭/괄호 세부 전공 대조를 유지한다. 완전한 모집단위 목록에서 해당 학과가 제외되면 선택할 수 없다. 불완전한 목록이나 학과 범위 없는 면접 기록은 `school_reference` 후보로 남기며, 선택창에 ‘학과 범위 확인 전’을 표시한다. 학교 참고 등록은 허용하지만 정확히 매칭한 날짜 목록은 비우고 `department_scope_confirmed:false`로 저장한다.

서류형·면접 미실시 전형, 공식/관리자의 `no_interview`·`unverified`, 제시문 등 기존 준비 범위 밖 전형은 선택 목록에서 제외한다. 공식 자료가 해당 모집단위의 면접을 명시하고 날짜만 미정/미공개인 경우는 날짜를 만들지 않고 해당 상태로 유지한다. 학교 참고 일정을 정확한 학과 응시일로 바꾸지 않는다. 관리자 보완 학교는 원본 공식 8개 학교 수에 합산하지 않는다. 학과 강제 재조회는 화면의 1시간 캐시와 공통 API 캐시를 모두 우회한다.

전체 3,551개 학과를 원본 변경 전후로 비교하면 전형 후보가 있는 학과는 3,387개, 학교는 78개로 유지된다. UNIST 3/3·POSTECH 1/1·서울교대 1/1·서울과기대 57/57 모두 등록 가능하다. 이 네 학교의 실제 원본 행으로 등록을 재현하고 학과 범위 미확인·정확 매칭 날짜 0개·개인 배정 시간 없음이 유지되는지 검사한다. 나머지 2개 학교도 80개 목록에는 유지하며 확인된 후보가 없다는 상태를 그대로 보여 준다.

## 검증

`node --import tsx tests/school-registration-read-api.mts`는 실제 route handler와 SQL을 무작위 전용 PostgreSQL 스키마에서 실행하고 해당 스키마만 삭제한다. 기존 계정·학생 기록·공개 원본은 수정하지 않는다. 인증 경계는 합성 학생으로 대체하며 외부 API/AI는 호출하지 않는다.

한 로컬 실행의 압축 전 측정값(HTTP·브라우저 시간 제외):

| 항목 | 변경 전 경로/전체 자료 | 분리한 경로 |
| --- | ---: | ---: |
| 첫 대학 목록 | public 목록 67,168 bytes와 별도 조회 대기 | 초기 고정 요약 11,456 bytes, 별도 목록 요청 없음 |
| 시립대 학과 응답 | 13,218 bytes | 5,602 bytes |
| 캘린더 DB 반환 자료 | 최초 합성 436,545 bytes / 4회 조회 | 동일 원본 388 bytes / 2회 조회 |
| 캘린더 route 처리 | 최초 64.48ms | 반복 7회 중앙값 2.85ms / 최대 4.30ms |

합성 결과 재사용·단일 전형 왕복 생략 외에도, 관리자 면접 미실시 정정/숨김/수정 제거가 다음 요청의 선택지와 fingerprint를 바꾸는지, 다른 학생의 지원처가 제외되는지, 고정 80개와 로고가 유지되는지 검사한다. 측정은 작은 로컬 표본이며 운영 지연 시간의 보장은 아니다. 개발 서버의 최초 모듈 컴파일은 별도 비용이다.
