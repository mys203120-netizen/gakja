## IA

| 주요 메뉴 | 역할 | 자식 페이지 |
| --- | --- | --- |
| MY `/my` | 일정·과제·준비 현황에서 다음 행동 선택 | 지원처 선택, 미응답·확인 필요·우선 활동, 시사 주제 |
| 각자ON `/on` | 자신의 승인 기록을 탐색하고 물어보기 | `/on/[threadId]`, 대화 안의 원문·활동·질문·교재 패널 |
| 면접 모드 `/interview` | 면접관의 질문에 답변 제출 | `/interview/new?kind=chat` 또는 `video`, `/interview/[id]` |
| 훈련 `/practice` | 회상 훈련·과제·재시도 | `memory/[id]`, `assignments/[id]` |
| 자료 `/materials` | 승인 자료를 읽고 답변 작성 | `guidebook`, `handbook`, `activities/[id]`, `questions/[id]`, `answers/[id]`, `briefings/[id]` |
| 기록 `/records` | 결과·녹화·답변 변경 확인 | `reports/[id]`, `history`, `comparisons/[questionId]` |
| 내 계정 `/account` | 지원 정보·사실 확인·개인 설정 | `confirmations`, `settings` |
| 운영 `/admin` | 배정·검수·학교 기준·발행 관리 | `students`, `assignments`, `schools`, `schedules`, `imports`, `content`, `reviews`, `knowledge`, `settings` |

기존 `/chat`과 `/practice/video` 진입 경로도 유지한다. 새 행동 링크는 각자ON·면접 모드로 연결한다. 각자ON은 학생이 질문하는 곳, 면접 모드는 학생이 답변을 제출하는 곳으로 구별한다. 교재·원문 패널을 열어도 대화 초안은 남는다. 면접에서 각자ON을 열면 초안을 저장하고 일시정지하며, 도움을 사용한 답변으로 기록한다.

## 현재 구조에서 보류한 이유

현재 서버는 Next 요청/응답과 PostgreSQL 저장을 중심으로 동작한다. 연속 PCM 수집, WebSocket→gRPC `StreamingRecognize`, half-close 및 여러 final 전사 합치기는 별도 음성 중계가 필요하다. 긴 음성의 GCS 배치 처리·정렬·삭제/재처리에는 지속 작업 큐가 필요하다. Face/Pose/VAD는 고정 모델·WASM 자산과 Worker 및 실제 영상의 품질 검증이 필요하다. 환경 변수만 넣어 이 기능들이 완료된 것으로 처리하지 않았다.

Google REST의 짧은 파일 전사와 TTS 연결 경로는 구현했다. 실시간 스트리밍으로 부르지 않으며, 자격 증명·API 활성화·모델/지역·비용·한국어 음질은 실제 프로젝트에서 검증해야 한다. 공급자는 `SPEECH_PROVIDER`로 명시하고 오류 시 개인 음성을 다른 공급자로 자동 전송하지 않는다.

MMI·집단/토론·스테이션 평가에는 별도 세션/평가 모델이 필요하다. 해당 학교 정보는 저장·검수할 수 있지만 기본 서류 면접 연습과 구별한다. Expo와 PDF 제작 파이프라인은 현재 웹 소스에 없으며 이번 작업에서 구현된 것으로 표시하지 않는다. 대학별 확정 문서의 과거 사례는 현재 공식 모집요강으로 자동 승격하지 않는다.

## 환경·검증

비공개 설정은 루트 `.env.local`, 비밀이 아닌 기본값은 `.env`, 입력 예시는 `.env.example`로 정리했다. 기존 값은 유지하고 `프로세스 → .env.local → .env` 순서로 모든 실행 스크립트와 Next가 읽는다. 자세한 설정은 [environment.md](environment.md)에 있다.

추가 DB migration은 `202610120001_prd_features.sql`, `202610120002_briefing_thoughts.sql`이다. 기존 계정과 학습 데이터를 다시 시드하지 않고 로컬 PostgreSQL에 적용했다. 검증은 콘텐츠 계약 테스트, TypeScript, 빌드, 로컬 API의 권한·동시 수정·중복 요청·기록 보존과 실제 브라우저의 데스크톱/모바일 화면을 대상으로 한다. 이번 구현 검증에서 유료 AI·음성 호출은 실행하지 않았다.

최종 확인: 루트 TypeScript·프로덕션 빌드 통과, 콘텐츠 계약 18건·일정 단위 검증 6건, 보안 API 57건·학습 API 32건·일정/브리핑 API 24건·학생 브리핑 의견 API 38건·면접 상태 API 105건 통과. API 검증에 만든 임시 자료와 세션은 해당 테스트 ID로 정리했으며, 기존 계정·답변·회상 기록은 유지했다. 브라우저에서는 학생 MY·각자ON·교재 패널·면접 복귀와 관리자 과제·학교 기준·일정 검수를 확인했다. 모바일 390px에서 면접·대화 메뉴와 가로 넘침을 확인했다.
