# 지원 학교와 첫 공통 면접

> 현행 계약·검증 갱신: 2026-10-14. [문서 적용 순서](document-authority.md)와 [서비스 PRD v2.2](../확정안/4.%20서비스_PRD_v2.2.md)를 따른다. [개선·검증 요약](learning-remediation.md)과 [후속 QA](../.local/learning-remediation-2026-10-14/report.md)·[화면 보고서](../.local/learning-remediation-2026-10-14/report.html)에 실제 API/저장값·학교 등록·같은 질문의 학습 연결 검증을 기록했다. 아래 이전 테스트와 화면은 당시 범위로 보존한다. 실제 OAuth·Live/STT·장기 회상·88교 전 학과 콘텐츠 품질·운영 보안은 후속 인수 게이트이며, 이번 결과가 모든 기능이나 실제 학습 효과의 완료를 뜻하지 않는다.

## 2026-10-14 학교 등록과 학습 맥락

학교 등록은 88개 대학의 목록과 학교에 속한 공시 학과 ID를 검증한다. 원본 2026 공시 조합 3,934개에서 통계 집계명 50개를 제외한 선택 가능 모집단위는 3,884개다. 이는 2027학년도 확정 선발단위·전형·지원 자격의 전수 확인이 아니다. 직접 입력한 신설·변경 모집단위는 미검증으로 표시한다.

신규 등록은 학교·학과/전형 선택 뒤 `POST /api/schools/onboarding-calendar`로 공개 일정을 조회한다. 최종 `POST /api/schools`는 `calendarReview:{fingerprint,acknowledged:true}`를 받아 선택 정보와 현재 표시한 일정 근거를 다시 대조한다. 첫 등록에서 일정 확인을 건너뛰거나 근거가 바뀌면 등록을 완료하지 않고 다시 확인하게 한다.

대학·캠퍼스·학과·학년도·전형이 실제로 달라진 기록은 현재 준비 상태에 섞지 않는다. 교재의 면접 단계가 누락·미정인 것은 변경의 증거가 아니며, 양쪽에서 단계가 알려졌을 때만 학습 연결에서 비교한다. 공식 학교 프로필 적용 검사는 별도의 엄격한 검사를 유지한다.

개인 과거 교재는 당시 버전·지원처의 연습으로 열고 현재 공식 프로필·출제 구성을 덧씌우지 않는다. 지원처가 달라진 공통 학교 질문은 당시 기록으로 보존하며 현재 학교 질문으로 강제 변환하지 않는다.

2026-10-12 구현. `내 계정 → 학교 등록 → 학교별 면접 안내 → 공통 질문 연습`으로 연결한다. 대메뉴 다섯 개는 유지하며 학교 안내는 `/schools`, 등록은 `/schools/new`, 개인 지원처 안내는 `/schools/{targetId}`이다.

2026-10-13 초기 9개 대학 연결 이후 공식 학교 정의를 88개 대학·89개 프로필로 확장했다. 정의는 인재상 75개·교육목표 12개·핵심역량 1개로 구별하고 대학 공통과 별도 학과 정의를 함께 제공한다. 출처 기반 연습 질문은 327개이며 실제 기출로 표시하지 않는다. 적용 범위와 검증은 [학교 정의 연결](school-talents.md)을 참고한다. 학교를 고르지 않은 일반 공통 질문은 10개다.

## 실제 제공 범위

- 학생은 학교·지원 학년도·캠퍼스·전형·학과/학부/모집단위를 등록한다. 기존 지원 정보의 미정 상태는 보존하되 첫 가입의 일정 확인 완료에는 학과와 전형 선택이 필요하다. 같은 조합의 중복 등록은 기존 지원처를 반환한다. 목록에 없는 학교도 등록할 수 있지만 없는 개요를 만들지 않는다.
- 제공 MD의 88개 대학 면접 개요를 원문 텍스트로 보존했다. 대학별 원문 줄·PDF 쪽·문서명·SHA-256을 함께 저장한다. 초기 상태는 `historical_reference`, 화면에는 `제공 자료 기준 · 공식 확인 전`을 표시한다. 사용자가 고른 2027학년도 전형의 확정 정보로 승격하지 않는다.
- 개요는 대학 전체의 참고 자료다. 같은 대학 안의 캠퍼스·전형·모집단위 자료가 함께 있으면 원문 구분을 유지하고 `전형별 적용 확인 필요`를 표시한다. 등록한 조합과 자동으로 정확하게 일치하는 프로필이라고 주장하지 않는다.
- 책의 평가 비율은 원문 표에 그대로 나타난다. 별도의 `evaluation_weights`나 `question_distribution` 값으로 자동 변환하지 않았다. 공식 확인된 운영자 프로필과 그 질문 비중은 기존 검수 계약을 따른다.
- 원문의 독립적인 공통 질문 9개와 각자ON 일반 연습 질문 8개를 분리했다. 특정 학과, `○○ 활동`, 학생부·실험·독서·결석 사실, 제시문·도표를 전제로 하는 자동 추출 후보는 제외했다. 책의 질문은 `자료 기반 일반 연습`, 직접 만든 문항은 `일반 연습`이다. 학교별 공식 기출·해당 전형 확정 질문이라고 표시하지 않는다.
- 개인 자료가 없는 신규 학생도 공통 면접을 시작하고 답변을 저장할 수 있다. 공통 질문은 실제 활동을 만들어 연결하지 않으며 이후 개인 질문 연습과 같은 질문별 이력 구조에 쌓인다.
- 제시문·MMI·집단 과제·영상 제출은 현재 질문·답변 엔진의 재현 범위에 포함하지 않는다. 대학 개요의 형식과 앱의 연습 설정을 분리한다.

## 권한과 고정 이력

학교 등록 API는 학생 본인의 지원처만 만든다. 공식 확인 상태·평가표·검수 시점을 요청 본문에 넣어도 채택하지 않는다. `department`를 모집단위의 정식 필드로 저장하고 `major` 별칭도 함께 둔다. 기존 운영자 검수 이력은 수정하지 않는다.

검수된 학교 프로필을 읽을 때 대학·연도·캠퍼스·전형·모집단위·면접 단계가 현재 지원처와 맞는지 검사한다. 지원 정보가 바뀌면 과거 `official_confirmed`는 선언 당시 상태로 보존하지만 화면 상태는 `needs_confirmation`, `stale: true`가 된다. 화면은 이전 적용 조건을 명시한다.

모의면접은 전체 적격 문항 후보를 확보한 뒤 복습 시점·최근 미해결 항목·미연습·최근 면접 회피를 반영한다. 처음 8개 후보로 자르지 않는다. 지정 질문은 첫 문항으로 고정하며 비중 배정 수에 포함한다. 범주 안에서는 적응 순서를 유지한다. 평가 배점을 출제 비중으로 사용하지 않는다.

세션은 공통 문항 버전·출처·질문·학교 프로필·편성 결과를 고정한다. 공통 문항 ID는 원문 질문 해시를 사용하여 후보를 제외해도 다른 문항으로 바뀌지 않는다. 제외한 옛 후보는 `withdrawn`으로 보존하며 세션의 당시 자료는 삭제하지 않는다. 확정 리포트는 이번 적재로 다시 쓰지 않는다.

`sourceType=personal&sourceVersion=N`은 본인의 해당 발행본만 읽는다. 현재 버전으로 조용히 대체하지 않는다. 이전 발행본의 지원처 정보를 고정하고 현재 지원처가 바뀌었으면 현재 학교 프로필·공식 질문 비중을 적용하지 않는다. `sourceType=common&sourceVersion=N`은 공통 문항 버전이며 개인 발행본 번호로 처리하지 않는다.

클라이언트 세션 DTO에는 질문·활동·근거·승인 답안·브리핑 등 본인의 고정 자료만 반환한다. 내부 학생 맥락·식별자·문항 선정 이력·전체 처리 컨텍스트는 반환하지 않는다. 원문 도움을 사용한 첫 질문은 `assisted`로 기록하고 독립 답변으로 표시하지 않는다.

## API와 운영

- `GET /api/schools?targetId=`: 인증된 학생의 `catalog`, `targets`, 해당 학교의 `commonQuestions`, `commonAvailable`.
- `POST /api/schools`: `{referenceId?, university?, admissionYear, campus, track, major}`. 학생 역할·요청 Origin·학교 ID·입력 길이 검사.
- `GET /api/interviews?preview=1&questionId=&targetId=&activityId=&sourceType=&sourceVersion=`: 선택 질문·고정 자료 미리보기. 브리핑 ID·질문 인덱스도 지원한다.
- `POST /api/interviews`: 기존 `action: start`에 공통 질문·`sourceType`, `sourceVersion`, 첫 질문의 `assisted`를 추가했다. 개인 발행본은 기존 소유권·승인 검사를 유지한다.

원문 추출: `node scripts/extract-school-bible.mjs`. 마이그레이션 적용 후 적재: `node scripts/import-school-learning.mjs`. 기존 버전의 행은 덮어쓰지 않는다. 새 원문이나 개요가 바뀌는 업데이트는 새 개요·문항 버전과 검수를 작성해야 한다.
