# 확인한 사실 기반 완성 예시답변 운영 안내

완료한 면접의 질문 상세에서 `완성 예시답변`을 연다. 학생은 연결된 생기부 원문과 당시 원답변 중 실제 경험에 맞는 문장을 고르고, 원답변 문장의 순서를 조정한 뒤 사실 확인을 한다. 결과는 한 문단이며 문장 복사, 사용 근거, 버전 이력, 훈련 리포트 다운로드에 연결된다.

## 생성과 보존

- 기존 `OPENAI_MODEL_INTERVIEW` / `OPENAI_MODEL` 설정과 일일 사용량 제한을 사용한다. GPT Live 1을 호출하지 않는다. 새 음성 모델·필수 키·추가 공급자는 없다.
- 서버 OpenAI 키가 있으면 선택한 확인 문장과 해당 질문만 Responses API에 전송한다. `store:false`, 최대 출력 토큰 1,800. 생기부 전체나 개인정보 프로필은 전송하지 않는다.
- 모든 생성 문장은 선택한 원발화의 fact ID를 하나 이상 가져야 한다. 선택하지 않은 ID, 원발화에 없는 내용 어휘(새 행동·개념·동의어 포함), 새 숫자, 명시적인 새 역할·성과·절차 단어, 부정·불확실성 누락을 보수적으로 검사한다. 검사 실패 시 실제 확인 문장을 연결한 완성 예시로 돌아간다. 이 검사는 의미적 사실성을 완전히 보장하지 않으므로 결과에 사용 근거와 재확인 안내를 표시한다.
- 키가 없으면 추가 AI 호출 없이 확인한 원발화의 문장들을 연결한다. UI에 이 방법을 명시한다. 유료 공급자 오류는 원인에 맞는 재시도 상태로 반환하며, 실패 응답에도 공급자가 반환한 토큰 사용량을 남긴다.
- 원답변, 원전사, 평가, 리포트 스냅숏은 덮어쓰지 않는다. `interview_turns.data.exampleAnswers`에 질문·리포트별 최대 20버전을 저장한다. 다운로드는 가장 최근 버전을 포함하고 현재 근거와 달라졌으면 표시한다.

## 권한과 경합

학생 본인의 완료 세션·리포트·유효 턴만 허용한다. 해당 리포트에 동일 턴의 섹션이 정확히 하나 있어야 한다. 질문과 연결된 생기부 출처만 근거로 사용하고 일반 학교 정보는 개인 경험 근거에서 제외한다. 학생이 다르다고 했거나 확인할 수 없는 활동은 생성을 보류한다.

`202610230005_interview_example_requests.sql`의 서버 전용 요청 임대가 동일 request ID의 동시 유료 생성을 막는다. 처리 중 재시도는 409이며, 성공 후 재시도는 같은 버전을 반환한다. 생성은 DB 트랜잭션 밖에서 수행하고 저장 직전에 소유권·완료 상태·근거 해시·버전을 다시 확인한다. 두 분의 임대가 만료되거나 처리 실패한 요청은 같은 입력으로 재시도할 수 있다. 브라우저 역할에는 이 테이블의 직접 권한이 없다.

## 검증 범위

단위·서비스 검사는 다른 학생 접근, 진행 중 세션, 무효 턴, 새 근거, 중복 요청, 버전 보존, 새 주장 차단, 실패 사용량, 다운로드 이스케이프를 다룬다. 로컬 시각 QA는 합성 학생 자료와 AI 미설정 상태에서 수행한다. 실제 유료 모델의 한국어 표현 품질·의미적 사실성은 API 계약 검사와 구분해 운영 표본으로 확인해야 한다.
