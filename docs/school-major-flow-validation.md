# 학교·학과별 학습 축 검증

검증일: 2026-10-13. 결과: **passed**.

88개 대학을 선택하는 가입·학교 등록 경로에서 실제 학과를 정한 뒤, 학교의 공식 인재상·교육목표·핵심역량을 같은 질문으로 연습하고 누적 기록을 비교할 수 있는지 확인했다. 정적 전수 검사와 실제 HTTP/PostgreSQL 검사를 구분했다. 브라우저 조작과 시각 QA는 별도의 CUA 검증으로 진행한다.

실제 학과 ID는 [교육부 대학알리미 2026 공시 자료](https://www.data.go.kr/data/15163924/fileData.do)에 있는 값을 사용했다. 이 목록이 2027년의 확정 모집단위라고 가정하지 않는다. 공식 학교 정의는 자료의 실제 종류인 인재상·교육목표·핵심역량으로 구분하고, 출처·적용 범위·연도 제한을 유지한다. 면접 평가 배점이나 기출 주제 비중을 학교 인재상으로 바꾸지 않는다.

각 조합에서 다음을 검사했다.

- 등록된 학교 내부의 학과 ID만 선택할 수 있다. 학교별 캠퍼스 명칭이 실제 학과 식별과 함께 유지된다.
- 대상 학교에 맞는 공식 정의 및 연습 질문이 존재하고, 다른 학교·학과의 제한된 정의를 잘못 적용하지 않는다.
- 연습 질문은 공식 출처를 기반으로 만든 연습이며, 실제 기출로 표시하지 않는다. 학생의 경험이나 모범답안을 자동으로 만들지 않는다.
- 퀴즈·공식 읽을거리의 ID는 학교·학과·캠퍼스·연도·전형·면접 단계·대상 ID와 출처 버전을 구분한다.
- 모든 학과에 공식 학교 읽을거리와 공개 학과 분류에 따른 영상 학습 렌즈가 존재한다. 학교·학과 정보는 생기부의 활동으로 위장하지 않는다.
- 동일 질문의 Q&A와 면접 답변은 비교하되, 별도의 개념 질문 및 다른 지원처는 분리한다.

## 실제 API·DB 검증

시드 `20261013`으로 분야별 표본을 재현할 수 있게 선택했다. 8개 합성 학생 계정을 생성했고 원래의 학생 계정·자료는 수정하지 않았다. 처음에는 개인 생기부 자료를 발행하지 않은 상태로 검사하고, 추가 경우에서 승인 상태의 합성 활동을 연결했다.

**529개 검증 통과. 유료 AI 호출 0회. 생성한 8개 학생 계정과 관련 기록 회수 완료.**

각 표본은 다음 실제 경로를 통과했다.

1. 학교·학과 등록 → 공식 학교 정의와 해당 학과 맥락 조회.
2. 학교 질문 선택 → 같은 `questionId`와 공식 출처 버전의 Q&A 생성·시작·답변 저장.
3. 같은 질문으로 모의면접 시작 → 학교·학과 및 공식 출처를 고정한 답변 저장. 경험이 없으면 미래 계획으로 답변 가능.
4. 리포트 → 같은 질문·지원처·출처의 Q&A와 면접 답변 비교. 키워드 표현의 관찰이며 면접 점수나 인격 판정으로 표시하지 않음.
5. 같은 질문의 공식 지식한입 읽을거리 → 내 설명 저장 → 같은 퀴즈 회상 ID로 복귀.
6. 같은 질문의 과제 생성·시작·제출 → 과제 답변도 같은 누적 비교에 포함. 생기부 발행 전에도 지원 학교를 정하면 가능.
7. 하나의 학습 세션에 퀴즈·면접·지식한입·과제의 4개 실제 이벤트가 같은 질문 ID로 저장. 종료 후 해당 리포트는 고정.

추가 경계 검사:

- 과제 생성 요청을 반복해도 같은 과제가 반환되며, 자기점검 답변은 정답·입학 적합성 점수로 변환되지 않는다.
- 위조한 학교 출처·학과 스냅샷은 저장에 반영되지 않는다. 지식한입의 잘못된 공식 질문 버전은 `409`로 거절된다.
- 퀴즈 조회·생성에 `sourceType=common`과 `sourceVersion`을 명시하여 출처 버전을 고정했다. 존재하지 않는 버전을 요청하면 최신 질문으로 조용히 변경하지 않으며, 해당 항목으로 퀴즈를 만들 수 없다.
- 다른 학생은 학교·퀴즈·면접·지식한입·과제·리포트의 대상과 기록을 읽거나 수정할 수 없다.
- 동일 학교의 다른 학과 지원처에서 같은 질문을 연습해도 회상 ID와 비교 그룹은 분리된다.
- 같은 지원처 ID의 학과를 수정해도 기존 퀴즈·면접 답변·공식 출처와 종료 리포트는 수정 전 상태로 보존된다. 수정 후 연습은 새 비교 그룹을 만든다.
- 승인된 합성 생기부 활동을 명시적으로 선택하면 학교 질문에 개인 근거를 추가할 수 있다. 미승인·다른 학생 활동을 추정해 연결하지 않는다.

## 검증 중 발견해 수정한 연결 문제

Q&A의 `practice_kind: personal`과 면접의 기본 답변 종류가 다른 비교 그룹으로 처리되어, 같은 질문의 연습 변화가 이어지지 않았다. 개인 답변을 하나의 비교 종류로 정리하고 별도 개념 문제만 분리했다.

리포트 응답을 만들 때 학교·학과 스냅샷을 빠뜨리는 경로가 있어 같은 지원처 ID에서 학과를 변경하면 과거 답변과 섞일 수 있었다. 퀴즈·과제·면접 답변의 대상 스냅샷과 출처 버전을 유지하고, 학교·학과·캠퍼스·연도·전형·면접 단계별 비교 키를 사용하게 고쳤다. 위 경우는 전수 모델 테스트와 실제 HTTP 테스트에 회귀 검증으로 남겼다.

## 재현

로컬 PostgreSQL 및 `AUTH_MODE=local`, 실행 중인 로컬 웹 서버가 필요하다. 서버 주소는 `.local/server.json` 또는 `SMOKE_BASE_URL`을 사용한다. 실제 서비스 DB에서는 실행을 거절한다.

```powershell
node --import tsx --test tests/school-major-matrix.test.ts
node --import tsx tests/school-major-flow-api.mts
```

생성되는 근거:

- `.local/school-major-matrix-coverage.json`: 학교·학과별 질문·출처 매칭 전수 결과.
- `.local/school-major-knowledge-coverage.json`: 공식 읽을거리 및 학과 분류별 영상 연결 전수 결과.
- `.local/school-major-flow-api-check.json`: 실제 표본의 학교·학과·공식 질문·읽을거리·종료 리포트와 검사 결과.

브라우저 시각 QA에는 별도 합성 계정 2개를 사용한다. `.local/school-major-visual-fixture.mts`의 생성·회수 명령으로 관리하며, API 검사 계정과 분리되어 있다.

```powershell
node --import tsx .local/school-major-visual-fixture.mts
node --import tsx .local/school-major-visual-fixture.mts --cleanup
```

## 결과 해석의 범위

전수 검사는 **공식 학교 정의·질문·선택 학과의 맥락이 학습 기능 사이에서 끊기거나 잘못 붙지 않는지**를 보장한다. 3,934개 학과 각각의 최신 면접 전형·교육과정·맞춤 영상 전체를 검증했다는 뜻은 아니다. 현재 학과 연결 영상은 실제 공개 분류에 따른 기초·인접 주제 렌즈이며, 학교마다 별도 확인한 공식 학과 정의가 없다면 대학 공통 정의임을 표시한다.

실제 HTTP 검사는 위 8개 표본의 저장·누적·분리·권한을 검증했다. 공식 OAuth 가입, 마이크·카메라, 유료 GPT 응답, 새 대학 모집요강의 내용 정확성은 이 검사의 범위에 포함하지 않는다.
