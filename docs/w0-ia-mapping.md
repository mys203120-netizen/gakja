## 청사진 §6·§20의 W0 경계

§6은 4메뉴·상단 지원처·프로필·H01/I00/A00/M00·전체 ID route map을 즉시 골격 범위로 정한다. 기존 면접 화면은 유지하고 가상 미리보기를 실제 기능 완료와 구분한다. MY 홈은 로고로 접근하며 G09는 가이드북 내부 플로팅 패널이다. `A05`는 폐기, `G08`은 미정의다.

§20은 G0부터 W0 골격을 병행하고 G3부터 계정·기록, G4~G5부터 원문·가이드북을 연결한다고 설명한다. W0 골격은 G3~G8 완료가 아니다. 실제 가입→지원처→PDF→발행→G04→연습→A01 흐름은 G5의 실제 데이터 E2E 관문이다. 실제 미디어·권리원장·동일 회차 복구·정상/부분 리포트는 G6, G09·암기·D-1은 G7, 법률·PG·운영·출시는 G8의 별도 관문이다.

연결 전 기능은 영구 로딩 대신 현재 이용할 수 없는 이유와 가능한 다음 행동을 안내한다. 실제 조회 실패를 개발 fixture 성공 데이터로 대체하지 않는다. 학생 화면에는 codec/binding/worker 등 내부 용어를 노출하지 않는다.

`docs/evaluation-supply-contract-v0.1.md` 156·170행에 따라 평가 자료 부족은 명시적 검수 대기이며 점수는 null이다. 질문 승인과 평가 범위 승인, 실제 session 결합 완료를 서로 대신하지 않는다. 점수 null을 0·평균·임의 총점·완료 배지로 바꾸지 않는다.

## 매핑 검증과 완료 상태

문서 생성 시 CSV를 파싱해 51행·ID 중복 없음·A05/G08 미포함을 확인했다. 사용자 원본 CSV의 네 열을 추출해 출력 파일의 같은 네 열·행 순서와 전체 비교했고 모두 일치했다. 원본 정본 파일은 읽기만 했다. 브라우저·타입·린트·빌드·실제 기기 검증 결과는 [W0 QA 기록](w0-qa.md)을 따른다. 이 매핑 문서 자체는 실제 API 연결이나 공개 가능 판정의 증거가 아니다.

각 화면의 `골격 / 인터랙션 검증 / 실제 API 연결 / 공개 가능`은 독립 상태로 기록해야 한다. W0 진입 화면을 구현해도 하위 기능 전체, G3~G8, 다사용자 출시, 평가 자료 검수 완료를 의미하지 않는다.
