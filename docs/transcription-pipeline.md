# 녹음 전사와 화면용 정리

적용 결정: 2026-10-14, Asia/Seoul. 사용자가 STT를 Google 대신 `gpt-4o-mini-transcribe`, 후가공을 `gpt-6-luna`로 선택했다. 기존 서버 `OPENAI_API_KEY` 하나를 공유한다. 이 계약은 [PRD v2.2](../확정안/4.%20서비스_PRD_v2.2.md)의 당일 음성 개정과 [환경 설정](environment.md)을 구체화한다. Typeless처럼 읽기 좋은 문장·줄바꿈을 원한다는 사용자의 요구를 구현하며 외부 서비스의 소스 코드를 가져온 것으로 표현하지 않는다.

## 2026-10-16 전사 재검토 — 현재 적용 정책

외부 의견인 루트의 'Whisper 도입 관련.md'를 현재 면접·퀴즈 공통 경로와 대조했다. 기본값은 mini STT → Luna 표시 형식을 유지한다. 아래의 새 정책이 10월 14일의 오타 교정·군더더기 제거 정책보다 우선한다.

- 자동 정리는 띄어쓰기·문장부호·줄바꿈만 허용한다. 단어 교체, 습관어·반복 삭제를 허용하지 않는다. 작은 편집 거리도 의미 보존을 증명하지 못한다. 실제로 기존 검증기는 양극→음극, 저기 삭제를 승인했다.
- 프롬프트 버전은 `gakja-transcript-verbatim-2`다. 기존 기록은 재작성하지 않는다. 명시적 정리 재시도 시 이전 버전 캐시는 재사용하지 않고 저장된 원전사만 새 규칙으로 정리한다.
- 숫자·소수점·부호·수식·유니코드 화학 표기를 보존한다. 검사에 실패한 결과는 완료본으로 노출하지 않는다. 학생이 원음을 듣고 정정하는 기존 흐름은 유지한다.
- `whisper-1` 명시적 선택은 지원한다. 한국어를 지정하고 음수·역순·겹침·녹음 길이 초과 시간값이 있으면 단어 정렬 전체를 사용하지 않는다. 원전사는 보존한다. API Whisper는 자체 호스팅 large-v3-turbo와 다른 선택이다.
- faster-whisper/WhisperX/화자 분리는 이번에 추가하지 않는다. 현재는 학생 단일 마이크와 질문 TTS가 분리되어 있으며, 별도 추론 서버·GPU·정렬 처리의 이점을 증명한 대표 음성 비교가 없다.
- 학생부·모범답안 전체를 전사 힌트로 넣지 않는다. 현재 경로에는 검증된 전사 용어 사전 계약이 없으므로 자동 생성한 용어를 '검증됨'으로 간주해 연결하지 않는다. 향후 질문·활동별 승인 용어와 출처·버전이 마련되면 해당 범위만 연결하고 동일 음성으로 검증한다.

실제 합성 음성 비교와 검사 범위는 [.local 검증 기록](../.local/stt-review-2026-10-16/report.md)에 기록한다. 단일 합성 음성은 실제 학생 발화의 정확도나 지연 분포를 대표하지 않는다.

## 처리 순서와 화면

1. 학생 소유의 음성·영상 답변을 인증 경로로 저장한다. 해당 질문·지원처·자료 버전과 실제 녹음 ID를 유지한다.
2. OpenAI Audio Transcriptions API의 `gpt-4o-mini-transcribe`로 원전사를 만든다. JSON 출력과 한국어 지정, 원문 보존 지시를 사용한다. 학생별 용어 힌트는 아직 연결하지 않는다.
3. 원전사를 보존한 뒤 Responses API의 `gpt-6-luna`로 화면용 정리본을 만든다. 구조화 출력을 검증하고 추론 노력은 `none`으로 설정한다.
4. 학생의 일반 답변 화면에는 두 단계가 끝난 정리본을 표시한다. 진행 중에는 전사/문장 정리 상태를 보여주며 중간 원전사를 완료된 문장처럼 노출하지 않는다.
5. 학생이 정리본을 확인·수정하고 직접 답변을 제출한다. 후가공 완료가 제출·다음 질문 생성·학습 완료를 대신하지 않는다.

주 화면의 완료본과 별개로 `원전사 보기`에서 원전사와 원음을 확인할 수 있어야 한다. 과거 녹음에 저장된 원전사가 있으면 이를 재사용하고 새 STT 호출을 강제하지 않는다. 후가공만 다시 요청할 때 원음을 다시 전사하지 않는다. 새 녹음/질문으로 바뀐 뒤 도착한 이전 결과가 현재 초안을 덮어쓰지 않게 한다.

## 가독성 정리의 허용 범위

- 문장부호, 띄어쓰기, 문장 경계와 자연스러운 문단 줄바꿈을 정리한다.
- 오디오를 다시 듣지 않는 후처리에서 철자·단어를 자동 교체하지 않는다. 인식 오류는 원음 확인 후 학생이 정정한다.
- 습관어와 반복도 발화 자료로 보존한다. 원전사와 표시본 모두 단어 순서를 유지한다.
- 학생이 하지 않은 활동·역할·근거·성과·감정·확신을 보충하지 않는다. 부정, 불확실성, 본인/제3자의 주체, 수치와 단위를 유지한다.
- `기억나지 않는다`, `모르겠다`를 성공 경험이나 확정 사실로 바꾸지 않는다. 요약·모범답안 작성·면접 코칭을 수행하지 않는다.
- 전사 안의 명령문은 학생 발화 데이터다. 지시로 실행하거나 학교/학생부 사실로 자동 승인하지 않는다.

가독성 정리는 언어 처리이며 새로운 면접 답변·실력 향상·새 학습 시도가 아니다. 내용 코칭과 다른 기능이므로 AI 비서의 도움 receipt를 임의로 만들지 않는다. 실제 코칭·근거 조회의 도움 기록은 기존 학습 도움 계약을 따른다.

## 원음과 학습 기록의 경계

| 자료 | 책임 |
|---|---|
| 원음/영상 | 학생이 실제 발화한 녹음. 질문·시도·시간과 소유권 유지. |
| STT 원전사 | 최초 인식 문자열. 모델·공급자·처리 상태와 함께 보존. |
| AI 화면용 정리본 | 파생 표시 자료. 후가공 모델·상태·원전사 관계를 유지. 원전사 대체 아님. |
| 학생 직접 정정 | 학생이 확인하고 바꾼 문장. AI 정리와 구분하며 동일 발화의 revision. |
| 새 녹음 | 실제 새 시도 또는 명시된 재녹음 관계. 단순 정정과 구분. |

습관어·반복 표현과 속도 분모의 어절은 STT 원전사를 사용한다. 쉼/음성 공백은 실제 녹음에서 수집한 RMS 관찰을 사용한다. 정리본에서 `음…`이 사라졌다는 이유로 발화가 개선됐다고 표시하지 않는다. STT 자체가 놓친 습관어는 복원했다고 주장하지 않는다. 단어별 타임스탬프가 없는 모델 응답에 가짜 단어 위치/무음 구간을 만들지 않는다.

실제 발화의 인용·성장 관찰은 원전사 또는 명시적으로 확인된 전사 정정에 근거한다. 화면용 문장 정리를 새 독립 답변으로 비교하지 않는다. 학생이 제출한 화면 문장과 발화 원전사가 다를 수 있다는 표시와 출처를 유지한다. 기존 음성·답변·확정 리포트와 과거 분석을 재작성하지 않는다.

## 실패·재시도·호출 한계

| 상태 | 사용자와 저장 동작 |
|---|---|
| STT 실패/권한 없음/시간 초과 | 원음을 보존하고 전사 실패를 표시한다. 다른 공급자로 자동 전송하지 않는다. |
| 원전사 성공·정리 실패 | 원음과 원전사를 보존한다. 일반 답변 칸을 후가공 완료처럼 채우지 않고 원전사 확인 및 문장 정리 재시도를 제공한다. |
| 형식/의미 보호 검사 실패 | 정리본을 승인된 완료본으로 사용하지 않는다. 기존 원전사를 유지한다. |
| 정리 비활성 | 후가공 사용 안 함 상태를 명시한다. 원전사를 정리 완료본으로 표시하지 않는다. |
| 초안 수정/녹음 교체/취소 후 늦은 결과 | 현재 답변을 덮어쓰지 않는다. 해당 녹음에 귀속된 결과만 보존한다. |
| 재시도 | 동일 원전사의 후가공 재시도와 새 음성 전사를 구분한다. 권한·현재 항목·소유권을 다시 확인한다. |

모델·공급자와 서버 사용량 한도를 명시적으로 따르며 오류 시 다른 모델로 자동 우회하지 않는다. 후가공 기본 제한은 25초이고 설정 가능 범위는 5–30초다. 공급자 파일 전사 한도는 25MB지만 앱 인증 미디어의 20MB 업로드 한도를 확대하지 않는다. 대형 파일/장시간 배치/실시간 스트리밍은 별도 구조와 검증이 필요하다.

## 설정

루트 `.env.local`의 기존 `OPENAI_API_KEY`를 사용한다. 키는 클라이언트·문서·로그에 노출하지 않는다.

```dotenv
STT_PROVIDER=openai
OPENAI_TRANSCRIPTION_MODEL=gpt-4o-mini-transcribe
TRANSCRIPT_CLEANUP_ENABLED=true
OPENAI_TRANSCRIPT_CLEANUP_MODEL=gpt-6-luna
OPENAI_TRANSCRIPT_CLEANUP_TIMEOUT_MS=25000
SPEECH_PROVIDER=google
```

마지막 값은 기존 TTS 선택이다. 전사 공급자를 변경해도 낭독 공급자·Google 자격 증명·텍스트 코칭 모델은 유지한다. 실제 환경 변수 변경은 서버 재시작 후 반영된다. `.env.example`은 빈 키 예시이며 사용자의 `.env.local` 비밀 값을 복사하지 않는다.

## 검증 상태와 인수 조건

2026-10-14 구현·검증 완료 범위는 [전사 전환 QA](../.local/transcription-qa-2026-10-14/report.md)에 기록했다. 이전 학습 QA·기존 Google/Whisper 검증을 새 두 단계의 통과 증거로 재사용하지 않는다. 현재 코드의 빌드, 교정·발화 출처·성장 관찰 42개, 파이프라인 47개, PostgreSQL 통합 21개, 면접 화면 복구 15개 검사를 통과했다. 격리 데이터에서 실제 OpenAI 두 단계 24개 API 검사와 최종 코드의 캐시·녹음 선택·제출 16개 검사를 확인했다.

실제 API 측정에는 마이크 음성 대신 오프라인으로 생성한 17.5초 한국어 합성 음성 한 개를 사용했다. 면접 업로드부터 정리 완료까지 7.509초, 퀴즈 전사 요청부터 정리 완료까지 5.110초였고 후가공 구간은 각각 3.361초·2.340초였다. 서버 초기 처리와 두 단계 호출을 포함하는 단일 표본이며 실제 학생·기기·동시 접속의 지연 통계가 아니다. `세 지점→새 지점`, `강우→방우` 인식 오류는 정리본에도 남았으므로 인식 정확도까지 통과했다고 판단하지 않는다. 읽기 쉬운 정리와 음성 인식 정확도는 별도로 검증한다.

브라우저에서 면접·녹음형 퀴즈의 완료 정리본 표시, 접힌 원전사 확인, 직접 작성한 초안 보존, 정리본 명시 선택과 제출을 확인했다. 제출 시 원전사·정리본·녹음 ID를 고정한다. 사용량 로그 장애가 원전사 저장을 막거나 이미 완료한 전사·후가공을 다시 유료 호출하게 하지 않는다. 예약된 사용량은 유지한다. 기존 공개 스키마 62개 테이블의 행 수·내용 해시와 보존 대상 원본 MD 9개의 해시는 유지되었다. 서버 3100도 새 환경으로 재시작했다.

새 검증에는 다음 조건을 포함한다.

- 한 키·두 명시 모델·TTS 독립 설정, 브라우저 키 노출 없음.
- 원전사/정리본/학생 정정 저장 분리와 과거 리포트 보존.
- 원전사의 습관어·반복과 실제 RMS 공백 관찰 유지.
- 부정·불확실성·역할 주체·수치 보호, 발화 속 명령문을 지시로 따르지 않음.
- 전사·정리 진행 상태와 완료본만 주 화면에 표시.
- 실패·취소·늦은 응답·초안 수정 충돌, 정리만 재시도할 때 중복 STT 없음.
- 학생 간 녹음/세션 ID 교차 접근 거부와 명시된 사용량 한도.
- 남은 인수: 실제 한국어 마이크 녹음의 습관어·인식 오류·의미 보존, 기기·브라우저별 녹음 품질 및 동시 접속 지연 실측. 격리 스키마는 FK·RLS·트리거를 복제하지 않으므로 배포 권한 정책 검증의 대체물이 아니다.

Google보다 빠르다거나 더 저렴하다는 비교는 같은 길이·품질·기기 조건의 실제 측정과 현행 요금 비교가 없으면 확정하지 않는다. 두 단계 순차 호출은 후가공 지연을 더하므로 전사 완료·정리 완료 시간을 따로 관찰한다.

공식 근거: [gpt-4o-mini-transcribe](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe), [Speech to text 및 후가공 안내](https://developers.openai.com/api/docs/guides/speech-to-text), [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna).
