# 연결된 학습 기록

> 현행 계약·검증 갱신: 2026-10-14. [문서 적용 순서](document-authority.md)와 [서비스 PRD v2.2](../확정안/4.%20서비스_PRD_v2.2.md)를 따른다. [개선·검증 요약](learning-remediation.md)과 [후속 QA](../.local/learning-remediation-2026-10-14/report.md)·[화면 보고서](../.local/learning-remediation-2026-10-14/report.html)에 실제 API/저장값·학교 등록·같은 질문의 학습 연결 검증을 기록했다. 아래 이전 테스트와 화면은 당시 범위로 보존한다. 실제 OAuth·Live/STT·장기 회상·88교 전 학과 콘텐츠 품질·운영 보안은 후속 인수 게이트이며, 이번 결과가 모든 기능이나 실제 학습 효과의 완료를 뜻하지 않는다.

## 2026-10-14 관찰 가능한 준비 상태

신규 답변의 도움 관찰 계약은 `assistance_recorded`로 명시한다. 도움 기록이 확인된 무도움 시도, 도움 사용 시도, 과거 도움 여부 미기록을 구별한다. 과거 `assisted:false`만으로 무도움 성공을 소급 인정하지 않는다. 기존 확정 리포트·원문·답변은 고치지 않고 새로운 파생 관찰과 당시 사실을 구분한다.

학습 축은 같은 학생·질문 의도·지원처 identity·개인 콘텐츠 버전/공통 출처 revision에 연결한다. 실제 새 답변·전사 정정·즉시 반복·시간이 지난 재확인을 별도로 보여 주고, 경과 시간이나 복습 만기만으로 기억 유지 성공을 선언하지 않는다. 작성/텍스트와 실제 음성 수행도 구분한다.

2026-10-14 전사 개정에서는 `gpt-4o-mini-transcribe` 원전사와 `gpt-6-luna` 화면용 정리를 별도 보존한다. 원전사·AI 정리·학생 직접 정정·새 녹음을 구분하며, 문장 정리만으로 새 발화/독립 수행/내용 발전을 만들지 않는다. 실제 발화의 습관어·반복과 인용은 원전사, 쉼은 실제 RMS 관찰을 사용한다. 학생이 제출한 화면 문장과 실제 발화 원문이 다를 수 있다는 출처를 유지한다. 기존 리포트와 당시 답변은 재작성하지 않는다. 상세 처리·실패·검증 계약은 [전사·화면용 정리](transcription-pipeline.md)를 따른다.

리포트의 보완 과제는 서버가 원래 리포트·실제 턴의 스냅샷에서 생성한다. 새 교재·학교 전환·질문 삭제가 이전 답변을 현재 맥락으로 바꾸지 않는다. 다음 한 가지는 질문별 필수 의미 요소와 실제 답변의 확인 가능한 근거로 정하며 자기 체크·완료 개수를 실력으로 해석하지 않는다.

답변 의미 자기 확인은 `POST /api/learning`의 `action:"answer_meaning_check",versionId,checkedMeanings,requestId`로 저장한다. 서버가 본인 시도와 당시 승인 요소를 대조하고 `selfCheckOnly:true`를 반환한다. 조회는 `self_checked_meanings,self_checked_at`을 제공한다. 체크는 해당 시도에만 연결되며 답변·확정 리포트·학습 이벤트·성취 수치를 바꾸지 않는다. 과제 마감 시각은 회상 만기가 아니다.

현재 독립 확인 집계는 도움 관찰이 명시되고 검수된 객관 정답이 있는 결과만 사용한다. 개인 경험의 독립 설명은 새로운 시도의 실제 답변·도움 기록·질문 요소·남은 불확실성을 함께 봐야 한다.

## 원본과 누적 기록

`202610120008_learning_events.sql`은 과거 퀴즈, 제출한 면접 답변, 암기 복습, 과제 답변, 영상 시청 체크·메모를 `study_imported_events`에 소급 연결한다. 원본 ID와 실제 수행 시점을 저장하며, 가져온 시점은 `imported_at`에 따로 남긴다. 과거 기록은 방문 세션에 억지로 끼워 넣지 않는다. 이미 확정한 `study_sessions.report`는 수정하지 않는다.

같은 학생·유형·원본 ID는 한 번만 집계한다. 퀴즈나 과제에서 함께 생성한 `memory_attempts`는 별도 암기 복습으로 중복 집계하지 않는다. 이미 방문 이벤트에 연결된 원본은 소급 버킷에 추가하지 않는다. 소급 SQL은 반복 실행해도 동일하다.

신규 암기 복습과 과제 제출은 원본 저장 트랜잭션 안에서 `recordStudyEvent`를 호출한다. 신규 지식한입도 동일한 계약을 사용한다. 영상 체크·메모·설명은 스스로 남긴 학습 사실이며 시청 텔레메트리나 이해도 점수로 표시하지 않는다.

## 현재 약점과 해결한 부분

오답·시간 초과·기억 안 남은 현재 복습 항목에 남는다. 이후 같은 항목에서 **검수된 정답을 힌트·AI 도움 없이 맞힌 경우** 현재 약점에서 해소 항목으로 이동한다. 이후 다시 틀리면 복습 필요 상태가 된다. 기존 오답 원본은 그대로 보존한다.

답변 저장, 녹음, `good` 자가평가, 영상 시청 체크만으로 약점을 해소하거나 실력 점수를 올리지 않는다. 미채점 답변은 미채점 상태로 남긴다. 도움 없이 정답 확인 수는 서로 다른 항목 수이며 합격 가능성이나 서술형 답변의 의미 품질이 아니다.

## 답변 비교

`GET /api/learning`의 기존 `versions`·`answerRevisions`에 Q&A, 퀴즈 녹음, 과제 답변을 추가했다. 작성본과 면접·전사 정정본도 함께 정렬한다. 첫 답과 최근 답을 기본 비교하고 다른 시점도 선택할 수 있다.

퀴즈는 세션 당시 문항 스냅샷, 힌트 사용, 원본 녹음 ID, 정오, 자료 버전을 사용한다. 전사 없이 녹음만 남겼으면 텍스트를 만들지 않는다. 새 작성본은 `answer_revisions.data`에 당시 질문·답변 설계·자료 버전을 저장한다. 과거 작성본은 수정 당시 발행돼 있던 자료로 복원할 수 있는 경우만 연결하며, 자료를 확인할 수 없으면 그대로 표시한다.

공통 질문의 재연습은 개인 자료 버전을 요구하지 않는다. 개인 자료에서 재연습할 때는 원래 자료 버전을 전달한다. 재발행 후에도 저장 당시 질문과 실제 답변을 읽을 수 있다. 글자 수 변화는 품질 점수로 표시하지 않는다.

선택형에서 개념을 설명한 Q&A·녹음은 개인 경험 답변과 분리한다. 과거 자료에서 개념 카드가 개인 면접 질문에 잘못 연결됐으면 `concept:암기항목ID` 별도 이력으로 묶고 원래 연결 ID만 출처로 보존한다. 해당 개인 질문의 답변 요소로 개념 설명을 평가하지 않는다. 새 자료의 전용 개념 질문은 실제 ID를 유지한다.

힌트와 AI 도움은 따로 기록한다. 기록이 없으면 사용하지 않았다고 단정하지 않는다. 성장 집계와 탐색은 원본 소스에서 도움·개념·검수 사실을 읽어 정규화하며, 기존 확정 리포트를 다시 쓰지 않는다. 확정 리포트 상세에는 원본을 보존한 `session.report`와 탐색에 필요한 `sourceFacts`를 따로 반환한다.

Chat에서 답변 후보를 저장할 때는 `chatThreadId`·`chatMessageId`를 서버에서 확인한다. 학생 소유의 같은 대화, 완료된 assistant 응답, 동일 질문, 현재 발행된 동일 자료 버전을 만족한 경우만 AI 도움 메타데이터를 저장한다. 다른 학생 소유·다른 질문·이전 자료·진행 중 응답은 거절한다. ID 없이 작성한 일반 수정은 기존처럼 저장하며 브라우저가 보낸 `assisted` 플래그만으로 AI 도움을 인정하지 않는다.

## API 계약

`GET /api/study-sessions`는 기존 `current`, `latest`, `sessions`, `totals.quiz`, `totals.interviews`, `totals.weakPoints`를 유지한다.

- `totals.resolvedPoints`: 이전 오답을 도움 없이 검수 정답으로 재확인한 항목.
- `totals.independentlyVerified`: `{ count, questions }`, 각 질문은 원본 ID·확인 시점 포함.
- `totals.memory`: `{ reviewed, verifiedCorrect, selfChecked }`.
- `totals.assignments`: `{ submitted, verifiedCorrect, ungraded }`, 제출한 문항 수.
- `totals.knowledge`: `{ updates, completed, reflections }`, 직접 체크하거나 메모한 영상별 사실.
- `totals.historical`: `{ eventCount, firstAt, lastAt }`.
- `history`: 원래 시점순의 소유 학습 이벤트. 소급 이벤트는 `historical: true`.
- `nextQuestion`: `{ questionId, prompt, activityIds, assisted } | null`.

다음 적용 질문은 저장한 퀴즈·과제 중 아직 같은 정확한 질문 ID로 면접에 적용하지 않은 최근 항목이다. 면접 자체는 새 후보를 만들지 않는다. 면접 이후 같은 질문을 새로 퀴즈에서 연습하면 다시 적용 후보가 된다. 이 단계 완료는 실력 확인과 별개이므로 오답·도움 사용의 현재 약점 판단을 바꾸지 않는다. 문자열 유사도나 개인 질문과 개념 질문의 연결 ID로 완료를 추정하지 않는다.

새 이벤트 종류는 `memory_review`, `assignment_submission`, `knowledge_progress`다. 공통 필드는 `questionId`, `memoryItemId`, `prompt`, `contentVersion`, `outcome`, `verified`, `hintUsed`, `assisted`, `evaluationMethod`이며 해당 활동에서 실제로 측정한 필드만 사용한다. 지식한입은 `${progress.id}:${revision}` 원본 ID를 사용한다.

화면의 내 기록 내보내기는 인증된 본인의 학습 이벤트·확정 리포트·답변 이력을 JSON으로 내려받는다. 화면에는 최근 50개 이벤트를 표시하고 내보내기에는 전체 소유 이력을 포함한다.

## 이전 기능 검증 기록

`node --conditions=react-server --import tsx tests/learning-records.mts`에서 50개 검증이 통과했다. 로컬 PostgreSQL의 실행마다 다른 합성 스키마에서 전체 기존 마이그레이션과 새 소급 SQL을 실행했다. 중복 방지, 원래 수행 시점, 확정 리포트 보존, 힌트 답의 미해소, 독립 정답의 해소, 미채점 보존, 재발행 후 Q&A·작성본 원문, 전사 없는 녹음, 학생 소유권, 실제 과제 제출 트랜잭션을 확인했다. 경험형·미승인·자가평가의 정답 판정 차단, AI 도움 구분, 개념과 개인 질문의 분리, 원래 학교·공통 자료 버전 유지, Chat 후보의 소유권·질문·현재 발행 버전·완료 상태와 일반 수정도 검증했다. 다음 단계 적용을 끝내도 오답 약점이나 도움 사용이 독립 정답으로 바뀌지 않는 것을 확인했다. 검증 스키마는 종료 시 제거하며 기존 학생 자료는 변경하지 않는다. 외부 OAuth·유료 AI·카메라·마이크 호출은 없다.

`node --import tsx tests/next-learning-question.test.ts`의 18개 검증은 DB나 외부 호출 없이 정확한 ID·원래 시간 순서·면접 적용 이후의 새 퀴즈·빈 답변·무효 기록·녹음 답변·오답과 도움 증거 보존을 확인한다.
