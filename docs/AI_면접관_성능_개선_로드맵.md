# AI 면접관 성능 개선 로드맵

기준일: 2026-11-02 · 대상: 현재 존재하는 AI 면접 화면의 질문·후속 질문·평가·피드백·대화 운영 엔진

최신 후속 구현: [면접 단일 코어 전환 및 최신 로그 검토](면접_단일코어_전환_및_최신로그_검토.md). 아래 본문은 변경 전 분석이고, 새 사전 캐시·단일 코어의 검증 범위와 잔여 과제를 별도 기록했다.

실행 상태(2026-11-02): 아래 본문은 변경 전 진단·로드맵이다. 이후 P0-1 경로·원문 검증, P0-2 전제 검수, P0-3 집계, P0-5 복구 회귀를 진행했다. P0-4는 구조 검증을 강화했으나 의미 검증이 남았고, P0-5도 실기기 전체 흐름·새로고침 복원을 완료한 상태는 아니다. 최신 구현·실제 API 검증·남은 지연 문제는 [P0 실행·검증 결과](P0_실행_검증_결과.md)를 기준으로 확인한다.

## 판단 요약

가장 큰 개선 과제는 더 그럴듯한 질문 문장을 만드는 것이 아니라, **학생의 실제 답변에서 무엇이 확인됐고 무엇을 더 확인해야 하는지를 기억하고 결정하는 면접관**으로 바꾸는 것이다. 현재는 원문 근거 검증과 진행 안전장치가 비교적 잘 갖춰졌지만, 확인할 내용의 구조화·대화 간 기억·심화 전략·묶음 평가가 충분히 연결되지 않았다.

실행 순서는 **정본·근거 경로 및 평가 계약 정합성 → 근거가 붙은 대화 기억과 후속 선택 → 사전 검수 질문 후보 및 난이도 조절 → 사람 면접관 기준의 반복 검증**으로 잡는다. 프롬프트에 MD 전체를 더 넣거나 면접관 목소리만 바꾸는 것으로 해결할 수 있는 문제가 아니다.

### 적용 범위와 증거 해석

- 지정 폴더의 MD **30개**를 목록화했다. 최신·관리 문서 17개와 원본 백업 13개이며 총 20,263줄이다. 최신본과 백업은 실제 변경분을 대조했다. 질문·평가·운영·학생부 분석 본문은 상세 검토하고, 다른 문서에서는 면접 성능에 관련된 계약만 추출했다. 문서별 적용 범위는 부록 A에 남겼다.
- 화면·IA·대시보드·리포트 페이지·설정·회원·업로드·결제·서비스 확장은 작업 대상이 아니다. 이 문서의 피드백과 점수 설계는 기존 엔진이 산출하는 내부 데이터와 문장 품질에 관한 것이다.
- 현재 제품은 **서울시립대학교 융합응용화학과의 서류기반 대학입학 모의면접**이다. 요청한 ‘직무 적합성’은 현 범위에서 전공·전형 적합성으로 해석한다. HR·실무진·임원을 구현된 채용 면접관으로 간주하지 않는다.
- 사용자가 말한 PDF 사전 학습 구조는 코드상 **사전 준비한 원문 발췌를 질문·평가 입력에 제공하는 방식**이다. 모델 가중치를 PDF로 별도 학습한 근거는 없다. 기존 자료를 더 잘 구조화하는 일은 업로드 기능 개발과 별개다.
- **구현 확인**, **과거 로그 관찰**, **정적 코드로 예상되는 위험**, **새 설계 제안**을 구분한다. 이번 작업에서 새 면접·외부 모델 호출·실기기 측정·코드 변경은 하지 않았다. 과거 회귀 시험 통과를 전문 면접관 수준의 품질 검증으로 대신하지 않는다.
- 최신 정본과 예시·과거 버전이 충돌하면 최신 문서의 명시적 우선 규정을 적용한다. 역사 자료의 학생 사례·통계는 현재 학생의 경험이나 현재 엔진 성능 증거로 사용하지 않는다.

## 1. 현재 면접관 구조 분석

### 1.1 질문 생성 방식

현재 흐름은 다음과 같다.

`사전 준비 학생부 근거 → 회차 질문 계획 → 답변 반응 판정 → 진행 위치·면접관·목소리 예약 → 질문 생성·검수와 연결 음성 준비 → 실제 음성 재생 → 다음 답변`

| 구성 | 현재 확인된 방식 | 품질에 미치는 영향 |
|---|---|---|
| 학생부 입력 | 24쪽 PDF의 검수된 구간 17개. 페이지·PDF 해시·원문 offset 보존 | 출처 추적은 가능하지만 활동 전체의 역할·선택·행동·결과·공백을 분석한 자료는 아니다. 발췌마다 별도 activity ID여서 같은 활동을 의미상 통합하는 단계가 부족하다. |
| 주질문 계획 | 학업·탐구, 문제해결, 공동체, 진로, 근거·한계의 키워드와 시드·분산 규칙으로 활동과 기능 선정 | 소재는 분산되지만 실제 학생의 강약·이미 확인된 역량·지원처 요구를 종합하는 선정은 제한적이다. |
| 질문 기능·깊이 | 주질문은 여러 기능을 쓰지만 함수별 D1/D2/D3 매핑이 중심 | 난이도 1·2·3과 실제 답변에 따른 심화 수준을 운영하는 정책은 없다. |
| 답변 반응기 | 현재 질문·현재 최종 전사만 받아 관련·부분·무관·불명확·무응답 등을 판정 | 빠르고 입력이 작지만 학생부와의 차이, 앞선 묶음 답변과의 모순을 안정적으로 볼 수 없다. |
| 평가용 후속 | 실제 인용의 구체화 `CLARIFY_CONTENT`, 새 주장·자기모순 확인 `VERIFY_CLAIM` 중심 | 원리→적용→한계 같은 다양한 심화 전략이 후속 선택 계층에 충분히 열려 있지 않다. |
| 검수 | 실제 원문 ID별 인용 대조, 단일 표적·길이·슬롯·역할·중복·금지 발화 검사 | 인용 추적은 강점이다. 인용 존재만으로 질문 전체의 전제·인지 요구·난이도 타당성이 증명되지는 않는다. |

질문·반응의 기본 모델은 코드상 Luna 계열, 종료 분석은 Terra 계열이다. 모델 이름보다 현재의 입력 범위와 결정 계약이 더 직접적인 제약이다. 연결 음성과 질문 준비는 이미 병렬 처리하며 실제 재생은 순차로 유지한다. 반응기와 생성기를 분리하는 구조 자체는 이미 있다. [C2] [C3] [C4] [C5] [C6]

**즉시 확인할 정본·원천 경로 문제:** 설정은 루트의 질문·답변 v2.1 MD와 PDF를 가리키지만, 이번 파일 확인에서 세 경로는 존재하지 않았다. 최신 MD는 지정 폴더의 v2.3이고 PDF는 `래퍼런스/윤지우학생 생활기록부.pdf`에 있다. 기존 발췌 캐시의 PDF 해시는 이동된 PDF와 일치했다. 현재 프로세스가 과거에 읽은 자료를 메모리에 보유할 수 있으므로 ‘지금 실행 중인 면접이 실패한다’고 단정하지는 않는다. 다만 새 실행·재현·평가 시 필수 자료를 같은 버전으로 읽을 수 없는 정적 결함이다. 파일명만 연결해도 압축 실행 규칙·스키마·평가 산식까지 자동 갱신되는 것은 아니다. [C1] [C2] [C3]

### 1.2 직무 반영 방식

현재 JD나 채용 직무 역량 모델은 없다. 실제 반영 대상은 대학·학과 인재상과 해당 학년도·전형의 공식 평가요소다. 세 자료를 출처별로 구분하고 지원처 ID·연도·전형을 검증하는 점은 좋다.

다만 학생부 후보 선정 뒤 `schoolConnections`를 붙이는 방식이어서, 해당 질문을 왜 그 전형에서 우선해야 하는지가 선정 점수에 충분히 반영되지 않는다. 개선 시 **공식 평가요소 → 관찰할 학생 행동 → 관련 활동 → 질문 기능 → 답변 증거**를 선정 단계부터 연결한다. 인재상 문구를 직접 외우게 하거나 공식 배점을 질문 개수 비율로 치환하지 않는다. 학과 지식의 전문성만으로 전형 적합성을 대신 평가하지 않는다. [C5] [D5] [D6]

### 1.3 답변 평가 방식

종료 평가 모델이 원문 인용·이유·축별 0~4 앵커를 출력하고 서버가 숫자를 계산한다. 질문 충족 I, 정확성·정합성 A, 구체성·근거 S, 논리·추론 R, 의미 명료성 C의 5축이다.

잘 구현된 부분은 실제 질문 ID 대조, 평가 누락·중복 차단, 인용의 실제 답변 구간 검증, 순수 재진술 답변의 원질문 통합이다. 반면 앵커를 지지하는 인용의 의미 적절성, 안정적인 사람 채점 일치도, 최신 묶음·회차 집계는 미완성이다. 개념 질문은 독립적인 정오 근거 부족 때문에 현재 일괄 보류된다. [C7] [C8]

### 1.4 피드백 생성 방식

종료 분석에 강점·보완·전달 코칭·사실 차이 확인 등의 문자열을 생성한다. 실제 발화 인용 검증과 내용 점수·음성/시선 코칭의 분리는 갖춰져 있다. 하지만 강점·보완 문장마다 요구 ID와 실제 증거를 구조적으로 연결하지 않아, 평가 이유가 추상적인 일반론으로 흐를 여지가 있다.

승인된 활동 우선도는 현재 없고 `STRATEGY_UNAVAILABLE`이다. 이는 질문에 답한 품질을 평가할 수 없다는 뜻은 아니다. 더 좋은 경험을 임의로 창작하거나 S등급 활동을 추천하는 전략 코칭만 구분해 제한해야 한다. [C7] [D5] [D10]

### 1.5 면접 흐름 제어 방식

현재 공식 자료에서 확인해 둔 12분과 서비스 정책상 주질문 목표 5개를 연결한다. 5개는 대학의 공식 출제 개수가 아니다. 같은 묶음의 평가용 F1/F2 상한은 2개이며, 순수 재질문은 별도이고 묶음당 한 번이다. 남은 주질문의 시간 확보를 위해 전환 시 예약 시간을 적용한다.

무응답 제출, 명시적 모름, 실제 음성 인식 오류를 구분하는 경로와 같은 화면의 일시 중단·재개가 있다. 반응 형식 실패는 최근 v3에서 제한된 재검증 후 안전한 재질문·전환으로 복구하도록 바뀌었다. 이 수정 이후의 복사본 검증과 과거 실사용 중단 로그는 다른 증거다.

새로고침·서버 재시작 후 같은 회차를 복원하는 기능은 정적 코드상 확인되지 않는다. 클라이언트의 세션 정보는 state/ref, 서버 조회는 메모리 Map, 저장소는 저장 중심이다. 현재 pause/resume가 문서의 동일 회차 복원 계약을 충족한다고 간주하면 안 된다. 복원은 현재 대화 연속성의 문제로 다루고 계정·새 화면으로 확장하지 않는다. [C9] [C10] [C14] [D4] [D8]

## 2. 면접 품질 진단

전문 면접관과의 차이는 ‘얼마나 자연스러운 존댓말인가’보다 **학생이 한 말을 실제로 들은 결과가 다음 질문에 드러나는가**에 있다.

| 학생이 느끼는 문제 | 관찰·근거 | 현재 판단과 개선 방향 |
|---|---|---|
| 새로운 설명을 했는데 같은 부족 항목으로 판단하거나 주제가 바뀜 | 과거 실사용 회차에서 새로운 방법 설명이 추가돼도 같은 표적 문자열 때문에 전환 | 해당 반복 판정은 이미 수정됐다. 남은 문제는 확인된 요소를 의미 단위로 기억하고 다음 검증 목적을 선택하는 구조다. |
| 답변을 못 했다는 이유로 시스템 오류처럼 멈춤 | 과거 무음 제출·`INVALID_REACTION` 실사용 기록 | 현재 복구 경로가 추가됐다. 수정 전 실패를 현재 미수정 결함으로 다시 세지 않고, 실제 다음 질문 재생까지 복구됐는지 추적한다. |
| 말은 받아 주지만 실제로 듣고 있는 느낌이 약함 | 현재 반응기 입력은 직전 질문·답변 중심 | 앞선 역할·수치·선택·정정 상태를 공유하고 답변의 새 정보가 다음 질문에 반영되게 한다. |
| 질문을 던지는 로봇처럼 소재만 바뀜 | 정적 주제 계획과 충분한 답변→다음 main 분기 | 충분하면 전환하되, 확인할 가치가 높은 새 근거·한계가 있는지 별도로 판단한다. 후속을 무조건 늘리지는 않는다. |
| 연결 멘트 뒤에 또 기다림 | 과거 두 전환의 실제 재생 공백 | 짧은 반응을 길게 늘리지 않고 생성·검수 재시도·TTS·재생 대기를 각각 줄인다. |
| 서로 다른 면접관이 같은 질문 방식 사용 | 같은 모델·생성 계약, 역할별 계획 구분은 있으나 독립된 질문 전략은 약함 | 목소리보다 역할별 확인 관점과 인수인계 기억을 구분한다. |
| 피드백이 일반적인 조언처럼 느껴짐 | 강점·보완이 증거 참조 없는 문자열 배열 | 실제 표현·요구·부족 이유·다음 행동을 연결해 학생이 고칠 한 지점을 명확히 한다. |

과거 실발화 두 전환에서는 제출→연결 음성이 **2.362/3.106초**, 제출→다음 질문이 **6.776/9.236초**, 연결 종료→질문 사이가 **1.886/3.175초**였다. 표본 2개의 관측이며 일반 p95나 현재 배포의 평균이 아니다. 유효한 LIMIT 표현을 검수가 오인해 재생성하면서 약 3.897초가 추가된 문제는 이후 보강됐다. [L1]

가장 최근의 실사용 중단 회차는 질문 1개·확정 답변 1개, 반응 판정과 다음 질문 재생은 0개였다. 종료·평가 상태가 completed였다는 사실은 대화의 정상 지속을 뜻하지 않는다. 이 회차는 reaction-v2이고 현재 v3 수정의 실제 사용 성공률을 나타내지 않는다. 현재 반복 멘트의 청취 피로도와 페르소나의 자연스러움은 코드에 근거한 가설이며, 사람 청취 평가가 추가로 필요하다. [L2]

## 3. 질문 품질 개선

### 3.1 질문 후보를 문장보다 먼저 구조화한다

현재 발췌 자료에서 `활동 → 본인 행동 → 선택 → 결과/관찰 → 근거 → 한계 → 확인되지 않은 내용`을 분리한다. 모든 칸을 채우는 것이 아니라, 원문에 없으면 미확인으로 보존한다. 같은 활동의 다른 학년·영역 기록은 근거를 유지한 채 연결한다.

후보에는 원문 참조, 지원처 연결 이유, 확인 목적, 가능한 깊이, 이미 질문한 의미 대상, 채점 가능성, 질문 전제의 확인 상태를 붙인다. S/A/B/C/F 준비 우선도를 바로 답변 점수나 출제 확률로 바꾸지 않는다. PDF 전체 구조화가 완성되기 전에도 기존 17개 근거로 이 계약을 먼저 적용할 수 있다. [D5] [D7]

### 3.2 난이도와 깊이를 분리해 조절한다

| 운영 수준 제안 | 확인 전략 | 심화·종료 조건 |
|---|---|---|
| 기초 | 실제 활동·본인 행동·기록에 나온 개념의 의미 | 질문 요구를 이해하는지 먼저 확인. 불명확하면 쉬운 재질문, 부족한 지식을 지어내게 하지 않음 |
| 표준 | 선택 이유·과정·주장 근거·결과 해석 | 실질적인 답변 한 지점을 검증. 설명이 충분하면 종료 가능 |
| 심화 | 적용 범위·한계·대안·기록 범위의 전이 | 앞선 답변에 충분한 근거가 있고 남은 시간·F 예산이 있을 때만 선택 |

이는 새 화면의 난이도 선택기를 제안하는 것이 아니다. 현재 엔진 내부의 질문 정책이다. 난이도가 높다고 F2나 D4를 강제하지 않고, 낮은 수준의 질문에 완벽한 STAR·수치·성찰을 요구하지 않는다. 깊이 조절의 이유는 실제 답변의 확인 상태로 설명할 수 있어야 한다. 질문 가이드 제10·19조 [D9].

### 3.3 다양성·적합도·중복·맥락을 함께 관리한다

- **다양성:** 활동 수뿐 아니라 질문 기능·학년·영역·확인 역량을 분산한다. 소재만 다른 PROCESS 질문 다섯 개는 충분히 다양한 면접이 아니다.
- **적합도:** 대학 일반 인재상, 학과 인재상, 공식 전형 평가요소를 별도로 연결하고 학생의 실제 행동을 확인한다. 취업 직무 데이터가 없는데 ‘직무 적합도 85점’ 같은 값을 만들지 않는다.
- **중복 방지:** 질문 문자열 외에 `활동 + 확인 대상 + 인지 요구 + 이미 확보한 증거`를 비교한다. 같은 표현을 쉽게 다시 말하는 비평가 재질문은 반복 오류와 구분한다.
- **맥락:** 과거 대화 전체를 매번 보내는 대신, 인용이 붙은 주장·확인 상태를 작은 기억으로 유지한다. 최근 답변의 핵심어를 붙이는 것만으로 장기 맥락을 유지했다고 보지 않는다.
- **질문 품질 검수:** 질문에 새로 등장한 역할·수치·성과·인과·갈등을 전제로 분해해 실제 근거가 있는지 확인한다. 원문 인용의 존재와 전제의 타당성을 별도로 검사한다.
- **사전 준비:** 주질문은 같은 검수 계약을 통과한 대체 후보를 준비한다. 학생 답변에 의존하는 F1/F2의 문장을 미리 고정해 읽지는 않는다.

## 4. 꼬리질문 품질 개선

### 4.1 목표는 부족한 말을 더 시키는 것이 아니라 필요한 증거를 얻는 것이다

현재 엔진은 새 주장·같은 답변의 자기모순·구체 행동 확인의 기초가 있다. 그러나 학생부와의 차이, 이전 답변 간 모순, STAR 요소, 수치의 분모·기간·측정법을 공유하는 구조는 없다. 다음과 같은 내부 기억을 도입한다.

| 기억 단위 | 필수 내용 |
|---|---|
| 주장 | 역할·행동·수치·결과·원리·선택·가치 등 유형, 실제 답변 span/turn ID |
| 원천 연결 | 관련 활동 ID·학생부 근거 ID·원문 버전 |
| 확인 상태 | 기록에 있음 / 학생 신규 진술 / 차이 확인 중 / 확인됨 / 미확인 |
| 검증 이력 | 무엇을 이미 물었는지, 어떤 답변으로 충족했는지, 남은 공백 |
| 질문 계약 | 현재 묶음·원질문 의도·허용 깊이·F 사용량·재질문 사용량·남은 시간 |

학생이 새 경험을 말했다고 학생부의 공식 사실로 자동 승격하지 않는다. 반대로 기록에 없다는 이유만으로 거짓말로 처리하지도 않는다.

### 4.2 실제 면접관 수준의 후속 선택 순서

1. **인식·청취 상태 확인:** 정상 확정 전사인지, 단순 무응답인지, 실제 기술 오류인지 구분한다.
2. **현재 요구 충족 확인:** 질문이 요청한 한 가지를 답했는지 판단한다. 추가 설명이 가능하다는 이유만으로 부족 판정을 하지 않는다.
3. **검증 후보 추출:** 모순 가능성, 본인 행동 공백, 수치의 근거, 선택 이유, 적용 한계 등 실제 답변에서 나온 후보만 만든다.
4. **검증 가치와 위험 판단:** 질문 의도에 관련되는가, 답하면 평가 증거가 달라지는가, 앞서 확인했는가, 허위 전제가 생기지 않는가를 비교한다.
5. **한 지점 선택:** 가장 중요한 확인 목적 하나와 적절한 기능·깊이를 고른다. 문장 생성은 그 다음이다.
6. **운영 예산 적용:** F2 상한·재질문·남은 시간을 확인한다. 충분한 답변·모름·검증 실익 없음이면 전환한다.
7. **발화 후 상태 갱신:** 실제 질문이 공개된 후에만 ‘질문함’으로 기록하고, 답변이 오면 확인 상태와 정정 이력을 갱신한다.

빠른 연결 반응은 이 판단의 결론을 꾸며내지 않는 중립 표현이어야 한다. 뒤에서 아직 검증 중인데 ‘충분히 설명했습니다’, ‘정확합니다’라고 말하지 않는다.

### 4.3 일곱 가지 검증 전략

아래는 **학생이 해당 진술을 실제로 했을 때 적용하는 가상 검증 예시**다. 현재 학생의 기록·답변을 인용한 것이 아니다. 한 행의 여러 검증 후보를 한꺼번에 질문하지 않는다. 첫 확인 예시가 모두 자동으로 F1이라는 뜻은 아니다. 순수 재진술·기술적 재청취와 새로운 사실·근거를 요구하는 평가용 후속을 구분한다.

| 전략 | 발동 조건 | 우선 확인 예시 | 추가 후속 또는 종료 |
|---|---|---|---|
| 모순 탐지 | 같은 활동·시점·조건에 관한 두 진술이 양립하기 어려움 | “두 설명은 서로 다른 단계를 말씀하신 건가요?”처럼 먼저 범위를 확인 | 정정되면 상태 갱신·종료. 진짜 새 평가 요구가 남을 때만 근거 한 가지를 검증. 거짓말 판정 금지 |
| 경험 깊이 | 활동명·팀 성과만 있고 개인 행동이 불명확 | “그 과정에서 직접 맡은 일 한 가지만 설명해 주세요.” | 실제 행동이 확인되면 그 행동의 선택 이유·어려움 중 필요한 하나. 이미 충분하면 종료 |
| STAR 검증 | 해당 질문의 의도에 필요한 상황·과제·행동·결과 중 공백이 있음 | 과정 질문이면 A, 결과 질문이면 R의 필요한 한 요소 | STAR는 엔진의 공백 점검 도구로만 사용. 모든 답변에 네 요소·성찰을 일괄 요구하지 않음 |
| 수치 검증 | 학생이 ‘20% 개선’ 같은 새 수치를 주장 | “그 20%는 어떤 기준과 비교한 값인가요?” | 필요하면 측정 방법·기간·표본 중 하나. 원음/전사 불확실이 먼저면 청취 확인. 수치가 없다는 이유만으로 감점 금지 |
| 근거 검증 | 결론·원리가 있으나 무엇을 보고 판단했는지 불명확 | “그 판단에 사용한 근거 한 가지는 무엇인가요?” | 근거가 확인되면 해석 범위·대안 중 평가 의도에 맞는 하나. 외부 지식 정오 확인과 분리 |
| 행동 검증 | ‘소통했다’, ‘해결했다’ 등 역량 단어만 있음 | “의견이 달랐을 때 실제로 한 행동은 무엇인가요?” | 그 행동에 대한 상대 반응 또는 선택 이유 중 하나. 갈등 자체가 실제 진술에 없으면 갈등을 전제하지 않음 |
| 역량 검증 | 특정 역량을 뒷받침할 실제 행동 증거가 필요 | 문제해결이면 선택 기준, 협업이면 조율 행동처럼 관찰 가능한 요구 | 한 경험으로 성격·역량 전체를 확정하지 않음. 다른 문항의 근거와 종합하거나 관찰 부족으로 남김 |

`같은 질문의 쉬운 재진술`, `기술적 청취 확인`, `새로운 사실·근거를 요구하는 평가용 질문`을 구분한다. 새 평가 요구는 F1/F2에 산입한다. 명칭만 확인 질문으로 바꿔 상한을 우회하지 않는다. 같은 묶음을 새 Q0로 열어 추궁을 계속하지 않는다. 공통 운영 제13~15조 [D8], 질문 가이드 제5·15·16조와 별표4 [D9].

### 4.4 다음 질문 선택의 정량 검증

같은 Q0에 충분·부분·무관·모름·모순·새 수치·STT 불확실 답변을 붙인 분기쌍으로 시험한다. 사람이 합의한 ‘전환/재질문/구체화/근거/한계/적용’과 모델의 선택을 비교한다. **그럴듯한 질문인지**와 **그 상황에서 물어야 할 질문인지**를 별도로 평가한다. 강한 말투나 많은 후속 질문은 전문성의 지표가 아니다.

## 5. 답변 분석 엔진 개선

### 5.1 판단 계층을 분리한다

`실제 발화·측정 보존 → 의미 요소·주장 추출 → 원문·대화와 대조 → 현재 질문 충족 판단 → 다음 검증 목적 선택 → 종료 후 정식 채점·피드백`

현재의 빠른 반응기를 최종 채점기로 만들지 않는다. 반응기 실패 상태인 `unassessed`도 학생 답변 품질 등급으로 사용하지 않는다. 정식 평가는 실제 답변과 질문 계약에서 별도로 수행한다.

### 5.2 요청한 여섯 역량을 기존 루브릭에 연결한다

새로운 공식 6축 배점을 임의로 만들기보다 현재 5축을 유지하고, 여섯 항목은 어떤 문항에서 무엇을 관찰했는지 설명하는 분석 관점으로 사용한다.

| 분석 항목 | 관찰 대상 | 정량 표현 제안 | 적용하지 않는 판단 |
|---|---|---|---|
| 논리성 | 주장·이유·근거·결론의 실제 연결, 비약·조건 누락 | 관련 문항의 R 앵커 0~4, 충족/누락 요소, 근거 span | 긴 답변·전문용어가 많으면 높은 점수 |
| 직무 적합성 | 현 범위에서는 전공 관심·학습 경험과 검증된 전형 요소의 연결 | MOTIVE/CONNECTION 등 관련 문항의 요구 충족과 행동 근거, 문항 수 N | 채용 JD 없는 직무 적합 점수, 인재상 단어 일치율 |
| 문제해결력 | 요청한 문제 정의·선택 이유·본인 행동·검증·한계 | 관련 문항의 I/A/S/R 앵커와 요구한 요소의 충족 상태 | 모든 질문에 전체 문제해결 서사를 사후 요구 |
| 의사소통력 | 질문에 맞는 의미 전달과 명료성 | C 앵커, 의미가 불명확한 실제 구간, 별도의 관측 음성 지표 | 억양·방언·성별·카메라 유무를 내용 점수로 반영 |
| 구체성 | 실제 행동·조건·자료·관찰·예시 | S 앵커와 정확한 인용, 질문이 요청한 구체 요소의 충족 상태 | 근거가 없는 숫자 추가, 수치 없는 답변 일괄 감점 |
| 설득력 | 요구에 맞는 주장과 근거·해석 범위의 연결 | I/A/S/R의 증거 설명 및 관련 앵커 분포 | 자신감·유창함을 진실성으로 추정하거나 별도 가중치로 이중 합산 |

관련 질문이 없으면 그 역량은 **미관찰/null**이다. 질문이 두 개뿐인데 모든 역량을 정밀한 백분위처럼 출력하지 않는다. 요소 충족률을 보조로 쓰더라도 요소의 중요도가 같다고 가정해 최종 점수를 단순 계산하지 않는다.

### 5.3 평가 단위의 내부 계약

평가 데이터에는 다음 연결이 필요하다.

`질문 ID·원래 의도·요구 ID·기능·깊이 → 평가가능성 → 실제 답변 span/부재 사유 → 축별 앵커·이유 → 검증 출처 또는 보류 이유 → 개선 행동`

높은 앵커에도 긍정 근거를 연결한다. 낮은 앵커는 단순히 인용이 없다는 이유가 아니라 ‘실제 질문에서 요청했으나 답변에 확인되지 않은 요소’를 명시한다. 인용이 실제 원문에 있다는 검사와 그 인용이 평가 이유를 지지한다는 의미 검수를 구분한다.

새 경험·새 수치·기록과 다른 설명은 확인 상태를 별도로 보존한다. 확인되지 않은 주장에 대한 검증 질문을 할 수는 있지만, 근거 없이 정확성 오류·핵심 오류로 확정하지 않는다.

### 5.4 피드백을 고칠 수 있는 행동으로 만든다

기본 구조는 **실제 표현 → 충족/미충족 요구 → 그렇게 판단한 이유 → 다음 답변에서 바꿀 행동 한 가지**다.

- “구체성이 부족합니다”에서 끝내지 않고, 본인 행동이 없었다면 어떤 행동을 설명해야 하는지 연결한다.
- 강점도 “잘했습니다” 대신 어떤 설명이 질문을 충족했는지 특정한다.
- 참고 답변은 확인된 사실만 재배열한다. 학생이 말하지 않은 성공·수치·감정·역할은 넣지 않는다. 빈 정보는 추가 확인이나 기입 자리로 남긴다.
- 프레임을 외운 문장과의 일치율로 채점하지 않는다. 학습 범위 안의 다른 정당한 설명도 인정한다.
- 시선·표정·속도·습관어 코칭은 측정된 구간·분모·불확실성을 붙이고 내용 점수와 분리한다. 반복 핵심 용어를 전부 군더더기로 세지 않는다. 평가 가이드 제3·12·17·26조 [D10], 구현 [C11] [C12] [C13].

## 6. 점수화 체계 개선

### 6.1 현재 문항별 계산

각 축의 앵커는 0~4 정수이며 함수별 프로필이 다르다. [C7]

| 프로필 | I 질문 충족 | A 정확성·정합성 | S 구체성·근거 | R 논리·추론 | C 의미 명료성 |
|---|---:|---:|---:|---:|---:|
| EXPERIENCE | 40 | 15 | 25 | 15 | 5 |
| KNOWLEDGE | 30 | 40 | 10 | 15 | 5 |
| REASONING | 30 | 20 | 20 | 25 | 5 |
| VERIFICATION | 35 | 30 | 20 | 10 | 5 |

EXPERIENCE는 사실·동기·역할·과정·결과, KNOWLEDGE는 개념, REASONING은 선택·근거·한계·대안·전이·연결·가치, VERIFICATION은 주장 검증에 대응한다. 구체화 후속은 부모 Q0의 프로필을 승계한다.

문항 점수는 `Σ(프로필 가중치 × 축 앵커 / 4) → 0.5 이상 올림으로 반올림 → 적용 상한 중 최솟값` 순서로 계산한다. I=0이면 상한 39점이다. 검증된 핵심 오류의 상한 59점 계산 함수도 있지만, 현재 종료 평가는 핵심 오류 검증을 활성화하지 않고 false로 처리한다. CONCEPT는 독립적인 검증 근거가 없어 일괄 보류한다. 이미 구현된 상한과 실제 활성화된 상한을 구분해야 한다. 현재 등급 경계는 90·75·60점이며 매우 우수·양호·보완 필요·집중 개선 필요로 나뉜다.

3점은 요구한 범위를 무리 없이 충족한 답변, 4점은 **그 범위 안에서** 완결성과 근거가 강한 답변으로 해석한다. D1 답변에 D4 수준의 반례까지 요구해야 4점을 주는 방식은 피한다. 높은 말속도·시선 접촉이 낮은 내용 충족을 상쇄하지 않는다.

### 6.2 최신 묶음·회차 산식을 연결한다

현재 `mainQuestionAverage`는 점수가 있는 주질문의 단순 평균이고 F 점수는 별도 목록이다. 최신 정본의 종합 점수와 다르다. `overallWeightedScore`가 null인 상태를 완성된 회차 점수로 설명해서는 안 된다.

| 실제 평가용 질문 구성 | 최신 정본의 묶음 점수 |
|---|---|
| Q0만 | Q0 |
| Q0+F1 | 0.70×Q0 + 0.30×F1 |
| Q0+F1+F2 | 0.70×Q0 + 0.15×F1 + 0.15×F2 |

순수 재질문은 별도 가중치를 받지 않는다. 존재하지 않는 F에 0점이나 가중치를 넣지 않는다. 실제 생성된 Q0 또는 F 하나라도 평가불능이면 정본에 따라 묶음 전체를 제외하며, 남은 F끼리 임의 재가중하지 않는다.

회차 분모는 미리 계획한 질문 수도, 점수가 나온 질문 수도 아닌 **실제로 정상 제시해 시작한 묶음**이다. 시작 후 오류가 난 묶음은 분모에서 사라지지 않아야 한다. 유효 묶음 비율이 60% 이상이고 유효 묶음이 최소 2개일 때만 유효 묶음의 동일 비중 평균을 산출한다. 묶음 가중·회차 평균을 계산하는 도중에는 반올림하지 않고 최종 표시 정밀도를 별도로 정한다. 이는 화면 신설이 아니라 내부 계산 계약의 이행이다. 평가 가이드 제35~38조 [D10].

### 6.3 무응답·평가 보류·개념 검증을 구분한다

- 현재 빈 최종 전사는 모두 평가불능으로 처리한다. 최신 정본은 정상 전달·수집이 확인된 실제 무응답/거부와 기술적 실패를 구분한다.
- VAD 0이나 빈 전사만으로 학생의 의도적인 거부를 단정하지 않는다. 질문 전달·장치·전사 상태·명시적 제출을 함께 보존해 판정한다.
- 기술 오류는 0점이 아니다. 실제 무응답은 정본의 요구 미충족 상태로 다루되, 관찰하지 않은 지식·성격까지 0점으로 확장하지 않는다.
- 개념 질문을 생성하기 전에 검증할 수 있는 학습 범위·출처를 확인한다. 정오를 확인할 수 없다면 한계를 예고한 내부 평가 상태를 유지한다. 관찰 가능한 설명 구조와 독립 검증이 필요한 정확성의 보류를 구분하는 세부 정책은 버전으로 고정한다. 보류 축을 임의로 제거하고 남은 축을 100점으로 늘리지 않는다.

### 6.4 일관성·신뢰도·근거 설명력·편향 검증

| 검증 대상 | 실행 방법 | 결과 해석 |
|---|---|---|
| 평가 일관성 | 동일 답변을 순서를 바꿔 반복 평가, 모델·규칙·프롬프트 버전 고정 | 앵커별 변화·총점 변화·보류 변화 기록. 온도나 JSON 형식만으로 일관성이 보장된다고 하지 않음 |
| 사람 기준 신뢰도 | 서로 독립된 2인 이상이 채점 후 불일치를 조정한 기준 세트 | 사람끼리의 일치도와 AI-사람 일치도를 따로 측정 |
| 근거 설명력 | 원문 인용 존재 + 인용이 해당 앵커를 지지하는지 검토 | 인용 문자열 검증 통과를 의미상 타당성 검증으로 대신하지 않음 |
| 보류의 정확성 | 정상 답변·무응답·STT 결함·지식 근거 부족을 분리한 사례 | 무조건 보류하면 안전하다는 식의 높은 보류율을 품질 향상으로 인정하지 않음 |
| 편향 감소 | 동일 전사를 유지한 채 이름·면접관 음성·표시 순서를 변경하고 장치/인식 품질별 비교 | 같은 전사는 내용 앵커 유지. 표현쌍 시험은 의미·근거·명료성이 동등한 경우로 한정. 실제 명료성 차이와 인식된 전사 차이를 채점 편향으로 오인하지 않음 |

기존 정본의 검증 사례를 먼저 자동화하고 실제 로그의 실패를 반례로 추가한다. 학생·활동·묶음 단위로 개발 사례와 최종 검증 사례를 분리해, 프롬프트를 다듬은 대화만으로 성능을 자가 평가하지 않는다. ‘모델 자신감 95%’는 측정된 신뢰도가 아니다.

## 7. 면접관 페르소나 개선

현재 구현은 학업·탐구와 공동체·인재상 관점의 두 역할이다. HR·실무진·임원 역할의 실제 수행 성능은 검증할 근거가 없고, 이를 그대로 도입하면 대입 면접을 채용 면접으로 바꾸게 된다. 요청한 세 역할은 **면접관의 확인 관점을 구분하는 비교 틀**로 적용한다. [C5] [D1] [D8]

| 요청한 관점 | 현재 면접에서의 대응 | 자연스럽게 만들 내부 전략 |
|---|---|---|
| 인사담당자 | 공동체·소통·학습 태도·동기 | 가치 단어보다 본인 행동·조율·책임의 실제 근거를 묻는다. 사생활·가족·성격 추정 질문을 하지 않음 |
| 실무진 | 학업·전공 탐구 | 실제 방법·개념·선택 기준·근거·한계를 구분하고 학생의 학습 범위 안에서 깊이를 조절 |
| 임원 | 종합 관점의 판단·성찰 | 이미 확인된 근거를 연결해 판단·학습 전이 한 지점을 확인. 현재 별도 세 번째 면접관이 구현됐다고 주장하지 않음 |

페르소나는 질문 정책·주의할 사실·허용 깊이·중립 반응 스타일로 정의한다. 학교의 실제 면접위원 직책이나 역할 분담을 추정하지 않는다. 원칙적으로 원면접관이 묶음을 이어가고 이미 재생 중인 질문의 목소리는 바꾸지 않는다. 필요한 교대에서도 근거·목적·F 누적 횟수와 확인 상태를 공유하고 인사·자기소개를 반복하지 않는다. 다음 면접관은 앞선 답변의 확인 결과를 공유해야 한다.

역할별 자연스러움은 목소리 선호와 별도로, ‘같은 학생 답변을 들었을 때 역할에 맞는 다음 확인을 선택했는가’로 평가한다. 역할·성별에 따라 내용 점수 기준을 바꾸지 않는다.

## 8. UX 개선 — 대화 경험만

### 질문 흐름과 인간적인 반응

- 모든 답변에 연결 멘트를 의무적으로 넣지 않는다. 주제가 자연스럽게 이어지면 질문 자체에 짧은 맥락을 담고 중복 요약은 생략한다.
- 새 상세를 짚을 때는 실제 답변의 짧은 표현만 사용한다. 키워드 인용은 목적이 아니라 ‘그 설명을 들었다’는 증거다.
- 무응답에는 생각 시간 안내와 허용된 재질문, 명시적 모름에는 중립적인 전환을 사용한다. 틀린 답처럼 추궁하거나 진행 오류로 만들지 않는다.
- 질문 도중 평가·칭찬·모범답안 교정을 끼우지 않는다. 긴장감은 단정적 압박보다 일관된 질문 목적과 적절한 검증 깊이에서 만든다.
- 단어가 서툴러도 의미가 충족되면 인정하고, 유창하지만 요구를 비껴가면 추가 확인한다. 화려한 어휘를 면접 역량으로 대신 보지 않는다.

### 몰입과 지연

반응·생성 에이전트를 무작정 추가하지 않는다. 이미 분리된 구조에 공유 상태와 검증 책임이 부족하면 빠른 반응이 뒤의 질문과 어긋날 수 있다. 한 번 확정한 다음 턴 ID·목소리·근거·검증 목적은 재시도에서도 유지한다.

제출→STT 확정, 반응 결정, 질문 생성, 검수 재시도, TTS, 연결 음성 종료→질문 시작을 같은 관찰 단위로 분리 계측한다. 첫 질문 준비와 실제 답변 전환, 캐시·무음 결정 경로와 실제 모델 경로를 섞어 개선율을 계산하지 않는다. 긴 시스템 대기가 학생의 답변 기회를 얼마나 줄였는지도 분리해 측정한다. 현재 시계에는 질문·확정·준비 시간도 포함되므로 분석 없이 시간 정책부터 바꾸지 않는다.

### 연속성과 복구

기술 장애의 학생용 안내는 일반적인 연결 문제로 유지하고 상세 원인은 내부에 남긴다. 복구의 성공은 에러 메시지가 사라진 시점이 아니라 **같은 답변을 보존한 채 다음 질문 음성이 재생되고 다음 답변을 받을 수 있는 시점**으로 정의한다.

현재 화면의 연결 끊김·새로고침 복원은 원래 질문·답변 ID, 확정 전사 상태, 남은 시간, 공개·재생 완료 상태를 기준으로 설계한다. 중복 전사·중복 질문·재인사·이전 묶음 재등장을 막는 것이 목표이며 새 페이지를 만들 필요는 없다.

### 공통 품질 기준과 반복 개선 운영

다음 수치는 **현재 측정된 성능이나 공인 기준이 아닌 초기 인수 목표 제안**이다. 사람 기준 세트의 난도·표본을 확인한 뒤 조정한다.

|---|---|---|

운영 순서는 **실패 로그 분류 → 재현 가능한 비식별 사례 고정 → 원인 하나 수정 → 계약 회귀 → 미사용 사례 검증 → 사람 청취/채점 비교 → 제한된 실제 사용 확인**이다. 모든 로그를 프롬프트에 계속 붙이거나 자동으로 학습됐다고 설명하지 않는다. 학생의 원래 발화·당시 질문·규칙·평가 버전은 보존하고 개선판 결과는 별도 revision으로 비교한다.

수정 효과는 연결 멘트 자연스러움, 후속 선택 적절성, 사실/인용 안전성, 채점 일치도, 피드백 실행 가능성, 실제 음성 공백으로 나누어 판단한다. 모델 교체나 프롬프트 길이 변경만으로 전문 면접관 수준에 가까워졌다고 결론 내리지 않는다.
