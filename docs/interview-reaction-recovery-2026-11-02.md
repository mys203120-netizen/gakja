# 반응 검증 오류 복구와 공개 오류 안내 · 2026-11-02

최근 실사용 회차 `10c0ac11-d171-476e-b934-51082f15fadc`에서 첫 답변 제출 후 서버와 클라이언트에 같은 `INVALID_REACTION` 오류가 기록됐다. 원본 세션과 저널은 보존했다. 이 코드는 학생 답변의 정오가 아니라 반응 판정 데이터의 검증 실패를 뜻한다. 과거 로그에는 거절된 출력이나 필드별 진단이 없어 어떤 필드가 실패했는지 소급 확정하지 않는다.

## 수정한 동작

- 모델 출력의 분류·행동·이유를 서로 맞는 조합으로 제한한다. 예산·반복·복구 사유는 서버만 결정한다. 원문 인용은 실제 전사의 검증된 후보, 질문 표적은 현재 질문의 후보로 제한한다.
- 형식·인용·표적 검증 실패는 한 번만 자동 재요청한다. 실제 통신·인증·할당량 오류와 미확정 전사는 이 경로로 숨기지 않는다. 반응 요청은 각 10초 한도이며 SDK 내부 자동 재시도는 사용하지 않는다.
- 두 번 검증에 실패하면 내부적으로 `unassessed / fallback`을 기록한다. 학생 답변을 무관·오답으로 분류하지 않고, 허용된 비평가 재질문 한 번 또는 중립적인 다음 질문 전환을 사용한다. 실제 답변 원문·평가 근거와 F1/F2 예산은 보존한다.
- 복구 여부·시도 횟수·실패 코드는 `reaction.recovery` 및 비공개 `data/diagnostics/answer-reactions.jsonl`에 남긴다. 이 값은 답변 점수로 쓰지 않는다.

## 서비스에 표시하는 오류

CLOVA의 제공자명·gRPC 상태·주소·응답 본문·`ECONNRESET` 같은 기술 내용은 내부 진단에만 둔다. HTTP JSON·진행 스트림·WebSocket 오류와 평가 상태 응답은 공개 안내로 변환한다. 클라이언트도 이전 서버의 상세 문자열과 브라우저 예외를 표시 전에 변환한다.

- 음성: “음성 연결에 문제가 생겼어요. 잠시 후 다시 시도해 주세요.”
- 질문: “다음 질문을 준비하지 못했어요. 잠시 후 다시 시도해 주세요.”
- 기록 저장과 평가 준비는 각각 다른 안내를 유지한다.

서비스 오류를 일반화하더라도 내부 원인과 기존 답변을 삭제하거나 정상 인식으로 바꾸지 않는다. 면접 화면의 디자인·배치는 변경하지 않았다.

## 검증

전체 자동 테스트 250개와 TypeScript·ESLint·Next.js 프로덕션 빌드를 통과했다. 실제 HTTP·NDJSON·WebSocket 장애 주입 검증에서 공개 응답에는 공급자 상세가 없고 비공개 저널에는 원인이 남는 것을 확인했다. 기본 주소의 웹·API 서버를 새 코드로 재시작했으며 상태 응답의 규칙 버전은 `reaction-v3`다.

`artifacts/reaction-recovery-live-verification.json`의 실제 모델 검증 세 가지도 통과했다.

1. 최근 실제 답변의 복사본을 새 출력 구조로 재판정: 유효한 재질문 결정, 약 2.352초.
2. 첫 출력의 불일치를 명시적으로 주입한 뒤 실제 모델로 재검증: 두 번째 시도 성공, 전체 약 1.790초. 첫 시도는 의도적으로 주입한 테스트 값이다.
3. 두 번의 잘못된 출력을 주입한 뒤 복구: 답변 품질을 단정하지 않고 원래 의도와 PDF 인용을 보존한 실제 재질문 생성.

이는 복사본·합성 오류를 이용한 검증이며 실제 마이크·TTS·브라우저 재생 시간 측정은 포함하지 않는다. 원본 세션과 저널의 SHA는 유지됐다. 지연 수치를 일반적인 성능 보장으로 해석하지 않는다.

## 가이드 적용 범위의 설명

초기 테스트 구조에서 원문 근거·회차 계획·비평가 재질문·진행 복구를 우선 옮겼다. 현재 PDF가 연결된 사실과 가이드 전체가 구현된 상태는 다르다. 활동 구조화, 답변에 따른 후속 기능·깊이 선택, 난이도 설정, 사전 검수 질문 후보, 독립적인 의미 검수는 더 확장할 수 있었지만 아직 구현하지 않은 항목이다. 이를 모두 추가 입력 부족이나 기술적 불가능으로 설명하면 부정확하다.

현재 자료로 가능한 확장과 별도 검증 근거가 필요한 항목은 [질문 생성 가이드 적용 점검](question-guideline-application.md)에 구분했다. 사용자가 PDF를 다시 제출하거나 분석 MD를 직접 작성해야만 진행할 수 있는 상황은 아니다.
