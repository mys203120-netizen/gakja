# 녹음 연습의 실시간 전사

녹음형 퀴즈는 질문 → 말로/글로 선택 → 마이크 확인 → 녹음과 실시간 전사 → 저장 후 전사 확인·편집으로 진행한다. 준비·3초 카운트다운 동안에는 전사용 마이크 복제 트랙이 꺼져 있다. 녹음 중 OpenAI WebRTC 전사로 글을 보여주며, 미리보기는 작성한 답변이나 채점 자료에 자동으로 반영하지 않는다. 기존 비공개 녹음 업로드와 저장 후 전사·문장 정리가 확정 답변의 경로다.

- 기존 서버의 `OPENAI_API_KEY`를 사용한다. 브라우저에는 키나 임시 인증 토큰을 전달하지 않고 서버가 SDP를 중계한다. `gpt-live-transcribe`, 한국어, 낮은 지연, 수동 발화 종료를 고정한다.
- 현재 학생의 활성 계정·진행 중인 비선택형 문항·revision을 연결 전후에 확인한다. 기존 AI 일일 요청 한도에 포함하고, 학생별 분당 6회·같은 문항 3초 간격을 적용한다.
- 연결 실패 시 녹음을 계속하고 저장 후 전사로 안내한다. 준비 취소 시 연결·마이크를 해제한다. 녹음 중 화면 숨김·pagehide·freeze·마이크 mute/ended·녹음 오류가 발생하면 녹음 시간을 즉시 확정하고 원본을 종료·보관하며 같은 질문을 일시정지한다. 복귀 후 자동 녹음·업로드는 하지 않고 학생이 재생·저장을 선택한다. 실시간 전사는 복제 트랙을 사용하고, 중단 처리는 원본 녹음도 명시적으로 종료한다.
- 원격 연결 종료는 발급된 학생·세션·문항·시도·call ID를 모두 대조한다. 브라우저는 종료 실패를 한 번 재시도한다.
- 실시간 전사 사용은 별도 API 비용을 발생시킨다. 기존 녹음 후 전사도 수행하므로 두 경로를 합쳐 사용량을 확인해야 한다.

## 검증

`npm test`에는 클라이언트 트랙 제어·이벤트 순서·취소·종료, 서버 인증·범위·한도·지연 응답, 실제 퀴즈 컴포넌트의 답변 보존·녹음 준비 취소·중단 복구 검사가 포함된다. `npm run build`로 타입과 프로덕션 빌드를 확인한다.

2026-10-20 로컬 브라우저에서 마이크 대신 오프라인으로 합성한 한국어 음성을 WebRTC로 보내 실제 OpenAI 전사를 확인했다. 음성 재생이 끝나기 전 글이 나타났고 전체 문장이 일치했다. 390×844 화면에서 질문 아래 녹음 시작 버튼을 확인했다. 실제 iOS/Android 마이크 권한·잠금 화면·운영 업로드는 별도 실기기 검증 대상이다. 합성 음성 검증용 임시 페이지와 파일은 배포하지 않는다.

공식 API 근거: [Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription), [WebRTC 연결](https://developers.openai.com/api/docs/guides/voice-webrtc?voice-api=realtime).

## 2026-10-20 모바일 왕복 검증과 보완

- 390×844 로컬 브라우저에서 오프라인 합성 음성을 실제 퀴즈의 MediaRecorder·IndexedDB·OpenAI WebRTC에 연결했다. 실시간 전사 → 화면 숨김 이벤트 → 복귀 → 기기 보관 음성 수동 저장 → 전체 전사·문장 정리 → 직접 수정 → 자동 저장 → 홈 이어하기 → 같은 질문·수정 문장 복구 → 최종 답변 저장을 실제 API와 로컬 DB로 확인했다. 최종 화면에 답변 1개·녹음 1개가 표시됐다. 실제 마이크 대신 합성 MediaStream을 제공한 검증용 스크립트는 배포하지 않는다.
- 컴포넌트 검사에서는 녹음 1.5초 후 숨김·pagehide·freeze·마이크 중단·오류를 주입하고 마지막 이벤트를 181초로 지연했다. 시간을 1.5초에 확정하고 마지막 조각을 유지하며, 명시적인 저장 전 업로드·마이크 재개를 차단한다.
- 실제 녹음 종료 시점을 알 수 없는 중단은 `needsMeasurement`를 기기에 함께 저장한다. 재시도 시 원본 파일을 디코딩해 길이·음성 측정을 다시 확인한다. 실패하면 원본을 보관하며 성공으로 표시하지 않는다.
- 강제 종료 직후 남은 녹음 잠금은 5초 재조회 및 focus·pageshow·화면 복귀로 확인한다. 살아 있는 다른 탭의 녹음을 덮어쓰지 않고, 잠금이 풀린 파일을 새로고침 없이 복구한다.
- 복구 저장은 세션 재개·디코딩 전부터 잠근다. 중복 저장·삭제를 차단하고, 이탈 후 지연 응답이 돌아오면 현재 질문·원본·화면 소유권을 확인해 업로드를 중단한다.
- 업로드 응답이 유실된 뒤 같은 파일로 재시도해도 문항·MIME·길이가 포함된 동일 저장 결과를 반환한다. 로컬 multipart와 Supabase 업로드 완료 경로를 모두 검사한다.

브라우저의 화면 숨김 이벤트와 지연 타이머는 실제 휴대폰의 화면 잠금·다른 앱 실행·통화 수신·운영체제 강제 종료를 대체하지 않는다. iOS Safari와 Android Chrome 실기기에서 이 항목을 별도로 확인해야 한다. 모바일의 녹음 조각 전달이 늦어질 수 있다는 근거는 [MDN MediaRecorder dataavailable](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event)에서 확인할 수 있다.

## 실기기 테스트 순서와 정상 동작 기준

아래는 사용자가 직접 확인할 체크리스트다. 작성된 기준은 현재 코드의 의도이며, iPhone·Android 실기기 통과 결과를 뜻하지 않는다. **화면 잠금·다른 앱 이동 시에는 녹음을 종료하고 보관한다. 잠금 상태에서도 녹음을 계속하는 기능은 아니다.**

### 준비

- iPhone은 Safari, Android는 Chrome에서 같은 배포 주소와 테스트 학생 계정을 사용한다. 일반 브라우저 탭에서 확인하고, 메신저 안의 브라우저·비공개 모드는 별도 결과로 기록한다. 데스크톱의 모바일 크기 화면은 실기기 결과를 대신하지 않는다.
- 휴대폰에서 접근 가능한 HTTPS 주소를 연다. 휴대폰의 `localhost`는 개발 PC가 아니다. PC와 휴대폰을 함께 사용할 때도 같은 학생의 같은 문항을 동시에 녹음하지 않는다.
- 실제 학생 개인정보 대신 아래 테스트 문장을 사용한다. 시작 전 기기 모델·OS·브라우저 버전·네트워크(Wi-Fi/모바일 데이터)와 앱 커밋을 기록한다.
- 첫 실행은 블루투스 이어폰 없이 진행한다. 기본 과정을 마친 뒤 이어폰·저전력 모드에서 반복하면 원인 구분이 쉽다.

테스트 문장: “학생회에서 설문을 맡았습니다. 의견을 모아 매점 운영 시간을 바꿨습니다. 마지막 확인 문장은 초록 나무입니다.” 마지막 문장은 중단 직전 음성 누락을 구분하는 용도다.

### 1. 시작 → 실시간 전사 → 수정 → 저장 → 이어하기

각 기기에서 아래 순서대로 한 번씩 진행한다. 이어하기를 확인하려면 **최종 ‘답변 저장’ 전에** 홈으로 이동한다.

| 순서 | 직접 할 일 | 정상 동작 기준 |
| --- | --- | --- |
| 1 | 연습 → 답변 녹음 → 질문을 열고 ‘말로 답하기’를 선택한다. | 질문 바로 아래에서 동의·녹음 동작을 찾을 수 있다. 큰 글 입력창을 지나야 녹음할 수 있는 구조가 아니다. |
| 2 | 동의 후 ‘답변 녹음’을 누르고 마이크 권한을 허용한다. 준비 화면에서 짧게 말한다. | 마이크 확인 중에는 답변 녹음·전사가 시작되지 않는다. 준비 중 음성이 답변에 들어가지 않는다. |
| 3 | ‘준비됐어요 · 3초 뒤 시작’을 누르고, 시작 후 테스트 문장을 20~30초에 걸쳐 말한다. | ‘녹음 완료 · n초’와 진행 시간이 보인다. 말을 마치기 전 실시간 미리보기에 글이 추가된다. 지연 시간도 기록한다. 미리보기는 편집할 답변에 자동 입력되지 않는다. |
| 4 | ‘녹음 완료’를 한 번 누른다. | 저장·전사 처리 상태가 표시되고, 성공하면 ‘녹음 저장됨’과 재생기가 나온다. 음성을 끝까지 들을 수 있다. 원본 저장 성공과 문장 정리 성공은 구분된다. |
| 5 | ‘전사 확인 · 답변 다듬기’에서 문장을 “설문 결과를 비교해 운영 시간을 제안했습니다.”로 수정한다. | 수정 내용을 입력할 수 있고 ‘자동 저장됨’이 표시된다. 전사 재시도·늦은 응답이 직접 수정한 문장을 덮어쓰지 않는다. ‘정리된 전사 사용’은 직접 선택할 때만 대체한다. |
| 6 | ‘자동 저장됨’을 확인하고 오늘 화면으로 이동한다. 홈의 이어하기를 누른다. | 같은 질문·수정한 문장·저장한 녹음으로 돌아온다. 일시정지 상태라면 ‘이어서 풀기’를 눌러 재개한다. 자동으로 마이크를 켜지 않는다. |
| 7 | 돌아온 화면을 새로고침하고 다시 확인한 뒤, 자기평가를 선택하고 ‘답변 저장’을 누른다. | 수정 문장과 재생 가능한 음성이 유지된다. 최종 답변이 한 번 저장되며 중복 기록이 생기지 않는다. 완료한 문항은 진행 중 문항 대신 저장 결과에서 확인한다. |

‘녹음 저장됨’은 음성 파일 저장, ‘자동 저장됨’은 글 초안 저장, ‘답변 저장’은 해당 문항의 최종 제출이다. 세 표시를 구분해서 기록한다. 실시간 연결에 실패하면 ‘저장 후 전사로 이어갈게요’가 보이고 녹음은 계속할 수 있어야 한다. 이는 음성 보존 경로는 정상이나 **실시간 전사 자체는 통과하지 못한 결과**로 따로 기록한다.

### 2. 화면 잠금과 앱 전환 — 각각 새 녹음으로 반복

| 상황 | 직접 할 일 | 정상 동작 기준 |
| --- | --- | --- |
| 준비 취소 | 3초 카운트다운 중 ‘일시정지’를 누른다. 다른 시도에서는 카운트다운 중 홈 화면으로 나갔다 돌아온다. | 녹음이 시작되지 않고 준비 타이머·마이크·실시간 연결이 정리된다. 돌아와도 자동으로 시작되지 않으며 직접 다시 시작할 수 있다. |
| 화면 잠금 | 15~20초 녹음하고 마지막 확인 문장 직후 전원 버튼으로 잠근다. 10초 뒤 잠금을 풀고 같은 탭으로 돌아온다. | 녹음을 멈췄다는 안내와 보내지 않은 음성이 표시된다. 잠금 시간만큼 녹음 시간이 늘어나지 않는다. 복귀만으로 녹음·업로드가 다시 시작되지 않는다. |
| 다른 앱 | 새 녹음에서 15~20초 말하고 메모 등 다른 앱을 10초 사용한 뒤 돌아온다. 같은 과정을 1분 대기로도 반복한다. | 잠금과 같은 종료·보관 동작이다. 다른 앱에서 말한 내용이 새로 답변에 들어가지 않는다. |
| 복귀 후 저장 | 보관된 음성을 재생하고 ‘녹음 다시 저장’을 누른다. | 같은 질문으로 저장하고 전체 전사·수정으로 이어진다. 복귀 직후 원본을 먼저 확인하며, 원본이 없는데 성공했다고 표시하지 않는다. |
| 저장 도중 전환 | 정상 녹음의 ‘녹음 완료’ 또는 복구의 ‘녹음 다시 저장’을 누른 직후 다른 앱으로 이동했다 돌아온다. | 이미 요청한 저장은 완료될 수 있다. 완료 상태를 표시하거나 같은 원본을 남겨 재시도할 수 있다. 계속 ‘저장 중’에 갇히거나 두 개로 중복 저장되지 않는다. |
| 빠른 복귀 | 앱 전환 후 곧바로 복귀·재개한다. 네트워크가 느린 상태에서도 반복한다. | 이전 일시정지 응답이 늦게 와도 재개한 화면을 과거 상태로 되돌리지 않는다. 새 녹음의 ‘녹음 완료’ 버튼이 사라지지 않는다. |

운영체제가 이벤트·마지막 녹음 조각을 늦게 전달할 수 있으므로 복귀 직후 잠깐 ‘마지막 음성을 기기에 보관’ 상태가 보일 수 있다. 중단 전 문장의 시작·끝과 재생 길이를 확인하고, 마지막 확인 문장의 포함 여부를 기록한다. 음성이 재생되지 않거나 끝부분이 사라졌다면 통과로 처리하지 않는다. 휴대폰의 마이크 표시가 반환 직후에도 계속 켜져 있다면 지속 시간과 당시 화면도 기록한다.

### 3. 실패·복구 확인

- **권한 거절:** 첫 마이크 권한을 거절한다. 녹음·전사가 시작되지 않고 안내가 보이며, 글로 전환해 답할 수 있어야 한다. 브라우저 사이트 설정에서 권한을 다시 허용한 뒤 새 시도가 가능해야 한다.
- **기존 메모 보존:** 녹음 전 메모에 “내가 직접 쓴 메모”를 적는다. 실시간 전사·저장 후 전사가 늦게 도착해도 이 글을 자동으로 덮어쓰면 안 된다.
- **통신 끊김:** 10초 이상 녹음한 뒤 비행기 모드로 바꾸고 종료한다. 저장 실패 시 같은 원본과 재시도·내려받기 기능이 남아야 한다. 네트워크를 복구하고 같은 파일을 다시 저장한다. 저장 중 버튼을 연속으로 눌러도 중복 처리되지 않아야 한다. 네트워크 복구만으로 학생의 새 녹음을 시작하면 안 된다.
- **전사만 실패:** 음성은 재생되는데 문장 정리가 실패한 경우 ‘전사 다시 시도’ 또는 ‘문장 정리 다시 시도’로 복구하거나 직접 입력할 수 있어야 한다. 전사 실패 때문에 이미 저장한 원본을 잃으면 안 된다.
- **브라우저 강제 종료:** 별도 테스트 녹음을 20초 이상 한 뒤 앱 전환 화면에서 브라우저를 종료하고 같은 브라우저·계정·질문으로 돌아온다. 이미 기기에 기록된 조각의 복구 여부와 실제 길이를 기록한다. OS 강제 종료에서는 마지막 미기록 조각·파일 전체 복구를 보장하지 않는다. 일부만 복구됐다면 그 길이까지 결과에 남긴다.
- **복구 대기:** 강제 종료 직후 ‘다른 탭…확인 중’ 표시가 나면 같은 화면에서 기다린다. 마지막 잠금 갱신으로부터 약 30초가 지난 뒤 5초 재조회 또는 화면 복귀 시 잠금 해제를 확인한다. 살아 있는 다른 탭이 녹음 중이면 그 녹음을 먼저 종료하며 잠금을 강제로 덮어쓰지 않는다.
- **긴 녹음:** 별도 녹음으로 약 3분까지 진행한다. 정상 타이머에서는 3분 직전에 종료되어야 한다. 중단으로 측정이 어려운 파일은 다시 길이를 확인하며, 확인 실패·3분 초과를 정상 파일로 조용히 제출하지 않아야 한다.

복구 파일은 **같은 기기·같은 브라우저 저장소·같은 학생·같은 문항**의 임시 데이터다. 7일 보관 기간을 두지만 브라우저 저장 공간 정리·사이트 데이터 삭제·비공개 탭 종료·OS 정리에 의해 먼저 없어질 수 있다. 다른 기기나 다른 브라우저에서 나타나는 서버 백업은 아니다. 실패 원인을 확인하기 전에는 사이트 데이터를 지우거나 ‘저장 안 된 녹음 지우기’를 누르지 말고, 필요하면 ‘원본 내려받기’로 보관한다. 재시도 가능한 경우에도 저장 성공 표시와 실제 재생을 모두 확인한다.

### 기기별 결과표

| 항목 | iPhone · Safari | Android · Chrome |
| --- | --- | --- |
| 기기 / OS / 브라우저 버전 / 커밋 | 미확인 | 미확인 |
| 정상 녹음·실시간 전사·직접 수정 | 미확인 | 미확인 |
| 저장·홈 이어하기·최종 제출 | 미확인 | 미확인 |
| 카운트다운 취소·권한 거절 | 미확인 | 미확인 |
| 잠금 10초·앱 전환 10초 / 1분 | 미확인 | 미확인 |
| 저장 중 전환·느린 응답·오프라인 재시도 | 미확인 | 미확인 |
| 강제 종료 후 복구 범위·3분 제한 | 미확인 | 미확인 |

각 칸에 `통과 / 실패 / 일부 복구 / 미실행`과 관찰값을 적는다. 문제를 재현하면 아래 양식을 함께 전달한다. 실패는 한 번 발생해도 기록하고, 반복해서 정상화됐다는 이유로 원래 실패를 지우지 않는다.

```text
기기 모델 / OS / 브라우저 버전:
배포 주소 / 앱 커밋 / 테스트 시각:
Wi-Fi 또는 모바일 데이터 / 이어폰 / 저전력 모드:
질문 또는 테스트 번호:
한 행동: (예: 녹음 18초 → 잠금 10초 → 복귀 → 녹음 다시 저장)
기대 결과 / 실제 결과:
실시간 글이 처음 나온 시점 / 중단 전 표시 시간 / 복구 음성 길이:
마지막 확인 문장 포함 여부 / 전사 수정 보존 여부:
재현 횟수 / 재시도 결과:
화면 캡처 또는 짧은 화면 녹화:
```

캡처에는 테스트 문장만 사용하고 비밀번호·API 키·인증 토큰을 포함하지 않는다. 녹화 시작으로 마이크 상태가 바뀐다면 그 사실도 결과에 기록한다.
