# 모의면접 학습 흐름 반영

> 현행 계약·검증 갱신: 2026-10-14. [문서 적용 순서](document-authority.md)와 [서비스 PRD v2.2](../확정안/4.%20서비스_PRD_v2.2.md)를 따른다. [개선·검증 요약](learning-remediation.md)과 [후속 QA](../.local/learning-remediation-2026-10-14/report.md)·[화면 보고서](../.local/learning-remediation-2026-10-14/report.html)에 실제 API/저장값·학교 등록·같은 질문의 학습 연결 검증을 기록했다. 아래 이전 테스트와 화면은 당시 범위로 보존한다. 실제 OAuth·Live/STT·장기 회상·88교 전 학과 콘텐츠 품질·운영 보안은 후속 인수 게이트이며, 이번 결과가 모든 기능이나 실제 학습 효과의 완료를 뜻하지 않는다.

## 2026-10-14 도움과 중단 복구

진행 중 근거·영상 조회는 `POST /api/interviews`의 `action:'help',sessionId,turnId,helpKind:'evidence'|'video',requestId`를 사용해 소유한 현재 미제출 턴에 기록한다. 도움은 정오·실력 점수가 아니며, 다음 새 턴의 도움 상태와 분리한다.

AI 비서 요청은 `interviewSessionId`와 `interviewTurnId`를 함께 전달한다. 서버는 일시정지된 턴·고정 질문·지원처·당시 자료 버전을 확인하고 첫 유효 스트림을 노출하기 전에 응답 조각과 도움 receipt를 함께 저장한다. 중단된 부분 응답도 도움 사용으로 보존하고 같은 receipt의 완료/중단 상태를 갱신한다. 출력 없는 실패는 AI 도움으로 만들지 않는다. 새 탭·재접속도 서버 기록을 사용하며 sessionStorage는 초안·요청 캐시다. 진행 중 도움 응답이 있으면 재개를 막는다. 제출 후 상태 정리는 원답변의 도움 표시와 과거 리포트를 바꾸지 않는다.

새 턴은 `assistance_recorded:true`로 도움 관찰 여부를 명시한다. 과거 플래그 누락은 '도움 여부 미기록'이며 독립 수행으로 승격하지 않는다. 근거 보기 도움과 AI 도움을 구분한다.

녹음 중 또는 저장하지 않은 녹음이 있는 전역 AI 이동은 보호한다. 초안 서버 저장 실패를 알리고, 제출 응답 유실 시 같은 요청 ID 재시도·현재 턴 재조회로 복구한다. 이번 브라우저 QA에서는 같은 질문의 근거·실제 AI 응답 도움, 새 탭의 초안·일시정지·도움 복원, 재개·답변·리포트·원래 지원처의 보완 과제를 확인했다. 녹음 보호와 저장 실패 복구의 자동 회귀 결과는 후속 QA에 기록하며, 실제 장치·물리적 통신 장애·Live/STT 실측은 아직 별도 게이트다.

2026-10-12 화면별 QA의 재연습·설정·자료 연결을 반영했다. 주 메뉴는 기존 다섯 개를 유지한다.

## 준비와 재연습

- 선택한 질문·브리핑·활동을 준비 화면에서 확인하고 기본 1문항으로 시작한다. 자유 면접은 4문항 기본값을 유지한다.
- 시작 버튼과 분량을 먼저 보여준다. 면접관 수, 질문 깊이, 피드백, 반응, 꼬리질문, 압박은 `상세 설정`을 펼쳐 조정한다.
- Chat/Live 링크는 선택 질문·활동·브리핑·지원처·자료 버전·오늘 학습 맥락과 모든 조정한 설정을 보존한다. 설정은 URL에 저장되어 새로고침·뒤로 이동에도 적용된다.
- 선택 질문 미리보기는 소유 학생의 발행 버전과 공통 질문 계약으로 확인한다. 다른 학생 자료나 미발행 버전으로 시작하지 않는다. 미리보기 확인 실패 시 시작을 막고 실제 오류를 표시한다.
- 개인 자료가 없어도 공통 질문을 시작할 수 있다. 공통 연습에는 학교 공식 형식을 재현한다는 표기를 하지 않는다. 생기부 기반 유형은 개인 자료 발행 전 비활성이다.
- 지원처에서 학교 면접 개요를 바로 연다. 공통 질문을 선택해 한 문항만 연습하는 경로도 제공한다.

## 도움과 답변 보존

- 준비 화면의 `질문과 근거`·`AI 도움`은 같은 화면에서 열고 닫는다. 준비 중 AI 도움 사용을 시작 시 첫 답변의 도움 사용 기록으로 전달한다.
- 진행 중 근거 보기는 면접 시작 당시 저장한 질문·활동·원문을 사용한다. 현재 자료가 재발행돼도 면접 근거를 조용히 바꾸지 않는다.
- 진행 중 AI 비서의 기존 일시정지·초안 저장·같은 질문 복귀를 유지한다. 관련 영상도 초안을 저장하고 일시정지한 뒤 이동하며 영상에서 원래 면접으로 돌아온다.
- 작성 중 답변은 학생·세션·현재 턴을 키로 임시 저장된다. 설정 변경과 새로고침 시 같은 초안을 복원한다. 진행 중 세션의 답변 방식은 서버에 저장한 Chat/Live를 따른다.
- 미제출 글이나 저장하지 않은 녹음이 있을 때 종료·취소를 바로 진행하지 않는다. 계속 작성하거나 답변 없이 마칠 수 있고 글 초안은 서버에 먼저 저장한다. 저장하지 않은 녹음은 이동 시 사라진다는 점을 표시한다.
- 면접 종료는 기존 면접 리포트로 연결된다. 완료한 면접에서 다음 복습으로 이동할 수 있다. 면접 진입은 가장 최근 진행 중인 면접을 먼저 보여준다.

## 반응과 호출 범위

면접관 반응은 기존 5 단위 표정과 원문 근거 검증을 유지한다. 켜면 피드백은 질문마다로 연결되고 종료 후 피드백을 선택하면 반응이 꺼진다. 설정 변경·질문 미리보기·근거 열기에는 AI 호출이 없다. 반응 옵션은 제출 이후 평가 시점이며 발화 중 스트리밍 의미 반응으로 표시하지 않는다.

## 2026-10-14 전사·화면용 정리 개정

Live의 저장한 녹음은 `gpt-4o-mini-transcribe` 원전사 → `gpt-6-luna` 가독성 정리 순서로 처리한다. 일반 답변 영역은 두 단계가 끝난 정리본을 보여주고 처리 중에는 단계 상태를 표시한다. 원음·원전사는 유지하며 원전사 확인, 학생 직접 정정, 새 녹음을 서로 구분한다. TTS 공급자는 기존 Google 설정을 유지한다.

습관어·반복 관찰은 원전사, 공백은 실제 RMS 관찰을 사용한다. 문장 정리로 습관어가 사라져도 실제 발화 개선으로 집계하지 않는다. 정리본에 역할·경험·성과·근거를 추가하지 않으며 자동 제출·다음 질문 생성·내용 도움 기록으로 처리하지 않는다.

후가공 실패는 원음/원전사를 보존하고 실패와 원전사 보기·정리만 재시도를 제공한다. 학생이 초안을 수정했거나 녹음을 교체·취소한 뒤 도착한 결과가 현재 답변을 덮어쓰지 않도록 한다. 이전 원전사는 재사용하며 후가공 재시도에 STT를 다시 호출하지 않는다. 상세 저장/실패/호출 계약과 이번 전환의 검증 상태는 [전사·화면용 정리](transcription-pipeline.md)를 따른다. 아래 이전 검증 이력은 새 모델 전환의 실행 증거가 아니다.
