# 면접 전 보완 영역 편성

`/training`의 **면접 전 보완 날짜 확인**은 보완 근거가 남아 있지만 면접일(또는 명시된 준비 목표) 전 같은 학교·자료 버전·학생부 영역의 미완료 화상 일정이 없는 경우에 사용한다. 개인 자료와 공통 질문의 버전은 별도로 비교한다. 반복 중지와 반복 간격도 유지한다.

`GET /api/training/review-placement`는 제안만 계산한다. 원문 조회의 공통 질문 seed, 읽기 캐시 저장, 보완 상태 저장을 수행하지 않는다. 가용일이 없으면 학습 시간 설정으로, 영역 또는 면접일이 불명확하면 해당 확인 화면으로 안내한다.

학생은 날짜를 고른 후 편성 근거, 학교·자료·영역, 교체할 기존 순서, 새 순서, 제외된 충돌 날짜를 확인한다. `preview`는 저장하지 않는다. `apply`에 서버 미리보기 fingerprint를 보내야 편성한다. 빈 날짜 또는 미시작 자동 계획만 있는 날짜 전체를 대상으로 하며, 받은 과제·수동 일정·학생이 날짜/순서를 바꾼 일정·시작/완료 기록이 있으면 그 날짜를 제외한다. 일부 과정을 떼어 옮기지 않고 기록 복습→가능한 검증 퀴즈→화상→정리 순서로 해당 날짜를 다시 구성한다. 일일 시간과 한 영역 원칙을 검증한다.

적용은 기존 캘린더와 같은 학생별 잠금·계획 행 잠금·변경 이력을 사용한다. 학교, 발행 자료, 보완 근거, 시간 설정, 기존 계획 revision이 달라지면 409로 재확인을 요청한다. 원래 자동 계획은 삭제하지 않고 교체 상태로 보존한다. 새 계획의 `calendarPlacement`는 일반 재편성이 덮어쓰지 못하게 한다. 원문·답변·평가에는 쓰지 않는다.

되돌리기는 `/api/planner/calendar`의 `undoPreview`→`undo`를 재사용한다. 교체 전 계획을 복원하고 새 계획을 비활성화한다. 편성 후 시작/수정된 학습, 새 일정, 변경된 시간 설정이 있으면 전체 되돌리기를 거부한다. 퀴즈·면접 세션이 시작된 경우에도 답변 제출 여부와 무관하게 보호한다. 변경 이력은 기존 정책에 따라 최근 20건을 유지한다.

검증: `tests/training-review-placement.test.ts`, `tests/training-review-placement-ui.test.mts`, `tests/training-review-placement-integration.mts`. 통합 테스트는 localhost PostgreSQL의 무작위 격리 스키마에서 실제 트랜잭션을 실행하고 종료 시 그 스키마만 정리한다. 합성 소스 사실을 주입하며 외부 AI는 호출하지 않는다.
