# 모바일 UI·데이터 관리 QA

2026-10-22. 사용자 제공 화면을 기준으로 수정 전 27개 화면을 먼저 캡처하고, 변경 후 45개 화면·상태를 기록했다. 증거는 로컬 `.local/mobile-qa-data-management-2026-10-22/`에 보관한다. 개인 기록이 보이는 캡처는 Git에 포함하지 않는다.

## 화면 확인

기본 뷰포트는 375×812, 좁은 화면은 320×740, 데스크톱은 1440×1000이다. 연결된 앱 브라우저에서 직접 이동하고, 메뉴·필터·확인 창을 열어 확인했다.

| 범위 | 확인한 화면·상태 |
| --- | --- |
| 주요 화면 | 오늘 훈련, 준비 현황, 내 경험, 자유 연습, 퀴즈, 면접 준비, 훈련 시작·경험 선택 |
| 자료·지원 | 학생부·교재, 지식한입, 시사 브리핑, 학교 목록·등록·상세, 사실 확인, 학습 시간 |
| 기록 | 발화·답변, 연습 이력, 답변 비교, 학습 리포트 상세 |
| 계정 | 내 계정, 설정, 데이터 목록·필터·휴지통·삭제 확인·백업·기기·전체 삭제 요청 |
| 공개 화면 | 로그인, 가입, 비밀번호 재설정, 초대, FAQ, 문의, 개인정보 안내 |
| AI 비서 | 질문 목록, 보관함, 입력창 고정, 하단 메뉴 표시, 입력 포커스 |

확인 결과:

- 모바일 보조 탐색 메뉴·경로 표시를 줄이고 상단 뒤로가기를 제공한다. 필수 온보딩의 순환 이동은 방지한다. 자료 진입은 준비 현황, 연습·비서는 오늘 훈련에서 유지한다.
- 제목 옆 캘린더·시간 설정은 모바일에서 접근 가능한 이름을 가진 아이콘으로 표시한다. 320px에서도 제목·학교 카드·데이터 목록·훈련 버튼이 가로로 넘치지 않는다.
- AI 보관함과 면접 연결이 같은 줄에 놓인다. 하단 메뉴의 위쪽은 744px, 입력창 아래쪽은 724px로 **20px 간격**을 확인했다. 입력 포커스에서는 메뉴를 숨긴다. iPhone 안전 영역은 CSS 예약 공간에 반영한다.
- UI 글자 크기는 14/16/20/28px 네 토큰이다. 실제 DOM의 계산된 글자 크기와 CSS 파서 검사로 확인했다. 모바일 텍스트 입력은 16px이다. 원본 교재 문서와 공유 이미지의 글자 디자인은 별도다.
- 내 경험의 단계 설명·초안 안내를 줄이고, 학교 카드의 수정·준비 종료를 일정 정보와 같은 줄에 놓았다. 학교 준비 종료는 과거 기록을 보존하며, 기록 삭제는 데이터 관리로 안내한다.

공개 문의는 기존 운영 설정에 따라 운영 빌드에서 준비 중 안내가 나타날 수 있다. 카메라·마이크 권한이나 실제 AI 답변 생성은 화면 QA 중 실행하지 않았다. 실제 iPhone 하드웨어 검사가 아닌 브라우저 뷰포트 검사다.

## 데이터 동작·권한 확인

브라우저에서는 기존 기록의 선택과 삭제 확인 창까지만 확인하고 취소했다. 삭제·복원·영구 삭제는 별도의 합성 계정으로 검증했다.

- 실제 API 108개: 소유권, 전체 선택의 원자성, 휴지통 이동·복원, 분리된 부모·자식의 복원 순서, 연결된 녹음·리포트·학습 이벤트, 백업 원본, 영구 삭제, 요청 상태·취소, 다른 기기 로그아웃.
- 새 마이그레이션·RLS 46개: 빈 DB에서 적용 및 비소유 계정의 접근 차단.
- 전체 회귀 1,103개와 bootstrap 31개 통과. 이후 모바일 수정 관련 57개 및 최종 집중 검사 통과. 탐색 경로·렌더 검사 215개 통과.
- 기기 정리는 다른 앱 탭이 열려 있으면 중단한다. 정리 후 이전 세대의 자동 저장은 차단한다. 저장소·브라우저 잠금 지원이 없어도 일반 앱 이용은 유지한다.
- 단독 녹음 삭제는 제출 답변·전사문을 보존한다. 없는 원본의 재생 링크는 숨기고 복원 후 되살린다. 타입별 범위는 확인 창에서 안내한다.
- 타입 검사와 최종 운영 빌드, `git diff --check` 통과.

## 운영 적용

로컬에는 다음 마이그레이션을 적용했다. 운영 DB도 새 코드 실행 전에 적용해야 한다.

- `202610220003_account_data_management.sql`
- `202610220004_account_data_tombstones.sql`
- `202610220005_account_session_revocations.sql`

Supabase 원본 영구 삭제에는 기존 `SUPABASE_SERVICE_ROLE_KEY`가 필요하다. 연결이 없으면 삭제를 시작하기 전에 자료를 보존하고 오류를 안내한다. 전체 자료 삭제·회원 탈퇴는 본인 확인과 실제 처리 후 운영자가 완료 상태를 기록하는 요청 흐름이다.
