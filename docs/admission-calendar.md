## 2026-10-14 첫 가입의 일정 자동 조회·등록

학교 → 그 학교의 학과 → 전형을 고르면 `POST /api/schools/onboarding-calendar`가 저장된 아컨·공식 보완·관리자 설정을 같은 학생용 projection으로 조회한다. 2027학년도 **수시 일정은 2026년 날짜**다. 다른 학년도·캠퍼스·학과·전형이 확정된 날짜와 맞지 않으면 대신 등록하지 않는다.

전형 일치 일정과 학교 참고 일정은 분리하며 출처·확인일·오래된 자료 상태를 표시한다. 면접 미실시(no_interview), 날짜 미정(date_pending), 미공개(unpublished), 미검증/추가 확인(unverified), 원문 미수록은 서로 다른 상태다. 영상 제출 기간도 대면 개인 면접일로 바꾸지 않는다.

최종 학교 등록은 `calendarReview:{fingerprint,acknowledged:true}`를 받는다. 서버가 선택 identity와 현재 근거를 다시 조회해 fingerprint를 비교하고 바뀌면 409로 재확인을 요구한다. 확인된 공개 날짜의 ID·출처와 확인 상태를 `support_targets.data.admission_calendar_registration`에 저장하고 캘린더에서 조회한다. 미실시·미정 등도 현재 확인 상태를 저장해 가입을 끝낼 수 있다.

이 연결은 **공용 일정 등록**이며 `personal_appointment_confirmed:false`다. 공개 기간의 첫날/시작시각을 개인 응시 시각·장소·D-day로 만들지 않는다. 기존 개인 일정·학생 계획을 덮어쓰지 않는다. 첫 등록은 일정 확인을 건너뛸 수 없고 중복 선택은 같은 지원처를 재사용한다.

아래 2026-10-13의 수집/공식 보완/관리자 검증은 각각 해당 범위의 기록이다. 이번 격리 학교 HTTP 검사 42개에서 일정 검토 fingerprint 변경 시 409·쓰기 없음, 학교 소유 학과·지원처 중복 재사용·일정 상태 계약을 확인했다. 첫 사용자의 서울시립대 환경공학부·학생부종합전형Ⅰ(면접형) 선택 → 2027학년도 수시 공개 면접일 2026-11-29 검토 → 등록 → 캘린더 표시도 브라우저와 저장값으로 확인했다. 개인 배정 시각은 생성하지 않았다. 이 한 표본의 확인은 88교 전 학과·전형의 공식자료 전수 확인이 아니다.

## 계정과 달력 연결

등록한 학교 ID·캠퍼스·모집 연도·전형·학과를 대조한다. 원문의 전형과 모집단위를 정확히 대조할 수 있으면 해당 날짜로 좁힌다. 학과명이 변경되었거나 대조가 불완전하면 학교 참고 일정임을 표시하며 개인 응시일로 확정하지 않는다. 범용 캠퍼스 번호에 임의의 지명을 붙이지 않는다.

하린의 서울시립대 환경공학부·학생부종합전형Ⅰ(면접형)은 **2026-11-29** 면접일만 연결된다. 인문 모집단위의 다른 날짜는 들어오지 않는다. 기존에 등록된 개인 시각은 그대로 유지한다. 날짜·전형이 일치하는 단일 공개 면접일과 개인 일정은 화면에서 한 번 보여 주며 양쪽 출처를 구분한다. 공개 일정으로 개인 시각·D-day를 만들지 않는다.

대시보드 캘린더는 기본으로 펼쳐진다. 현재 달에 면접일이 없어도 다가오는 면접 목록이 보이고, 날짜를 누르면 해당 달·날짜로 이동한다. 긴 모집단위 목록은 펼쳐 확인할 수 있다. 확인 불가 일정은 별도 안내에만 표시한다.

## 저장과 갱신

- `admission_calendar_versions`: PostgreSQL의 출처별 불변 수집본.
- `admission_calendar_sync_state`: 마지막 성공본·확인 시각·갱신 시도와 재시도 상태.
- `/api/planner`: 인증된 학생의 지원처에 해당하는 일정만 반환. `targetId`는 소유권을 확인한다.
- 마지막 확인 후 24시간이 지나면 앱의 계획표 조회 응답을 보낸 다음 Next `after()`에서 원문을 다시 수집한다. 앱을 사용하지 않는 동안 실행되는 예약 작업은 아니다.
- 네트워크 오류·원문 구조 변경·불완전한 수집은 이전 성공본을 유지한다. 확인일과 오래된 자료/갱신 지연 상태를 표시한다.
- 기존 `support_targets.schedule`의 개인 날짜·시각·장소와 학생 계획은 덮어쓰지 않는다.

새 환경에서는 migration을 적용한 뒤 전체 원문을 다시 수집한다.

```powershell
node scripts/migrate.mjs
node --import tsx scripts/sync-acon-calendar.mts
```

`--no-db` 옵션은 검증된 JSON만 갱신한다. 기존 JSON을 PostgreSQL에 반복 적재하려면 `node --import tsx scripts/import-admission-calendar.mts`를 사용한다. 동일 수집본의 반복 적재는 새 버전을 만들지 않는다.

## 관리자 면접 일정 관리 (2026-10-13)

관리자 메뉴의 면접 일정(/admin/schedules)에서 기존 아컨·입학처 자료와 수동 등록 일정을 조회하고 추가·수정·삭제·복원할 수 있습니다. 공용 일정과 학교 등록 계정/개인 일정을 별도 탭으로 제공합니다. 계정 탭은 등록한 학교·학과·캠퍼스·전형·학년도, 학생 이름·이메일·계정 활성 여부·등록일·개별 한국 시각을 표시합니다.
