# 각자의답 — HTML 청사진의 부속 스키마와 검증 사례

이 폴더는 2026-11-06 작성한 **각자의답 아키텍처 청사진 v2 HTML**에서 언급한 실제 파일을 별도로 묶은 것이다. 기존 개발설계패키지의 `gakja-blueprint-v2/implementation-contracts/`에 포함된 13개 파일을 그대로 제공한다.

## 포함 파일과 사례 수

| 스키마 파일 | 담당 계약 | 형태 검증 사례 |
|---|---|---:|
| `answer-submission.schema.json` | 텍스트·확정 전사·정상 무응답의 배타적 제출 | 12 |
| `evidence-ref.schema.json` | 학생부·대학 자료·실제 답변·학생 확인 근거 | 11 |
| `playback-event.schema.json` | 실제 재생 시작·완료·중단·실패 이벤트 | 9 |
| `interview-decision.schema.json` | 답변 해석·행동·발생 계기·질문 기능 | 12 |
| `evaluation-scope-approval.schema.json` | 승인된 평가 범위와 버전 연결 | 8 |
| 합계 | 정상 입력 22개 + 거부해야 하는 입력 30개 | 52 |

- `fixtures.json`: 위 52개 입력과 기대 통과/거부 결과.
- `runtime-source-fixtures.json`: 별도의 UTF-16·정확 인용/해시 검증 4개.
- `examples.json`: 개인정보 없는 정상 형태 예시.
- `validate_contracts.py`: 스키마와 fixture를 실제로 검사하는 Python 스크립트.
- `validation-results.json`: 원래 패키지에 포함된 실행 결과.
- `requirements.txt`: 검증 의존성 `jsonschema==4.26.0`.
- `build_contracts.py`: 스키마·fixture를 다시 생성하는 원본 생성 스크립트.
- `README.md`: 기존 상세 설명. 반드시 필요한 서버 검사와 현재 TS 엔진 매핑 포함.
- `delivery-check.json`: 이번 별도 패키지의 파일 동일성·재실행 확인.
- `package-manifest.json`: 원본 파일 및 전달 파일의 SHA-256 목록.

## 검증 실행

ZIP 압축을 풀고 이 파일이 있는 `implementation-contracts` 폴더에서 실행한다. Windows PowerShell 예시는 다음과 같다.

```powershell
python -m pip install -r requirements.txt
Copy-Item validation-results.json validation-results.before-rerun.json
python -X utf8 validate_contracts.py
```

WSL/Linux/macOS는 다음과 같다.

```bash
python3 -m pip install -r requirements.txt
cp validation-results.json validation-results.before-rerun.json
python3 -X utf8 validate_contracts.py
```

이미 의존성이 설치돼 있으면 설치 명령은 생략할 수 있다. 검증기는 새 결과로 `validation-results.json`을 덮어쓴다. 검증 자체에는 API 키·네트워크 호출이 필요하지 않다. 패키지 설치에는 인터넷이 필요할 수 있다.

**검증만 하려면 `build_contracts.py`를 실행할 필요가 없다.** 그 파일은 스키마와 예시를 다시 생성하므로, 원래 파일 그대로 검사할 때는 `validate_contracts.py`만 실행한다. 이 설명이 기존 README의 재생성까지 포함한 명령보다 좁은 검증 목적에 맞는 절차다.

기대 요약은 스키마 5개, `shape_passed=52`, `source_span_passed=4`, `status=passed`이다. 실패하면 프로세스는 0이 아닌 종료 코드를 반환한다. 거부 사례가 실제로 거부되는 것도 검증 통과에 포함한다.

## 이 자료의 범위

이 파일들은 **PROPOSED_NOT_INTEGRATED** 상태의 제안 계약이다. 현재 앱에 적용됐다는 뜻이 아니며 기존 TS 도메인 codec을 바로 교체하는 용도로 쓰지 않는다. TS/Ajv·Pydantic 어댑터, DB 권한·상태·실제 모델 출력·실기기 음성은 별도로 검증해야 한다.

JSON Schema가 검사하는 형태와 서버가 확인해야 하는 사실·권한·상태는 다르다. 예를 들어 offset 순서나 인용 내용이 실제 원문과 같은지 확인하는 것은 별도 source-span 검사이며, 근거를 읽을 권한이 있는지는 DB/서버 검사다.

이 52개는 실제 앱 테스트 1,202개, 실제 답변 의미 검수 45회, 이후 작성한 **4대 구현 정책의 수용 사례 51개**와 각각 다른 자료다. 후속 정책 명세에서 추가한 공통 분석 분리·목적 승계·시간/재고·발행 승인 규칙을 이 스키마들에 이미 구현했다고 해석하면 안 된다.
