## 공통 캔버스와 좌표

제작 마스터는 **1920×1080, sRGB, 16:9**로 정한다. 원본 640×360은 정확히 3배 좌표로 대응한다. 1672×941 후보는 비율 차이가 있으므로 한 번의 균일한 contain 변환으로 정렬하고 극소 여백을 복원한다. 가로·세로를 따로 늘려 얼굴을 변형하지 않는다. 단순 확대는 세부 원화 복원의 대체물이 아니다.

모든 파츠·마스크·레이어는 동일한 마스터 원점 `(0,0)`을 사용한다. 제작 기록의 정규 좌표는 `u=x/1920`, `v=y/1080`이며 원점은 왼쪽 위, 오른쪽·아래가 양수다. 실행용 `SceneModel.layout`의 `centerX`, `centerY`, `width`, `height`는 **공통 캔버스의 픽셀 단위**다. 정규 좌표 기록을 실행 설정에 옮길 때 X·width에는 1920, Y·height에는 1080을 곱한다. 예를 들어 `(u=.3,v=.5,width=.4,height=.8)`은 `{centerX:576,centerY:540,width:768,height:864}`다. 이는 단위 변환 예시이며 최종 모델 배치값이 아니다. Cubism 내부 좌표계 변환은 어댑터 한 곳에서 수행한다.

제공 이미지에서 대략적인 얼굴 중심은 남성 `(u≈0.31,v≈0.25)`, 여성 `(u≈0.73,v≈0.28)`이다. 이는 구도 확인용 관찰값이며 모델의 피벗이나 확정 layout 값이 아니다. 최종 원화에서 머리·목·어깨·팔꿈치·손목·손과 펜 접촉점·책상 경계의 좌표를 다시 측정한다.

레이어별 위치 기록에는 다음을 포함한다.

- 기준 캔버스, 레이어 이름, 실제 파일명, 비어 있지 않은 RGBA 영역의 경계
- 회전·변형 피벗의 정규 좌표와 마스터 픽셀 좌표
- 앞뒤 관계, 상위 변형 그룹, 클리핑·접촉 상대
- 허용 변형 범위, 노출 시 복원해야 할 영역, 제작 버전

실행용 장면 레이어는 마스터와 같은 크기의 PNG로 납품한다. 손·머리 파츠를 자를 때는 위치를 잃지 않도록 PSD 좌표 또는 별도 파츠 등록표를 함께 유지한다. 알파는 실제 채널이며 체크무늬를 그림에 넣지 않는다. 정적 배경은 완전 불투명이어도 되지만 인물·전경 분리 파일은 실제 투명 영역이 필요하다.

화면에는 전체 장면을 한 번만 contain 배치한다. 배경·몸통·책상을 각기 `object-fit: cover`로 조정하지 않는다. 모바일 세로에서도 두 사람이 함께 보이는 가로 장면을 먼저 확보하고 자막·녹음·카메라·조작을 별도 영역에 배치한다.

## 장면 원화와 두 단계 가림

배경은 사람·의자·책상과의 겹침을 확인한 뒤 인물 자리를 복원한다. 움직이는 머리·몸·손의 뒤에 원래 인물의 잔상이 남아 있으면 불합격이다. 의자는 등받이와 팔걸이를 필요한 깊이로 분리한다. 머그컵·노트·서류·펜은 손과 교차하는 부분만 필요한 단위로 나눈다.

**1단계 — 몸통 뒤와 책상 상판:** 방 배경과 의자 뒤에 몸통을 배치하고, 책상 상판의 실제 경계가 몸통 하단·무릎 쪽을 가려야 한다. 소매가 책상에 닿는 부분의 그림자는 팔에 붙는 그림자와 상판에 투영되는 그림자를 구분한다. 허리·소매 아래가 드러날 수 있는 작은 범위까지 원화를 복원한다.

**2단계 — 상판 앞의 손과 접촉 소품:** 상판보다 앞에 팔뚝의 노출 부분·손목·손·펜을 그린다. 펜은 손가락 앞뒤로 나뉘는 접촉 관계를 유지하고, 손가락은 책상에 놓인 노트·서류를 필요한 부분만 가린다. 노트의 앞 표지나 종이 모서리가 손 앞에 오는 경우 별도 전경 조각을 둔다. 책상 전면·앞쪽 테두리는 상판·몸통 아래쪽을 가리되 책상 위 손을 덮지 않는다. 컵 뒤로 손이 들어갈 때만 컵의 앞면/손잡이 전경이 손을 가린다.

목표 깊이의 예는 `방/의자 뒤 → 몸통 → 책상 상판 → 팔·손·펜/접촉 물체 → 책상 앞 테두리/필요 전경`이다. 머리와 목·안경·머리카락의 내부 순서는 캐릭터 모델 안에서 따로 관리한다.

현재 `SceneManifest`는 전체 모델을 order 100/110으로 그리는 계약이다. 이것만으로 한 모델의 몸통과 손 사이에 상판을 넣을 수 없다. 최종 제작 시 다음 중 하나를 선택하고 실제로 검증해야 한다.

1. 몸통과 손의 drawable을 분리하여 책상 전후에 두 번 그린다. SDK 마스크·그림자·블렌딩이 각 패스에서 유지되는지 어댑터를 검증한다. 현재 계약을 확장해야 하므로 구현 완료로 간주하지 않는다.
2. Cubism 리깅에서 몸통 하단을 책상 경계에 맞춰 클리핑하고 손은 그 마스크에서 제외한다. 이때 상판은 모델보다 앞 순서로 먼저 그리고, 잘린 몸통과 책상 위 손을 포함한 모델을 그린 후, 앞 테두리·필요 소품을 그린다. 카메라와 책상은 고정이며 경계가 바뀌는 제스처는 추가 검증이 필요하다.

위 두 경로 모두 미검증이다. 승인 전에는 `ParamQuestionGesture=0`, 손 고정 기본 자세만 허용한다. 완성된 가림이 없는 상태에서 큰 팔 동작을 추가하지 않는다. 여성의 손·턱 접촉 포즈는 기본 자세에서 제외하며 접촉 리깅 승인 전에는 사용하지 않는다.

## 캐릭터 파츠 규격

얼굴 베이스, 귀·목·필요 피부, 좌우 눈썹, 좌우 눈의 흰자·홍채·눈꺼풀, 입술·입안·치아·필요 혀, 앞·옆·뒷머리, 옷·몸통, 상완·전완·손·펜, 필요한 그림자·하이라이트를 동작 범위에 따라 분리한다. 안경은 코받침·좌우 테·다리·반사 중 실제 변형에 필요한 부분만 분리하고 얼굴과 같은 변형 계층을 사용한다. 귀걸이·시계도 접촉 신체를 따라가야 한다.

눈 뒤 피부, 머리카락 뒤 얼굴, 턱 아래 목, 소매 안·뒤 몸통, 손가락 뒤 펜과 상판을 복원한다. 파츠 파일에는 이름표·설명·경계선을 그리지 않는다. 파츠 목록 PNG는 미리보기일 뿐 PSD 납품이 아니다. 남성을 먼저 제작하여 얼굴·립싱크·가림을 승인한 뒤 여성 모델을 같은 규격으로 제작한다.

## 모션·표정과 음성 소유권

| 계획 모션/표정 | 사용 조건 | 금지되는 충돌 | 제작 상태 |
|---|---|---|---|
| neutral / ready | 초기 준비 완료·발화 사이 | 입 열림 없음 | 파일 미제작 |
| restrained-smile | 인사 구간, 짧게 적용 후 중립 | MotionSync 입 모양 덮어쓰기 없음 | 파일 미제작 |
| focused | 질문·경청의 낮은 강도 | 정답/오답 평가 신호 없음 | 파일 미제작 |
| listening | 학생 답변 | 두 사람 입 0, 큰 손짓·반복 끄덕임 없음 | 파일 미제작 |
| question-gesture | 발화 중 선택적 1회 | 기본 자세 복귀·손 가림 승인 전 비활성 | 차단됨 |
| settle / pause | 취소·일시정지 | 입이 열린 채 정지하지 않음 | 실제 리깅 검수 필요 |

`interviewer-1`은 남성 primary 음성, `interviewer-2`는 여성 secondary 음성으로 연결한다. 실제 재생의 `playing`에서 설정한 `{turnId,speakerId}`와 공유 오디오의 재생 위치·정지·종료를 기준으로 한다. 학생 마이크 PCM은 녹음·전사로만 흐르며 립싱크 입력으로 사용하지 않는다. 장면은 기존 음성을 두 번째로 재생하지 않는다.

MotionSync 모드에서는 내보낸 설정의 `CubismParameters` 대상 ID 전체가 입 제어의 소유자다. 질문·대기·표정 모션과 director의 진폭 입 값이 이 ID들을 덮어쓰지 않도록 어댑터 업데이트 순서를 정한다. 무음·중단·학생 답변에는 해당 모델의 Silence/닫힌 입 값을 적용한다. 진폭만으로 모음 입 모양이나 한국어 발음 일치를 구현했다고 표시하지 않는다.

SDK 버전·Core 획득·CLOVA 저장/재사용 정책은 [공식 문서 조사](sdk-research.md)를 따른다. 실제 계약을 확인하기 전에는 기존 음성 영구 캐시가 허용된다고 가정하지 않는다. 모델·텍스처 캐시와 생성 음성 저장은 별도 정책이다.

## 정적 에셋 검사와 실제 검수

```text
node scripts/verify-live2d-assets.mjs --report artifacts/live2d-asset-check.json
```

검사는 장면 설정, 두 모델의 참조, 실제 비어 있지 않은 파일, PNG 기본 구조·캔버스 크기·레이어 알파 채널, model3의 Moc/Textures/Physics/Motions/Expressions/MotionSync JSON 구성을 확인한다. 누락·빈 자리 파일·외부 URL·공개 디렉터리 밖 링크·blocked 상태는 exit 1이다. `--manifest`와 `--public-root`는 별도 제작 폴더/검사 fixture에 사용할 수 있다.

보고서 `status: ready`는 **정적 참조 검사만 통과**했다는 뜻이다. `scope: static-asset-integrity`, `runtimeValidation: not-run`, `releaseReady: false`를 함께 기록한다. 특히 `.moc3`의 확장자·파일 크기·해시·첫 바이트 기록은 Core의 실제 로드 검증을 대신하지 않는다. 임의 텍스트를 확장자만 바꾼 파일, 비어 있는 설정, 샘플 모델을 전용 모델 납품으로 승인하지 않는다. 이 스크립트는 MOC3 형식을 추측하여 magic/version을 판정하지 않는다.

참조 JSON 필드의 근거는 [공식 Web ModelSetting 구현](https://github.com/Live2D/CubismWebFramework/blob/5-r.5/src/cubismmodelsettingjson.ts), [공식 MotionSync 모델 설정](https://github.com/Live2D/CubismWebMotionSyncComponents/blob/5-r.3/Samples/Resources/Kei_vowels/Kei_vowels.model3.json), [공식 MotionSync 설정 예](https://github.com/Live2D/CubismWebMotionSyncComponents/blob/5-r.3/Samples/Resources/Kei_vowels/Kei_vowels.motionsync3.json)다. 공식 샘플은 형식 확인용이며 전용 면접관 대체물로 사용하지 않았다.

최종 출시 전 다음의 실제 증거를 따로 남겨야 한다.

- 실제 모델 로드·Core 호환·텍스처/마스크·파라미터 매핑·손/책상 두 단계 가림·최대 회전에서 빈틈 없음
- 대학명·학과명·숫자·영문 약어를 포함한 실제 CLOVA 질문의 시작·무음·종료·취소·두 발화자 교대 립싱크
- 학생 발화 때 두 입이 닫히는지, 재개·백그라운드·오디오 장치 전환·외부 전화 중단 후 복구되는지
- 웹과 지정 Expo/WebView 실제 기기에서 두 모델·카메라·녹음/전사·시선 분석·자막 동시 실행
- 지원 하한 기기를 먼저 지정한 뒤 30FPS 목표, 텍스처 메모리·드로우콜·마스크·메쉬·물리 비용·장시간 메모리·발열·배터리 측정
- 편집 원본·내보내기 버전·SDK/Plugin/Core 버전/해시·에셋 및 상용 배포 라이선스 확인

현재 전용 원화/모델과 검증된 Core가 없어 위 항목은 차단됨 또는 미검증이다. 하한 기기도 지정되지 않았다. 정적 대체 이미지 표시나 코드 테스트 통과를 이 검수의 성공 결과로 기록하지 않는다.
