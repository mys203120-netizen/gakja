## 실제 수행한 검증

각 `psd-verification.json`은 저장된 PSD를 다시 읽어 레이어 RGBA 바이트·알파·이름·순서·그룹·좌표·숨김 상태·RGB8·ICC가 원본 PNG 입력과 일치함을 기록한다. 가져오기 PSD는 아트 레이어 35개이며 모두 표시 상태다. 원본 PSD에만 참고 레이어 2개를 숨겨 두었다. 단일 평면 이미지를 복제하여 레이어 수를 채우지 않았다.

PSD 합성 미리보기의 8bit white-matte 변환은 사용한 ag-psd 버전의 절삭·반올림을 픽셀 단위로 재현해 예상 결과 바이트와 일치하는지 확인했다. 독립 레이어 RGBA와 알파 검증은 이 허용 오차와 별개로 정확한 바이트 비교다. 이 파일 검사로 Photoshop/Cubism의 실제 가져오기를 검증했다고 표시하지 않는다.

`source-artwork-inspection.mjs`로 실제 소스 6개의 RGBA8·실알파·크기·SHA·경계를 검사했다. ImageGen이 일부 보완 원화를 1671×941로 내보내, 추출 시 오른쪽에 투명 열 1픽셀만 추가했다. 원화를 늘리거나 이동하지 않았으며 `parts-provenance.json`에 기록했다.

모션 파일 18개의 증가하는 시간, 제한된 Bezier 구간/점 수, 계획 ID·범위·중립 시작/끝·해시를 검사했다. 입 곡선은 0개이며 손 제스처는 0, 경청에는 반복 끄덕임을 넣지 않았다. 손상 사례 12개를 거부하는 검사도 수행했다. 관련 장면/재생 정체성 테스트 13개가 통과했다. 이 결과는 실제 모션 재생·립싱크·실기기 성능 검수와 다르다.

## 남은 제작 사항

파츠는 실제로 독립되어 있으나, 눈꺼풀/홍채/안경의 가림, 입안/치아/입술의 키폼, 경계 블렌딩, 변형 시 드러나는 팔·소매/손의 전체 보완은 실제 리깅에서 확인해야 한다. 기본 자세의 파츠 분리를 곧바로 완성 리깅 원화 승인으로 바꾸지 않는다. 이전 네 가지 외형 보정을 다시 요구하는 것이 아니라 새로 분리한 파츠의 기능과 변형을 검증해야 한다는 뜻이다.

현재 환경에서 Cubism Editor를 찾지 못했다. 공식 SDK는 이미 내보낸 모델을 표시·제어하며 PSD→MOC3 저작 도구를 대신하지 않는다. 검증된 공식 CLI 저작/내보내기 경로도 확인되지 않았다. Computer Use 금지 지시를 지키므로 GUI를 통한 설치·가져오기·리깅·내보내기를 수행하지 않는다. 자세한 공식 근거는 `authoring-tools.md`에 있다.

실제 Editor에서 두 PSD를 가져와 메쉬·디포머·입 2축/눈/고개/호흡 키폼을 제작하고, `.cmo3`·`.can3`와 실행 에셋을 내보낸 뒤에야 웹·앱의 최종 검수로 이어갈 수 있다. 현재 장면의 `blocked` 상태와 `releaseReady:false`를 유지한다.
