# 공식 SDK 렌더러 연결

이 폴더의 `renderer.mjs`는 실제 Cubism Web Framework와 MotionSync Plugin 소스를 가져다 쓰는 애플리케이션 어댑터다. 전용 면접관 모델이나 Core 바이너리를 포함하지 않는다. 현재 Core·모델이 없어 실제 모델 표시와 립싱크 품질은 미검증이다.

## 재현 가능한 빌드

프로젝트 루트에서 실행한다.

```text
node scripts/setup-live2d-sdk.mjs
```

Git과 설치된 `esbuild`가 필요하다. 스크립트는 공식 공개 저장소의 고정 태그·커밋을 확인하고 소스를 `node_modules/.cache/live2d-sdk`에 둔다. 기존 소스가 다른 버전이거나 수정되어 있으면 덮어쓰지 않고 종료한다. 공개 소스 사용 조건은 생성된 `public/live2d/runtime/licenses`에서 확인한다.

출력은 `public/live2d/runtime/renderer.mjs`, `shaders/`, `licenses/`, `provenance.json`이다. provenance에는 실제 커밋·빌드 도구 버전·파일 크기·SHA-256을 기록한다. `runtimeVerified: false`는 실제 모델·Core를 실행하지 않았다는 뜻이다.

## 별도로 필요한 파일

- Cubism SDK for Web R5 공식 배포 패키지의 Core와 그에 딸린 파일.
- MotionSync 사용 시 Plugin Web R3 공식 배포 패키지의 `Core/CRI` 내용 전체. 파일 이름을 바꾸거나 `.wasm` 등 동반 파일을 임의로 생략하지 않는다.
- 두 전용 면접관의 `.model3.json`, `.moc3`, 텍스처, 선택적인 물리 설정, 모델과 일치하는 `.motionsync3.json`.
- 장면 배경·전경의 실제 알파 레이어와 검수한 좌표.

Core는 공식 배포 패키지의 사용권을 확인한 뒤 제공해야 한다. setup은 Core를 다운로드하거나 사용권 동의를 대행하지 않는다. 모델이 준비되기 전에는 manifest의 `status`를 `blocked`로 유지한다.

## 애플리케이션 계약

`lib/live2d/types.ts`의 `SceneRenderer` 계약을 따른다. 브라우저 장면 호스트가 manifest에 지정한 Core 스크립트를 먼저 로드한 다음 빌드 결과를 동적으로 가져와 `createRenderer()`를 호출한다. 어댑터는 오디오를 재생하거나 학생 마이크를 열지 않는다. 호스트가 실제 출력 오디오의 `turnId`, `speakerId`, `src`, `timeSeconds`, `playing`을 매 프레임 전달한다.

`prepare`는 같은 출처의 모델·텍스처를 읽고 moc3 일관성 검사를 요청한다. `render`는 상태·파라미터·현재 출력 오디오 위치를 적용한다. `resize`는 장면 전체를 하나의 비율로 맞춘다. `dispose`는 진행 중인 자체 요청과 음성 디코딩을 무효화하고 모델·텍스처·WebGL 버퍼·프로그램·SDK 참조를 해제한다. 에러는 호스트에 전달되어 학생 답변 저장 경로와 분리된다.

공식 R5는 모듈 평가 시 Core 상수를 읽으므로 **Core 로딩은 동적 import보다 먼저 완료**해야 한다. 준비 중 해제와 셰이더 요청의 경쟁을 피하려고, 셰이더 소스는 취소 가능한 자체 요청으로 먼저 읽은 뒤 R5의 선언된 필드와 공개 `registerShader`·`registerBlendShader` 함수로 동기 등록한다. 이 부분은 고정한 R5 소스 구조에 의존하므로 SDK를 올릴 때 재검증해야 한다. 하나의 캔버스에 동시에 두 렌더러를 준비하는 것은 거부한다.

모델은 manifest 배열 순서대로 100·110에서 그리고, 정적 레이어는 명시한 `order`에 끼워 넣는다. 따라서 몸통을 가리는 책상 레이어와 책상 위 손의 관계는 실제 원화·모델의 메쉬/마스크·전경 구성에서 해결해야 한다. 이 렌더 순서만으로 모든 손 가림이 자동 해결되지는 않는다.

`layout`은 **기본 모델 메쉬 전체 경계가 들어갈 픽셀 사각형**이다. `centerX`, `centerY`는 장면의 왼쪽 위를 기준으로 한다. 초기 메쉬의 모든 drawable 경계를 한 번 계산하고 원래 비율을 유지하여 해당 사각형에 맞춘다. 숨겨진 포즈용 메쉬가 크게 떨어져 있으면 경계가 커질 수 있으므로, 최종 리깅에서 경계를 확인하여 layout을 조정해야 한다. 자동 얼굴 검출이나 원화 캔버스의 피벗 복원을 수행하지 않는다.

## 립싱크 구현 범위

- `amplitude`: 호스트가 출력 음성에서 얻은 입 파라미터 값을 현재 발화자에게만 적용한다. 이 경로를 공식 MotionSync 결과로 표시하지 않는다.
- `motion-sync`: 같은 출처의 현재 출력 음성을 메모리에서 디코딩하여 48kHz mono PCM으로 만든다. 실제 재생 위치까지의 PCM만 해당 면접관의 공식 `CubismMotionSync`에 전달하고 처리한 샘플을 버린다. 음성을 추가 재생하지 않는다. 입력은 현재 턴에만 유지하며 디스크 캐시를 만들지 않는다.
- 출력 음성 URL에 한해 같은 출처의 `blob:`도 허용하여 기존 플레이어의 메모리 사전 로드와 연결한다. 모델·텍스처·셰이더는 HTTP(S) 같은 출처만 허용한다. 디코딩 결과는 300초로 제한하며, 분석기가 진행하지 않아 대기 PCM이 0.5초를 넘으면 장면 오류로 처리한다.
- 다른 턴·취소된 디코딩 결과는 버린다. 새 발화와 큰 재생 위치 변경에서 분석 상태를 재생성한다. 무음·일시정지·학생 답변·다른 면접관 발화에서는 입 파라미터를 기본값으로 복귀시키고 `ParamMouthOpenY=0`을 적용한다.
- 입 파라미터는 물리 업데이트 뒤에 적용한다. MotionSync 설정이 참조하는 파라미터가 모델에 없으면 준비를 실패시킨다. 모델별 실제 기본 입 모양은 원화·리깅 검수가 필요하다.

어댑터는 `ParamMouthOpenY`가 실제 모델에 있음을 확인한다. 그 외 눈·호흡·고개 등의 값은 호스트가 전달한 ID 중 실제 모델에 있는 것만 적용한다. 모션 파일 재생, 제스처의 팔 메쉬 전환, 표정 모션 파일 로딩은 이 어댑터에 아직 구현하지 않았다. 정해진 파라미터 제어와 실제 제작된 리깅으로 표현 가능한 범위까지만 움직인다.

실제 파일로 빌드했다는 사실과 전용 모델을 실행했다는 사실은 구분한다. 현재 수행한 검증은 고정 소스 확보·어댑터 구문 확인·번들 생성이며, 한국어 발음·모바일 오디오 중단·30FPS·장시간 실행 검수는 남아 있다.
